## Step 1: Extend the shared navigator without changing existing defaults

**Interfaces**: `runNavigator(options: { mode: 'single'|'multi'; question?: string; options: string[]; defaultSelected: string[]; input?: object; output?: object; footer?: string|null; preventEmptyConfirm?: boolean }) -> Promise<{ status: string; items?: string[] }>`; `promptSelect(question: string, options: string[], input?: object, footer?: string|null) -> Promise<string|symbol|null>`; `promptChecklist(items: string[], defaultSelected: string[], input?: object, footer?: string, navigatorOptions?: { preventEmptyConfirm?: boolean }) -> Promise<{ status: string; items?: string[] }>`.

**Test assertions**:

- A multi-select navigator with no marked items and `preventEmptyConfirm: true` remains open after Enter and produces no confirmed empty selection; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Opt-in empty-confirm protection`, Scenario `Model checklist refuses an empty confirmation`.
- The same navigator with the option omitted or false preserves the existing empty-confirm result; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Opt-in empty-confirm protection`.
- `promptSelect` without a footer forwards `Up/Down move · Space/Enter confirm · ←/Esc back · q/Ctrl-C cancel` to `runNavigator`; an explicit `null` footer forwards no footer; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Visible selection-screen back affordance`.
- The installer `main()` `promptChecklist` call omits the guard, while the model-customization call is the sole enabled call; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Opt-in empty-confirm protection`, Scenario `Installer first screen keeps its empty-confirm exit`.
- Static production-surface checks find exactly seven `promptChoice` invocations, three default `promptSelect` bindings, and one explicit no-footer post-setup menu override; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Visible selection-screen back affordance`.

## Step 2: Integrate cyclic passes, diagnostics, and setup exit mapping

**Interfaces**: `runPostSetupMenu(options?: object) -> Promise<{ status: 'skipped'; reason: 'cancelled'|'settings-unavailable'|'non-tty'; skippedAgents: string[]; diagnostics: string[] } | { status: 'completed'; skippedAgents: string[]; diagnostics: string[] } | { status: 'persistence-failed'; failedAgents: string[]; diagnostics: string[] }>`; `materializeLocalOverride(options: object) -> { status: 'persisted'|'skipped'|'persistence-failed'; diagnostic?: string }`; `main() -> Promise<void>` maps the final customization status to process exit status without rendering target diagnostics.

**Test assertions**:

- After one completed selected-target pass, the next menu prompt starts with a fresh adapter, harness, scope, targets, settings, outcome, and diagnostics record; each new single-select starts at index 0 and the checklist starts at index 0 with every enumerated target selected; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Cyclic post-setup customization passes`, Scenario `A later pass starts with no selections from the prior pass`.
- A completed pass emits each skipped or failed target diagnostic once in selected-target order before the next menu or termination; persisted targets emit none and earlier-pass diagnostics are not repeated; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Post-setup pass diagnostics and exit status`, Scenarios `Diagnostics are emitted once for a completed pass`, `Diagnostics remain separated across passes`, and `Mixed target outcomes keep diagnostic order and omission`.
- After a target reports `persistence-failed`, every remaining selected target is attempted once, the pass terminates without another menu, and `runPostSetupMenu` returns the collected failed-agent and diagnostic record; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Post-setup pass diagnostics and exit status`, Scenarios `Persistence-failure diagnostics are emitted before termination` and `Remaining targets are attempted after a persistence failure`.
- In a completed pass, a skipped target contributes exactly `Skipped <name>: installed source is unavailable.` and appears in `skippedAgents`; in a persistence-failed pass, its name is omitted from `failedAgents` and represented by that diagnostic alone. A failed target contributes its non-empty returned diagnostic and appears in `failedAgents`; persisted targets contribute neither; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Post-setup pass diagnostics and exit status`.
- A non-empty checklist invokes settings exactly once, forwards identical settings to every selected target including a `Both`-scope set, and never invokes settings after an empty confirmation; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Shared settings selection`, Scenarios `Settings selector runs exactly once per customization pass`, `Same settings applied to every selected target`, `Both scope applies one settings pass across both families`, and `Empty confirmation never reaches settings`.
- Selecting `Exit` after zero or more successful passes returns a normal cancelled result and setup exits 0; a persistence-failed result exits non-zero; an unexpected exception follows the existing `post-setup-failure` catch and exits non-zero; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Post-setup pass diagnostics and exit status`, Scenarios `Exit after successful passes is successful`, `Exit before any pass is a normal cancellation`, and `Persistence failure is non-zero`.
- Harness, scope, Claude settings, and OpenCode provider/model/variant selectors use the default single-select legend; the post-setup menu explicitly suppresses its footer; the target checklist keeps the multi-select legend; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Visible selection-screen back affordance`, Scenarios `Single-select screens announce back`, `The checklist announces back and toggle behavior`, and `The first menu does not announce back`.
- A pass whose targets all persist produces no diagnostic output and still re-enters the menu, while a non-TTY invocation returns before the first menu and an unexpected materialization exception reaches the existing failure path; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirements `Cyclic post-setup customization passes` and `Post-setup pass diagnostics and exit status`, Scenarios `Non-interactive setup does not enter the cycle` and the diagnostics/exception rules.
- A scope that enumerates no targets emits the documented empty-enumeration notice, returns to scope selection, does not render a zero-row checklist, and does not invoke settings; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Navigable target-selection checklist`, Scenario `Empty target enumeration returns to scope`.
- Cancelling on a later pass preserves overrides from earlier successful passes and exits normally with status 0; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Post-setup pass diagnostics and exit status`, Scenario `Cancellation preserves earlier passes`.
- Cancelling at the post-setup menu, harness, scope, target checklist, or settings screen stops the current cycle without presenting another screen; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Cyclic post-setup customization passes`, Scenario `Cancellation terminates the current cycle without rollback`.
- Back from harness, scope, target, or settings returns to that screen's predecessor without creating an override or completing a pass; traces to `openspec/changes/cyclic-post-setup-menu/specs/model-customization-menu/spec.md` Requirement `Cyclic post-setup customization passes`, Scenario `Back navigation abandons only the current unmaterialized path`.
