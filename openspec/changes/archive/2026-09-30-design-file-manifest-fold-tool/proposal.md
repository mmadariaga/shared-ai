> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

`sai/commands/design/steps/tasks.md` (the largest instruction file in the design chain) spelled out the File Manifest net fold as a prose state-transition table, and `sai/commands/design/steps/design.md` also pre-planned the same manifest. The model therefore folded the manifest twice and had to reconcile the two results. Moving the fold into a deterministic tool makes the manifest reproducible and removes the duplicated instruction text.

## What Changes

- Add `sai/tools/file-manifest.js` with two sub-commands: `fold`, which writes the net-folded `### File Manifest` into `design.md`, and `verify`, which compares the persisted manifest with the fold without writing. Both accept `--json` and `--cwd`.
- The tool reproduces the existing transition table of the `design-target-state` capability (step attribution, byte-wise sort by destination path, the `None — no files affected` sentinel) and is idempotent.
- The tool fails with a located diagnostic and writes nothing on a malformed `**Files Affected**` entry, an illegal transition such as `M` after `D`, a `tasks.md` with no entries, or a `design.md` with nowhere to hold the manifest. It creates a missing `### File Manifest` beneath `### Architecture Snapshot`.
- Replace the prose fold table in `sai/commands/design/steps/tasks.md` with a call to the tool after `tasks.md` is fully written; a non-zero exit is blocking.
- Stop pre-planning the manifest in `sai/commands/design/steps/design.md`; the manifest appears only after the tasks step runs the tool.
- Align `sai/commands/design/change-overview.md` so its manifest cross-check uses the tool's `verify` verdict.
- List `file-manifest.js` and its invocation form in `sai/policies/tool-resolution.md` and in the `AGENTS.md` tools inventory. The existing `sai-tools` projection installs the tool for both Claude Code and opencode with no new manifest entry.
- Add `test/file-manifest-tool.test.js`, which pins the transition table, the write and verify behavior, the diagnostics, and the projection.

## Capabilities

### New Capabilities

- `design-file-manifest-tool`: deterministic fold and verification of the design File Manifest by `sai/tools/file-manifest.js`, called from the design tasks step.

### Modified Capabilities

- `design-phase-consolidation`: the requirement about where the file-manifest algorithm lives now points at the tool invoked from the tasks step.

## Impact

- New files: `sai/tools/file-manifest.js`, `test/file-manifest-tool.test.js`.
- Modified files: `AGENTS.md`, `sai/commands/design/change-overview.md`, `sai/commands/design/steps/design.md`, `sai/commands/design/steps/tasks.md`, `sai/policies/tool-resolution.md`.
- Trade-off accepted: `design.md` no longer carries a pre-planned manifest before tasks exist; the manifest appears only after the tasks step runs the tool.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
