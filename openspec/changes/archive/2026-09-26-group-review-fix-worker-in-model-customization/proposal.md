## Why

The review-fix worker applies review findings, yet the All model-customization table showed it among unrelated workers at the end because it had no command association in the display ordering. Placing it with the review worker makes its relationship to review visible without changing worker execution or model settings.

## What Changes

- `bin/model-customization.js`: the `sai-5-review` block in `COMMAND_WORKER_ORDER` now lists `sai-review-fix-worker` immediately after `sai-5-review-worker`.
- All checklist order is now `command:sai-5-review`, `worker:sai-5-review-worker`, `worker:sai-review-fix-worker`, then `command:sai-6-security`.
- `test/model-customization-menu.test.js`: combined ordering constant and All grouping slice boundaries updated to match the new order.
- Regression coverage added for All adjacency, filtered Workers alphabetical order, and missing-worker display without empty or duplicate rows on both OpenCode and Claude Code.
- The fix worker is shown once beside `sai-5-review` rather than repeated under both review commands.

## Capabilities

### New Capabilities

None — this change introduces no new capability; it repositions an existing worker in the display order.

### Modified Capabilities

- `model-customizer-grouping`: the review-fix worker is presented in the review group in All scope, while the filtered Workers view keeps alphabetical ordering and unavailable workers are omitted without empty or duplicate rows on both harnesses.

## Impact

Modified files:

- `bin/model-customization.js` — `sai-5-review` block pairs `sai-review-fix-worker` behind `sai-5-review-worker`.
- `test/model-customization-menu.test.js` — combined ordering, slice boundaries, and new coverage for All order, Workers alphabetical order, and missing-worker handling on both harnesses.

New files: none.
