## Why
Generic merge and squash subjects say nothing about what entered. Listing every contained commit as bullets makes the synthesized message an inventory of the work it introduces.

## What Changes
- Add a single-source **Informative messages** rule in `sai/commands/merge/coordinator.md`, referenced from Launch (squash creation) and Authorization (merge finalization).
- Keep the synthesized subject as today within 50 characters, then append a body listing every contained commit enumerated with `git log --reverse --format=%s <range>`, one `- <first line>` per line in that order, literal with no reformat, translation, or hash, all commits with no truncation, with a blank line between subject and list and each bullet kept on one line even past 72 characters with no rewrap or trim.
- Use `merge_base..source_sha` for merge finalization and `merge_base..HEAD` for squash creation (the current-branch uniques before the soft reset).
- Emit the subject alone when the range is empty; emit one bullet for a single contained commit, never folded into the subject; reflect only contained commits so conflict resolution adds or removes no bullets; carry no list for plain rebase or a finished rebase with nothing staged.
- Rewire the `rebase-squash` squash commit and the merge finalization commit to the informative message instead of the generic commit-rules composition.

## Capabilities
### New Capabilities
- None — all behavior modifies the existing merge command.
### Modified Capabilities
- sai-merge-command: synthesized merge and squash messages carry an inventory body listing every contained commit.
