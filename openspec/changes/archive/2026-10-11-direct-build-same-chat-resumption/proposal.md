## Why

An interrupted Direct Build - Unattended execution previously returned to initial route selection and could initialize a fresh attempt. This exposed incompatible Plan choices and risked repeating implementation, reconstructing an available agent's context, resetting recovery counters, or renewing an existing commit authorization. Same-conversation resumption now continues retained pending work.

## What Changes

- Added `resume-direct-build` to consume the first pending Direct Build slice's parked stage without a new route-choice activation.
- Made initial route selection reject a parked Direct Build execution with `RESUMPTION_REQUIRED`.
- Separated pending-execution decisions from the initial three-route selector.
- Defined conversation-only retained execution state in the Direct Build route, including role handles, opaque histories, pending internal step, accepted checks, verification references, counters, and commit-authorization consumption.
- Required continuation of the corresponding existing agent before permitted replacement, using existing reconstruction and recovery contracts.
- Required unchanged validator input and accepted checks before step advancement; rejected responses preserve existing changes.
- Preserved immutable slice references while closing and reopening window-local no-commit guards at human boundaries.
- Required verification of uncertain execute effects and single consumption of the original local-commit authorization.
- Added machine and instruction-contract tests and documented equivalent Claude Code and opencode behavior.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `explore-pipeline-selector`: distinguish initial selection from decisions for pending Direct Build work.
- `explore-slice-machine`: resume the first pending Direct Build slice at its saved stage without creating a new execution.
- `unattended-resilience-rule`: preserve existing recovery limits and use pending-execution decisions for same-conversation Direct Build stops.
- `direct-build-commit-coverage`: retain slice verification references and consume the original commit authorization once.
- `explore-pipeline-supervision`: retain execution context, continue the corresponding agent, and advance only after accepted results and checks.
