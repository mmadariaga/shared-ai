**Complexity**: high

## Why

The backlog skills supported GitHub but could not import or publish the agreed issue workflow against GitLab. The implemented adapters reuse authenticated glab for project resolution and structured issue operations.

## What Changes

- Register GitLab through the existing provider-owned resolution seam, retaining GitHub host and domainless-reference precedence.
- Import canonical GitLab issue content and all user comments; preserve retrieved content when pagination fails.
- Create GitLab issues without board insertion and update only the originating issue's title and description after exact confirmation.
- Verify publication from remote reads and retain private receipts for conservative, non-creating recovery.
- Generalize common creation confirmation while retaining GitHub's issue-and-Project question.
- Add simulated-glab tests, fail-closed issue-enablement checks, and both-harness projection coverage.

## Capabilities

### New Capabilities

- `gitlab-issue-publication`: Exact confirmed creation and origin updates, remote verification, private receipts, and read-only recovery through glab.

### Modified Capabilities

- `from-backlog-conversation-import`: Apply the existing conversation-preserving read-only boundary to every selected provider.
- `from-backlog-provider-resolution`: Ship GitLab fallback resolution and structured, paginated issue retrieval alongside GitHub.
- `from-backlog-harness-installation`: Include the GitLab import adapter and provider reference in mirrored installation.
- `to-backlog-conversation-capture`: Make creation confirmation provider-specific and Project presentation conditional.
- `to-backlog-provider-resolution`: Ship GitLab publication mechanics and resolve GitLab origins through their provider.
- `to-backlog-harness-installation`: Extend simulated publication and projection coverage to GitLab while retaining GitHub tests.
