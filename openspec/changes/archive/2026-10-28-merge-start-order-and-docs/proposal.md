## Why

The `/sai-merge` coordinator saved `provenance.json` into a run directory that it created only in the following step, and it asked the autostash question after the baseline suite had already run, so a declined autostash had spent a full suite run for nothing. The command's documentation and both wrapper descriptions also claimed it ran with no human in the loop, while it asks the branch, the method, and autostash at the start.

## What Changes

- `sai/commands/merge/coordinator.md` reorders the fresh-run Start steps. The autostash question for a rebase or squash becomes step 5, asked as soon as the method is known and before the run state, the provenance, and the baseline; a declined autostash, or no picker, ends the run before any suite has run and before anything is launched. The run state and run directory are opened in step 6, which also records `stash-base.txt` when autostash was accepted. `merge.js provenance` moves to step 7 and saves `provenance.json` into the run directory step 6 created. The test command (step 8) and the baseline (step 9) follow, and the launch stays step 10. A resumed run still skips Start and asks nothing.
- The coordinator's Goal now states that the run asks only at the start (the branch when missing, the method without a method flag, autostash when needed) and on escalation, and runs unattended otherwise.
- `docs/commands/sai-merge.md`, `docs/on-demand-commands.md`, the Claude Code and opencode `sai-merge.md` wrapper descriptions, and the merge section of `AGENTS.md` describe the command the same way and no longer claim it runs with no human in the loop. `AGENTS.md` removes the method question from its list of retired questions, and the authorization text places the autostash question before the baseline suite.
- `test/merge-goal-driven.test.js` checks the new Start order, that the run directory exists before `provenance.json` is saved, that a resumed run asks nothing, and that every description states when the command asks. `test/claude-default-preset-alignment.test.js` updates the generated-output hash for the changed wrapper descriptions.
