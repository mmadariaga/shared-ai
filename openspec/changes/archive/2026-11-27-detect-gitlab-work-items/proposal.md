## Why

`/sai-explore` imports an argument URL only when `from-backlog.js detect` classifies it as an issue. The offline detector accepts GitLab `/-/issues/N` URLs but not `/-/work_items/N` URLs, although the GitLab import adapter accepts both routes. On recent GitLab instances with the work-items view enabled, ordinary issues open at `/-/work_items/N`, so a pasted work-item URL becomes ordinary idea content and the import never runs. The user must invoke the `from-backlog` skill manually.

## What Changes

- `issueRoute` in `sai/tools/from-backlog-gitlab.js` accepts both `issues` and `work_items` routes through the existing `issueURL` parser and keeps the HTTPS-only check. Detection therefore returns `verdict: issue` with `provider: gitlab` for an HTTPS GitLab `/-/work_items/N` URL, on gitlab.com and on self-hosted hosts, with query parameters and fragments ignored.
- Only a positive integer `N` classifies; a missing, zero, or non-numeric number returns `verdict: none`. Other GitLab routes keep their current verdicts, `http://` work-item URLs return `none`, and GitHub and Azure DevOps detection is unchanged.
- Tests extend the `detect` matrix in `test/from-backlog.test.js` and add direct `issueRoute` assertions in `test/backlog-gitlab.test.js`.
- `docs/commands/sai-explore.md` names both GitLab routes.
