## Why

The adversarial expert review checkpoint asked the user to decide which corrections to keep while showing only the number of findings per severity and the coordinator's recommendation. The findings themselves appeared only in the closing report, after the decision, so the user could not make an informed decision. In `auto` mode, no summary of the reported and accepted findings appeared at the decision point, so the user saw only the closing report.

## What Changes

- `sai/policies/adversarial-expert-review.md` now prints every finding before the reconciliation picker wherever the question is asked (`ask` mode and an explore checkpoint whose yes/no question was answered `Yes`), with the five fields of `@sai/policies/artifact-review-contract.md` § Finding shape in the conversation language and with identifiers, paths, and severities literal.
- Before the findings list, the coordinator prints a `Recommended: <ids>` line naming the corrections it recommends keeping, or `Recommended: none` when it recommends none.
- In `auto` mode, the coordinator prints one summary line with the reported and accepted counts per severity after deciding every finding and before reverting a correction or amending a stored document, for example `Expert review: reported High=1 Medium=2 Low=0; accepted High=1 Medium=0 Low=0`.
- A finding without a correction appears in the list and stays outside the decision; when no finding carries a correction, no reconciliation question is asked and the findings are reported in the closing report.
- A review with no findings keeps its single line and opens no findings list, no reconciliation question, and no summary line.
- The findings list lives only in the chat: the checkpoint creates no repository file. The closing report keeps its per-finding detail, and the decision, verification, revert, and commit rules stay unchanged.
