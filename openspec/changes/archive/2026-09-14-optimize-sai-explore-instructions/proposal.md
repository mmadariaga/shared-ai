## Why
Explore sessions loaded detailed boot text that duplicated ownership held by step files and risked contradictory guidance at session start. Avoiding the load of unnecessary or contradictory instructions keeps startup minimal and leaves deferred content to trigger-based loading.

## What Changes
- Simplified the explore-mode write prohibition in sai/commands/explore/instructions.md to a single read, search, and discuss rule with delegated writes solely via the crystallization-close choice.
- Generalized boot preload to the explore instruction pack plus sai/policies/stage-machine.md, with every other step file loading only when a returned next.follow names that exact file.
- Replaced explicit route-selector and review-loop fetches and the post-Manual handoff pointer with a literal token review-loop trigger that loads via next.follow only then.
