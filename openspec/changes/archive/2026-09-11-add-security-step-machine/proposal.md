## Why

The security coordinator is a line-for-line twin of the review card and currently derives its pointer by judgment from a static table in `sai/commands/security/coordinator.md:29-39`. It is the only step-gated audit command in this family without a machine. Giving security its own step machine (`security-standalone@1`) brings it into parity with implement and review, ensures deterministic pointer derivation, and simplifies the coordinator contract.

## What Changes

- **New file:** `sai-state/machines/security-standalone.js` — a data module built by the linear-step factory that owns stateful stage routing for standalone security runs and chained security segments in `/sai-review`. Declares five steps: `resolve-security-scope` (fileless), `discover-module-map`, `resolve-sast-analysis`, `resolve-sca`, `close-security-outcome`.

- **Updated file:** `sai-state/registry.js` — registers `security-standalone@1` machine alongside spec, design, implement, review, and apply machines.

- **Updated file:** `sai/commands/security/coordinator.md` — replaces the static `step_pointer_map` table (lines 29-39) with a `step_machine: security-standalone@1` declaration. Adds a fetch for `@sai/policies/stage-machine.md` to own continuation behavior. Updates the `replacement_reconstruction_fields` documentation to reference the step machine instead of the static map.

- **Test updates:** Modified `test/linear-step-machines.test.js`, `test/security-coordinator-worker.test.js`, and `test/step-machine-wiring.test.js` to include security-standalone@1 in machine registration and discovery validation tests. A five-coordinator discovery scenario is added to step-machine-wiring-verification.

## Capabilities

### New Capabilities

- **security-standalone-loading** — Security's step machine governs every activation of the security adapter, direct (`/sai-6-security`) and chained (as position 1 of `/sai-review`). No shared sessions or state exist between activations.

### Modified Capabilities

- **security-step-gated-delivery** — Static step pointer map is replaced by step machine architecture. Pointer continuations are now delivered through the step machine via `@sai/policies/stage-machine.md`.

- **coordinator-step-pointers** — Security moves from the static-map list to the step_machine list, joining implement and review in the two-routed-phases requirement.

- **step-machine-wiring-verification** — Security coordinator discovery and validation now includes security alongside spec, design, implement, and review.
