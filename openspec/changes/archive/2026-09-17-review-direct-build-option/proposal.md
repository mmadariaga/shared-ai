## Why
Re-entering sai-3 and sai-4 after review is slow and expensive for small fixes. A code-first lane beside the plan lane shortens the loop for review and active audit findings, grounded in the meta-review terminal and the explore Direct Build supervision pattern.

## What Changes
- Adds a findings-driven Direct Build close lane at the end of sai-review that applies review.md plus activated audit findings directly on code.
- Adds a distinct sai-review-fix-worker that writes code only, never under openspec, never implementation.md or tasks.md, reusing the direct-build prohibitions by reference.
- Extends the worker matrix, install manifest, bindings, agents, and model customization from fourteen to fifteen workers with the review-fix entry.
- Updates the meta-review coordinator terminal with a two-option selector offered only when findings remain and a single-commit path-scoped local close.
- Updates installer, doctor, and uninstall tests and counts from fourteen to fifteen and twenty-eight to thirty where applicable.

## Capabilities
### New Capabilities
- review-direct-build-close: findings-driven Direct Build close at sai-review with selector, scoped input, fix loop, conditional backfill, and single-commit local close.
- review-fix-worker: distinct findings-driven fix worker with code-only scope, prohibitions, fix loop, and lifecycle contract.
### Modified Capabilities
- None. No existing capability requirement text was changed; the change adds new behavior alongside the existing plan lane.
