**Complexity**: high (1 new capability, 13 requirements, 6 affected paths; no breaking change or new dependency)

## Why

When a run halts on an error or an unexpected condition, the user needs to decide the next move from the message alone, and a Direct Build stop that ended with a costed, recommended decision proved far more actionable than a bare failure summary. Before this change only the unattended stop notice asked for "what the user must decide" (`sai/policies/unattended-runtime-recovery.md`), and no contract said how to present that decision.

## What Changes

- Add `sai/policies/stop-options.md`, the single source of the stop-options rule: an unplanned stop closes with a stop report followed by two or three concrete, costed options with the recommended one first. It excludes planned stops and contract-pinned stop texts, defers to contract-defined choices, presents a single viable path as the next step, defines a default stop report where the contract defines none, ties options to evidence the stopping surface already holds, uses the native picker per `question-context.md`, closes a composition stop once at the supervisor, and states that options are proposals that grant no authorization, retry budget, read scope, or write scope.
- Add a conditional pointer to `sai/orchestration/command-runner.md` right after the `public-chat.md` line, so the policy loads only when a run stops on an error or an unexpected condition and covers every command on both harnesses.
- Change `sai/policies/unattended-runtime-recovery.md` § Stop condition so "what the user must decide" is presented as the stop options of the new policy; the rule against a routine "how should I proceed?" question stays.
- Add one line to `sai/commands/explore/steps/pipeline-direct-build.md`: the Direct Build terminal report keeps its four sections, and on an incomplete run the stop options follow after `Incidents` as a separate question.
- Add `test/stop-options.test.js`, a contract test pinning the policy content, the runner pointer, the references from the unattended recovery policy and the Direct Build pipeline, the harness-neutral wording, and the `AGENTS.md` entry.
- Add the new policy to the `sai/policies/` row of `AGENTS.md`.
- `sai/install-manifest.json` is unchanged: the existing `sai-policies` projection already installs the policy for Claude Code and opencode.
