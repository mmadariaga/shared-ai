## Why

The wiring paragraph for how coordinators consult step machines was duplicated in spec (41-43) and design (37-41) coordinators, largely restating shared behavior in command-runner (119-148) and stage-machine policy. The spec, implement, and review step machines differ only in their data (step ids and step file mappings), not in their behavior. The sai-3 and sai-5 coordinators do not consult their machines at all currently; wiring them is a later change. No test existed to verify coordinator-machine alignment, allowing implementation to proceed without validation.

## What Changes

- Consolidates shared step machine consumption rules into stage-machine.md (new § Step machines section)
- Adds a linear step machine factory (sai-state/machines/linear-steps.js) that builds every linear step machine from a machine id, step list, and stage-file map
- Adds a per-machine reset verb (`sai-state reset <id> <machineId>`) that clears one machine's state without affecting other machines in the same session
- Refactors spec-standalone, implement-standalone, and review-standalone machines from monolithic implementations to data modules calling the factory
- Adds step_machine adapter field to command-runner (optional, static, immutable per segment)
- Updates spec and design coordinators to declare `step_machine: spec-standalone@1` / `design-standalone@1`
- Condenses routing documentation in spec (41-43) and design (39-41) coordinators, replacing long paragraphs with fetch and step_machine declaration
- Adds machine id recognition to lint.js patterns (review-standalone, security-standalone)
- Consolidates three parallel test files (spec-, implement-, review-standalone-machine.test.js) into parameterized test
- Adds test/step-machine-wiring.test.js to verify coordinator-machine wiring and step alignment
- Adds reset command tests to sai-state.test.js
