**Complexity**: high (4 capabilities and 9 affected paths)

## Why

Users need to explore Azure Boards work with the same read-only from-backlog experience used for GitHub and GitLab. Azure DevOps Services work items require project-based provenance and separate paginated comment reads to supply their discussion context.

## What Changes

- Registered a separate Azure DevOps Services reader through the existing provider-resolution seam.
- Added modern and legacy Services-link validation, canonical organization/project identity, and isolated-ID resolution from unambiguous existing organization context.
- Added Azure CLI work-item reads and paginated comments API reads with explicit complete, incomplete, and error outcomes.
- Preserved original rich content, custom work-item types and states, and project provenance without inventing an associated repository.
- Updated import instructions, provider-resolution guidance, README scope, and simulated regression coverage for both Claude Code and opencode.
- Added Windows Azure CLI launcher handling that avoids shell interpretation and disables automatic extension installation.
- Retained existing GitHub reference selection and GitLab fallback selection, including self-hosted GitLab.

## Capabilities

### New Capabilities

- `from-backlog-azure-devops`: Read Azure DevOps Services work items and all available comment pages with project-based identity, faithful content, explicit failure outcomes, and read-only execution.

### Modified Capabilities

- `from-backlog-provider-resolution`: Register Azure DevOps direct reference claims and permit organization-context resolution of isolated positive IDs instead of rejecting every isolated identifier.
- `from-backlog-conversation-import`: Present Azure Boards organization, project, and work-item type rather than repository archived state.
- `from-backlog-harness-installation`: Include the new adapter and provider instructions in existing mirrored projections, and document and test the expanded import scope.
