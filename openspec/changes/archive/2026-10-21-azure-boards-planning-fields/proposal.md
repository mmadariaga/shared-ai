## Why

Ordinary Azure Boards work-item publication left parent linkage, sprint and authenticated-user assignment to manual follow-up. The implementation extends existing publication, identity and recovery foundations without changing pull-request publication.

## What Changes

- Ordinary creation and updates prepare and approve the complete intended content and planning result. Known intended parent PBI references are included automatically; sprint and authenticated-user assignment require explicit requests.
- Deterministic tooling validates native parent and iteration references and authenticated identity, publishes content first, then applies requested planning fields in a separate revision-tested request.
- Completion and no-op checks include all requested planning fields. Partial completion retains the item and receipt; read-only recovery verifies actual state before explicitly approved pending-only continuation.
- Reads expose validated parent, iteration and assignment metadata. Shared instructions for Claude Code and opencode delegate mechanics to code and retain provider-specific approval boundaries.
- Offline regressions cover planning-only updates, identity/reference validation, SDK routes, partial completion, lost responses and concurrent changes. The functional review's content-only early exit and conflicting recovery documentation were corrected.

## Capabilities

### New Capabilities

- None; the implementation extends existing publication, capture and reading capabilities.

### Modified Capabilities

- azuredevops-backlog-publication: approved two-step planning publication and verified pending-only continuation.
- to-backlog-conversation-capture: provider-supported planning extraction, complete-result preparation and exact approval.
- from-backlog-azure-devops: ordinary reads expose validated planning metadata.
