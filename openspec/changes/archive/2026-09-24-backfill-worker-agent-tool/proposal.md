> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

On Claude Code, `/sai-backfill` failed during Phase 4 conflict detection with "No such tool available: Agent". The backfill worker card loads `@skills/budget/SKILL.md`, and its instructions delegate spec scanning to a `budget-explorer` subagent. However, the `sai-backfill-worker` worker-matrix entry in `sai/install-manifest.json` granted no `Agent` tool, so the generated agent file's `tools:` frontmatter omitted it. The defect was in source, not install drift. The same gap could come back whenever a worker card starts loading a `budget*` skill without a matching tools update, so the fix ships with a guard test.

## What Changes

- `sai/install-manifest.json`: the `backfill` worker-matrix entry's `claudeAgent.tools` becomes `Read, Glob, Grep, Bash, Write, Agent, Skill, SendMessage`, in the same ordering as the design worker. Model, effort, description, and `opencodeAgent` are unchanged. The opencode permission block already carried `budget: allow` and `explore: allow`.
- New `test/worker-delegation-tools.test.js` (`node:test`). It loads worker-matrix entries through `bin/install-manifest.js` and `bin/worker-matrix.js` and treats a worker as delegating when a `Fetch` line naming `@skills/budget/SKILL.md`, `@skills/budget-explorer/SKILL.md`, `@skills/budget-executor/SKILL.md`, or `@skills/budget-subagent/SKILL.md` appears in any of these places:
  - the entry's `workerContract`;
  - that contract's transitive `Fetch @sai/...` closure, which is resolved against repository sources with a visited set, skipping targets absent from source such as install-generated bindings;
  - any `*.md` file in the `steps/` folder beside the contract.
- For each delegating worker, the test asserts that `claudeAgent.tools` contains `Agent` and that `opencodeAgent.permissionBlock` contains `budget: allow` and `explore: allow`. Failure messages name the worker and the file where the `Fetch` line was found. A control assertion requires a non-empty delegating set that includes `sai-backfill-worker`. A separate check confirms that prose mentions without `Fetch` are not detected.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `managed-worker-registry`: worker-matrix tool and permission declarations must grant subagent dispatch on both harnesses to every worker whose loaded instructions fetch a `budget*` skill. A repository-source guard test enforces this.

## Impact

- Modified: `sai/install-manifest.json`
- New: `test/worker-delegation-tools.test.js`
- The generated Claude Code agent file `sai-backfill-worker.md` gains `Agent` in its `tools:` frontmatter after reinstall and restart. opencode registration is unchanged.
- The check is one-directional. It does not flag workers that hold `Agent` without delegating, such as apply RED/GREEN, and `executor: allow` is not required on opencode.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
