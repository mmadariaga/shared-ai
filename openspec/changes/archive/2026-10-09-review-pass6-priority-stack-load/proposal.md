> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Review pass 6 (Maintainability) told the reviewer to cite the Code Quality Priority Stack in `sai/commands/implement/steps/common.md`. The review worker never loads that file, and the sentence carried no `Fetch`, so the reviewer had no stack to apply and the tie-breaker between conflicting code-quality practices varied between runs (GitHub issue #69).

Known limitations: a candidate finding dismissed because of a tension leaves no trace in `review.md`, so that branch can be checked only indirectly. The implementation worker spends one more tool call per run to load the policy. `sai-direct-build-worker` and `sai-review-fix-worker` are not changed, and the scope of GitHub issue #61 (review report shape, other conditional loads, text cleanup) is not addressed.

## What Changes

- New policy `sai/policies/code-quality-priority-stack.md` with the heading `# Code Quality Priority Stack`. Its body is byte-identical to the former `## Code Quality Priority Stack` section of `sai/commands/implement/steps/common.md`: the lower-number-wins resolution statement, the six numbered rules, and the Project alignment meta-rule.
- `sai/commands/implement/steps/common.md` no longer contains the `## Code Quality Priority Stack` section. Its always-loaded fetch block now has `Fetch @sai/policies/code-quality-priority-stack.md` right after `Fetch @sai/policies/glossary-format.md`, so the implementation worker loads the stack on every run.
- In `sai/commands/review/steps/resolve-review-analysis.md`, pass 6 replaces the sentence that pointed at the implement step file with a conditional load. The reviewer fetches the policy only on a tension between two Maintainability practices in a finding it reports or dismisses. A reported finding names its result as `<winner> over <loser>`, each side written as `rule N <name>` or `project alignment`. A review with no tension loads nothing extra.
- New test `test/code-quality-priority-stack-policy.test.js` checks three things:
  - no `sai/**/*.md` file contains the `## Code Quality Priority Stack` heading, and the policy starts with `# Code Quality Priority Stack`;
  - the implement step library contains the policy `Fetch` line;
  - review pass 6 contains the same `Fetch` line.
