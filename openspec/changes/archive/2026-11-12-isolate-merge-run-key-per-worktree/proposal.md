> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Two concurrent `/sai-merge` runs in different worktrees that integrate the same branch shared the run-state session key `merge-{branch}`. One run closed and deleted the other's live `merge-run@1` state, and the surviving run then rebuilt its state silently after it misread the rejection. The key must identify the worktree as well as the branch, a run that vanishes from the store mid-run must be handled as a store failure, and the `sai-state` usage error for a non-identifier `--set` value must point to the form that accepts it.

## What Changes

- `sai/tools/merge.js`: `preflight` returns a new `worktree_id` in its `data`: the first 16 hex characters of the sha256 of the worktree's real top-level path (`git rev-parse --show-toplevel` resolved with `fs.realpathSync.native`), with `/` separators and lowercased on Windows, so one folder keeps one id whatever its letter case or separators, and two worktrees get different ids.
- `sai/commands/merge/coordinator.md`: the run-state session key is `merge-{worktree_id}-{branch}`, with the `worktree_id` of the current preflight, in Start step 2 (the resume check), Start step 6 (the `spawn`), and § Resuming (the lookup of the run that owns an operation in progress).
- `sai/commands/merge/coordinator.md` § Run state: a `rejected` emit saying `run is not running` or `run is not started` after `start` is a failing emit with no retry; the coordinator keeps the facts in the `run-state.md` fallback with no new `spawn` or `start` and states the store loss in the closing report.
- `sai/commands/merge/mechanics.md`: the `preflight` row documents `worktree_id` and the slot key it feeds.
- `bin/sai-state.js`: the usage error for a `--set` value outside `ID_PATTERN` now ends with `use --set-path <field>="<value>"` for that field, and still changes no state.
- `AGENTS.md`: the `/sai-merge` Resilience bullet names the key `merge-{worktree_id}-{branch}`.
- Tests: `test/merge-efficiency-tool.test.js` checks that `worktree_id` is stable across invocations, the CLI, and letter-case and separator spellings of one path on Windows, and differs between two worktrees of one repository; `test/sai-state.test.js` checks the `--set-path` hint and that no transition occurs; `test/merge-goal-driven.test.js` pins the new key text, the store-loss fallback, and the `mechanics.md` field, and raises the coordinator card size bound from 24000 to 24500 characters.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `merge-run-state`: the `/sai-merge` session key is scoped to the worktree, and a run that disappears from the store mid-run uses the `run-state.md` fallback.
- `sai-merge-command`: `merge.js preflight` returns `worktree_id`, and the start guard looks up a run in progress under the worktree-scoped key.
- `stage-machine-cli-interface`: the usage error for a non-identifier `--set` value names `--set-path` for that field.

## Impact

- Modified files: `sai/tools/merge.js`, `sai/commands/merge/coordinator.md`, `sai/commands/merge/mechanics.md`, `bin/sai-state.js`, `AGENTS.md`, `test/merge-efficiency-tool.test.js`, `test/merge-goal-driven.test.js`, `test/sai-state.test.js`.
- No new files.
- Only the `/sai-merge` session key changes; the `implement-{name}`, `review-{name}`, `plan-{name}`, and `{audit}-{name}` keys stay as they are, and `merge-run@1` gains no state field.
- Claude Code and opencode follow the same key and fallback rules.
- Known limitations: a merge run interrupted under the old `merge-{branch}` key does not resume after the update; the implement, review, plan, and audit keys keep their latent cross-worktree and cross-repository collision risk; two concurrent invocations in the same worktree for the same branch still share one slot.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill

## Request Additional Notes

Future scope, outside this change: the other run keys (`implement-{name}`, `review-{name}`, `plan-{name}`, `{audit}-{name}`) carry the same latent collision when two worktrees or repositories use the same change name; a tool-level option (`sai-state spawn --cwd`) could scope all of them at once if a failure is ever observed.
