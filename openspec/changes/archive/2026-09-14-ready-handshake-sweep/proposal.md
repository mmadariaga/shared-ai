## Why
Subagents receiving a bare ready instruction searched the repository for the handshake shape, hit superseded emitted_on references, and improvised timestamps, wasting tokens and risking malformed handshakes. Embedding a copy-paste ready example in every initial dispatch prompt removes that guesswork while preserving strict-zero withholding.

## What Changes
- sai/orchestration/worker-core.md removes the leftover emitted_on line from the ready return shape, pinning the handshake to event ready plus empty changed_files with no time field.
- bin/install-flow.js extends expectedDispatchPrompt to append the literal two-line ready example to the ready-only sentence.
- sai/orchestration/workers/bindings/claude/worker-template.md and sai/orchestration/workers/bindings/opencode/worker-template.md embed the same literal example in their initial Agent and task dispatch prompts while keeping single-line escaped encoding.
- test/install-claude.test.js and test/install-opencode.test.js update expected prompts, relax the end-anchored ready-only match, and add a dedicated assertion that the prompt carries the literal ready example.

## Capabilities
### New Capabilities
None — all behavior in this change extends existing handshake and dispatch capabilities.

### Modified Capabilities
- worker-dispatch-prompt-template — initial dispatch template now carries the literal ready example with single-line escaped encoding and installer exact-match enforcement.
- two-phase-worker-handshake — ready-only opening and install validation now cover the example-bearing prompt under strict zero with post-ready disclosure unchanged.
- worker-fast-handshake — handle-first timing preserved with the example-bearing prompt returning ready before any expensive work.
- timeless-worker — ready handshake pinned to exactly event plus changed_files with no emitted_on and no time field.
