## Why

Users need to locate explanatory messages that require or have required their attention when scrolling through a conversation. A consistent leading marker makes these messages easier to find across Claude Code and opencode.

## What Changes

- Added a centralized message-prefix rule to the shared public-chat policy for both harnesses: authors start user-facing explanatory messages with exactly `➡️` followed by one space, regardless of language.
- Covered progress updates, questions, and summaries, including user-facing `question`, `message`, and `summary` string values.
- Required one marker per message, added at the source and forwarded unchanged without duplication.
- Preserved exact-first-line and no-prefix exceptions and kept markers out of protected internal content.
- Added regression tests for coverage, source authorship, unchanged forwarding, and exceptions.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `public-chat-communication-policy`: add a language-independent single-marker rule for user-facing explanatory messages while retaining scope and exact-text protections.

- Added `test/public-chat-prefix.test.js`: three tests cover the prefix rule, forwarding, and protected-content exceptions.
- Existing contracts that require an exact first line or prohibit prefixes retain precedence; those messages may remain unmarked.
