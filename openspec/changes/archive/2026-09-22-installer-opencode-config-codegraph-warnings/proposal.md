## Why
The installer output asked to verify the `external_directory` permission, showed a relative example path, and printed a generic CodeGraph wiring hint. The implemented change aligns the output with the agreed installer contract in `bin/install-flow.js` print/merge paths and the observed `codegraph status` output: existing configs require only `experimental.subagent_depth = 2`, and CodeGraph state produces three targeted per-layer recommendations.

## What Changes
- `printOpencodeConfigMessage` in `bin/install-flow.js` now prints an `Ensure experimental.subagent_depth is set to 2` message with an `experimental` block, shows the full example path under `configs/opencode.jsonc`, and states the installer only ensures that one setting.
- `mergeOpencodeAgents` in `bin/install-flow.js` only ensures `experimental.subagent_depth = 2` (create when missing, raise when below 2) and never verifies, merges, or warns about `permission.external_directory`; top-level `subagent_depth` and all permission content are left untouched.
- `CODEGRAPH_MCP_INSTALL_CMD` is now `codegraph install -y -t claude,opencode`.
- New CodeGraph helpers `readJsoncConfigAt`, `isCodegraphMcpEnabledInConfig`, `codegraphDbPathFor`, `isCodegraphMcpConfigured`, and `emitCodegraphStateNotices` implement binary → MCP → db detection in that order, each absence only recommending without executing.
- `main` now emits the three-layer CodeGraph notices after the install offer.
- Tests in `test/install-opencode.test.js`, `test/implementation-harness-bindings-step-3.test.js`, and `test/model-customization-menu.test.js` now assert depth-only ensure, untouched permissions, full example path, per-layer commands, and a codegraph log filter for the silence assertion.
