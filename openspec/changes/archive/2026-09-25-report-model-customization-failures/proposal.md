## Why

After pressing Enter in `node bin/install setup`, the post-setup model customization menu could disappear without an explanation. An empty or invalid model catalog was treated as an unavailable setting and then as a successful setup, and a closed terminal input could leave a waiting menu without a result.

## What Changes

- `bin/install-flow.js`: adds an `INPUT_CLOSED` sentinel and a settled `finish` guard to the shared navigator, listens for terminal input `end`/`close`/`error` to settle a pending menu as `input-closed`, hardens output teardown, removes all listeners on settle, and extends `promptSelect` with an optional `distinguishClosedInput` flag defaulting to backward-compatible behavior that returns `INPUT_CLOSED` for closed input instead of conflating it with cancellation.
- `bin/model-customization.js`: converts every OpenCode catalog and variant-list failure (thrown query, non-zero exit, unparseable output, empty catalog) from a silent null into a `failed` result carrying a diagnostic, maps null provider/model/variant-screen selections to `CANCELLED`, wraps menu choice and checklist prompts to throw on closed input, maps failed or invalid settings including a null selector result to a visible `failedCustomization` error with console output, and catches all menu errors into the same failed result.
- `bin/setup.js`: maps a `failed` customization outcome or a missing customization outcome to `post-setup-failure` instead of silent success, while preserving `completed`/`skipped` as success and `persistence-failed` as persistence-failed.
- `test/install-flow-navigator.test.js` and `test/model-customization-menu.test.js`: cover input-closed settlement and listener removal, closed-versus-cancel-versus-back distinction, catalog and variant failure diagnostics, closed-input and later-step failures, and setup rejection of failed or missing outcomes.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `shared-readline-navigator`: closed terminal input settles a pending navigator in a controlled way and `promptSelect` distinguishes closed input from voluntary cancel and back navigation with a backward-compatible default.
- `opencode-settings-selection`: OpenCode catalog and variant discovery failures report actionable diagnostics as failed results and null screen selections cancel without configuring agents.
- `model-customization-menu`: the shared post-setup menu surfaces null, invalid, closed-input, and later-step failures as reported failures instead of silent success or normal skipped exits, for both harnesses.
- `setup-post-run-hooks`: failed or missing post-setup customization outcomes fail setup instead of reporting success, with menu-owned versus setup-owned diagnostics distinguished.

## Impact

- Modified: `bin/install-flow.js`, `bin/model-customization.js`, `bin/setup.js`
- Modified tests: `test/install-flow-navigator.test.js`, `test/model-customization-menu.test.js`
- Behavior preserved: `q`, Ctrl-C, and back or left navigation keep their voluntary cancel or return meanings; the OpenCode service and unrelated installer workflows are unchanged; the disposable diagnostic test is not part of this change.
