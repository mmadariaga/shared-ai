## Why
Planning artifacts cited repository paths without existence validation. A recent plan cited `src/services/mcp/CVL.SmartLocks.MCP/Common/Services/Email/Notifications/ExternalUserPasswordResetOtpRequestedDomainEvent.cs` while the event lives at `src/services/shared/CVL.SmartLocks.Domain/ExternalUsers/Events/ExternalUserPasswordResetOtpRequestedDomainEvent.cs`, forcing a stop-and-fix decision inside `sai-build`. Research confirmed `tasks.md` `Files Affected` is copied verbatim into the implementation plan with no existence check, so hallucinated paths surfaced mid-apply instead of failing fast at spec/design time.

## What Changes
Added a deterministic read-only cited-path existence checker (`sai/tools/check-cited-paths.js`, plain Node, exit 0 pass / 1 fail / 2 usage error) with `sai-1` strict semantics versus `sai-2` prefix semantics, designated-section extraction, rename origin rule, basename-candidate suggestions, and a `--findings` report mode. Wired it as a blocking gate in the `sai-1` spec validation step and the `sai-2` design interfaces step, and as a `High`-finding report mode in the explore `review-loop` Review Engine. The tool never rewrites artifacts and never auto-fixes; the worker or person decides using the suggestions.

## Capabilities
### New Capabilities
- `cited-path-existence-checker`: deterministic cited-path existence checker binary with `A`/`M`/`D`/`R` semantics, designated-section extraction, rename handling, basename suggestions, and findings report mode.
### Modified Capabilities
- `spec-evidence validation`: `sai-1` validation step now blocks on missing cited evidence paths in `proposal.md` and `specs/**`.
- `design-plan validation`: `sai-2` interfaces step now blocks on missing `M`/`D`/`R` and unprefixed planned paths in `tasks.md` and `interfaces.md` while `A` paths may stay absent.
- `review-loop report mode`: explore `review-loop` now maps checker violations to `High` findings with `Artifact location` for `sai-1`/`sai-2` review transactions.
