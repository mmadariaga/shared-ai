> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Inside the shared-ai repository, Claude Code attaches every bare `@` path of a loaded skill or command body as a Read of the repository copy, once per mention. This duplicates context (for example, three copies of `sai/policies/cache-warming.md` when the `budget-*` skills load), and the loaded-copy reuse rule cannot prevent it because the attachment happens before the model acts. A reference written inside an inline code span is not attached, so the installed instruction files now write every reference that way.

## What Changes

- Every `@sai/…`, `@skills/…`, and `@commands/…` reference in the installed instruction files (`sai/`, `skills/`, `commands/claude/`, `commands/opencode/`, `agents/claude/`, `agents/opencode/`) is written inside an inline code span. This covers `Fetch` and `Also fetch` directives and prose mentions. Only the path token sits in the span; the surrounding text and trailing anchors stay outside it.
- Text below the `<!-- User customizations below this line -->` marker of a wrapper is not changed. The opencode wrapper bootstrap line `Fetch @~/.config/opencode/skills/fetch/SKILL.md before you continue.` stays bare.
- `skills/claude/fetch/SKILL.md` and `skills/opencode/fetch/SKILL.md` state that a directive whose path sits in an inline code span is the same directive as the bare form, and their resolution tables show the backticked form for the Skill-tool rows and the fetch-tool row.
- `bin/worker-matrix.js` generates the canonical worker-contract fetch line of each worker binding in the backticked form, and `bin/install-flow.js` validates worker dispatch prompts against the backticked form.
- `bin/doctor.js` reads a backticked `Fetch` or `Also fetch` directive as the same reference as the bare form when it checks wrapper fetch resolution.
- A new test, `test/instruction-reference-guard.test.js`, runs under `npm test`. It fails on any reference outside an inline code span in an installed instruction file, and on any fenced reference that names an existing repository file, and reports `file:line` for each violation.
- Existing tests and `fixtures/thin-command-wrappers-baseline.json` that matched the bare `Fetch @…` literal now match the backticked form.

## Capabilities

### New Capabilities

- `instruction-reference-format`: references in installed instruction files sit inside inline code spans, generated wrappers and worker bindings emit the backticked form, and fenced references name no existing file.
- `fetch-directive-resolution`: a backticked `Fetch` or `Also fetch` directive resolves exactly like the bare form in the Claude Code and opencode fetch skills and in the doctor's fetch-reference check.
- `instruction-reference-guard`: an `npm test` check fails on any unwrapped reference, or any fenced reference that names an existing file, and reports `file:line`.

### Modified Capabilities

None
