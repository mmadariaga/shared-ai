> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Three run defects found in the v0.12.0 milestone review (issue #486, F9, F12, F16). The Direct Build implementer's watch covered only the paths the block cites, so new tests or modules beside them were invisible and the watch could end `silent` falsely. Round 2 of the explore route selector called its preparation read-only although the `new-change-branch` preparation fetches every remote, and that fetch could open a Git Credential Manager window on Windows. A `/sai-build` request published ready for review did not tell its reviewer which findings the run left pending or excluded.

## What Changes

- The Direct Build implementer's writable paths are the directories of the paths the verified block cites, taken without their `:line` ranges. A cited path at the repository root is listed as that file alone, never the root directory. A cited path whose directory does not exist yet is listed through its nearest existing parent directory below the root, or as the path itself when that parent would be the root. `transfer.js watch` is unchanged, because it already walks directories.
- `sai/tools/new-change-branch.js` runs every fetch with `GCM_INTERACTIVE=never` beside `GIT_TERMINAL_PROMPT=0`, so a fetch that needs credentials fails without opening a window, and branch creation continues as after any failed fetch.
- Round 2 of `sai/commands/explore/steps/route-selector.md` prepares "without publishing or creating anything" and names the remote fetch as the only change the preparation makes, instead of calling it read-only.
- When `/sai-build` writes the request description, it adds a `## Pending findings` section, right before `## Out of Scope / Follow-ups`, listing with identifier, title, and reason the findings still pending (the `review.md` findings the fix segment left open and the step-review findings left pending after the third fix round) and the findings marked ` (EXCLUDED: …)`. With neither, the description has no such section. The request stays ready for review.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `undelivered-report-recovery`: the Direct Build implementer's writable paths are directories of the cited paths.
- `new-change-branch`: the remote fetch runs with `GCM_INTERACTIVE=never`.
- `explore-route-close`: round 2 is no longer called read-only and names its remote fetch.
- `build-publication`: the request description lists pending and excluded findings.
