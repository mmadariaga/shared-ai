> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The spec worker's proposal step (`sai/commands/spec/steps/proposal.md`) fetched the ~8 KB `openspec-propose` lifecycle skill only for its proposal mechanics. That skill also tells a small model to create `design.md` and `tasks.md`, which contradicts the step's own instruction not to. The `specs` step and the archive coordinator already call the OpenSpec CLI directly, so the skill was an avoidable cost and a source of conflicting instructions. With the fetch gone, `openspec-propose` has no consumer left, so the prerequisite preflight no longer needs to require it.

## What Changes

- `sai/commands/spec/steps/proposal.md` no longer fetches `@skills/openspec-propose/SKILL.md`. It runs an explicit OpenSpec CLI sequence instead:
  1. It loads project context on every run by reading the `context` string of `openspec/config.yaml` (or `config.yml` only when `config.yaml` is absent). It applies that context as a constraint without copying it into an artifact, and continues without context when the file is missing or unreadable.
  2. It runs `openspec new change "<name>"` only on creation. A refinement run skips this because the change directory already exists.
  3. It runs `openspec status --change "<name>" --json`, then `openspec instructions proposal --change "<name>" --json`. It writes `proposal.md` to the returned `resolvedOutputPath` from `template`, `instruction`, and `rules`, applying `context` and `rules` as constraints without copying them.
  4. It stops before `specs/**`. `design.md` and `tasks.md` stay with `/sai-2-design`. `--store` is not supported.
- `sai/commands/spec/steps/specs.md` writes each delta spec from the `template`, `instruction`, and `rules` of `openspec instructions specs --change "<name>" --json`, with no reference to the openspec-propose skill.
- `sai/tools/prereqs.js` sets `REQUIRED_SKILLS = ['openspec-explore']`. The comments, usage text, and pass message now describe a single OpenSpec skill.
- `sai/commands/meta-review/coordinator.md` names a single OpenSpec skill in its inline prerequisite list.
- `AGENTS.md` names `openspec-explore` as the only live OpenSpec skill fetch and describes the skills check with one required skill. Its artifact table attributes `proposal.md` and `specs/**` to the openspec CLI.
- `test/prereqs-tool.test.js` and `test/spec-coordinator-worker.test.js` now pin the single-skill check and the CLI-based proposal step. The proposal step must not mention `openspec-propose` and must contain `openspec new change` and `openspec instructions proposal`.
