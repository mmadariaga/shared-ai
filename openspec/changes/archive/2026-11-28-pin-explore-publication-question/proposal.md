## Why

The `/sai-explore` round-3 publication question was model-composed: the contract fixed only the stable values `yes` and `no` and the English labels "Publish" and "Do not publish", so a run could render internal terms ("slices", "set", "petición", "ruta") in a sentence that is the held confirmation for a push and a pull-request creation or update. A reader who joins the chat midstream could not tell what is published, on which branch, or what a `yes` authorizes.

## What Changes

- `sai/commands/explore/steps/route-selector.md` § Publication question: the opening definition sentence now says the answer is whether the changes of the set publish a pull request when their automatic run ends.
- The **Question** paragraph fixes the English sentence “Should a pull request be published when each change's automatic run ends?” and the Spanish form, used verbatim: “¿Quieres que se publique una pull request al terminar la ejecución automática de cada cambio?”. In any other chat language, the run translates the sentence, the option labels, and the option descriptions, and keeps “pull request” and “PR/MR” as written.
- The same paragraph fixes both options: `yes` has label “Publish the PR/MR” and description “Push the branch and create or update its PR/MR”, with the Spanish label “Publicar la PR/MR” and description “Subir la rama y crear o actualizar su PR/MR”; `no` has label “Do not publish” and description “Push nothing and publish nothing”, with the Spanish label “No publicar nada” and description “No subir ni publicar nada”.
- The text before the picker keeps naming the branch, its remote, and the pull-request state each route produces, and now uses the same terms: a slice is a “change”, the request is a “pull request”, and a route is named by its picker label. A Manual change has no automatic run, and a detached HEAD with no pending branch shows no sentence.
- `test/explore-question-rounds.test.js` asserts the fixed English sentence, the Spanish form, both labels, and both descriptions on the existing `publication` slice.
