## Why

Audit findings that contradict existing requirements or decisions (criterion 3) or propose work exceeding the change's scope and requiring new acceptance criteria (criterion 5) were previously classified only as Discard or Apply. This meant findings revealing incomplete or contradicted specifications — often the most valuable findings of an audit — were buried in one-line reasons inside Discarded findings sub-blocks, losing context and momentum for follow-up. The Escalate outcome provides a dedicated path: when any finding is classified as Escalate, the run stops before implementation planning, and the finding is served as a paste-ready Ready to Propose block for a new change, preserving context and enabling action.

## What Changes

The sai-3-implement command's artifact-analysis and plan-generation steps now recognize a third outcome in the Judgment Rubric for Audit Findings: Escalate. Findings failing criterion 3 (contradicts existing decisions or requirements) or criterion 5 (exceeds scope, needs new acceptance criteria not yet established) are classified as Escalate instead of Discard.

When Escalate findings exist in any audit artifact (review.md, security.md, performance.md, or accessibility.md), artifact-analysis:
1. Stops before continuing to plan-generation
2. Groups escalated findings by scope of work (findings from different artifacts belong together if they describe the same missing change or capability gap)
3. For each group, emits a Ready to Propose block using the format from sai/policies/ready-to-propose-format.md
4. Returns terminal status with all blocks as chat output

Plan-generation checks at start whether escalations were detected in artifact-analysis. If found, no implementation.md is generated; the run is concluded. Escalate classification is exclusive to artifact-analysis and never re-evaluated at append time.
