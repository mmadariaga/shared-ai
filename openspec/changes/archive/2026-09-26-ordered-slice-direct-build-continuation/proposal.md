## Why
> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

Slices already have a dependency order, but the current picker permits running them out of order. The existing Direct Build choice authorizes only its selected slice, so automatic continuation needs explicit consent for the later slices.

## What Changes
- Route selection uses the first pending slice in crystallization order for Manual, Plan, and Direct Build with no slice-name picker and no Cancel picker.
- On the first Direct Build selection with multiple slices pending, one continuation question is asked once per crystallization set, even if earlier slices used Manual or Plan.
- A yes answer auto-starts each later slice in order after clean success with one local commit per automatically started slice and no push; a no answer or queued route request returns to route choice after the current slice.
- Parked first-pending slices block later slices and resume only in their own mode at the parked step; failed, cancelled, or incomplete slices never start the next slice.
- Explicit chat-stated continuation changes queue without interrupting the active slice and apply after the current slice completes cleanly.
- Stage-machine route events carry no slice name; only recordedList carries change names. Tests cover order, one-time prompting, continuation, failure blocking, and change-of-mind queuing.

## Capabilities
### New Capabilities
None. All implemented behavior modifies existing capabilities.

### Modified Capabilities
- explore-pipeline-selector: ordered first-pending route selection with no slice picker and a one-time Direct Build continuation authorization.
- explore-slice-machine: first-pending-only starts with no pick, parked-slice blocking, and success-gated advancement.
- deferred-selector: deterministic first-pending choice without multi-entry picker or Cancel.
- explore-pipeline-supervision: ordered Direct Build selection, auto_continue versus route_choice completion, and pick-free slice-machine emits.
- stage-machine-emit-delivery: recordedList carries change names while route events carry no slice name.
