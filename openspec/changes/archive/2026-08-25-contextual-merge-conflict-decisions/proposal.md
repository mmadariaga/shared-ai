# Contextual Merge Conflict Decisions

> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

**Complexity**: high (8 modified capabilities, 8 affected source files, no new dependency)

## Why

`/sai-merge` needed to distinguish semantic conflict decisions from mechanical text selection. When branches express different objectives, ownership boundaries, lifecycle rules, gates, tests, or invariants, choosing one side without contextual analysis can silently discard important behavior. The implementation adds branch-objective analysis, complete alternatives, human decision gates, and coordinator validation while retaining read-only worker verification and coordinator-owned mutations and authorization.

## What Changes

- Extend merge-worker analysis with explicit Facts and Inferences, branch objectives, affected contracts, and complete marker-free current and incoming alternatives.
- Add an optional safe synthesis only when it preserves one owner for each responsibility, one authoritative source for each fact, compatible lifecycle behavior, and no duplicated gate or competing contract.
- Add a contextual decision stage for semantic ambiguity, including a mutation-free `more-context` continuation; obvious deterministic conflicts remain lightweight.
- Require the coordinator to validate complete resolution-file payloads atomically before writing or staging, rejecting fragments, reconstructed content, unexpected paths, and conflict markers.
- Add a coordinator-owned `contextual-analysis` lifecycle/TODO stage and preserve the fast-track rule that only runtime scope selection may be bypassed.
- Preserve the worker-owned read-only verification loop; the coordinator applies proposed fixes, stages validated paths, and retains final commit authorization.
- Add contract tests covering worker instructions, coordinator ownership, presentation state, fast-track boundaries, and adaptive TODO behavior.

## Capabilities

### New Capabilities

None. The implementation extends existing merge, presentation, fast-track, panel, question, and lifecycle capabilities.

### Modified Capabilities

- `sai-merge-command`: contextual conflict analysis, complete alternatives, semantic decisions, complete-file validation, and read-only verification ownership.
- `merge-presentation-seam`: contextual decision rendering, pending-decision mutation blocking, and exact complete-file validation.
- `sai-fast-track-flag`: merge fast-track bypasses only runtime scope.
- `harness-panel-render-binding`: the coordinator-owned merge TODO includes contextual analysis.
- `progress-plan-declaration`: the merge adaptive TODO remains separate from worker progress plans.
- `question-context-policy`: contextual decision prompts carry complete decision context.
- `closed-choice-prompts`: contextual decisions use native option-picker semantics and stable values.
- `worker-lifecycle-protocol`: `more-context` uses same-worker `needs_input` continuation without new lifecycle statuses.
