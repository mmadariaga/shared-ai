> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The GitHub ProjectV2 `items` connection reflects new insertions only after tens of seconds to about two minutes. Slice-set publication re-read that connection right after `addProjectV2ItemById`, so it stopped with `Project membership not verified` even though the issue was already in the Project. Single-issue publication trusted the mutation response and never re-read membership.

## What Changes

- `sai/tools/to-backlog-github.js` gains and exports `membership(io, projectId, issueId, itemId)`. With an item id it runs the direct item read: `node(id)` on the ProjectV2 item, accepted only when its `project.id` is the destination Project and its `content.id` is the issue. Without an item id it runs the issue-side read: `Issue.projectItems`, paginated with the existing `pages` helper, filtered by the destination `project.id`. This read counts archived items, and a `null` connection counts as no items.
- `sai/tools/to-backlog-github.js` gains and exports `verifyMembership`, the bounded post-insertion verification. It reads once immediately, then up to four more times 2 s apart (five attempts). The wait is synchronous, uses an injectable `io.sleep(ms)`, and falls back to `Atomics.wait`.
- Single-issue `insert` checks membership with the issue-side read before adding. After the add mutation it calls `verifyMembership` with the returned item id, or with the issue-side read when the response carries no `item.id`. It marks the receipt `complete` only after verification. An unverified insertion ends as `partial_failure` with `Project membership not verified`, the receipt left at `insertion_pending`, and the created issue preserved. The inline items-connection query is removed.
- `sai/tools/backlog-set-github.js` `perform` checks membership with the issue-side read before adding and verifies after the add with `verifyMembership`. When verification fails it throws `Project membership not verified`, which leaves `project:N` pending. `recover` decides `project:N` with the issue-side read. The `projectItems` items-connection helper is removed.
- `skills/universal/to-backlog/providers/github.md` now says membership is verified with direct reads because the Project items index can take minutes to reflect changes. Its recovery text now says recovery reads the issue's Project items.
- Test fakes in `test/to-backlog.test.js` and `test/github-backlog-slice-lifecycle.test.js` now model a lagging or forbidden items connection and direct reads that see an insertion at once or after a configurable number of reads. They also support archived items, items in other Projects, a `null` `projectItems`, a missing `item.id`, and Auto-add pre-membership. New tests cover these cases and assert the injected sleep counts.
