> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Finding and pasting an individual backlog-item reference interrupted discussion.
The implemented command selects the first manually ordered item from an
identified pile while leaving unresolved choices with the user. It reuses the
existing importer instead of maintaining another import flow.

## What Changes

- Added the explicit, no-argument `/from-next-backlog-item` command for Claude
  Code and opencode, preserving the active conversation and exploration stage.
- Added a selection skill and read-only Node helper with GitHub Projects,
  GitLab project issue-list, and Azure DevOps Services team-backlog adapters.
- Implemented missing-context questions, actual pile candidates, manual-order
  checks, complete-empty detection, unsupported-item handling, access-failure
  handling, and cancellation.
- Kept unsupported views, filters, missing ranks, incomplete responses, and
  ambiguous first positions pending rather than substituting another pile or
  ordering.
- Allowed one existing `from-backlog` import continuation after explicit
  selector invocation supplies a complete selected reference.
- Added mirrored installation projections and bounded selection/import access.
- Added simulated provider, reference-handoff, cancellation, installation, and
  command-enumeration coverage.

## Capabilities

### New Capabilities

- `next-backlog-item-selection`: Conversation-preserving selection of an
  importable first item from a supported manually ordered pile, with explicit
  pending, empty, and cancelled outcomes.

### Modified Capabilities

- `from-backlog-conversation-import`: Permit one import continuation authorized
  by explicit `/from-next-backlog-item` invocation while prohibiting autonomous
  invocation.
- `from-backlog-harness-installation`: Install mirrored selector entries,
  instructions, provider references, and helpers with simulated coverage.
- `contract-tool-capabilities`: Assign the selector bounded read-only access
  and include it among twenty-two commands.
- `command-wrapper-body`: Reflect twenty-two wrapper files per harness without
  changing the SAI wrapper-body contract.
- `sai-1-command-inventory`: Include the selector in mirrored command inventory.
