## Why

The outcome benchmark reported accepted-run counts and wall time only, but comparing configurations also needs tokens and cost. Claude Code records no cost in its transcripts, and the repository had no price table, so the benchmark could not compare the two routes on Claude Code by cost.

## What Changes

- When a run ends, the Docker backend copies the harness data out of the container before removing it, including for a run that timed out, and reads its usage: Claude Code transcripts through `sai/tools/claude-transcripts.js` and the opencode database through `sai/tools/opencode-db.js` (new `benchmark/measure.js`). The root session and every subagent count. The measurement holds per-model token counts (input, output, cache read, cache write), tool-call counts, request counts, and the cost the harness recorded; no session identifier, project path, or credential.
- `sai/tools/claude-transcripts.js` also reports the 5-minute and 1-hour cache-write tokens of each Claude Code request.
- The new `benchmark/cost.js` computes each run's usage section from the measurement and the corpus price table: Claude Code cost is estimated from token counts and the price table (cache writes pay the 5-minute or 1-hour price as the transcript splits them, and the 5-minute price when unsplit); opencode uses the cost it recorded per message and prices from the table only a model that recorded none. A price entry matches a recorded model by exact key or by the longest key whose words appear in the model name as one run; a tie gives no price. A model without a usable price has cost `null`, shown as `no price`, never as zero.
- The runner stores the usage section in each run's JSON result. A run whose harness data cannot be read keeps its classification and has no usage.
- Corpus validation accepts optional `cacheReadPerMTok`, `cacheWrite5mPerMTok`, and `cacheWrite1hPerMTok` price keys and rejects them when they are not numbers of at least 0.
- Each configuration report adds token, tool-call, and cost lines to its Result section (totals and per run, with the cost note and the price table date), a `Usage by model` table, and token, tool-call, and cost columns in the run table. Runs without usage data are counted apart and excluded from these figures.
- `docs/benchmark.md` and `AGENTS.md` describe the measurement, the price table, and the cost rules.
