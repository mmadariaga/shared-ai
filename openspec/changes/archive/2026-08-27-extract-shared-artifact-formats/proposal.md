## Why

Both formats are about to gain a second author, and two copies of a format whose bytes matter will drift: a divergent `Ready to Propose` block parses differently in `/sai-1-spec`, and a divergent section shape stops matching the exact `## Step N` lookup that apply's routing tree performs. Today each format is fused with the step machinery that happens to emit it, so there is no seam to extend to other consuming surfaces.

## What Changes

Two inline format specifications are extracted from command step documentation files and moved to shared policy files under `sai/policies/`, enabling multiple surfaces to consume them by reference without duplication:

1. `sai/policies/ready-to-propose-format.md` — new file, specifies the complete `Ready to Propose` block structure, field rules, mandatory sections, and all rules governing its format and content.
2. `sai/policies/step-contract-format.md` — new file, specifies the `## Step N` section format for `interfaces.md`, including field structure, omission rule, anchoring rule, and per-step keying rules.
3. `sai/commands/explore/steps/crystallization-protocol.md` — updated to reference `sai/policies/ready-to-propose-format.md` via fetch directive instead of inline format specification.
4. `sai/commands/design/steps/interfaces.md` — updated to reference `sai/policies/step-contract-format.md` via fetch directive instead of inline format specification.
5. Test files updated to account for the extracted policies and verify contract preservation.

## Capabilities

### New Capabilities

- **Shared crystallization block format**: The `Ready to Propose` template and its field rules are now single-sourced in `sai/policies/ready-to-propose-format.md` and consumed by explore's crystallization protocol via fetch directive. Enables future surfaces to adopt the format by reference.
- **Shared step-contract section format**: The `## Step N` shape for `interfaces.md` — the `**Interfaces**` and `**Test assertions**` fields, omission rule, and spec-anchoring rule — are now single-sourced in `sai/policies/step-contract-format.md` and consumed by design's interfaces step via fetch directive. Enables consistent step contract formatting across multiple consumers.
