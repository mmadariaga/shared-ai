## Why

Both experimental settings, `experimental.changeTelemetry` and `warming`, were reachable only by hand-editing `.sai/settings.jsonc`. The `Cache warming` entry of the post-setup menu was hidden behind a disabled module constant (PR #309, `b869462f`), and `experimental.changeTelemetry` was deliberately left out of the Project behavior settings screen. This change gives both settings one entry point: a new `Experimental` section of the settings screen, whose label signals that the features are still untested.

## What Changes

- `sai/tools/project-settings.js`: the `experimental.changeTelemetry` catalogue entry gains the label `Change telemetry`, the section `Experimental`, and the absent text `off`. Validation is unchanged.
- `bin/project-settings-screen.js`:
  - `experimental.changeTelemetry` is appended to the screen's key list, so an `Experimental` section is shown after `Pull requests`.
  - A boolean key offers exactly the choices `On` and `Off` (no `ask`) and is shown as `on` or `off`; an absent key shows `off`.
  - `On` records `true`. `Off` removes the key from `.sai/settings.jsonc`, and records an explicit `false` when the key is saved to `.sai/settings.local.jsonc`, so a shared `true` cannot apply.
  - A `Cache warming` action row follows `Change telemetry`. Selecting it calls an injected `openCacheWarming` callback and then returns to the settings screen with the pending edits kept; those edits save when the user leaves the settings screen.
- `bin/model-customization.js`:
  - The hidden-entry mechanism is removed: `CACHE_WARMING_MENU_ENABLED`, `ALL_MENU_OPTIONS`, `visibleMenuOptions`, the `Cache warming` menu dispatch, and the test-only `cacheWarmingMenuEnabled` parameter. The post-setup menu keeps its six actions.
  - Opening `Project behavior settings` now injects an `openCacheWarming` callback that builds the guided warming pairs with `guidedWarmingPairs` and runs the existing warming screen (`runWarmingSetup`).
- `docs/project-settings.md`: documents the `Experimental` section, the `Change telemetry` row and its `On`/`Off` semantics, the `Cache warming` row, and a new `Cache warming screen` subsection; the "edited by hand only" statements for `warming` and `experimental.changeTelemetry` are replaced.
- Tests: the screen key list, section headers, menu assertions, and catalogue assertion are updated, and new tests cover the telemetry display, choices, base and local saves, invalid stored values, the `Cache warming` row callback, and a telemetry edit plus a nested warming save that both persist.

The runtime behavior of change telemetry and cache warming is unchanged; only menu access changes. The warming screen itself is reused unchanged.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `project-settings-screen`: adds the `Experimental` section with the `Change telemetry` boolean row and the `Cache warming` action row.
- `model-customization-menu`: removes the hidden `Cache warming` entry and its visibility constant; cache warming is reached through `Project behavior settings`.
- `change-telemetry`: the setting carries screen presentation fields and is editable from the settings screen as well as by hand.
- `cache-warming-settings`: the documentation directs readers to the `Cache warming` row of the `Experimental` section instead of stating that `warming` is edited by hand only.
- `project-settings`: the catalogue presentation fields include `experimental.changeTelemetry`.
