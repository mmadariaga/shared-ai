> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Project settings in `.sai/settings.jsonc` could be found only through documentation and hand edits: the post-setup menu customized models only, and the reader writes nothing. The legacy `.to-backlog.json` fallback also kept a second source for one value.

## What Changes

- The post-setup menu of `node bin/install setup` gains a `Project settings` action between `Load preset` and `Exit` (`bin/model-customization.js`). The action opens the new screen and then returns to the menu. Without a TTY the action is skipped together with the rest of the menu.
- New `bin/project-settings-screen.js`: the `Project settings` screen lists `explore.readyToProposeLanguage`, `explore.overviewLanguage`, and `backlog.provider` with their current values, and edits them through injected prompts.
  - `backlog.provider` offers `ask` plus the union of the provider ids in the to-backlog and from-backlog registries.
  - Both language ids offer `ask`, `English`, and a free-text language name. `explore.overviewLanguage` also offers `none`.
  - Leaving the screen saves only when a value changed. An interrupt discards the edits. An unparseable settings file is reported when the screen opens, before any edit.
- New `bin/project-settings-writer.js`: edits `.sai/settings.jsonc` in place with `jsonc-parser` `modify` + `applyEdits`. It validates and normalizes each value through the reader's `CATALOGUE` and writes `ask` as the string `"ask"`. It refuses unparseable text, creates `.sai/` on the first save, and leaves the file byte-identical on any failure. It keeps CRLF line endings and saves through a temporary file and a rename.
- `sai/tools/project-settings.js` no longer reads `.to-backlog.json`. `source` is `setting` or `absent`, and `isKeyword` is exported for the writer. The reader stays read-only and dependency-free.
- Documentation: `docs/project-settings.md` describes the screen, says the writer goes through `bin/project-settings-writer.js`, and drops the `.to-backlog.json` migration section, "no command writes it yet", and the `legacy` source. `README.md`, `docs/models.md`, and `AGENTS.md` link that page.
- Tests: new `test/project-settings-screen.test.js` covers the writer, the screen (E15–E21), and the menu entry. In `test/project-settings.test.js` the legacy cases are replaced by `.sai/settings.jsonc`-only cases.
- **BREAKING**: a project with only `.to-backlog.json` no longer has a configured provider and gets the normal provider question again, with no warning.

## Capabilities

### New Capabilities

- `project-settings-screen`: the post-setup `Project settings` screen that shows and edits the three managed setting ids.
- `project-settings-writer`: in-place, comment-preserving saves of `.sai/settings.jsonc`, validated through the reader's catalogue.

### Modified Capabilities

- `project-settings`: the reader reads only `.sai/settings.jsonc`. The legacy `.to-backlog.json` transition is removed, and the CLI `source` is `setting` or `absent`.
- `model-customization-menu`: the post-setup menu has six actions, adding `Project settings`.
- `to-backlog-provider-resolution`: the destination resolution no longer mentions a legacy `.to-backlog.json` settings source.

## Impact

- New files: `bin/project-settings-screen.js`, `bin/project-settings-writer.js`, `test/project-settings-screen.test.js`.
- Modified files: `bin/model-customization.js`, `sai/tools/project-settings.js`, `test/project-settings.test.js`, `docs/project-settings.md`, `docs/models.md`, `README.md`, `AGENTS.md`.
- Dependencies: the writer uses `jsonc-parser`, already an installer dependency. Installed `sai/tools/` content gains no dependency.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
