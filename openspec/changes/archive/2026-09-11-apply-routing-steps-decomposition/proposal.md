> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Apply command routing and terminal lifecycle were monolithic sections in single files with no individual addressability. Every other routed command that carries a steps library was decomposed into `steps/` first, creating per-mode files that pointers can target.

## What Changes

Decomposes the Step Routing Tree from `sai/commands/apply/runner.md` into a condition-to-file routing table, with each routing mode pointing to its own step file. Moves the terminal lifecycle section (final sweep, learnings promotion, terminal documentation evaluation, visibility, authorization, commit) from `sai/commands/apply/runner.md` to a new `terminal-lifecycle.md` step file, replaced with a Fetch directive in runner.md. Created five routing-mode step files and one terminal-lifecycle step file under `sai/commands/apply/steps/`.

### Files Modified
- `sai/commands/apply/runner.md`: routing list converted to table with Fetch directives per mode; terminal lifecycle section replaced with Fetch directive.

### Files Added
- `sai/commands/apply/steps/routing-green-direct.md`
- `sai/commands/apply/steps/routing-green-exception-test-only.md`
- `sai/commands/apply/steps/routing-stop-missing-contract.md`
- `sai/commands/apply/steps/routing-split-flow.md`
- `sai/commands/apply/steps/routing-green-exception-no-production.md`
- `sai/commands/apply/steps/terminal-lifecycle.md`

## Capabilities

### New Capabilities
- `apply-steps-library` — The apply command's Step Routing Tree (five exclusive routing modes) and terminal lifecycle (final sweep, learnings promotion, terminal documentation evaluation, visibility, authorization, commit) are decomposed into addressable step files under `sai/commands/apply/steps/`, following the precedent established by other routed commands.

### Modified Capabilities
- `apply-routed-card-set` — The terminal-lifecycle-contract-coverage and apply-card-set-is-routed requirements are updated to reflect that terminal lifecycle content is now in a dedicated steps file (`terminal-lifecycle.md`) rather than inline in `runner.md`, while remaining accessible through Fetch directives and part of the active routed card set.

## Impact

### New
- Six new step files under `sai/commands/apply/steps/`: five routing modes and one terminal lifecycle.

### Modified
- `sai/commands/apply/runner.md`: routing decisions converted to table; terminal lifecycle section replaced with Fetch directive.

### Out of scope
