## Why

Azure DevOps work items could be imported through from-backlog, but the corresponding publication skills did not support Azure Boards or Azure Repos. This change extends the existing publication workflows using the existing authenticated Azure CLI environment.

## What Changes

- Registered Azure DevOps Services adapters for to-backlog creation and origin updates and for to-pr creation and updates.
- Extended registry-driven destination selection with provider-owned address classification, organization input, and origin-provider selection.
- Added deterministic conversion of supported Markdown to Boards HTML before approval; unsupported forms stop preparation. Title-only updates preserve the existing HTML.
- Added Boards updates that test the confirmed revision in the same JSON Patch request as title and description changes, without bypassing project rules.
- Added Azure Repos repository and branch checks, pre-approval disclosure of the unprotected concurrent-edit interval, and separate branch-push authorization.
- Added private publication evidence and query-only recovery that does not infer creation from a coincident title or automatically repeat creation.
- Reused the Azure CLI runner and address interpretation from from-backlog. Added installed-extension SDK access for distinct work-item and identity routes, locally disabled dynamic extension installation, and cleaned owned transport scratch without deleting recovery receipts.
- Added offline protocol, instruction, and both-harness projection tests. No live Azure publication was validated.

## Capabilities

### New Capabilities

- `azuredevops-backlog-publication`: Azure Boards creation and title/description-only updates with invocation-selected types, supported HTML conversion, conditional revision checks, and conservative recovery.

### Modified Capabilities

- `to-backlog-provider-resolution`: Organization input, provider-owned classification, Azure registration, and registry-driven origin selection.
- `provider-resolution`: Azure-aware provider recognition and normalized repository destination checks.
- `to-pr`: Azure Repos publication, update concurrency disclosure, and identity-backed query-only recovery.

- Modified to-backlog references: `create.md`, `update.md`, `providers/registry.json`, and `providers/resolution.md`.
- New to-pr reference: `skills/universal/to-pr/providers/azuredevops.md`; modified `SKILL.md` and `providers/registry.json`.
- New tests: `test/azure-publication.test.js`, `test/azure-publication-corrections.test.js`, and `test/fixtures/azure-sdk-routing.py`; modified `test/to-pr.test.js`.
- Existing recursive managed projections install the added tools and references for Claude Code and opencode without new direct provider-CLI permissions.
- Publication requires the existing Azure CLI, installed azure-devops extension, authentication, and destination permissions. The SDK bridge supports standard Windows MSI and absolute Python-shebang launchers; unsupported packaging stops rather than installing or guessing an interpreter.
- Additional required fields remain enforced by project rules at write time; this change does not add required-field metadata validation or automatic field filling.
- Azure Repos update rereads are not atomic concurrency protection. The interval between reread and PATCH remains unprotected and is disclosed before approval.
- The existing provider extension seam is reused. GitHub, GitLab, and the from-backlog import contracts are retained.
