**Complexity**: medium (2 capabilities, 5 files)

## Why

`sai-explore` fetched crystallization and slice instruction files up front from `instructions.md` and `steps/common.md`, so those contracts loaded even when the chat never reached those stages.

## What Changes

- `sai/commands/explore/instructions.md` — boot preloads only the explore instruction pack (`instructions.md` and `steps/common.md`). It does not fetch `crystallization-protocol.md`, `slice.md`, or `pipeline-direct-build.md` at session start. After each sidecar `/emit`, the agent fetches whatever `next.follow` names with no file whitelist. Follow-load failure stops, shows the error, and waits; it does not guess another file and does not route through worker Bounded Recovery. If `/emit` fails or returns `rejected`, those three files are not fetched on the agent's own. Entering Crystallize starts the slicing assessment and language-gate sequence only after the crystallization step named by `next.follow` is fetched.
- `sai/commands/explore/steps/common.md` — removes eager Fetches of `slicing-assessment.md`, `artifact-review-language-gate.md`, `crystallization-language-gates.md`, and `crystallization-protocol.md`.
- `sai/commands/explore/steps/crystallization-protocol.md` — hosts those nested assessment and language-gate Fetches so they load only with crystallize.
- `test/explore-contract-preservation.test.js` — expects eleven step files, including follow-loaded `slice.md`.
- `test/explore-step-reachability.test.js` — asserts the boot pack does not fetch the three follow-loaded files, `common.md` does not fetch nested crystallization files, `crystallization-protocol.md` fetches the assessment and language gates, follow-load is driven by `next.follow` with no whitelist and a stop-on-failure rule, and sidecar `STAGE_FILES` still name those files.

Known limitations left behind: a surprising `next.follow` path is loaded because there is no allowlist, and a fetched file cannot be unloaded if the idea later resets. Sidecar machines and `STAGE_FILES` were not changed. review-loop, pipeline selector, and Plan/Direct Build worker contracts were not touched.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `explore-instruction-delivery`: startup pack is `instructions.md` plus `steps/common.md`; eleven step files; `crystallization-protocol.md`, `slice.md`, and `pipeline-direct-build.md` are reachable via sidecar `next.follow` rather than boot Fetches; nested crystallization Fetches live in `crystallization-protocol.md`.
- `explore-pre-crystallization-stages`: after each `/emit`, fetch whatever `next.follow` names with no whitelist; follow-load failure stops, shows the error, and waits; emit failure or `rejected` does not self-fetch those three files; Crystallize assessments start only after the follow-named crystallization step is fetched.
