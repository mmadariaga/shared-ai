## Why
Users who customized models via node bin/install setup had no safe way back to shipped defaults without hand-editing files. The change restores factory model tunables into existing project-local overrides by reusing the post-setup customization menu flow and the tunable patch machinery.

## What Changes
- bin/model-customization.js: MENU_OPTIONS gains Reset to default models; runPostSetupMenu gains mode customize versus reset with harness reuse and a new reset-targets screen that enumerates All targets filtered to existing local overrides, renders factory settings, and collects checklist selection; both adapters gain factorySetting, localOverrideExists, and resetLocalOverride; new resetLocalOverrideToFactory patches only model plus effort/variant from the installed global source via patchFrontmatter plus atomicReplace; outer persistence branches on mode to iterate resets, log Post-setup customization diagnostics, and re-enter the menu on success.
- test/model-customization-menu.test.js: empty-confirm guard assertion updated from one to two checklist calls covering customize plus reset.

## Capabilities
### New Capabilities
- Reset menu flow: menu plus harness plus checklist reset with no scope screen and no settings selection.
- Factory display: reset checklist SETTING column shows the factory model to be applied with plain-text unavailable fallback.
- Tunable-only restore: overwrite of only model plus effort/variant from the global installed source, preserving remaining local content.
### Modified Capabilities
- Post-setup customization menu: now offers three actions with mode routing to scope versus reset-targets while preserving the seven promptChoice invocations and the single no-footer override.
- Target checklist empty-confirm protection: now enabled on both customize and reset checklists.
