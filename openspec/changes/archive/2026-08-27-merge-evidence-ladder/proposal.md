## Why

The merge command currently infers branch objectives from code archaeology, generating ~1,230 lines of derivative reasoning to recover what 91 lines of declared intent already state. The repository contains normative specs and decision records that both the coordinator and worker should consult rather than reconstruct.

## What Changes

1. **Coordinator-owned rule capture** — Before merge launch, the coordinator runs a two-phase read (identify relevant specs/ADRs/DDRs touched on each branch, then read their content) and forwards the governing rules indexed by branch and path.

2. **Worker-side evidence ladder** — The conflict analysis now uses L1 (declared rule from governing specs/ADRs/DDRs) before L2 (textual context). When a declared rule governs a conflict region, it becomes a Fact with the rule's source identified. When no rule exists, the worker emits a visible on-screen notice: `[No declared rule found for this region]`.

3. **Prose-only strategy presentation** — The strategy proposal text carries prose explanations only (identifying facts, inferences, governing rules, branch objectives, and alternatives) while complete file content is reserved for the JSON payload. The coordinator never reconstructs a resolution from prose; it uses only the JSON `files` records.

## Capabilities

### Modified Capabilities

- `sai-merge-command` — Conflict analysis now reads governing specs and decision records from coordinator-captured `target_rules` and `source_rules`; adds evidence ladder (L1/L2) with explicit missing-rule notices; strategy carries prose only, complete content in JSON payload only.
