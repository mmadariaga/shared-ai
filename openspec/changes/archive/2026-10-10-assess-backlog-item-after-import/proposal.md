> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Users import backlog items to work on them. Previously, the shared import flow stopped after faithfully presenting the source and reporting that it was loaded for discussion. This left project assessment to a separate request.

The implemented continuation investigates the requested work against the current project, gives an evidence-based recommendation, and identifies the first substantive uncertainty or recommended next step without authorizing execution.

## What Changes

- Added default project assessment to the universal `from-backlog` instructions after complete faithful presentation of the item and every comment.
- Required a separate assessment of fit, currency, existing implementation, feasibility, and recommendation, with concrete references or explicit evidence gaps.
- Added handling for incomplete delivery, an unclear objective, covered work, outdated assumptions, and unavailable project or dependency evidence.
- Replaced display-only completion with the first substantive unresolved question that could change the recommendation, or a recommended next step when no such question remains.
- Kept assessment read-only and preserved conversation decisions, scope, originating-issue provenance, and exploration stage.
- Updated `from-next-backlog-item` completion to inherit assessment through its single authoritative import continuation without duplicating analysis.
- Updated workflow documentation and added instruction-contract and shared-projection checks.
