**Complexity**: high (6 capabilities, 28 requirements, pure deletions)

## Why
The Orca container will not be used, so keeping its implementation and active references would preserve unnecessary maintenance and imply unsupported capability. The staged implementation retires the unused Docker appliance from the repository while preserving ADR 0117b–0121 as historical records and leaving Docker-host runtime resources untouched.

## What Changes
- Delete the self-contained Orca appliance under `docker/orca/` (Dockerfile, Compose definitions including credential overlays, entrypoint and launcher scripts, healthcheck, JSON consumer, package manifests, checksums, example env, full test harness with fixtures).
- Remove active repository references: Orca env ignores in `.gitignore`, the `docker/orca/` index line in `AGENTS.md`, and the Orca Environment term plus its usage rule in `GLOSSARY.md`.
- Retire the six live Orca capability specs via REMOVED deltas; no Docker stop, volume, credential, or `.env` cleanup is performed.
- Retain ADR `0117b–0121` as history.

## Capabilities

- None — this change evidences only retirement; no new behavior was implemented.

### Modified Capabilities
- `orca-compose-operations`: retired (Compose lifecycle, privilege posture, diagnostics, external-Docker note).
- `orca-container-image`: retired (Ubuntu runtime, explicit Orca extraction, integrity verification, non-root user, no embedded secrets).
- `orca-headless-runtime`: retired (headless serve, Xvfb/software rendering, readiness/lifecycle observability, sandbox, pairing retrieval).
- `orca-runtime-configuration`: retired (non-secret version/endpoint variables, runtime-only credentials, pairing-advertisement validation, socket-free external Docker).
- `orca-persistent-state`: retired (workspace mount, Orca/agent state mounts, ownership enforcement, backup/restore guidance).
- `orca-operational-guidance`: retired (README install path, auth/pairing secrets, persistence/lifecycle, resource/network expectations, external-Docker path).
