> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

**Complexity**: low (3 files, prompt rule plus one test)

## Why

The fetch skills read every instruction file from the project-local root first and fall back to the user-global root one file at a time. Projects almost never have a local SAI copy, so traces show about 12–15 wasted reads per worker, in every agent of every phase.

## What Changes

- `skills/claude/fetch/SKILL.md` and `skills/opencode/fetch/SKILL.md`: the `Fetch @<subpath>` row of the resolution table now points to a new `### Project-local sai/ root probe` section.
- The probe runs exactly once per session, on the first `Fetch @<subpath>` directive whose path begins with `sai/`. It checks the project-local `sai/` directory through that directive's own Read, not the harness root. A project without a local SAI copy can still have `.claude/skills/` or `.opencode/skills/` from `openspec init`.
- Before the probe, or after it finds the local `sai/` root present, resolution stays as before: Read project-local, then Read user-global directly, then stop with the unchanged `File not found` report.
- After the probe finds the local `sai/` root absent, every later `Fetch @<subpath>` directive, of any prefix, is read from the user-global root directly, with no local Read attempt. The `File not found` report is unchanged.
- A local `sai/` root created after the probe is not seen until the next session.
- The `@skills/<name>` → skill-tool rows, the path-scope rules, the error report, and the path-composition rule are unchanged. Both harness variants are mirrored.
- `test/doctor-fetch-resolution.test.js`: a new test pins the probe wording in both skills (probe-once, `sai/`-prefixed scope, probed-absent branch, no local Read attempt, next-session visibility, no Glob/LS). An existing comment now says the session probe is Read-based.

## Capabilities

### New Capabilities

- None

### Modified Capabilities

- `claude-fetch-resolution`: Claude Code `Fetch @<subpath>` resolution gains a once-per-session probe of the project-local `sai/` root. When that root is absent, resolution reads the user-global root directly. Recursive resolution carries the same probe state.
- `fetch-resolution-path-scoping`: opencode resolution gains the same probe. The shared-contract and mirror requirements now describe the probe-gated two-root order.

## Impact

- `skills/claude/fetch/SKILL.md` — resolution table row and new `### Project-local sai/ root probe` section.
- `skills/opencode/fetch/SKILL.md` — the mirrored row and section.
- `test/doctor-fetch-resolution.test.js` — new `fetch-root-once` test and an updated comment.
- `openspec/specs/claude-fetch-resolution/spec.md` — delta modifies the `Fetch @subpath` and recursive-resolution requirements.
- `openspec/specs/fetch-resolution-path-scoping/spec.md` — delta modifies the shared-contract, opencode-resolution, and mirror requirements.

Trade-off accepted: a project-local `sai/` root created mid-session is not seen until the next session.

Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
