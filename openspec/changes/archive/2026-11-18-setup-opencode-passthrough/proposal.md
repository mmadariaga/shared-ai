## Why

Claude Code can already dispatch an agent whose agent file carries `harness: opencode` through the OpenCode CLI (`sai/policies/opencode-dispatch.md`, `sai/tools/opencode-dispatch.js`), but `bin/model-customization.js` never read or wrote that line, so the routing was reachable only by a manual edit of the agent file.

## What Changes

- The Claude Code harness of the setup "Customize models" menu offers `OpenCode passthrough` as the first setting option when at least one selected row is an agent file (AGENT or WORKER). ORCHESTRATOR and UTILITY rows, which are command wrappers, do not offer it.
- Choosing `OpenCode passthrough` writes `harness: opencode` in the project's `.claude/agents/<name>.md` and leaves its `model` and `effort` lines unchanged, as the runtime fallback model. It does not edit OpenCode configuration.
- In a selection that mixes agent rows and command rows, the option applies to the agent rows only; the other rows keep their setting and a warning names them. The adapter refuses to route a command wrapper.
- After a passthrough apply, setup checks once, through the new `checkAgents` export of `sai/tools/opencode-dispatch.js`, whether the `opencode` binary and the same-named OpenCode agent exist. When a piece is missing, the line stays written and a warning names the agent and the missing piece.
- Choosing a Claude model on a routed row writes `model` and `effort` and removes the `harness:` line. "Reset to default models" removes the line too, because the factory definition has none.
- The SETTING column of a routed row shows `-> opencode: <model> (<variant>)`, read when the menu draws from the same-named OpenCode agent file (project `.opencode/agents/` first, then the OpenCode global root), or `-> opencode: (unresolved)` when that file cannot be read.
- "Save preset" records for every Claude Code agent entry whether it is routed (`"harness": "opencode"` or `null`). "Load preset" writes or removes the line from that value, and leaves the line as it is for an older entry without the key. Preset validation accepts only `"opencode"` or `null` for the key.
- The preset preview table appends ` -> opencode` to the raw setting of a routed Claude Code entry, and "Load preset" also warns when a loaded routed agent cannot run through opencode.
- `route` in `sai/tools/opencode-dispatch.js` keeps its behavior; its opencode check moved into a shared helper that `checkAgents` reuses.
- `docs/models.md` documents the option, its display, its preset handling, and that installation still writes no default `harness:` line.
- The OpenCode harness screen of the menu does not change.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `model-customizer`: the Claude Code harness of "Customize models" offers, displays, applies, and resets the `OpenCode passthrough` setting for agent-file targets.
- `model-customization-menu`: the Claude settings selection returns the routing-only `OpenCode passthrough` setting for agent-file selections, and the factory restore removes a Claude Code agent file's `harness:` line.
- `install-model-presets`: Claude Code preset entries save and load the passthrough state.
- `agent-tunable-ownership`: the setup menu adds and removes the user-owned `harness:` line of a Claude Code agent file, and installation still ships no such line.
