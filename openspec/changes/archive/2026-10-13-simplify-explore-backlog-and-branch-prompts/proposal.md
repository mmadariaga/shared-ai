## Why

Generic translated tracking terminology obscured Explore's optional backlog action. Full Git namespace prefixes added noise to branch-base choices. The implemented wording makes the backlog action recognizable across languages and distinguishes branch choices without requiring users to read namespace prefixes.

## What Changes

- Explore's optional backlog question and option descriptions retain the word `backlog` in every language, with a Spanish example beside the owning question.
- Yes describes creating or updating the backlog; No describes skipping that action. Localized labels and stable `yes` and `no` values remain intact.
- Suggested branch bases display short names by removing only leading `refs/heads/` or `refs/remotes/` prefixes.
- Coincident local and remote short names receive localized qualifiers, checked against the complete inventory across pages.
- Each suggested option remains associated with its full, exact Git reference, which is passed to base resolution.
- The presentation exception applies only to suggested branch-base options. Free-text input, option order, the helper's returned data, and the general verbatim-identifier rule elsewhere remain unchanged.
- Documentation describes the presentation behavior for Claude Code and opencode, including Explore and standalone branch creation.
- Regression assertions cover localized backlog wording, separate authorization, short names, collision handling, exact-reference mapping, and the exception's scope.

- `new-change-branch`: Display readable, unambiguous suggested branch-base names while retaining exact references for execution.
