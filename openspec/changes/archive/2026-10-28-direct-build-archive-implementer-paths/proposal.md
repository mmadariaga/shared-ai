> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Direct Build Step 7 sent the archive worker only the change name, so the worker's prepared plan could not list the implementer's changed paths as owned staging paths. Step 8 commit coverage (`sai/policies/slice-path-scope.md` § Commit coverage) and the archive worker's plan-consistency rule both need those paths. A coordinator that followed the contract therefore ended with an execute order that the archive worker had to reject, and the single pre-authorized commit could not carry the code change together with the synced specs and archived artifacts (observed on v0.10.0-beta, 711ff76e).

## What Changes

- `sai/commands/explore/direct-build-coordinator.md` Step 7 adds the implementer path set (the first-seen changed-path union of Step 1, deletions included) to the `--direct-build-prepare` envelope, under a `--implementer-paths` marker line after the change name, one repository-relative path per line. A path set missing from run state stops the route before the dispatch and escalates under `obstacle-escalation.md`; the coordinator never rebuilds it from the git index.
- The same card adds Step 7b, a prepare-time coverage check: after the prepared plan is read and before any execute order, the coordinator runs the `slice-path-scope.md` `verify` check with `slice_snapshot`, the Step 8 slice paths, and the plan's owned staging paths as the covering list. A non-empty `uncovered` sends no execute order; the coordinator continues the same archive worker with a corrected-result request naming the uncovered paths, spends one `step-7` attempt per request, and escalates when the budget is exhausted.
- Step 8 sends the prepared plan's owned staging paths unchanged in the execute order. A missing path set stops the route before the continuation. An `uncovered` path found at Step 8 after a clean Step 7b keeps the order unchanged and returns to Step 7 with a corrected-result request that spends one `step-7` attempt.
- `sai/commands/archive/worker.md` parses the optional `--implementer-paths` marker in the Direct Build envelope and keeps the path set as worker state. In prepare mode the owned staging paths are only the worker's own `openspec/` paths and every path of the implementer path set; a path whose staged diff entry is a deletion is recorded as a deletion, and every other staged entry stays foreign under `foreign-index-preservation.md`. Execute validation treats the implementer-owned path set as exactly the set received at prepare. An envelope without the marker (the ordinary `/sai-archive` route) behaves as before.
- `sai/policies/slice-path-scope.md` § Commit coverage adds a rule for orders bound to a prepared plan: the coordinator checks the plan before any order and returns any gap to the plan's owner for a corrected plan, at the plan check and at the order check alike, and never extends a bound order. The existing extend-and-verify text applies only to orders that no prepared plan binds.
- `test/direct-build-archive-ordering.test.js` adds four text-contract tests for the Step 7 envelope marker, the Step 7b check before any execute order, the prepared-plan gap rule in the policy, and the archive worker's prepare-mode owned-path rule.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `direct-build-commit-coverage`: the Direct Build coordinator delivers the implementer path set in the archive prepare envelope, checks commit coverage on the prepared plan before any execute order, and returns any coverage gap to the archive worker instead of extending the order.
- `auto-fast-archive-execution`: the archive worker's Direct Build preparation lists the envelope's implementer path set as owned staging paths, and execute validation uses exactly that set.
- `slice-path-scope`: the commit coverage policy returns a gap in an order bound to a prepared plan to the plan's owner instead of extending the order.
