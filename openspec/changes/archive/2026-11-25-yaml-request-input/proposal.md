> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

`to-pr.js` and `to-backlog.js` receive model-written free text (a Markdown title and description) inside a JSON input file. Markdown in a JSON string becomes one line full of `\n` and escaped quotes: hard for a person to read in the tool-call display and error-prone for the model to escape. A `to-backlog` query written for issue #526 was a single line of about 3,000 characters. Worker reports already avoid this with YAML block scalars validated by a strict YAML subset parser, so the same parser can carry these requests.

## What Changes

- The strict YAML subset parser (`parseYaml`, its block-scalar and flow helpers, and `yamlError`) moves out of `sai/tools/worker-report-validator.js` into the new shared module `sai/tools/yaml-subset.js`; the validator imports it and reads worker reports as before.
- `sai/tools/yaml-subset.js` adds `readRequest`, which reads a request as JSON only when its first non-blank character is `{` and as the YAML subset otherwise (a leading byte-order mark is ignored), and rejects a request that is not a mapping.
- `sai/tools/yaml-subset.js` adds `normalizeRequestText`, which rejects a `title` or `description` that is not a string with an error naming the field, and removes the trailing line breaks of both fields.
- `sai/tools/to-pr.js` and `sai/tools/to-backlog.js` read every `--input-file` (or stdin) request through `readRequest` and `normalizeRequestText` instead of `JSON.parse`, so a YAML request is accepted, a JSON request keeps working, and a malformed or wrong-typed request fails before any provider call. Their usage messages name JSON or YAML requests.
- The `to-pr` skill (`SKILL.md`, `description-format.md`) and the `to-backlog` provider instructions (`github`, `gitlab`, `azuredevops`, and their `-update` variants) write their requests as YAML in a `.yaml` file, with a quoted title and `description: |` as a block scalar.
- `sai/policies/tool-resolution.md` § Invocation states that a request carrying model-written free text, such as those of `to-pr.js` and `to-backlog.js`, may be written in the YAML subset; `AGENTS.md` lists `yaml-subset.js` among the tools.
- Tests: the new `test/yaml-request-input.test.js` covers format detection, subset rejections with line numbers, block-scalar fidelity, wrong-typed fields, trailing line-break normalization, and both CLIs; `test/backlog-gitlab.test.js` expects the trailing line break removed; `test/sai-state-progress-emit.test.js` copies `yaml-subset.js` into its installed layout.

## Capabilities

### New Capabilities

- `yaml-request-input`: `to-pr.js` and `to-backlog.js` accept requests in the strict YAML subset as well as JSON, validate the type of `title` and `description`, normalize their trailing line breaks, and their instructions write the requests as YAML.

### Modified Capabilities

None
