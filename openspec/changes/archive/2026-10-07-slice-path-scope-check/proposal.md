## Why

In a real Direct Build run the slice's local commit contained only `openspec/` paths while the implementer's source files stayed staged. The owned-path list of the archive execute order was composed and validated by prose only (`sai/commands/explore/steps/pipeline-direct-build.md` Step 8 and the Direct Build plan validation in `sai/commands/archive/coordinator.md`), so no tool rejected an incomplete list. The data needed for the check already existed in the changed-files union, and the prose rule was already present when the defect happened.

## What Changes

- Add `sai/tools/slice-path-scope.js`, a read-only tool with two sub-commands. `snapshot` records every path `git status` reports as modified, with its status and a content hash, plus HEAD, and returns an opaque reference. `verify` reads the slice paths and an optional covering list from standard input and reports `foreign` (paths changed since the snapshot that lie outside the slice paths) and `uncovered` (slice paths outside the covering list) with a verdict of `clean`, `mismatch`, or `n/a`.
- The snapshot record is stored in the OS temporary directory, outside the repository; the tool never mutates the repository.
- A listed directory stands for every path beneath it in both lists. Staging and committing since the snapshot count as changes.
- Exit codes: 0 for `clean` or `n/a`, 1 for `mismatch`, 2 for a usage or IO error, with no verdict printed on an error.
- Add `sai/policies/slice-path-scope.md` as the single source of the terms, the invocation, the verify payload, and the commit coverage rule.
- Direct Build takes the initial snapshot before the implementer dispatch and holds the reference as the conversation-only run state `slice_snapshot`.
- Direct Build sends the archive `--direct-build-execute` order only when the order's owned paths cover every slice path. While a slice path is uncovered, the coordinator adds it to the owned paths and verifies again. On an `n/a` verdict the coordinator prints one line naming the reason and sends the order.
- The archive coordinator's Direct Build plan validation references the same coverage rule.
- `AGENTS.md` documents the new tool in the `sai/tools/` row.
- Add `test/slice-path-scope-tool.test.js` covering the tool, the policy, and both route cards.

Known limitations: one new piece of conversation-held state per slice, the snapshot reference. A file that was already modified and that the implementer also reports counts as a slice path, so the commit carries the user's earlier edits in that file, as it did before. Recovery behavior, re-issuing execute orders, and detecting out-of-slice changes after a recovery attempt are not part of this change.

## Capabilities

### New Capabilities

- `slice-path-scope`: a deterministic, read-only snapshot of already-modified files and a verification of slice paths against the working tree and a covering list, each with a JSON verdict.
- `direct-build-commit-coverage`: a Direct Build archive execute order is sent only when its owned paths cover every slice path.

### Modified Capabilities

None.
