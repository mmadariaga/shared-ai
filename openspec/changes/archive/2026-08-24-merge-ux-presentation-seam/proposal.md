## Why

The current merge worker payloads combine technical analysis and user-facing questions, while the coordinator forwards them almost verbatim. This makes concise merge decisions difficult to present without changing merge behavior. The staged implementation establishes a coordinator-owned presentation seam while preserving the existing merge lifecycle and mutation boundaries.

## What Changes

- Add a merge-local presentation seam fetched by the coordinator.
- Keep worker source, merge presentation state, and mutation outcomes as separate coordinator-local values.
- Route gate, progress, and terminal rendering through named coordinator responsibilities.
- Preserve existing questions, option values and order, continuation semantics, timestamps, changed-file aggregation, verification-round behavior, and commit authorization.
- Keep the active renderer legacy-compatible: the visible selector, TODO, compact authorization summary, and visible ADR/DDR label improvements remain outside this preparatory slice.
- Extend the worker's read-only ADR/DDR collision plan with exact old/new H1 and index-label values so the coordinator can maintain record consistency without rereading artifacts.

## Capabilities

### New Capabilities

- `merge-presentation-seam`: A coordinator-owned, merge-local boundary for rendering validated worker source together with coordinator-owned presentation state without authorizing or executing mutations.

### Modified Capabilities

- `merge-collision-metadata`: Merge collision plans now carry synchronized path, suffix, H1, and index-label data for coordinator-owned rename execution.
