> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The `/sai-review` composition coordinator carried text that did nothing: an unused load of `bounded-recovery.md` (every segment declares `recovery_policy: false`), an "Edge cases" list pasted from a proposal that hid the one live audit-failure rule, and sections that restated rules owned elsewhere. Three behaviors were also defective or undefined. A triage value that was neither `Yes` nor `No` silently disabled its audit. The error close for a missing `review.md` was named but never defined. The Direct Build close's non-convergence ending pointed to an undefined "manual-route note". Later slices edit the same card, so each rule needs to be stated once, in the place that owns it.

## What Changes

- `sai/commands/meta-review/command-bootstrap.md`: the triage parse is the single definition. Exactly `Yes` activates an audit and exactly `No` leaves it inactive. Any other value is illegible: that audit does not run, the summary carries a warning line naming it, and the value adds no correction authorization. A new `## Error close` section defines the close used when `review.md` is missing or none of the three values is legible. It dispatches no audit, offers no correction choice, reports the gap, shows the changed files, and ends with no Direct Build round.
- `sai/commands/meta-review/coordinator.md`: the unused `bounded-recovery.md` fetch is removed. So are the duplicated "Triage parse and conditional audit activation" section, the "Edge cases" list, and the "No intermediate approval gate", "Non-removable stops", and "No Step ceiling" sections. The audit-failure rule now sits in the soft-parallel dispatch section as an audit-only exception to `sai/orchestration/composition.md` § 2: a `failed` or `cancelled` audit does not close the composition, the other audits continue, nothing retries, review does not re-run, and the combined terminal shows each audit's status. The coordinator defers to the bootstrap's Error close and names the close "Direct Build close" throughout.
- `sai/commands/meta-review/direct-build-close.md`: the close is named "The Direct Build close". On non-convergence after three fix rounds, the run stages and commits nothing and appends a non-convergence close. That close states that nothing was committed, names the selected findings still open, and lists the modified files left uncommitted. The card now fetches `@sai/policies/autonomy-audit-log.md` and `@sai/policies/commit-rules.md` where it uses them (evidenced scope drift).
- `sai/orchestration/composition.md` is unchanged.
- `AGENTS.md`, `docs/commands/sai-review.md`, and `docs/review-triage.md` describe the audit-failure exception, illegible triage values, the error close, and the non-convergence close.
- `test/review-coordinator-worker.test.js` asserts the new wording and the absence of the removed sections, the `bounded-recovery` load, and the "manual-route note".

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `review-triage-parse`: a legible value is exactly `Yes` or `No`. Any other value is illegible, and the error close is defined.
- `conditional-audit-activation`: activation follows the legible triage values, and the Error close and the Direct Build close are named.
- `concurrent-audit-dispatch`: audit-failure isolation is declared as an audit-only exception to the composition close rule.
- `findings-driven-fix`: the non-convergence close content is defined.
- `standalone-close-selector`: the non-convergence close replaces the manual-route note, and the zero-audit branch uses the Direct Build close and Error close names.
