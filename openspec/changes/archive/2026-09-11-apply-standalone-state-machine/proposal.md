## Why

The coordinator re-derived the Step cursor as prose at `coordinator.md:68`, so a cheap model re-executed on every Step a decision a deterministic `transition()` function can make. Relocating the derivation into a run-scoped state machine removes the prose judgement while keeping `implementation.md` as the durable authority, and lets the coordinator fetch only the routing file the active Step needs instead of holding all five for the whole run.

## What Changes

- Add `sai-state/machines/apply-standalone.js` (`apply-standalone@1`), a pure-function machine owning the Step cursor and routing-mode pointer for apply runs
- Register `apply-standalone@1` in `sai-state/registry.js`
- Wire `coordinator.md` to spawn the machine at run start, seed it from the parsed `#### Step N:` headings and per-Step checkbox state, emit the active Step's routing mode, and fetch only the file named by the returned `next.follow`
- Remove the duplicate cursor-derivation prose from `coordinator.md`, leaving the derivation in exactly one place
- Document the degraded-store fallback so a store failure completes the run at full context cost instead of halting
- Add `test/apply-standalone-machine.test.js`
- Add ADR 0183 recording why apply follows the explore self-gating precedent rather than ADR 0172c's

## Capabilities

### New Capabilities

- `apply-standalone-state-machine` — The apply Step cursor and routing-file delivery are owned by the `apply-standalone@1` machine, re-seeded from `implementation.md` at every spawn and driven by the coordinator through emit and `next.follow`.
