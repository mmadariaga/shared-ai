**Complexity**: high

## Why

A recorded single-conflict merge took approximately 22 minutes while worker tools and tests each took approximately 11 seconds, motivating reduction of repeated mechanical deliberation, broad instruction disclosure, and duplicated explanations. The implemented change reduces instruction volume and model-facing collection boundaries without attributing unmeasured latency to reasoning, generation, or provider behavior.

## What Changes

- Added `sai/tools/merge.js` to collect preflight, provenance, conflict, suite, verification, and collision facts through structured results.
- Added dependency receipts with explicit validity checks, immutable historical provenance, and exclusive external records retained by exact reference and checksum.
- Added pre-write conflict snapshots and explicit correction snapshots. Resolution checks compare authored replacements with the captured working file, retaining Git-combined content and unrelated content.
- Changed merge worker task delivery to disclose only the active stage from the authoritative instruction library while retaining the same persistent worker.
- Expanded continuation and replacement state to carry complete inventories, exact references, confirmed strategies, correction counters, verification outcomes, collision plans, and operation history.
- Required validation of the original received worker result rather than a reconstructed substitute, alongside independent coordinator review before staging.
- Added report selection that presents each strategy completely once and retains necessary outcomes without repeating settled semantic explanations.
- Added regression fixtures and mechanical comparison evidence. The retained measurement baseline identifies an exact revision and checksum instead of reading moving HEAD.
- Included suffixed source-introduced ADR/DDR records in family-aware collision applicability, and required semantic judgment for uncertain survival or references.
- Used existing Markdown and JavaScript installation projections for Claude Code and opencode, without model, permission, or command-local executable changes.

## Additional Notes

The mechanical comparison establishes fewer model-facing collection calls and smaller initial disclosure, not a full-runtime speedup. In the documented sample, deterministic preflight execution was slower because it collected validity state and checked for races. Paired full-runtime traces on both harnesses remain unmeasured; the documented comparison protocol keeps configuration constant and separates human waiting, tests, tools, and time outside tools. Persistent worker context is retained, so stage disclosure does not promise a lower cumulative instruction volume for every route.
