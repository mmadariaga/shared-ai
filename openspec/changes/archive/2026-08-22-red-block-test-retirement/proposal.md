## Why

Replacing an obsolete guard test inside `/sai-4-apply` produced a logical dead end: the GREEN worker's absolute test-file prohibition is correct, but test-file retirement had no owner anywhere in the routing tree — the RED worker's scope said "write ONLY", the coordinator performs no technical writes, and recovery routes a forbidden-test cause out of scope. A real run stopped at Step 1 GREEN because verification required removing `test/report-template-parity.test.js` and every automatic route was closed, forcing manual human intervention to correct a blind spot. This change gives that scenario a route: retirement is owned by the test-authoring dispatch and sealed by coordinator checklist verification, so the pipeline channels through instead of halting.

## What Changes

- `sai/commands/apply/red-worker.md`: § Scope gains a bounded retirement exception — the worker MAY remove exactly the test files the plan names as retired, by exact repository-relative path; the exception grants no read access and every path not named as retired remains forbidden. § Recovery Continuation inherits the same bounded authorization for the same named files only. Report field 8 now covers written, created, or removed paths and declares removed retired files by exact path; the Prohibitions report-completeness line matches.
- `sai/commands/implement/instructions.md`: planner guidance in three surfaces — retirements live ONLY inside RED blocks with exact paths marked `retired`; green-direct Steps never carry them; every Step whose RED block retires files adds one Verification Checklist absence item per retired file, run by the coordinator after the RED dispatch returns and before GREEN may be dispatched.
- `sai/commands/implement/implementation-plan.template.md`: the RED phase block carries the same Retirements rule for plan authors.
- `AGENTS.md`: the RED → GREEN convention documents that retirement is owned by the RED dispatch (or the green-exception flow), never by GREEN, and pins the anti-pattern — tests assert the absence of retired files; they never encode routing vocabulary such as "must be removed in GREEN".
- `test/apply-red-retirement-authority.test.js` (new): seven contract tests pinning the wording and boundaries above.

## Capabilities

### New Capabilities

- `apply-test-retirement`: plan-named obsolete test files are removed by the test-authoring dispatch only, sealed by coordinator checklist absence verification between RED return and GREEN dispatch.

### Modified Capabilities

- `apply-test-impl-split`: the RED worker's authorized test/stub file boundary gains the plan-named retirement exception, preserved across recovery continuations.
- `apply-subagent-report-contract`: report field 8 covers written, created, or removed non-scratch paths and declares removed retired files by exact repository-relative path.
- `implement-red-phase-contract`: RED phases may additionally carry retirement declarations (exact paths marked `retired`) beside the failing test, stubs, and scaffolding.
- `apply-pre-commit-file-report`: the pre-commit add-list includes retired-file removals, so previews, staging, plan cross-checks, and Subagent↔git sync observe them.
