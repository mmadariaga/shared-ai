> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Single-item backlog capture and import did not preserve the structure of crystallized work. The implementation adds a GitHub-first path that publishes agreed slices, retrieves their complete source contents, transports selected-child identities, and checks responsibility before implementation without another decomposition interview.

## What Changes

- Added individual and complete-set dependency validation alongside the Ready to Propose parser, with stable blocker-first ordering.
- Included dependency and optional canonical GitHub origin fields in stored block text and hashes.
- Validated complete sets before storage and publication, and validated the resulting set before an amendment replaces a stored block.
- Rejected amendments that change the existing execution order, requiring complete-set re-emission.
- Added GitHub parent-and-child publication with separately verified Project membership, written references, native hierarchy and native dependency operations when supported.
- Added conservative partial-result recovery, explicit identification of uncertain creations, and approval-bound continuation without blind issue recreation.
- Added structured parent/child correspondence in published issue bodies.
- Added complete read-only hierarchical GitHub import with paginated comments, assignees and supported relationships.
- Added validated transport of actual child issue URLs into stored blocks, recomputed hashes, manual handoffs and spec-created change metadata.
- Added coordinator-owned responsibility inspection, exact assignment proposals, authorized assignment and verification at implementation start.
- Preserved parent assignees, ordinary publication/update paths, GitLab and Azure DevOps behavior, next-item selection and existing initial-branch ownership.
- Added regression coverage and mirrored installation of the new shared surfaces for Claude Code and opencode.

## Capabilities

### New Capabilities

- `backlog-slice-lifecycle`: GitHub crystallized-set publication, verified relationship representations, conservative recovery, complete hierarchical import, durable child provenance and separately authorized implementation-start responsibility.
- `crystallized-dependencies`: Individual dependency syntax checks, complete-set reference and cycle validation, stable blocker-first ordering, stored dependency hashing and safe amendments.

### Modified Capabilities

- `to-backlog-github-publication`: Ordinary creation still creates one issue; explicitly crystallized sliced sets use parent-and-child creation with separately approved and verified relations.
