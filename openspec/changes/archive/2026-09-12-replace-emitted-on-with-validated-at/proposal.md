**Complexity**: high (flag-day, 35 files, 4 capabilities)

## Why
The timestamp exists only so humans can see durations in the coordinator prompt and panel. Centralizing the clock in the validator removes the worker clock dependency while keeping a single time source for prompt and panel.

## What Changes
- **BREAKING** Remove time fields from all closed payload shapes so workers never read a clock and payloads stay timeless.
- Add validator-observed validated_at sidecar as text suffix and JSON field with exit codes and ok/errors semantics unchanged and payloads never rewritten.
- Have the coordinator forward verdicts verbatim and surface validated_at in its prompt for terminal and progress results at minimum with no wall-clock calls.
- Source the panel Milestone Stamp from validated_at only as closure-only HH:mm with no conversion, fallback, or coordinator clock.
- Update contracts, decision records, glossary, bindings, and tests to timeless shapes and observation-time wording across 35 files.

## Capabilities
### New Capabilities
- validator-stamping: valid results carry additive validated_at sidecar as text suffix and JSON field with exit codes unchanged; invalid results carry no timestamp.
- timeless-worker: worker payloads carry no time field and never read a clock; unknown fields ignored with no explicit legacy handling.
- prompt-display: coordinator surfaces validated_at in its prompt for terminal and progress results at minimum with no wall-clock calls.
- panel-stamp: panel Milestone Stamp reads validated_at as sole time source with closure-only rendering.

### Modified Capabilities
None — all behavior in this change is introduced as new deltas. Overlapping time-bearing main specs are listed in the conflict report and synchronize at archive time.
