## Why

Bare consecutive file lines collapse into one paragraph in Markdown previews. Explicit bullet lists make generated file and research-source entries readable without relying on invisible trailing whitespace.

## What Changes

- Shared design instructions and templates require one Markdown bullet per file declaration, existing broken-test entry, and required-documentation path or URL. Notes remain alongside their entry, and empty markers stay unchanged.
- The proposal template requires bullet lists for consulted local files and external URLs.
- File Manifest generation prefixes each non-empty net-fold entry with `- ` while retaining change tokens, rename paths, ordering, and Step attribution.
- Read-only manifest verification accepts either the new bullet prefix or its legacy absence, without masking content or ordering differences. Explicit regeneration emits bullets and remains idempotent.
- Tests cover the shared formatting contract, legacy compatibility, rename folding, notes, absence markers, and repeated generation.

## Capabilities

### New Capabilities

- `artifact-file-list-format`: Readable bullet-list presentation for design file declarations, task documentation, and proposal research sources through shared generation sources.

### Modified Capabilities

- `design-file-manifest-tool`: Bullet manifest output and read-only verification compatible with legacy unbulleted entries.
- `design-target-state`: Bullet presentation for the normative net-fold manifest, preserving all fold semantics.
- `tasks-scaffold-format`: Bullet presentation for generated task file entries and their instruction/template contract, retaining legacy input compatibility.
