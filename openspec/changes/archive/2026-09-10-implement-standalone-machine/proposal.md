## Why
Standalone `sai-3` relied on an advisory `Active step` pointer that small models could drift from by prefetching later steps; a sidecar-owned stage table makes just-in-time loading enforceable and keeps cheap-model context minimal.

## What Changes
- Added `sai-state/machines/implement-standalone.js` (new, 188 lines) implementing `implement-standalone@1` with the six standalone states, follow mapping, minimal-wire outcome, monotonic transition, and re-resolution projection.
- Updated `sai-state/registry.js` (1 line) to register `implement-standalone@1` alongside `explore-idea@1`, `explore-slice@1`, and `spec-standalone@1`.
- Standalone runs now route each step through the sidecar `next.follow`; chained `/sai-build` implement runs keep supervised transition and never consult this machine.
- Boot is nucleus-only (`worker.md` + `steps/common.md`); each of the five step files loads only when named, with stop-and-wait on any follow-load failure and skip when already loaded.

### Modified Capabilities
