**Complexity**: medium (3 capabilities, 8 requirements, 5 files)

## Why
Batching groups closed merge questions to avoid extra round trips, but squash was left outside Batch 1 because it only applies after choosing rebase. That left an extra singular round on the rebase path. Folding squash into the initial method selector as `Rebase with squash` removes that round while keeping Batch 1 conditional-free.

## What Changes
The sai-merge method selector now shows three labels (`Merge` / `Rebase` / `Rebase with squash`). The third label is a presentation shortcut that fixes the existing pair `method=rebase` + `squash=yes` with no new method value or state; `Rebase` alone equals `method=rebase` + `squash=no`. The standalone conditional squash gate is retired. The Batch 1 branch question uses single neutral text for all three options because the batch renders before the method answer exists; direction is compensated in the gate summary with current branch plus explicit direction. The method gate summary absorbs the squash explanatory context (unify `merge_base..HEAD` vs replay commit by commit). Authorization summary, adaptive TODO, and provenance reuse the existing rebase with squash `yes` rendering. Fast-track stays pinned to merge with no squash choice. Files changed (staged): `sai/commands/merge/coordinator.md`, `sai/commands/merge/instructions.md`, `sai/commands/merge/lifecycle.md`, `sai/commands/merge/presentation.md`, `sai/commands/merge/worker.md`.
