## Why

The sai-explore POC lane promised to abandon its isolation when it closed, but no step created or removed that isolation and "abandon" was undefined, so a POC experiment could stay on disk without the user ever deciding its fate. The lane now creates a concrete isolation and asks the user, at every lane exit, whether to destroy it.

## What Changes

- `sai/commands/explore/steps/poc-lane.md` § Reversible isolation: the lane creates the POC isolation as the coordinator with `worktree.js create <repo>.poc-<idea-slug> --json`, a sibling worktree on the exclusive branch `poc-<idea-slug>` started from committed `HEAD`, and records the returned `path` and `branch` in the conversation only. It tells the user that uncommitted changes are not carried over. A `create` refusal stops the lane before the POC runs, with no destroy question and no reuse of an existing branch.
- `poc-lane.md` § Destroy question: at every lane exit (`Continue with <Cn>`, `none`, execution failure, cancellation, discard of the idea) the lane asks `Destroy the POC` / `Keep the POC` through the native picker, naming the recorded targets; `Stay here` asks nothing; on `Continue with <Cn>` the answer comes before advancing; an interrupted run is asked on the next lane turn. On destroy it checks the recorded targets with `worktree.js inventory --json`, then runs `remove <path> --force` and `delete-branch <branch> --force` in that order, removing nothing on a mismatch and reporting a partial cleanup with the manual command and no retry. On keep it reports the exact path and branch. The verdict menu entries for `Continue with <Cn>` and `none` now ask the question.
- `sai/commands/explore/instructions.md` and `steps/common.md`: the Explore read-only rule names the POC isolation creation and its forced removal on the recorded targets as a coordinator-owned exception.
- `sai/commands/explore/steps/pipeline-direct-build.md` and `sai/commands/explore/direct-build-worker.md`: the `--no-specs` envelope carries `--work-root <path>` as its second line, the POC worker reads and writes only under that path, and "abandon" is replaced by the create/destroy-question flow.
- `docs/commands/sai-explore.md`: the user-facing description of the POC isolation and destroy question.
- Incidental CI maintenance included in this slice at the user's request, not POC-lane behavior: `.github/workflows/ci.yml` pull_request branches become `[main, v0.11.0-beta]`, and `test/ci-workflow.test.js` matches it.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `explore-viability-poc-pause`: the POC isolation is a recorded sibling worktree on an exclusive branch, and every lane exit asks the destroy question with its removal, retention, mismatch, and partial-cleanup outcomes.
- `explore-direct-build-no-specs`: the `--no-specs` envelope carries `--work-root <path>`, the implementer is confined to it, and POC code is discarded only on a confirmed destruction.
- `explore-context-isolation`: the Explore read-only rule carries the POC isolation exception for creating and, on confirmation, force-removing the recorded worktree and branch.

Known limitations: each kept POC leaves a sibling directory on disk until the user destroys it; the POC starts from committed `HEAD`, so uncommitted work in the user's checkout is invisible to it; the recorded targets live in the conversation only, so a chat that never resumes leaves the POC on disk with no automatic cleanup.
