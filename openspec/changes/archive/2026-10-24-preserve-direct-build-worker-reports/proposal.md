## Why

Issue #224 described report corruption introduced while a coordinator copied report text into a shell command, followed by repeated closing checks after archival and commit. The implemented change uses private report references and validates the verified bytes without coordinator transcription, while separating pending report checks from confirmed repository operations. The historical incident motivates this record; it is not an independently reproduced validator hang.

## What Changes

- Added a shared full Direct Build report-transport policy for Claude Code and opencode. Implementation, backfill, and archive workers write complete closed reports with the existing transfer helper and return path/hash references after the unchanged ready handshake.
- Extended the report validator with file-mode arguments and exported `validateFile`, using one verified read for integrity checking and report validation. Accepted reports expose their parsed payload; failed delivery and invalid content remain separate outcomes. Legacy stdin and pure validation retain their existing behavior.
- Integrated the policy into the three worker cards, Direct Build pipeline, shared runner, tool-resolution instructions, and unattended recovery policy. Report-only recovery cannot replay confirmed archive moves or commits, and unresolved verification retains report and draft evidence.
- Added focused transport and compatibility tests and documented the bounded route scope. POC and standalone reused-worker transport remain unchanged; no timeout, shell sanitization, broader migration, or new mutation authority was introduced.

## Capabilities

### New Capabilities

- `direct-build-report-transport`: Private report references, verified-byte validation, distinct delivery/validity outcomes, and Direct-Build-only worker integration.
- `direct-build-report-recovery`: Autonomous bounded report recovery, retained evidence, and protection of independently confirmed operations.

### Modified Capabilities

- `backfill-draft-transport`: Direct Build report-directory ordering and retention of separate draft evidence through unresolved closure.
- `validator-stamping`: File-mode response fields alongside the unchanged first-key `received_at` and legacy stdin behavior.
- `validator-tool-paths`: Full Direct Build reference-based invocation through the resolved validator.
- `orchestration-core`: Full Direct Build exception to stdin report submission without changing other validation routes.
