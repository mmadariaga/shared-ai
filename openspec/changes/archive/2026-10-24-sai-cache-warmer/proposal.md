## Why

Users near a subscription usage limit need to pause substantive work while periodically reusing the current conversation context until allowance recovers. The explicitly invoked activity avoids requiring a separate conversation, but provider cache retention and cost savings remain unverified and are not guaranteed.

## What Changes

- Added the explicitly invoked, provider-agnostic `/sai-cache-warmer` universal skill for Claude Code and opencode, without command wrappers or OpenSpec prerequisites.
- Added a bundled Node.js helper that parses positive intervals and local targets, preserves valid values and exact resolved instants across corrections, confirms implicit day changes, and fixes closing time at the target plus one minute.
- Added native picker instructions with the agreed presets and free-text entry, asking only for missing or invalid values and required date confirmation.
- Added one-wait-per-call background execution instructions: the main agent continues in the same conversation on native completion notifications, without polling or a script-owned repeated activity loop. Final waits are shortened; late completion, cancellation, and failure stop further waits.
- Added both-harness installation, capability declarations, deterministic timing tests, and user documentation. Completion notifies the user without resuming previous work; no provider, model, subscription, or configuration is inspected or changed.

## Capabilities

### New Capabilities

- `cache-warmer-invocation`: Explicit invocation, deterministic argument resolution, fixed closing time, and input preservation.
- `cache-warmer-pickers`: Missing-value collection and day-change confirmation through native pickers.
- `cache-warmer-cycle`: Main-conversation background waits with fixed closure, interruption handling, and honest limitations.

### Modified Capabilities

- `contract-tool-capabilities`: Register the skill-only cache-warmer command requirements and bounded Node helper access for both harnesses.
