> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The `/sai-explore` hand-off wait failed for every answer except `No`: `wait.js begin` read `--interval` and `--max` with `Number()` while the hand-off picker offers `30 min` and `4h`, so every picked value was rejected. In addition, an opencode worker that was still warming could escape its dispose, because `dispose-shells.js` reports `none` in the gap between a wait's exit and its re-arm and the dispose treated `none` as complete. A main-session `begin` without a harness session id silently opened a new chain on each call, which breaks the one-live-wait rule. Finally, the warming policies described end conditions and switch recipients that the code does not have, and the `harness-coordination-parity` specification still described the retired opencode `task` dispatch.

## What Changes

- `skills/universal/sai-cache-warmer/wait.js`: `begin` reads `--interval` and `--max` through a new `minutesOf` helper built on the existing `intervalMilliseconds` parser, so `20`, `30 min`, `4 min`, `4h`, `2h`, `1h`, and `1.5h` are accepted (unitless values in minutes) and `1h30` is refused with a usage message that names the accepted forms. A main-session `begin` without `--session` and without the harness session variable (`CLAUDE_CODE_SESSION_ID` on Claude Code, `OPENCODE_SESSION_ID` on opencode) now throws a `UsageError` that names the variable and arms nothing; a subagent `begin` is unchanged. The session environment can be injected through `io.env` for tests.
- `sai/policies/worker-lifecycle.md`: on opencode, `removed` is a complete dispose; after a `none` listing the coordinator sends the `dispose` message only when the worker's last real message carried `warming: true`, and keeps that last `warming:` line with the handle in conversation state. A worker that never sent the line receives no message. Claude Code never sends the `dispose` message.
- `sai/policies/cache-warming.md`: the warming switch reaches workers and `budget-explorer`, and `budget-subagent` only on a continuation; a message without a switch supersedes nothing, so an earlier wait keeps re-arming until its window closes or its dispose; a main-session `begin` without a session id is listed as a non-zero `begin`; the hand-off wait documents the accepted duration forms; the warming diagnostic gates no stop and is kept only for the opencode `none` case.
- `sai/commands/explore/steps/handoff-warming.md` and `docs/commands/sai-explore.md`: list exactly the accepted interval and duration forms, keep answers as given without the `(Recommended)` suffix, and treat any other free text as invalid under the existing ask-again rule.
- `AGENTS.md` § Isolation Mode: states that `sai-cache-warmer` and `sai-context-cache-ttl-benchmark` keep their wrappers without the isolation preamble on both harnesses, enforced by `test/command-launcher-card.test.js`.
- `test/cache-warmer.test.js`: tests for the accepted and refused `begin` forms (E2), the main-session `begin` without a session id on both harnesses and the unchanged subagent `begin` (E3), and the preamble exemption of the two context-preserving wrappers and its AGENTS.md statement (E4).
- The `harness-coordination-parity` specification is corrected to the v2 `subagent` dispatch of opencode (ADR 0206).

## Capabilities

### New Capabilities

- None

### Modified Capabilities

- `worker-dispose`: the opencode `dispose` message follows a `none` listing when the worker's last real message carried `warming: true`, and the coordinator keeps that last diagnostic with the handle.
- `explore-handoff-warming`: the hand-off question accepts the interval and duration forms its picker offers plus unit-bearing or unitless free text, and refuses compounds such as `1h30`.
- `agent-self-warming`: `begin` parses the hand-off timings with `intervalMilliseconds`, a main-session `begin` without a session id fails visibly, and the warming-switch recipients and the no-switch rule match the code.
- `harness-coordination-parity`: opencode routed dispatch is the v2 `subagent` tool with background dispatch, not the retired `task` dispatch.
