> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation. It describes a decision already made, not one being proposed.

## Why

The harness-native task-panel mechanics were embedded in the explore-scoped idea-list bindings. Claude Code's `TaskList`/`TaskGet`/`TaskUpdate` mechanics, the `description` marker carrier, and in-place panel convergence lived only in `sai/adapters/claude/idea-list-render.md`, with the opencode equivalent mirrored in its idea-list binding. A second panel-consuming surface would otherwise need to duplicate those mechanics or widen an explore-specific file. The extraction creates the missing per-harness extension seam without adding user-facing value.

## What Changes

- Add a Claude Code panel-render binding that owns the native task-panel mechanics, `description` marker carrier, convergence behavior, and surface-scoped clearing.
- Add an opencode panel-render binding that owns the native todo-panel mechanics, `priority` marker carrier, full-array replacement, and surface-scoped clearing.
- Refactor both explore idea-list bindings to reference their harness panel-render binding while retaining their own marker vocabulary, labels, statuses, review `in_progress` rules, and coordinator ownership policy.
- Update the explore render contract, install manifest, repository inventory documentation, installer/doctor coverage, and binding-specific tests.
- Preserve behavior symmetrically across Claude Code and opencode; no new render act, progress step, or plan-deduplication behavior is introduced.

## Capabilities

### New Capabilities

- `harness-panel-render-binding`: per-harness bindings define the native task-panel mechanics, machine-readable marker-carrier field, and panel convergence or replacement behavior for consuming surfaces.

### Modified Capabilities

- `explore-idea-list-binding-delegation`: the explore idea-list bindings retain surface-specific policy and delegate shared panel mechanics to the corresponding per-harness panel-render binding.
