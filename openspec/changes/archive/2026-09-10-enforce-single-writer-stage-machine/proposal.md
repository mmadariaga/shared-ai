## Why

The single-writer invariant is real but currently holds by accident: no worker card emits today, and `sai/commands/spec/coordinator.md` guarantees "no shared sessions or state". However, nothing prevents a future worker card from acquiring an emit call. The previous change (replace-state-sidecar-with-cli) removed enforcement from the sidecar process; this change restores it by declaring the rule explicitly and enforcing it mechanically.

## What Changes

The implementation adds a new `worker-emission-ownership` lint check to `sai/tools/lint.js` that validates worker cards against the stage machine emission surface:

- Detects sai-state command invocations (emit, spawn, close, run)
- Detects references to bin/sai-state.js
- Detects quoted sai-state command references
- Detects stage machine IDs (explore-idea@1, explore-slice@1, spec-standalone@1, design-standalone@1, implement-standalone@1)
- Detects legacy /emit HTTP command

The check discriminates on the stage-machine emission surface, not the English verb "emit", because worker cards legitimately emit progress events to their coordinator. All real worker cards in the repository pass the check.

### New Capabilities

- **stage-machine-write-ownership**: Only coordinator sessions may emit to the stage machine; the rule is declared and mechanically enforced
