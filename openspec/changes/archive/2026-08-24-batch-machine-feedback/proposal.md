## Why

`MachineFeedbackAdapter` forwarded supervised review findings to the same phase worker with one continuation per finding. Each continuation reprocessed the worker's whole context (~N× context tokens) and serialized N turns (~2× latency in observed runs) without adding quality for independent findings, because the per-item legitimacy discipline lives in the feedback rules themselves — the human feedback path already processes multi-item batches in a single turn. The extra cost bought only failure isolation and sequential-collision safety that rarely materialize with the 0–3 findings typical of converging rounds.

## What Changes

- Batched the machine-feedback transport: each completed supervised review round is now continued to the same spec/design worker in exactly **one** continuation carrying that round's complete ordered findings list, replacing the previous one-continuation-per-finding forwarding (`sai/policies/artifact-feedback-gate.md`, canonical adapter paragraph and interactive-mode continuation sentence).
- Within that single batched turn, the worker applies the existing per-item rules sequentially for every item in array order, performs exactly one verification at the close of the turn (`openspec validate`), emits one block reporting every individual disposition (`applied`, or `discarded` with its specific reason), and completes the decision-summary recomputation exactly once from the artifacts as they exist on disk.
- Aligned the two explore adapter surfaces by reference: the spec-phase round contract step 3 and the `DesignMachineFeedbackAdapter` paragraph in `sai/commands/explore/instructions.md` now describe the batched single continuation; semantics remain single-sourced in the shared policy.
- Re-pinned the guard tests that assumed one-continuation-per-finding: renamed tests, re-pinned regex assertions to the batched phrasing, added assertions pinning the single end-of-turn validation, the single disposition block, and the once-only decision-summary recomputation, and added a negative guard against restored per-finding continuation wording (`test/explore-pipeline-selector.test.js`).
- Preserved intact (confirmed): per-item legitimacy judgment, individual specific-reason discard reporting, worker-owned writes only, round counter incrementing once per completed round, per-finding `needs_input` pause handling (an item requiring user input still pauses processing and supervision continues the same worker with only the selected answer), and the three-round cap per phase.

## Capabilities

### New Capabilities

None — this change modifies existing capabilities only.

### Modified Capabilities

- `artifact-feedback-gate` — machine-feedback transport is one batched same-worker continuation per completed review round instead of one continuation per finding, with a single end-of-turn validation, one disposition block per item, and once-only decision-summary recomputation.
- `supervised-review-rounds` — a round is counted once under the batched continuation; per-finding continuation steps no longer exist as a counting basis.
