> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

GitLab now returns the canonical `/-/work_items/<iid>` URL for ordinary issues, but the archive closing-line rule in `sai/policies/commit-rules.md` § Closing Lines named only the `/-/issues/N` form. A change whose `backlog_origin` was a work-item URL therefore produced no `Closes` footer in its archive commit, and the merge request never closed the issue (observed on `onira-hub-front` work item 14, commit `1532750`, MR `!43`).

## What Changes

- `sai/policies/commit-rules.md` § Closing Lines: a GitLab `https://host/group/project/-/work_items/N` origin now becomes `group/project#N`, the same qualified form as `https://host/group/project/-/issues/N`. The rule now states that the closing line is derived from the URL shape alone, with no API call. The GitHub mapping, the fully qualified form, and the no-origin and Azure DevOps cases are unchanged.
- `test/to-pr.test.js`: a regression test shows that, for a GitLab destination, `closingReferences` resolves both `Closes <namespace>#N` and `Closes https://<host>/<namespace>/-/work_items/N` to issue `N`, and that the merge-request closing block writes `Closes #N` for the same repository and `Closes <namespace>#N` for another repository.
- `test/to-pr.test.js`: a text assertion checks that § Closing Lines of `sai/policies/commit-rules.md` names the `/-/work_items/N` form, so the prose rule cannot silently lose it.
- `sai/tools/to-pr.js` and `sai/tools/to-pr-gitlab.js` are unchanged: they already accept `work_items` URLs.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `commit-rules`: archive commit closing lines are also derived from a GitLab `/-/work_items/N` backlog origin, from the URL shape alone.

## Impact

- Modified: `sai/policies/commit-rules.md`
- Modified: `test/to-pr.test.js`
- Accepted trade-off: a hand-pasted `/-/work_items/` origin that points to a task or epic still produces a closing line, because no work-item type check is made at archive time.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
