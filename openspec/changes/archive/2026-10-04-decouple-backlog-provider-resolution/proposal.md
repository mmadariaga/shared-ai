**Complexity**: medium

## Why

Shared backlog resolution previously selected providers through registered host lists before provider-specific mechanics ran. A provider whose CLI determines server and project compatibility needs a narrow extension that separates provider selection from destination or issue-reference resolution.

This preparatory change added that extension without adding GitLab functionality or changing the shipped GitHub registry entries.

## What Changes

- Added opt-in `resolution: provider` registry semantics to the shared publication and import helpers.
- Preserved registered-host priority while allowing provider-owned resolvers to handle unmatched hosts without declaring a host catalogue.
- Passed raw destination inputs or trimmed issue references and command-running IO to selected provider adapters.
- Preserved resolver outcomes and attached registry-selected provider, instruction, and adapter metadata.
- Prevented import reads when delegated resolution does not return `resolved`.
- Added validation of publication-provider instruction references before loading adapters.
- Added concise skill guidance and separate provider-resolution extension references.
- Added delegated-resolution, ambiguity, outcome-pass-through, path-validation, installation-projection, and permission regression tests.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `to-backlog-provider-resolution`: Added provider-owned destination resolution, unmatched-host fallback selection, outcome forwarding, and validated instruction references.
- `from-backlog-provider-resolution`: Added provider-owned issue-reference resolution, delegated compatibility validation, and prevention of reads after unsuccessful resolution.
