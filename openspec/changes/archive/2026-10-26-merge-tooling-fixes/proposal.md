## Why

A retrospective `/sai-merge` run exposed four defects in the merge tooling and its coordinator card. On Windows, `temp-root.js remove` rejected the long form of a run directory that `mkdtemp` had returned in its 8.3 short form. `merge.js status` reported `rebase_in_progress: true` after a rebase had finished, because a leftover `REBASE_HEAD` counted as an operation in progress. The coordinator card did not state the shape of a `merge-run@1` event, so the coordinator spent several calls discovering the `kind` field. At close, the coordinator removed the directory of an earlier stopped run, which the contract says to keep.

## What Changes

- `sai/tools/temp-root.js` `removeInside` resolves the SAI temp root, the target directory, and the nearest existing ancestor of a missing target with one resolver. On Windows that resolver is the native real-path resolution (`fs.realpathSync.native`), which expands 8.3 short names, so the short and long forms of one directory compare equal. Other platforms keep `fs.realpathSync`. A path outside the SAI temp root is still rejected and nothing is deleted.
- `sai/tools/merge.js` `inProgress` derives `rebase_in_progress` only from git's `rebase-merge` and `rebase-apply` operation directories. A leftover `REBASE_HEAD` alone no longer reports a rebase in progress, in both `preflight` and `status`.
- `sai/commands/merge/coordinator.md` states the `merge-run@1` event shape where Start introduces the machine: every event is one JSON object whose `kind` field names the event. The Run state section lists the fields each event takes.
- `sai/commands/merge/coordinator.md` Close removes only the completed run's own directory (the `dir` of its `start` event), removes no other directory of the SAI temp root, and keeps diagnostic scratch files inside that directory. A directory of an earlier stopped run stays.
- Tests cover the leftover `REBASE_HEAD` case and, on Windows, the removal of a directory given in its long form together with the continued rejection of a path outside the root.

## Capabilities

### New Capabilities

- None

### Modified Capabilities

- `sai-temp-root`: removal accepts every spelling of a directory inside the SAI temp root on Windows.
- `sai-merge-command`: rebase-in-progress detection ignores a leftover `REBASE_HEAD`.
- `merge-run-state`: the coordinator states the `merge-run@1` event shape and removes only the completed run's own directory.
