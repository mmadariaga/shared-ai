> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

`/sai-cache-warmer` and `/sai-context-cache-ttl-benchmark` only load a skill into the current conversation. Both wrappers deliberately declare no `model:` line on either harness, so they inherit the session model. The model-customization menu nevertheless offered both wrappers as command targets with an unmapped `Unknown` context and difficulty profile, so a user or a preset entry could pin a model for either name. Either behavior breaks the intended inheritance.

## What Changes

- `bin/model-customization.js`: a new `SKILL_LAUNCHER_NAMES` list holds `sai-cache-warmer` and `sai-context-cache-ttl-benchmark`, and `enumerateProjectionTargets` skips those names before the command-versus-utility split. The filter is command-name based, reads no frontmatter, and applies on both harnesses, so the target checklist, the reset preview, and the save and load preset previews no longer list either wrapper.
- `test/default-presets.test.js`: a new test pins that the three distributed opencode presets already carried no key ending in `:sai-cache-warmer` or `:sai-context-cache-ttl-benchmark`.
- `test/model-customization-menu.test.js`: a new real-manifest test asserts that neither wrapper appears in any target family or as a `command:` checklist value in any scope on Claude Code or opencode, and the existing retained-command assertion excludes the two names.

The wrappers themselves, the install manifest, the capability profiles, and existing project-local overrides are unchanged. A personal preset that still names either wrapper loads without error and applies no model to it.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `model-customization-menu`: command-target derivation, and every customization surface and preview built from it, no longer includes the two skill-launcher wrappers.
- `opencode-defaults-alignment`: the opencode command-wrapper model rule excepts the two skill-launcher wrappers, which keep no model line and inherit the session model, and the distributed opencode presets carry no entry for either name.

## Impact

- Modified: `bin/model-customization.js`, `test/default-presets.test.js`, `test/model-customization-menu.test.js`.
- Behavior: the customization checklist and its reset, save-preset, and load-preset previews omit both wrappers on Claude Code and opencode; every other target keeps its family, membership, profile, order, and effective setting.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
