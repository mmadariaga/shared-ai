## Why

A live-session simulacro proved every live `/emit` corrupted session state: the `/emit` handler re-wrapped `transition()`'s single-level return `{state, snapshot, next}`, so `cloneState` fell back to `explore-change` and the session never passed `review-edge-cases` (bin/sai-state.js:285-318). Separately, `recordedList` was defined in explore's prose but never read by the machine (sai-state/machines/explore-stage.js:62), leaving the spec's content-based empty-set auto-advance unreachable through HTTP. And because a bash-tool sidecar process dies at turn end, spawn + restore per stage-event turn is the only viable live protocol.

## What Changes

- `bin/sai-state.js` — the `/emit` handler consumes `transition()`'s single-level outcome: it stores `result.state` (the plain machine state) as session state, returns `{state, snapshot, next}` without re-wrapping, returns the machine's own snapshot instead of re-deriving one, and carries `result.rejected` in-band on a rejected emit.
- `sai-state/machines/explore-stage.js` — `transition()` consumes `recordedList`: a non-null `recordedList` records into the current stage's own list (`STAGE_LISTS` maps `explore-change`→`ideaList`, `review-edge-cases`→`edgeCaseList`, `implementation-details`→`implementationDetailsList`) without advancing. Recording and advancing stay separate emits; the existing content-based empty-set rule advances on a later no-intent emit.
- `sai/commands/explore/instructions.md` — the shared sidecar lifecycle prose prescribes the restore-per-turn cycle on every stage-event turn: spawn (reuse-or-fresh), `/restore` with the last conversation-carried snapshot, then `/emit`, carrying the returned `snapshot` in conversation for the next stage-event turn, with the single-level `{state, snapshot, next}` response shape documented.
- `test/sai-state.test.js` — two new live-server HTTP seam tests cover the single-level envelope, monotonic consecutive stage walks, `/restore` of the carried snapshot, list recording without advancing, empty-set auto-advance on a later no-intent emit, idempotent replay, and no-intent rejection.
- `test/explore-stage-machine-consumption.test.js` — the prose guard test now requires the restore-per-turn wording instead of the lazy first-event spawn wording.
