## Why

The shared backlog workflows support GitHub, GitLab and Azure DevOps, but the established crystallized-slice lifecycle was GitHub-first. This implementation extends that lifecycle to GitLab and Azure DevOps through existing provider adapters and shared owner contracts rather than introducing separate platform workflows.

## What Changes

- Enable crystallized parent-and-child publication for GitLab and Azure DevOps through shared query, publication, recovery, continuation and lookup operations.
- Preserve complete child blocks and immediate dependency order. GitLab uses disclosed written hierarchy and native blocking links; Azure uses native Parent/Child and Predecessor relationships.
- Retain private publication receipts, identify uncertain creations before continuation and require exact approval of pending operations or a changed written relationship representation.
- Extend versioned parent/child correspondence and canonical origin validation to all three providers. Azure stores escaped visible correspondence in HTML.
- Deliver complete parent and direct-child content, or selected-child content with parent context, without changing the selected origin or importing siblings automatically.
- Resolve Azure related items through their verified actual projects. Reconcile readable GitLab native blockers with written correspondence; native read failures remain blocking unless capability unavailability is established and disclosed.
- Add separate inspect, propose, assign and verify operations for selected-child responsibility, preserving parent responsibility and unrelated remote fields.
- Generalize existing identity transport and implementation-start owner contracts. Add the explicit publication-helper access declaration to the shared Explore profile without expanding import permissions.
- Add offline provider parity regressions for publication, import, correspondence, recovery, responsibility, relationship fallback and mirrored installation.

## Capabilities

### New Capabilities

- None. Provider parity and relationship representation extend existing lifecycle and Azure capabilities.

### Modified Capabilities

- `backlog-slice-lifecycle`: extend publication, durable correspondence, import, origin transport and separately authorized implementation responsibility to GitLab and Azure DevOps.
- `azuredevops-backlog-publication`: add verified hierarchical slice sets with invocation-selected types, lossless child-block representation and explicitly approved written fallback.
- `from-backlog-azure-devops`: add complete hierarchical reads with actual cross-project identities and preserved selected origin.
