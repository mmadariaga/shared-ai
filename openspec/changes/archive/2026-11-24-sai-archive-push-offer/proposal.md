## Why

A `/sai-archive` run ended after the post-archive commit gate (`sai/commands/archive/coordinator.md`), so the archived change and the updated main specs stayed local until someone pushed the branch by hand. The command now offers that push itself, collected as one answer at the start of the run and applied at its close, so the run never stops again after the commit.

## What Changes

- `sai/commands/archive/coordinator.md`: the ordinary route parses `--push yes|no` before `--fast-track`; any other value, or `--push` with no value, ends the run before anything is written with `Cannot start /sai-archive: --push takes yes or no.`
- Without `--push`, after the archive plan is not refused and before anything is written or moved, the coordinator settles the push destination (the branch's upstream, or `origin/<branch>` when the branch has no upstream and an `origin` remote exists) and asks once: context as plain text first (branch, destination, every local commit of the branch is sent, never with force, nothing asks again), then the picker question `Push {branch} to {destination} when this archive ends?` with options `Push the branch` and `Do not push`. A cancelled question counts as `no`. With no destination (detached `HEAD`, or no upstream and no `origin` remote) nothing is asked and nothing is pushed.
- After the commit gate, a `yes` answer pushes once, only when the gate executed a commit: a new commit (fast-track included) or an amend whose existing pushed-HEAD check found `HEAD` unpushed. It runs `git push` with an upstream and `git push -u origin <branch>` without one, never with `--force` or `--no-verify`, and never creates or updates a pull request.
- A failed push is a planned stop of the push alone: the archive and the commit stand, nothing is retried, and `Archive done.` still prints.
- The closing summary always states the push outcome: pushed, not requested, not applicable with its reason (no destination, no commit executed, or an amend of an already-pushed `HEAD` that needs a force push), or failed with the error and the retry command.
- The Direct Build route receives neither the question nor `--push`; the archive worker keeps its push prohibition.
- `commands/claude/sai-archive.md` and `commands/opencode/sai-archive.md`: the description names `--push yes|no`; the Claude Code `argument-hint` gains `[--push yes|no]`.
- Documentation: `docs/commands/sai-archive.md`, `docs/on-demand-commands.md`, and `README.md` describe the option, the push condition, and that `--fast-track` keeps the push question.
- `test/claude-default-preset-alignment.test.js`: the expected hash of the generated opencode wrappers follows the changed wrapper description.

## Capabilities

### New Capabilities

- `sai-archive-push-offer`: the `--push yes|no` argument, the start-of-run push question, the conditional push at close, and the push outcome in the closing summary of the ordinary `/sai-archive` route.

### Modified Capabilities

None

- Modified: `sai/commands/archive/coordinator.md`, `commands/claude/sai-archive.md`, `commands/opencode/sai-archive.md`, `docs/commands/sai-archive.md`, `docs/on-demand-commands.md`, `README.md`, `test/claude-default-preset-alignment.test.js`.
- Unchanged by design: `sai/commands/archive/worker.md`, `sai/commands/archive/archive-commit-gate.instructions.md`, `sai/commands/explore/direct-build-coordinator.md`, and the `archive-command` profile of `sai/install-manifest.json`, which already allows `git push`.
- Accepted limits: a bare `git push` has no post-push readback verification, so its exit status is the only evidence reported; the push sends every local commit of the branch, not only the archive commit, and the question warns about it.
