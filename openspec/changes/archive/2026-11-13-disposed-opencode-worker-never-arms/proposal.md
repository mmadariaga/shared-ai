## Why

On opencode, disposing a worker removes its running shells, but its cache-warm chain stays open. A woken worker can therefore re-arm and keep waking after its dispose. A `/sai-retrospective` of an opencode Direct Build run showed a disposed backfill worker woken by `Shell.NotFoundError` and re-arming for about 45 minutes, because the chain record carried no closed marker and `dispose-shells.js` only knew the worker's session. The fix makes the end of warming deterministic in the tools instead of depending on the worker judging the error wake correctly.

## What Changes

- `skills/universal/sai-cache-warmer/wait.js` gains a `close --chain <id>` verb (`closeChain`) that writes `closed_ms` into the chain record under the chain lock. It is idempotent and prints `closed`, `already-closed`, `absent`, or `refused`; it refuses a main-session chain (`identity.role: agent`) and exits 1 only for `refused`.
- `wait.js` checks the closed marker before any lease, timing, or window rule: the arm check answers `launch: false`, `warm --chain` and `warm --state` return `finished`, a wake of a closed chain loses ownership, and `renewLease` refuses to renew, so a wait already in flight returns `finished` at its next renewal.
- `wait.js` exports `decodeStateToken`, extracted from its `--state` CLI parse, and `closeChain`.
- `sai/tools/dispose-shells.js` keeps each running shell's `command` launch line from the `GET /api/shell` listing, splits it with a quote-aware tokenizer (`splitCommand`), and recognizes a `wait.js warm` shell by the base name `wait.js` followed by `warm` (`warmChain`), reading the chain id from `--chain <id>` or decoding it from `--state <token>`. After the removal, whatever its outcome, it closes each distinct chain of the session's removed `warm` shells once through the installed `wait.js` module (located through `resolveGlobalRoot('opencode')`), counting `already-closed` as closed. Every result object gains `closed` and `close_failed` arrays; `status` and exit codes stay unchanged.
- `sai/policies/cache-warming.md` § Wake gains a fallback rule: a wake that is not the JSON `wait.js` prints (a shell error, a non-zero exit, unparseable output) is treated as a `dispose` message. § Dispose states that the opencode removal also closes the chain of each removed `wait.js warm` shell and that the main session's chain is never closed.
- `sai/policies/worker-lifecycle.md` § Stop call states the chain close, the `closed` and `close_failed` fields, and that a failed close never changes `status` or the exit code.
- Claude Code behavior is unchanged: `TaskStop` ends the agent and its wait together, and no chain is closed.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `worker-dispose`: the opencode shell removal tool closes the cache-warm chain of each removed `wait.js warm` shell and reports `closed` and `close_failed`.
- `agent-self-warming`: a closed chain never warms again, `wait.js close` refuses a main-session chain, and an error wake is treated as a dispose.
