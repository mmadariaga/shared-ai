## Why

New worktrees created by `/sai-worktree` start without a CodeGraph index, so sessions opened in them fall back to slow grep/glob research; this change indexes each freshly created worktree automatically.

## What Changes

- `sai/commands/worktree/instructions.md`: the Create action (Step 3) gains a new numbered step 6 — after `git worktree add -b <derived-branch> <sibling-path>` succeeds, the command prints one pre-announcement line stating that `codegraph init` is about to run in the new worktree, runs `codegraph init <sibling-path>` quoted per the same Windows PowerShell quoting notes applied to git invocations, then prints exactly one one-line result notice for whichever outcome occurred: success (index created), `codegraph` binary not available, or initialization failure including its reason. The pass never rolls back, never auto-retries, and never fails the Create action — every outcome continues to the re-render step (renumbered 6 → 7).
- The indexing pass runs only inside the Create action: Delete actions and inventory re-renders never invoke `codegraph`.
- `AGENTS.md`: the Prerequisites paragraph documenting that `sai-commit` and `/sai-worktree` are the only commands exempt from OpenSpec prerequisites now additionally records `/sai-worktree`'s best-effort, non-fatal post-creation `codegraph init <worktree-path>` step with its single one-line result notice — the command still requires no OpenSpec prerequisites.
- Known limitations left behind: indexing is synchronous with no timeout, so large repositories block the selector loop while init runs; existing index-less worktrees are not retro-indexed; failures surface only as one-line notices.

## Capabilities

### New Capabilities

- `worktree-create-indexing`: best-effort, never-fatal CodeGraph indexing of every freshly created worktree — pre-announcement, quoted `codegraph init <sibling-path>`, exactly one tri-outcome one-line notice, Create-only scope.

### Modified Capabilities

- `worktree-command-distribution`: the "OpenSpec prerequisites omitted and the omission documented" requirement's `AGENTS.md` documentation scenario is extended to cover the recorded codegraph init exception wording.
