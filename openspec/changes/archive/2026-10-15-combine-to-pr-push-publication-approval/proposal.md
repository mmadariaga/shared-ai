## Why

The to-pr workflow asked separately for publication approval and branch-push approval. This added an unnecessary interaction when the user intended to authorize both operations together. The implemented workflow combines the human decision while retaining separate operation tokens, validation, and execution.

Backlog origin: https://github.com/mmadariaga/shared-ai/issues/130

## What Changes

- Updated the universal to-pr skill to run publication and push queries before requesting approval.
- Replaced separate approval questions with one combined approval when a non-force push is required, or publication-only approval when the remote branch already contains the approved commit.
- Required the complete publication proposal, warnings, and exact push destination and commit before combined approval.
- Used PR approval labels on GitHub and Azure Repos, and MR approval labels on GitLab.
- Retained Edit and Cancel. Editing reruns both queries and requires complete presentation and fresh approval. Cancellation preserves the draft and performs none of the proposed operations.
- Required fresh approval after changes to content, destination, baseline, or HEAD, limited to still-pending operations; completed pushes are not repeated.
- Kept push and publication tokens separate and non-interchangeable. The same explicit answer authorizes each operation named in the question.
- Retained execution order: push when needed, verify the remote commit, prepare the publication receipt, then publish.
- Required publication to be skipped after a failed or unverifiable push. Publication failure or uncertainty after a verified push is reported separately without undoing the push.
- Updated command documentation and skill-text assertions, and added GitHub and GitLab tool tests covering separate tokens under combined consent, publication-only consent, push failures, unverified pushes, and uncertain publication followed by read-only recovery.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `to-pr`: Combined human approval for a required non-force push and exact publication, publication-only approval otherwise, provider-specific labels, and explicit cancellation, stale-approval, and partial-outcome handling.
