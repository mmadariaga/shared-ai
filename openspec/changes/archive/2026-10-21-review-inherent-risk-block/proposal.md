## Why

The inherent-risk ratings should describe the code after review findings are applied. Computing them once at the close of a `/sai-3-implement` fix round and storing them in `review.md` lets `/to-pr` publish that block without a second computation, as long as its merge-base and code fingerprint still match the code being published.

## What Changes

- `sai/tools/risk-signals.js` gains `validate --parent <branch> --file <review.md> [--cwd <project-root>]`. It extracts the ratings block between the `sai-inherent-risk` markers, parses its merge-base, code fingerprint, and four levels, and prints `status: ok` with `state` `fresh` (with the `block` text), `stale`, or `absent`. A malformed block, a missing file, or a stored level below the floor computed now is `absent`; a merge-base or fingerprint mismatch is `stale`. The module also exports `validate` and `extractBlock`.
- `sai/policies/inherent-risk.md` gains a `## Stored block` section: where a fix round stores the block in `review.md` (after the title and its `**Reviewed:**` line, before the first triage section, replacing any previous block), which parent branch it is computed against, the `validate` command, and the meaning of `fresh`, `stale`, and `absent`. `sai/policies/tool-resolution.md` documents the `validate` invocation.
- The `/sai-3-implement` coordinator's `## Close` gains a first item: when the run completed, marked at least one report finding fixed, and `review.md` exists, it computes the ratings against the parent branch named on the `**Reviewed:**` line, stores the block, requires `validate` to print `fresh`, and commits `review.md` alone in its own local commit (skipped, with the block left uncommitted, when Git ignores `review.md`). Otherwise `review.md` is left as `HEAD` holds it and the closing report states the reason. The closing report gains one line on the ratings block.
- The `/sai-deep-review` coordinator's commit rule counts the extra ratings commit; the `/sai-build` coordinator notes that segment 3 stores and commits the block when it fixes a finding.
- `sai/tools/to-pr.js collect` returns an `inherent_risk` field: the stored block's state against the merge-base of HEAD with the request's base, with the `block` when `fresh`; a block that cannot be checked is `absent`.
- The `to-pr` skill publishes a `fresh` block as stored and computes the ratings only when the state is `stale` or `absent`; `description-format.md` allows the stored `fresh` block as the block's content source.
- `docs/commands/sai-3-implement.md`, `docs/commands/sai-build.md`, `docs/commands/sai-deep-review.md`, `docs/commands/to-pr.md`, and `AGENTS.md` describe the stored block, its extra local commit, and how `/to-pr` publishes or recomputes it.
- Tests cover `validate` (`test/risk-signals-tool.test.js`), the `collect` `inherent_risk` field (`test/to-pr.test.js`), and the implement close ordering (`test/implement-family.test.js`).

## Capabilities

### New Capabilities

- `implement-fix-round-ratings`: the `/sai-3-implement` close that computes, stores, validates, and commits the ratings block in `review.md` after a completed fix round, and the compositions that count that commit.

### Modified Capabilities

- `inherent-risk-ratings`: the stored ratings block in `review.md` and its `fresh` / `stale` / `absent` validation by `risk-signals.js validate`.
- `to-pr`: `collect` reports the stored block's state, and the skill publishes a `fresh` stored block instead of recomputing.
