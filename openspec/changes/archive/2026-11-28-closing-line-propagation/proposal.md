> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Pull requests published for a change with a `backlog_origin` do not close the linked issue when they merge. `/sai-build` publishes before the archive commit that carries `Closes owner/repo#N` exists, and the Direct Build archive commit lost the plan's `closing_line` footer, while the coordinator did not compare the commit body with the plan. `/sai-plan` must keep publishing a draft without a closing reference, because planning is not the completion of the issue.

## What Changes

- `sai/tools/to-pr.js` accepts two optional fields in `query` and `publish`: `closing_change`, which reads `backlog_origin` from the change's active and then archived `.openspec.yaml`, and `closing_line`, a complete `Closes owner/repo#N` line that wins over the metadata. The origin reference joins the closing set before the branch-id child rule, is deduplicated by issue, warns only for a non-canonical origin, and enters the approval digest.
- `sai/commands/build/publication.md` passes `closing_change` with the completed change name and, when its caller hands one over, that caller's `closing_line`; `/sai-build` hands none.
- The Direct Build close passes the archived change name and the archive plan's `closing_line` to `sai/commands/build/publication.md`.
- `sai/commands/plan/publication.md` passes neither field, so a plan publication closes no issue.
- `sai/tools/archive-plan.js` gains the `footer` subcommand and the exported pure `closingFooterStatus`, judging the archive commit message as `present`, `missing`, `moved`, or `additional` and writing the corrected message for a local amend.
- The Direct Build coordinator runs the footer check after the archive worker's clean result and before the telemetry commit or closing report, amends the same local commit when needed, and stops before publication when the amendment fails.
- `/sai-direct-build` requires the footer check to leave the plan's `closing_line` last before it prints `Direct build done.`.
- Tests cover origin-driven closing, the plan publication's absence of closing fields, and archive commit bodies with the footer present, missing, moved, and additional; the `to-pr` skill and the command documentation state the new contract.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `archive-plan-tool` — the tool gains the `footer` subcommand and the exported footer judgment.
- `to-pr` — the closing set accepts origin-driven references from `closing_change` and `closing_line`.
- `build-publication` — the unattended build publication passes the closing fields.
- `explore-publication` — the Direct Build publication hands the archive plan's closing line.
- `auto-fast-archive-execution` — the Direct Build archive commit's closing footer is verified and corrected.
- `explore-pipeline-supervision` — the eight-step flow permits the closing-footer amendment.
- `direct-build-command` — the closing literal requires a present footer, and the footer amendment keeps one commit.
