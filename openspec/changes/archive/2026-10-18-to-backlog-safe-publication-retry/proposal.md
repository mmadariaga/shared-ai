## Why

Partially published issue sets previously required another continuation approval even when the remaining work was already approved. Direct read-only verification and one bounded retry reduce interruptions while preserving existing issues and preventing duplicate creation.

## What Changes

- Added one shared recovery sequence for failed new-issue publications: warn with completed and pending work, verify directly, retry verified pending work once, then verify and consult if incomplete.
- Added durable publication-wide retry accounting consumed before remote writes. Recovery and re-entry do not reset it; verification and already-completed publications consume nothing.
- Retained exact continuation-token checks and renewed review for changed content, destination, visibility or relationship representation. Unknown creation outcomes and unread relationships authorize no retry.
- Made individual GitHub recovery inspect membership without mutation and return a token for pending insertion. Set continuation reuses existing issues and performs only verified pending creation, membership and relationship operations.
- Applied the shared instructions to GitHub, GitLab and Azure DevOps, identically in Claude Code and opencode. Existing-issue content edits receive no automatic mutation retry.
- Added regression coverage for partial results, durable exhaustion, completion, uncertain creation, scope changes and provider parity.

### Modified Capabilities

- `backlog-slice-lifecycle`: verified pending-only continuation, durable exhaustion and unread-relationship protection across supported providers.
- `to-backlog-github-publication`: separate read-only recovery from authorized pending Project insertion.
- `gitlab-issue-publication`: direct verification and shared set-recovery instructions without replaying uncertain individual creation.
- `azuredevops-backlog-publication`: direct query-only verification and bounded set recovery without automatic scope or type changes.
