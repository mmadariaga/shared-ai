## Why

On a .NET repository a `/sai-merge` run reported verification `unavailable` and finished with no test executed. The merge tool's marker list checked only root-level files of other ecosystems, so a repository whose tests were plainly documented, or whose only marker was a solution or project file, was treated as having no test suite. A command that could not start was also indistinguishable from a failing test run.

## What Changes

- The coordinator fixes the test command once, in preflight and before the integration launches. It takes the first source that names an explicit command: `AGENTS.md` at the project root, then `README.md` at the project root, then the merge tool's marker list. Only a command written literally counts; a document that names several test commands with none clearly the general one counts as naming none.
- Every verification round uses the command fixed in preflight. `verify` and `enter --stage verify` accept `--command <line>` for a documented command, or `--suite <record> --suite-hash <sha256>` for the marker-list outcome captured in preflight with `suite --record`. A missing or changed record hash, or both sources at once, is refused.
- The marker list gains .NET: a `*.sln` at the root or one level below, else a `*.csproj` at the root, run with `dotnet test`. The existing markers keep their precedence. Several .NET candidates give no command and verification is `unavailable` with the candidates listed.
- A command that fails to start is recorded as `unavailable` with the reason, apart from failing tests. It uses no correction round and starts no test correction. The `unavailable` result carries `unavailable_reason`: `no-suite`, `ambiguous-suite`, or `not-runnable`.
- The verification texts gain a not-runnable notice, the ambiguous-suite notice lists the candidates, and the final summary gains the verification status `unavailable (command not runnable: <reason>)`.
- `docs/commands/sai-merge.md` states the detection order, the fixed command, and the not-runnable result.
- Unchanged boundaries: the three-round correction budget, the rule that `unavailable` lets the run continue, and the rule that a clean integration skips verification.
- Known limitations: a project that documents its tests only in other files still falls to the marker list, and running tests adds time to runs that previously skipped verification for lack of a detected suite.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `sai-merge-command`: the bounded verification loop runs a test command fixed in preflight from `AGENTS.md`, `README.md`, or the marker list; the marker list recognizes .NET solutions and projects; a command that cannot start is an `unavailable` outcome with its reason.
