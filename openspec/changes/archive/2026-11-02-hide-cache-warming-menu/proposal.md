## Why

Cache warming will not be tested before the next release, so the setup UI must not offer it. Hiding the post-setup `Cache warming` action, instead of deleting it, keeps the warming setup handler and the runtime feature in the codebase, so the next release can re-enable the action by flipping one module-internal constant.

## What Changes

- `bin/model-customization.js` keeps the full ordered option list as `ALL_MENU_OPTIONS` and derives the displayed list by filtering on the module-internal constant `CACHE_WARMING_MENU_ENABLED`, which ships as `false`. The exported `MENU_OPTIONS` is the displayed six-entry list: `Customize models`, `Reset to default models`, `Save preset`, `Load preset`, `Project behavior settings`, `Exit`. No environment variable, setting, or CLI flag reads or sets the constant.
- The `Cache warming` dispatch branch of the post-setup menu is guarded by the same visibility value, so while the action is hidden an answer that names `Cache warming` falls through to the existing unknown-label outcome: the menu run ends as `cancelled` and the warming section does not open.
- `runPostSetupMenu` accepts a test-only `cacheWarmingMenuEnabled` option that overrides the visibility constant, so the hidden branch stays covered by tests. With visibility enabled, `Cache warming` is shown immediately before `Exit` and opens the existing warming section with unchanged behavior.
- `bin/warming-setup.js` and the runtime resolution of the `warming` setting are unchanged.
- `docs/project-settings.md` no longer points readers to the `Cache warming` menu action: the opening paragraph states that `warming` is edited by hand only, and the former "Cache warming section" subsection is replaced by "Editing `warming` by hand", which explains setting the `warming` key in `.sai/settings.jsonc` or `.sai/settings.local.jsonc`, the value constraints, the local-override replacement, and checking the result with the resolver command.
- Tests assert the six-entry menu with `Cache warming` absent, exercise the warming branch through the test-only override, and assert that a `Cache warming` answer is cancelled and writes no settings file while the action is hidden.
