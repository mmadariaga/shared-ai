## Why

Violations of the no-commit guard are detectable but not remediable in 9 planning and audit wrappers, and worktree and status cannot run the tool their instructions designate as the sole decider. The staged implementation grants the minimum execution permissions needed for remediation and decider execution and aligns wrappers, tests, and the permissions policy.

## What Changes

- 9 planning and audit Claude wrappers gain Bash(git reset:*) for the exact mixed remediation: sai-1-spec, sai-2-design, sai-3-implement, sai-5-review, sai-6-security, sai-7-performance, sai-8-accessibility, sai-build, sai-review
- sai-worktree wrapper gains node-scoped worktree.js execution in both roots alongside existing Bash(git:*)
- sai-status wrapper gains node-scoped change-picker.js and status.js execution in both roots alongside existing Bash(openspec:*)
- sai/policies/tool-execution-permissions.md records the guard-remediation scoped reset plus the worktree and status roles with their closed scoped grants
- Pinning tests updated together with wrappers and policy: design-coordinator-worker, implement-coordinator-worker, install-claude, result-emission-time; no relaxation to free Bash

## Capabilities

### New Capabilities

- guard-remediation: run the exact mixed git reset remediation after a guard violation
- worktree-execution: run the worktree decider tool from its wrapper
- status-execution: run the status panel and bulk tool from its wrapper

### Modified Capabilities

- None. All evidenced behavior is introduced as new capabilities.
