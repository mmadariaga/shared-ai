> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

On opencode a closed skills list in a capability profile becomes a per-name `deny`, so the `sai-3-green-worker` stalled when `sai/policies/remember.md` loaded `token-efficient-languages` through its normal load chain (`sai/commands/implement/worker-common.md`). The narrowing adds no security, because a skill grants instructions and no tools, and on Claude Code it has no effect.

## What Changes

- `sai/install-manifest.json`: the `research`, `executor`, and `worker-execution` capability profiles no longer declare `"skills": ["fetch"]`, so they inherit the `["*"]` skills grant of `boot`. No other grant of any profile changes, and `bin/capabilities.js` is unchanged.
- On opencode, the generated permissions of `budget-explorer` (profile `research`), `budget-executor` (profile `executor`), `sai-3-red-worker`, and `sai-3-green-worker` (profile `worker-execution`) now allow every skill (`skill` on `*`) after the general denial, with no per-name skill denial. On Claude Code the generated agent files keep the same `tools` and `allowedTools`, because the `Skill` tool was already granted.
- `test/capability-profiles.test.js`: a new test fails when any profile assigned to an agent declares its own `skills` key or resolves to a skills list other than `["*"]`.
- `test/explore-agent-tools.test.js`: the opencode explorer test now asserts that the only skill rule is an allow on `*` placed after the general denial, while shell, edit, subagent, and question keep their general denials.
- `test/claude-default-preset-alignment.test.js`: the snapshot hash of the generated opencode output is updated to the new permissions.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `contract-tool-capabilities`: agent capability profiles grant every installed skill on both harnesses and may not narrow the inherited skills grant; command profiles keep their explicit skills lists.
- `explorer-research-capability`: the opencode explorer permissions allow every skill instead of only the fetch skill, while writes, delegation, general shell, and unknown actions stay denied.

## Impact

- Modified files: `sai/install-manifest.json`, `test/capability-profiles.test.js`, `test/explore-agent-tools.test.js`, `test/claude-default-preset-alignment.test.js`.
- New files: none.
- Agents may load any installed skill, including ones irrelevant to their role, at a possible token cost.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill

## Request Additional Notes

Existing opencode installs keep the old restriction until the installer runs again; the managed agent file lifecycle then rewrites the divergent file with a console notice, preserving the user's `model` and `variant`, and `doctor` reports the divergence meanwhile. No new mechanism is needed.
