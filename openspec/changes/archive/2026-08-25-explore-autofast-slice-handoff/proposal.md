## Why

The Auto-fast contract combined slice selection, execution, completion bookkeeping, and terminal navigation in one run, leaving no behavior-preserving transition for successful completion to return to slice selection. This change adds that transition seam while preserving the existing worker order, payloads, commit ownership, and single-slice behavior.

## What Changes

- Treat each selected crystallized slice as an independently completed Auto-fast run.
- Record a cleanly completed slice before deciding whether another crystallized slice remains.
- Re-enter the existing deterministic selector only for remaining, uncompleted slices and preserve crystallization order.
- Reset per-attempt Auto-fast state for each re-entered slice while retaining completed-change state and completed progress entries.
- Defer terminal reporting until all crystallized slices are complete; a single-slice run continues directly to its existing terminal behavior.
- Keep the existing pre-dispatch compatibility refusal, fixed worker order, payload ownership, failure handling, and commit ownership unchanged.
