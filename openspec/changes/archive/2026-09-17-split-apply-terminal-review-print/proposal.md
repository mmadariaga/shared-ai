## Why
The /sai-4-apply cards bound terminal findings print to execution time, so the Final sweep, learnings promotion, visibility listing, and terminal documentation commit sit between findings and the pinned completion literal. Two honest coordinators diverge on when warnings print and what the synthetic entry latches on.

## What Changes
Split terminal functional review into execute and print moments across three instruction cards:
- `sai/commands/apply/steps/terminal-lifecycle.md`: single review becomes execute (once after Step loop, Human Verification gates, per-Step commits, and appendices, before Final sweep; coordinator-owned read-only re-verification; assigns pass/fail/unverifiable with one-line reason; holds verdicts in invocation memory; prints nothing) and print (after terminal documentation commit, no-op, or decline, invoke bound terminal_navigation; this section prints nothing itself).
- `sai/commands/apply/invocation.md` § Completion: owns print order only; emits held cluster as last consecutive block: (a) findings slot, (b) fast-track deferred HV list only, (c) literal; sweep, learnings, listing, and commit occur before cluster, never between items; literal unchanged.
- `sai/commands/apply/coordinator.md`: synthetic entry pending through execute, sweep, learnings, and commit until print slot emitted including empty; handoff starts learnings after execute stored verdicts and sweep passes; Terminal Navigation emits cluster as part of bound action; incomplete apply emits neither findings, nor completion, nor transition.

## Capabilities
Two modified terminal capabilities; no new capabilities.

### New Capabilities
None — this change modifies existing terminal behaviors only.

### Modified Capabilities
- terminal-review: execute once before Final sweep, hold verdicts, keep print out of execution; synthetic entry completes when print slot is emitted.
- terminal-report: consecutive findings / fast-track deferred HV list / unchanged literal after intervening work, never between cluster items.
