## Why

Captured backlog issues used inconsistent section names and agreement markers. Later exploration could therefore treat tentative proposals as requirements. A provider-neutral format now records agreed work separately from unresolved questions and measures exploration maturity through explicit agreement.

## What Changes

- Added one authoritative `issue-format.md` beside the owning to-backlog skill, with section-local rules and final drafting checks.
- Defined imperative outcome-focused titles, ordered mandatory and optional sections, explicit missing-agreement markers, verifiable Scope, and non-authoritative Research leads.
- Defined cumulative agreement-based maturity, including lowering maturity when a refinement invalidates an agreement.
- Defined stable E/I/Q identifiers and retained maximum-used counters, including initialization from existing identifiers when historical counters are absent.
- Required both creation and update drafting to load the reference from the selected installed skill directory and satisfy its checks before preparation completes.
- Preserved unaffected update content and section structure outside the agreed edit boundary; publication approval remains separate.
- Added the companion file to the existing managed reference projection for Claude Code and opencode.
- Added focused source-contract and projection-expansion regression tests.
