> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Eight tests failed in a normal Windows developer checkout for reasons unrelated to the code under test, which hid real regressions behind a standing set of failures. The backlog tests read the checkout's own `.sai/` settings (for example `backlog.provider: github`) and Git remotes through `process.cwd()`, and the link-creating tests failed with `EPERM` when the account had no symlink privilege.

## What Changes

- Added `test/helpers/isolated-project.js`: `isolatedProject(t)` creates an empty directory under the real path of `os.tmpdir()`, with no `.sai/` and no enclosing Git repository, registers its removal with `t.after`, and returns its path.
- Added `test/helpers/links.js`: `linkDirectory(target, link)` creates a `'junction'` link (a normal directory symlink outside Windows); `linkFile(t, target, link)` creates a file symlink and, on `EPERM` or `EACCES`, skips the test with a reason that names the error code and returns `false`, rethrowing any other error.
- `test/from-next-backlog-item.test.js`: every test runs in its own isolated project, and every `io` object passed to `select` carries that directory as `cwd`; the spawned `select` CLI runs use it as their process `cwd` too.
- `test/from-backlog.test.js` and `test/to-backlog.test.js`: the spawned CLI scripts `require` each tool by absolute path under the repository root and run with `cwd` set to an isolated project instead of the repository root.
- `test/install-writing-for-agents.test.js` and `test/to-pr.test.js`: directory links are created with `linkDirectory`.
- `test/to-pr.test.js`: the receipt-boundary test gives each receipt case its own subtest, so only the linked-file case (created with `linkFile`) skips without privilege while the outside-repository and directory-alias cases still run.
- `test/direct-build-report-transport.test.js`: the `process.platform !== 'win32'` guard around the linked-report case is replaced by a subtest that creates its link with `linkFile`, so the case runs on Windows when privilege is available and skips visibly when it is not.
- Production code under `sai/`, `bin/`, and `skills/` is unchanged; isolation goes through the existing `io.cwd` and spawned-process `cwd` seams.

## Capabilities

### New Capabilities

- `test-suite-hermeticity`: test results depend only on the code under test, not on the developer checkout's `.sai/` settings, its Git remotes, or Windows symlink privilege.

### Modified Capabilities

- None

## Impact

- New files: `test/helpers/isolated-project.js`, `test/helpers/links.js`.
- Modified files: `test/from-next-backlog-item.test.js`, `test/from-backlog.test.js`, `test/to-backlog.test.js`, `test/install-writing-for-agents.test.js`, `test/to-pr.test.js`, `test/direct-build-report-transport.test.js`.
- Known limitations: on Windows without symlink privilege the file-link cases are skipped rather than exercised; each affected test passes an isolated `cwd` itself instead of relying on one global switch.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
