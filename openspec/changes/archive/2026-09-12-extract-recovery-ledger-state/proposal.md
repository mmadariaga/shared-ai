## Why

Bounded recovery asks the coordinator to hold a three-slot per-segment ledger, canonicalize a three-part diagnosis key, and detect duplicate keys across many turns of a run. Slot counting, path canonicalization and duplicate detection are mechanical, and holding them across turns is the failure mode a language-model coordinator handles worst: a miscounted slot silently breaks the recovery contract. The repository already runs a deterministic per-chat state store for exactly this class of state, so the accounting belongs there rather than in prose.

## What Changes

The `recovery-ledger@1` stage machine is added at `sai-state/machines/recovery-ledger.js` and registered in `sai-state/registry.js`. It owns diagnosis-key normalization, key equality, duplicate detection and three-slot per-segment accounting. The coordinator supplies the raw tuple and reads the machine's verdict; constructing the diagnosis itself remains the coordinator's judgment.

The machine reports through the existing emit wire with no new fields: `stage` carries the consumed slot ordinal as a string, and `rejected` carries a stopping reason from the closed vocabulary already defined in the recovery policy. It routes to no step file, so `next.follow` is always `none`. A segment boundary clears it with `reset <id> recovery-ledger@1`, which leaves every other machine in the same session untouched. `bin/sai-state.js` is not modified.

`sai/policies/bounded-recovery.md` items 1, 5, 7 and 8 are rewritten to name the machine as the owner of that mechanical work while keeping the judgment the policy has always owned: the three routing diagnoses, Cause Locus and its dual inspection channels, eligibility, the zero-attempt branches and hand-back reporting.

The invocation-scoped `changed_files` union deliberately stays in prose and outside the store, and the phase-static `design-overview-repair` registry match matrix stays where it is.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `bounded-worker-recovery` — gains one requirement recording that a registered stage machine owns the ledger and its normalization. No published requirement is invalidated: every outcome the existing requirements norm — `/` separators, a leading `./` removed, non-semantic whitespace collapsed, exact-tuple equality, a duplicate rejected before a slot is spent, three slots per segment, Cause Locus outside key identity — is implemented unchanged by the machine. Only the computing party moved, and the coordinator still owns the decision, the same way `sai/policies/prereqs-check.md` delegates precondition mechanics to `sai/tools/prereqs.js` without changing who owns the check.
