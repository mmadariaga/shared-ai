> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

UI labels already moved toward Plan/Build/Manual, but internal route ids, worker ids, markers, step files, active specs, and AGENTS still keep Auto/autofast (including an earlier "keep Auto as internal identity" stance). That drift confuses maintainers and collides mentally with `/sai-build`.

## What Changes

- Renames the explore crystallization-close lanes to `Plan - Unattended`, `Direct Build - Unattended`, and `Manual`, with route identities `plan-unattended`, `direct-build-unattended`, and `manual`.
- Renames the live supervised and direct-build step files, implementer contract, fetch targets, dispatch markers, and conversation-only state keys.
- Replaces the former direct-build matrix identity with phase and binding stem `direct-build`, worker `sai-direct-build-worker`, and mirrored Claude Code and opencode projections.
- Adds hash-guarded retirement coverage for obsolete installed step, contract, binding, and managed-agent destinations.
- Updates archive/backfill route wording, glossary and guidance, and projection and ordering tests while preserving `/sai-build`, `meta-build`, generic automatic behavior, and historical provenance.
- The selected staged diff contains no `openspec/specs/**` changes; active-spec cleanup was supplied intent without selected-diff evidence and is not claimed as implemented here.

## Capabilities

### New Capabilities

No new capabilities were added; this change renames and consolidates existing explore pipeline capabilities.

### Modified Capabilities

- `explore-pipeline-selector` — updates selector labels, stable route identities, deferred step-file fetches, and slice continuation wording.
- `explore-pipeline-supervision` — updates the direct-build route, markers, session state, worker ownership, and fixed eight-step flow.
- `worker-matrix-collapse` — replaces the former direct-build identities with one `sai-direct-build-worker` entry and mirrored projections.
