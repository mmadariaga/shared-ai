> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

In a retrospective run, `/sai-merge` launched with no arguments defaulted to a merge; the user asked mid-run whether a rebase was possible, and the abort discarded a 9-minute baseline and a worker strategy. ADR 0201 had retired the method question, and the dirty-tree refusal for a rebase then forced a manual stash and a second baseline. The branch question also offered only local branches, so the remote tracking branch the user usually integrates was missing from the choices.

## What Changes

- `sai/commands/merge/coordinator.md` Start asks what the arguments leave open in one native picker call, before the test command is fixed and the baseline runs: the branch when none is given, and the method (merge, rebase, or squash) when neither `--rebase` nor `--squash` is given. Without a native picker the method is a merge and the run goes on. Cancelling either question ends the run with nothing launched and nothing written. A resumed run takes the method from the store and asks nothing.
- `merge.js preflight` candidates now include, besides the local branches not merged into `HEAD`, the current branch's upstream and each remote's default branch (the target of `refs/remotes/<remote>/HEAD`) when `HEAD` does not hold them yet. Each candidate carries its `name` and full `ref`, the symbolic `refs/remotes/<remote>/HEAD` itself is never a candidate, and a missing upstream or remote adds nothing and raises no error. Nothing is fetched. A picked candidate names its `ref`.
- `merge.js provenance` accepts a source ref under any remote (`refs/remotes/<remote>/<name>`), not only `origin`.
- A new Start step 9 asks, for a rebase or squash only, whether to launch with `git rebase --autostash` when tracked unstaged changes exist and `rebase.autoStash` is not set; untracked files never trigger it and a merge keeps its behavior. On yes the coordinator records the stash reference before the launch as `stash-base.txt` in the run directory and the rebase command line carries `--autostash`; on no, or without a picker, the run ends with the cause before the first mutation. `git config` is never changed. The former step-4 refusal for tracked unstaged changes now waits for this step, and the launch becomes step 10.
- Finalize compares the stash reference with `stash-base.txt`; a different value means git kept the entry, which the run leaves in place. The closing report then names the stash entry that stays (`git stash list -1`) and the command that restores it (`git stash pop`). The run's authority now also excludes dropping or popping a stash.
- `docs/commands/sai-merge.md`, `docs/on-demand-commands.md`, and `sai/commands/merge/mechanics.md` describe the method question, the new candidates, and the autostash question.
- Tests in `test/merge-efficiency-tool.test.js` cover the new candidates, and `test/merge-goal-driven.test.js` covers the Start order, the method and autostash questions, and the stash wording.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `sai-merge-command`: the method question at start, the autostash question for a rebase or squash, the wider preflight candidates and source refs, the stash prohibition in the run's authority, and the kept-stash line of the closing report.
- `method-selection`: the method comes from the arguments when given and is asked otherwise.
- `merge-branch-scope-presentation`: branch candidates include the upstream and the remote default branch, each with its full ref.
- `branch-selector-localization`: a picked candidate names its full ref, and the method question shares the branch question's picker call.
- `rebase-paths`: an accepted autostash adds `--autostash` to the rebase command line.

## Impact

- Modified: `sai/commands/merge/coordinator.md`, `sai/commands/merge/mechanics.md`, `sai/tools/merge.js`, `docs/commands/sai-merge.md`, `docs/on-demand-commands.md`, `test/merge-efficiency-tool.test.js`, `test/merge-goal-driven.test.js`.
- A `/sai-merge` run without `--rebase` or `--squash` gains one question turn before any work. In a squash, autostash protects only the rebase step; the squash commit never takes unstaged changes.
- Claude Code and opencode run the same coordinator and present the same questions through their native picker.
