> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Disposing workers and closing run directories cost one model turn per call. In a measured opencode Direct Build run, `dispose-shells.js` ran 4 times in 4 separate turns, and each coordinator turn re-read about 189k cached tokens; each call also made two server listings per session. The cost unit is the model turn, not the tool call, so independent stops and closes of one point belong in one same-turn batch.

The three tools involved also silently kept the last value of a repeated single-value flag (`sai/tools/dispose-shells.js`, `sai/tools/transfer.js`, `sai/tools/temp-root.js`), so a malformed call could act on a different target than the caller intended.

## What Changes

- `sai/tools/dispose-shells.js` accepts `--session` several times. With one `--session` it prints today's `{status, removed, failed}` object with today's exit code. With two or more it lists the running shells once, partitions them by `metadata.sessionID` in the client, removes every target shell, verifies with one more listing, and prints the envelope `{status, results}` with one `{session, status, removed, failed}` entry per distinct session in the order given. The top `status` is the worst entry (`unavailable` > `failed` > `removed` > `none`) and sets the exit code as today. A refused removal in one session does not stop the removals of the other sessions. Every argument is validated before any removal, and a repeated `--cwd` is a usage error (exit 2) that removes nothing.
- `sai/tools/transfer.js` and `sai/tools/temp-root.js` reject a repeated single-value flag as a usage error (exit 2, `<flag> accepts one value`) that changes nothing.
- `sai/policies/worker-lifecycle.md` gains `## Same-turn batch`: at each dispose point the coordinator issues every stop of the point in one model response, and at each close point every `transfer.js close` and `temp-root.js remove` of the point, on Claude Code and opencode alike. A `TaskStop` answered with `No task found` counts as a result. A call of a batch that returns cancelled or without a result is re-issued alone in the next turn, the point completes only when every call has a result, and a cancellation is not an obstacle attempt. § Stop call describes one `TaskStop` per worker in one batch on Claude Code and one `dispose-shells.js` call with one `--session` per worker on opencode, with the per-worker `dispose` fallback read from that worker's envelope entry.
- The close sentences of `sai/commands/explore/direct-build-coordinator.md`, `sai/commands/implement/coordinator.md`, `sai/commands/merge/coordinator.md`, and `sai/commands/plan/cycle.md` issue their disposes, directory closes, and removals in one same-turn batch, pointing to `worker-lifecycle.md` § Same-turn batch.
- The AGENTS.md entry for `dispose-shells.js` names the multi-session envelope.
- Tests cover the envelope, the worst-status order, the per-session failure isolation, argument validation before any removal, the repeated-flag usage errors, and the lifecycle policy wording (`test/dispose-shells.test.js`, `test/transfer-tool.test.js`, `test/temp-root.test.js`, `test/cache-warmer.test.js`).

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `worker-dispose`: the opencode shell removal tool takes several sessions with a per-session result envelope, and coordinators issue the stops and directory closes of one dispose or close point in one same-turn batch.
- `sai-temp-root`: a repeated single-value flag of `temp-root.js` is a usage error.
- `transfer-file-transport`: a repeated single-value flag of `transfer.js` is a usage error.
