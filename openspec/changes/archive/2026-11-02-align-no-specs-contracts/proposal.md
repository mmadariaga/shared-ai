## Why

The v0.10.0 review found that the no-specs feature was not aligned across its contracts. The upstream text copied into the `specs` artifact instruction of `openspec/schemas/sai-workflow/schema.yaml` tells the author to announce each file, not to rewrite existing files, and allows Purpose edits under `<planningHome.root>`; these lines contradict unattended runs, refinement runs, and the spec worker write surface. `sai/policies/ready-to-propose-format.md` said that Explore agrees the `**Specs**` field, but no Explore step asked about it. The crystallization language gate did not protect `**Specs**`, `**Depends on**`, and `**Backlog origin**`, and `AGENTS.md`, `docs/commands/sai-status.md`, and the README did not describe `skip_specs`.

## What Changes

- **Spec worker overrides.** The SAI additions block of the `specs` instruction in `openspec/schemas/sai-workflow/schema.yaml` gains three lines: in an unattended run the spec worker writes each spec file without announcing the capability first; in a refinement run it rewrites the existing spec files that the feedback touches; and it never edits a file under `openspec/specs/**`, recording a needed capability Purpose change in the proposal's Additional Notes. The copied upstream text is unchanged.
- **Explore no-specs question.** `sai/commands/explore/steps/crystallization-protocol.md` gains a no-specs question that runs after the slicing assessment and before the crystallization language gate. For a no-specs candidate (a change or slice with no spec-level behavior), and once per candidate slice in a sliced set, Explore asks through the native picker (`yes` / `no`) with a proposed reason and the consequence, and emits `**Specs**: none — <reason>` only on `yes`. A non-candidate gets no question and no line. A user request on a non-candidate is confirmed after Explore states the consequence. The single-change and sliced crystallization protocols now run this question.
- **Format rule pointer.** The `**Specs**` field rule in `sai/policies/ready-to-propose-format.md` now points to the Explore no-specs question.
- **Language gate scaffolding.** `sai/commands/explore/steps/crystallization-language-gates.md` adds `**Depends on**`, `**Backlog origin**`, and `**Specs**` to the English bold labels, and keeps the `**Depends on**` values, the `**Backlog origin**` URL, and the literal `none` with its em dash in English; only the Specs reason is translated.
- **Documentation.** `AGENTS.md` states in both specs approval passages that a `skip_specs: true` change gets no approval key. `docs/commands/sai-status.md` documents the `skipped` specs value. `README.md` and the `docs/commands` pages of `sai-explore`, `sai-1-spec`, `sai-2-design`, and `sai-archive` explain the `**Specs**: none — <reason>` declaration and how each phase honors `skip_specs`.
- The selected diff does not modify `sai/tools/ready-to-propose.js`, `sai/policies/issue-format.md`, or the copied upstream text in `schema.yaml`.
