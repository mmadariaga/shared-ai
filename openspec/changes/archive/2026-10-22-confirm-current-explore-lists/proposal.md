## Why

Users could unknowingly confirm stale E/I lists when a partial question omitted the effect of next-step or a side discussion changed an item's meaning without redisplay. The implemented shared presentation rule and conversation-based currency check make confirmation refer to the latest complete, informed display.

## What Changes

- Centralized the complete conversational E/I display and confirmation question in list-writing.md; both list stages reference it instead of partial questions.
- Required both explicit agreement and next-step to pass a conversation-only presentation check before recording agreement and advancing. Missing notice or changed meaning triggers review, full redisplay, a question, and a fresh confirmation.
- Kept same-turn revision precedence, ordered record-then-advance events, meaning-preserving discussion, automatic empty E recording, and user confirmation of I - None.
- Added contract tests for these instructions and shared Claude Code/opencode installation; updated question-tool tests and user documentation.
