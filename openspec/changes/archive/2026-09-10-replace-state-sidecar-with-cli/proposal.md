## Why

The HTTP sidecar's process lifetime equals one shell invocation; it self-terminates on stdin EOF, making `reused: true` impossible to achieve across separate agent invocations (each runs the sidecar fresh). The HTTP layer serves only requests from the shell that launched the sidecar — the same process that spawned it — introducing pure ceremony and a silent, undiagnosable failure mode when agents attempt to reuse or share sessions across invocations.

## What Changes

Removes the HTTP loopback sidecar (`bin/sai-state.js` lines 3-576 HTTP server, net/http imports, port/token generation, process polling, liveness checks, health-check and restore endpoints, and the parent-process EOF exit model). Replaces with a three-verb local CLI interface:

- `sai-state spawn --key <stable-key>` - Returns `{id}` (deterministic UUIDv4 derived from key)
- `sai-state emit <id> <machineId> <eventJson>` - Invokes CLI verb, returns minimal wire outcome `{stage, next, rejected?, warnings?}` via stdout
- `sai-state close <id>` - Deletes session file (no tombstone delay)

Session state persists in temp directory files (unchanged). Consumers updated: `sai/commands/explore/instructions.md` (lifecycle paragraph rewritten), the four `explore/steps/` files (CLI verb calls), `spec/coordinator.md` and `design/coordinator.md` (CLI invocation). Five machines and envelope/registry modules untouched.

## Capabilities

### New Capabilities

- **stage-machine-cli-interface** — The three-verb local CLI replaces HTTP transport while preserving session file store, minimal wire outcomes, and closed error vocabulary.

### Modified Capabilities

- **explore-stage-progression** — Stage advancement now invoked through local CLI `emit` verb instead of HTTP POST to `/emit`.

- **machine-registry-envelope** — Machine registry, error vocabulary, and idempotency model survive; routing changes from sidecar `/emit` to CLI `emit` verb.
