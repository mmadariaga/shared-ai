## Why

An opencode session always runs its SAI workers inside opencode, and the inverse of the existing OpenCode passthrough does not exist: setup offers the routing option only for Claude Code agent rows, `sai/tools/opencode-dispatch.js` only drives `opencode run`, and `sai/policies/opencode-dispatch.md` only covers Claude Code dispatchers. A run started in opencode therefore cannot send one step to Claude Code's harness — its tools, permission model, skills, and plan mode — without moving the whole session. Any `/sai-*` pipeline run started in opencode whose step needs Claude Code's harness is affected.

## What Changes

- A new `sai/tools/claude-dispatch.js` reads the route key from an opencode agent file, runs one `claude -p` turn per message, serializes turns of one session with a turn lock, and stops a running turn's process tree.
- A create turn passes `--agent`, `--output-format json`, and a tool-generated `--session-id`; a continue turn passes `--resume`; the message reaches stdin unchanged; the Claude Code agent file's `tools:` and `permissionMode:` become `--allowedTools` and `--permission-mode`; `--model` and `--effort` are never passed.
- The route answers `opencode` for every cause that is not a clean Claude Code install with a matching agent file, and a missing piece adds one notice naming the agent and the cause.
- A new `sai/tools/dispatch-common.js` carries the route-key reader, the turn lock, and the shared result shape; `opencode-dispatch.js` and `opencode-launcher.js` are refactored onto it without changing the existing direction.
- The opencode routed-worker binding template queries the route before every creation, a replacement included, continues and stops on the recorded route, and falls back to native `subagent` creation when the ready turn fails.
- Setup's "Customize models" menu offers `Claude Code passthrough` for opencode worker rows, writes `harness: claude` in the project-local opencode agent file, leaves the opencode `model` and `variant` lines in place as inert values, displays the Claude Code model and effort in the SETTING column, removes the line on an opencode model choice or reset, and records the route state in save/load presets.
- The installer treats `harness` as a user-owned tunable key of opencode agents, so install, project refresh, doctor, and uninstall preserve or ignore it.
- `sai/policies/claude-dispatch.md` is the inverse single source; `cache-warming.md`, `worker-lifecycle.md`, `worker-report-transport.md`, `opencode-dispatch.md`, the opencode binding template, and `docs/models.md` point to it.

## Capabilities

### New Capabilities

- `claude-code-passthrough`: an opencode coordinator runs a marked SAI worker in Claude Code, per worker and per turn, and receives its reports through the existing file-plus-hash transport.

### Modified Capabilities

- `model-customizer`: the setup screen writes and removes the per-worker Claude Code route for opencode worker agents, displays the effective Claude Code model, and records the route in presets.
- `agent-tunable-ownership`: `harness` joins `model` and `variant` as a user-owned tunable key of opencode agents.
- `opencode-agent-dispatch`: the inverse route is carved out of the rule that opencode as the main harness keeps its native dispatch unchanged.
