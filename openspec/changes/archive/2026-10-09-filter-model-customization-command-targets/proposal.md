## Why

Model customization admitted non-SAI command wrappers as ORCHESTRATOR entries, including `from-backlog`, `from-next-backlog-item`, `to-backlog`, and `to-pr`. These entries showed Unknown/unavailable settings because command enumeration accepted every matching Markdown wrapper rather than restricting eligibility to the existing `sai-*` command family.

## What Changes

- Restrict the shared command enumeration in `bin/model-customization.js` to wrapper names beginning with `sai-` for Claude Code and opencode.
- Exclude non-SAI wrappers centrally so they do not appear in either the Orchestrators or All customization checklist.
- Update shipped-command expectations and package-source fixtures in `test/model-customization-menu.test.js`.
- Add regression coverage for both harnesses showing exclusion of the four reported wrappers and an additional non-SAI wrapper, retention of supported SAI commands, unchanged agent and utility classification, and retention of an unmapped SAI target displaying Unknown/unavailable.
- Verify that enumeration leaves wrapper contents unchanged.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `model-customization-menu`: make non-SAI wrapper exclusion explicit in derived target families, with coverage for both harnesses and selector scopes while retaining valid SAI targets with missing profiles or settings.

## Impact

- Modified `bin/model-customization.js`: add the naming-family filter at the shared command enumeration entry point.
- Modified `test/model-customization-menu.test.js`: correct expected command inventory and cover exclusions and retained targets across both harnesses.
- The accepted limitation is that installed command wrappers outside the `sai-*` naming family are not eligible for command model customization.
