> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Gate 9, the question whether to create `change-overview.md` and in which language, fired as a standalone question after the route picker returned Plan (unattended) (`sai/commands/explore/steps/pipeline-plan-unattended.md`), outside the grouped post-crystallization rounds (`sai/commands/explore/steps/route-selector.md`), so users perceived it as lost.

## What Changes

- `sai/commands/explore/steps/route-selector.md`: new `## Change overview question` section. Round 3 carries gate 9 as a conditional question beside the route question and the Direct Build continuation question. A pre-check before round 3 resolves the overview language, first match wins, in this order: explicit `--overview-lang` or a direct user statement, a value already resolved for the set, the `explore.overviewLanguage` project setting, then an active `--fast-track` (literal `None`). When any of them resolves it, round 3 carries no overview question. The answer takes effect only when the route answer is Plan - Unattended; Direct Build, Manual, or no valid route ignore it and leave the value unresolved, so a later Plan round asks again. The value is resolved once per crystallized set and applies to every Plan slice. The question keeps the existing options (do-not-create first, the literal `English`, the endonym for non-English conversations, no `Recommended` marker) and its context states that it applies only to Plan - Unattended.
- `sai/commands/explore/steps/pipeline-plan-unattended.md`: gate 9 at Plan activation now uses the value that round 3 resolved. It asks gate 9 on its own exactly once before the first spec-worker dispatch only when the round-3 overview answer was missing or cancelled. The settings notice is printed once before the first worker dispatch of a Plan route.
- Wording sync in `GLOSSARY.md`, `docs/commands/sai-explore.md`, `docs/on-demand-commands.md`, `docs/project-settings.md`, `docs/sequential-pipeline.md`, `sai/commands/explore/body.md`, `sai/commands/explore/steps/common.md`, `sai/commands/explore/steps/crystallization-language-gates.md`, `sai/commands/explore/steps/crystallization-protocol.md`, `sai/commands/explore/steps/pipeline-selector.md`, and `sai/commands/explore/steps/slicing-assessment.md`: gate 9 is now described as asked in round 3 of the route round and applied only for Plan (unattended), instead of at Plan activation.
- Tests: `test/explore-pipeline-selector.test.js` and `test/explore-pre-crystallization-stages.test.js` pin the round-3 question and the fallback instead of the deferred Plan-activation ask; `test/explore-question-rounds.test.js` adds coverage for the round-3 overview question, its pre-check order, the Plan-only effect, the fallback, and the once-per-set resolution.

A configured `explore.overviewLanguage` still answers gate 9 without a question. Direct Build and Manual never generate a change overview, and no overview question runs at block emission.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `explore-overview-language-gate`: gate 9 is asked as a conditional question in round 3 and applies only on a Plan route answer; the settings and fast-track pre-check runs before round 3; a missing or cancelled answer falls back to one standalone ask before the spec worker; non-Plan route answers ignore the overview answer.
- `explore-route-close`: round 3 conditionally carries the change overview question.
- `explore-pipeline-supervision`: the supervised Plan run uses the round-3 overview value and asks gate 9 itself only when that answer is missing.
- `explore-pre-crystallization-stages`: the `Crystallize` stage defers gate 9 to round 3 of the route round instead of a later Plan activation.
