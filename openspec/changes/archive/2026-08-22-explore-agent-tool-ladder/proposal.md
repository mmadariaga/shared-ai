## Why

Research subagents start with clean context and never inherit harness-level prefer-codegraph guidance, so they default to plain text search even when codegraph tools exist; encoding the ladder in the policy closes that gap on both supported harnesses.

## What Changes

- `sai/policies/explore-agent.md` gains one new section, `## Tool-preference ladder`, defining a fixed research-tool order for the explorer: codegraph first when `codegraph_*` MCP tools are present in the session (structural questions — definitions, callers, change impact — go to codegraph before any text search); `git grep` via shell second when shell and git are available; Glob/Grep/direct file reads as the final fallback when neither earlier level is available or neither answered the question.
- Every level is conditional and skipped without any attempt when its precondition fails; all wording stays presence-based so no level instructs calls against nonexistent tools.
- The section closes with a non-modification clause: the ladder governs only research-tool choice and does not alter the directed out-of-root access rules, structured scope escalation, or the per-segment tool-call ceiling already defined in the policy.
- The edit is confined to this single explorer-subagent policy; main sessions are untouched.
- Known limitations left behind: the git grep level depends on shell availability inside the explorer runtime; the policy harmlessly duplicates prefer-codegraph guidance some harnesses already inject into main sessions.

## Capabilities

### New Capabilities

- `tool-preference-ladder`: fixed, conditional three-level research-tool preference order for the explorer subagent — presence-gated codegraph, shell-gated git grep, direct-disk fallback — scoped strictly to tool choice.

### Modified Capabilities

- None. The additive section leaves every requirement of `canonical-opencode-agent-behavior` (read-only contract, output-contract rules, 30-call ceiling) intact; its flagged overlap is absorbed by the new capability above.
