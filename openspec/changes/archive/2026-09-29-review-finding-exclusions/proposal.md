## Why

The Direct Build close previously passed every eligible finding directly to the delegated fix worker after consent. The user must see the reported bugs and control which fixes enter the delegated write and the one authorized local commit.

## What Changes

- Adds a dedicated finding-selection stage after Direct Build consent and before any `sai-review-fix-worker` dispatch in the `/sai-review` and `/sai-5-review` close routes.
- Displays every issue from the reports available to the active route with source-qualified finding IDs, severity, title, problem or impact, and location; identifies Questions and findings requiring requirement or design changes as ineligible for Direct Build fixes.
- Lets the user fix all eligible findings or provide source-qualified exclusions through the native picker, including its built-in free-text response without an extra turn.
- Validates exclusions, preserves report order, leaves excluded findings unresolved in their reports, and closes without a fix or commit when every eligible finding is excluded.
- Sends only selected findings and a labeled exclusion list to the existing fix worker, keeps exclusions in force across continuations, and rejects coupled selected/excluded fixes before writing.
- Verifies the resulting diff against both selected findings and exclusions before staging or committing; a pre-write worker failure, unauthorized excluded fix, or unresolvable dependency produces no commit.
- Adds contract coverage for the shared selection stage in both review routes.

## Capabilities

### New Capabilities

- None. This change extends existing Direct Build close and findings-driven fix capabilities.

### Modified Capabilities

- `review-direct-build-close`: Adds user-controlled finding selection and exclusion validation before the fix worker, plus selected-versus-excluded verification before the single local commit.
- `findings-driven-fix`: Restricts delegated work and continuation scope to selected findings while retaining exclusions and the existing convergence limit.
- `review-fix-worker`: Makes selected findings the sole fix targets and requires a pre-write failure when a selected fix necessarily resolves an excluded finding.
