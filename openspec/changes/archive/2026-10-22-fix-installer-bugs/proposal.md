## Why

The installer had several bugs that surfaced when installing from a clean machine. A `[y/n]` offer shown after the tool checklist exited at once without waiting for an answer. The opencode install command still targeted the v1 `opencode-ai` package; with npm 12 blocking postinstall scripts, installing opencode v2 left a broken binary. The writing-for-agents offer passed `--skill=writing-for-agents`, which the skills CLI ignores, so it installed every skill in the repository. `setup` opened its readline before the openspec and CodeGraph install offers, so keys echoed twice and stdin was left paused, which made the later `Run 'openspec init'?` prompt exit. CodeGraph MCP detection did not recognize the opencode v2 `mcp.servers.codegraph` entry. To reproduce these failures, a clean Docker environment for testing installs was added.

## What Changes

- `promptYesNoReadline` in `bin/install-flow.js` prepares stdin for line input (`prepareLineInput`) before it opens its readline, so a yes/no offer that follows the raw-mode checklist waits for the user's answer.
- The opencode install command becomes `npm i -g --allow-scripts=@opencode/cli @opencode/cli@latest`. The executed command and the printed manual command share one constant.
- The writing-for-agents skills arguments become `--skill writing-for-agents` (two arguments), in the spawned command, the manual notices, and `docs/skills.md`.
- `bin/setup.js` creates its readline only after the openspec and CodeGraph install offers and the CodeGraph index step have run.
- `isCodegraphMcpEnabledInConfig` also accepts the opencode v2 shape `mcp.servers.codegraph`, which counts as configured unless it sets `disabled: true`. The v1 `mcp.codegraph` / `enabled` shape still works.
- New `docker/` clean-install test environment: an Ubuntu image with Node.js and the latest npm, an unprivileged `dev` user with a user-level npm prefix, `docker/run.sh` to open a throwaway container with the checkout mounted read-only at `/src`, and helpers `sai-local-install-test` and `sai-local-setup-test`.
- Tests cover each fix.

## Capabilities

### New Capabilities

- `clean-install-docker-environment`: a disposable Docker environment that reproduces an end-user machine for testing shared-ai installs and project setup from GitHub or from the local checkout.

### Modified Capabilities

- `installer-opencode-cli-bootstrap`: the install command targets opencode v2 (`@opencode/cli`) with its postinstall script allowed, and the yes/no offer waits for input after the checklist.
- `installer-writing-for-agents-offer`: the skills.sh command passes the skill name as a separate `--skill writing-for-agents` argument pair.
- `codegraph-state-warnings`: MCP detection accepts the opencode v2 `mcp.servers.codegraph` entry.
- `shared-ai-uninstall`: the list of untouched external global CLIs names `@opencode/cli` instead of `opencode-ai`.
- `setup-post-run-hooks`: setup creates its readline only after the CLI install offers and the CodeGraph index step.
