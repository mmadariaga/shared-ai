> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Small implementer models get the general behavior right but miss exact details such as status codes, names, and formats. A vague THEN such as "the system returns an error" lets RED write a test that accepts any error, so a wrong value passes unnoticed. Before this change the spec step only required that every requirement has a scenario (`sai/commands/spec/steps/specs.md`), and the spec coordinator's review checked the presence of scenarios, not their exactness (`sai/commands/spec/coordinator.md`).

## What Changes

- `sai/commands/spec/steps/specs.md` gains an `## Exact values in scenarios` section: each scenario's THEN states the exact observable values its behavior produces. A sourced value is written literally as its source states it; a per-run value (timestamp, generated identifier) is stated by its format; a behavior with no exact value keeps its THEN; an unsourced value takes a value that follows the project's conventions and is kept for the decision summary; when the block's value differs from the current code's value, the THEN carries the block's value and the difference is kept for the decision summary. Scenario titles never change for this rule, because `scenario-coverage.js` links tests to scenarios by normalized title. A refinement run applies the rule to every scenario of the change's delta specs.
- `sai/commands/spec/steps/validation.md` adds an **Assumptions** block to the decision summary, with one line per unsourced value (`Unsourced value: <capability> / <scenario title>: <value>`) and one per input-versus-code difference (`Input differs from code: <capability> / <scenario title>: input <value>, code <value>`). Assumptions lines are never trimmed and do not count toward the 15-line cap.
- `sai/commands/spec/coordinator.md` adds a **Decision-summary assumptions** paragraph: the coordinator appends each Assumptions line to the run's `assumptions.md` (source `judgment` for an unsourced value, `Ready to Propose block` for a difference), emits `record` (`assumption`) the first time the file is written, lists them in the closing report, and does not treat them as excess scope.
- The **Review criteria** paragraph of `sai/commands/spec/coordinator.md` adds exactness of each scenario's THEN: a THEN that cannot be checked against a concrete value, when the behavior has one, is a `Medium` finding, or a `High` one when it leaves the required behavior too untestable to implement reliably; a behavior with no exact value, a format stated for a per-run value, and a declared conventional value are no finding; on refinement the criterion covers every scenario of the change's delta specs.
