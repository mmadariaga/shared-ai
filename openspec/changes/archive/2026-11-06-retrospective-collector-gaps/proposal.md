> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The `/sai-retrospective` collector (`sai/tools/retrospective.js`) missed four kinds of evidence. It did not find an opencode `ses_` session recorded outside the current project. It did not match instruction paths recorded with Windows backslashes. It did not report shell calls that hit the harness timeout, because neither harness marks them as errors. It did not count any instruction that the agent loaded through the `fetch` skill's `fetch.js` tool. Without these loads and errors, the retrospective cannot evaluate instruction drift for most SAI executions.

## What Changes

- An explicit opencode `ses_` target is looked up in `session_v2` by its ID, whatever directory the session recorded. Without `--paths`, a session recorded in another directory is read from that directory and reported under it. An ID that the database does not hold produces a note that the session was not found and no execution. With `--paths`, a session whose recorded directory is outside the supplied projects produces a note that `--paths` excluded it and no execution. Child-session resolution to the root session is unchanged.
- Every instruction load path (Claude Code `Read` results, `file` and `already_read_file` attachments, `Skill` bodies; opencode `read`, synthetic reads, and `skill` base paths) is converted from `\` to `/` through one shared `forwardSlashes` helper before it is matched against the instruction path pattern, and the index reports the converted path. The existing backslash handling in `writtenChanges`, `directoryForms`, and `sameDirectory` now uses the same helper.
- A shell call (Claude Code `Bash` or `PowerShell`, opencode `bash` or `shell`) that runs `node` on `skills/fetch/fetch.js` as its script, with either path separator, is paired with its output. The single-subpath output (`path:` line, `root:` line, blank line, content) is recorded as one loaded instruction with source `fetch`, the path of the `path:` header, and the content after the header as its text. A multi-subpath output (`subpath:` blocks) or a `too-large` output records no load of its own. A `fetch.js` output with an `error:` line or without a `path:` header is recorded as a tool error.
- Scope refinements found during the fix loop: a command that only mentions the `fetch.js` path (in a heredoc body, a `node -e` / `node -p` script, or another argument) is not a `fetch.js` call; a `fetch.js` run whose standard output is piped (`|`) into a later command is treated as unobservable, so it records neither a load nor an output-based tool error.
- Every `tool_errors` entry now carries a `class`. A shell call that hit the harness timeout has class `timeout`: on Claude Code when the tool result carries `toolUseResult.timedOutAfterMs`, on opencode when the shell output contains `bash tool terminated command after exceeding timeout`. Other failures (Claude Code `is_error`, opencode `error` state, failed `fetch.js` call) have class `error`. Entries are keyed by tool-call ID, so a call that is both flagged and timed out appears once, with class `timeout`.
- `test/retrospective-tool.test.js` gains fixtures for backslash loads on both harnesses, single- and multi-subpath `fetch.js` calls, a failed `fetch.js` call, piped and mentioned-only `fetch.js` commands, a timeout on each harness, a `ses_` target outside the current project, a `ses_` target excluded by `--paths`, and an absent `ses_` ID.

Known limitations accepted with this change:

- A multi-subpath `fetch.js` call whose follow-up `Read` never happens leaves no load record.
- A Claude Code timeout is classed as a tool error although the command may still finish successfully in the background.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `sai-retrospective`: the collector resolves an opencode `ses_` target from its recorded directory with explicit not-found and `--paths`-excluded notes; counts instruction loads from backslash paths and single-subpath `fetch.js` calls on both harnesses; and reports shell timeouts on both harnesses as `tool_errors` of class `timeout`.
