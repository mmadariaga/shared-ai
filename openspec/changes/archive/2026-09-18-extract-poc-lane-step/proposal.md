> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The viability-POC pause was stated inline in `sai/commands/explore/steps/crystallization-protocol.md`, interleaved with the single-change and sliced emission protocols in one file. Any relocation or behavioral change to the lane therefore required editing crystallization logic in place, mixing a move with a behavior change in one dense prose diff. Extracting the lane into its own step file first creates the seam and keeps the later behavioral diff reviewable on its own.

## What Changes

- `sai/commands/explore/steps/poc-lane.md` is added and owns the whole lane: the uncertainty pause, Ask 1 with its fixed informational context and its two fixed options, the Direct Build `--no-specs` execution, the verdict, and both post-POC menus. The text is carried over unchanged; the trigger, the question, the option labels and order, and the verdict shape are identical to the previous inline version.
- `crystallization-protocol.md` no longer states any part of the lane. It carries a hand-off that emits the `poc-lane` intent to `explore-idea@1` and follows the returned `next.follow`, and it documents that crystallization resumes only through the lane's own `crystallize-resume` return route.
- `sai-state/machines/explore-idea.js` gains lane routing: a `ROUTE_FILES` table mapping `poc-lane` to the new step file, a `LANE_ROUTES` table binding each routing intent to the stage at which it is valid, and a persisted `route` field carried through `cloneState`, `project`, and every `transition` branch. `nextFor(stage, route)` returns the lane's step file while a lane is active and the stage's own file when `route` is `null`. Both routing intents leave the stage at `crystallize`, record no list, and are rejected with `READINESS_IS_NOT_INTENT` when emitted at any other stage. Advancing a stage clears the route.
- `common.md` and `slicing-assessment.md` point at the POC lane step instead of "the uncertainty pause machinery in the crystallization protocol"; `pipeline-direct-build.md` names `poc-lane.md` as the dispatcher of the `--no-specs` profile. These are pointer updates only.
- Guard tests are extended: the lane is asserted to be follow-loaded and never nested-fetched, the crystallization protocol is asserted to no longer contain the lane's option or menu strings, the lane file is asserted to contain them, the step-file count moves from 11 to 12, and new state-machine tests cover lane entry, lane return, pointer re-derivation from persisted state across a non-advancing emit, and rejection outside `crystallize`.

## Capabilities

### New Capabilities

- None

### Modified Capabilities

- `explore-viability-poc-pause` — the lane is relocated into a single independently loadable step file (`poc-lane.md`) reached through `next.follow` and never nested-fetched, and crystallization re-entry is defined as an explicit lane return route. The trigger, Ask 1 text and option order, verdict determination, post-POC menus, and `--fast-track` non-bypass are unchanged.
- `explore-stage-machine` — the explore-idea intent allowlist additionally accepts two routing-only lane intents (`poc-lane`, `crystallize-resume`) at the `crystallize` stage as non-advancing routing signals, and the projected `next.follow` is derived from a persisted `route` field that survives snapshot writes and non-advancing emits.
