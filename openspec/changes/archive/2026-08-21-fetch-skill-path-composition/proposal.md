**Complexity**: low (2 files, additive prompt rule)

## Why

Agents were observed composing absolute project paths that drop a path segment. Relative paths and literal absolute paths resolved correctly; composed absolute paths failed in two of three observed runs. On opencode a mis-composed path becomes a permission prompt that never renders at subagent depth ≥ 2 and hangs the session.

## What Changes

- Add a `### Path composition` rule to the `## Active harness and roots` section of `skills/claude/fetch/SKILL.md`.
- Add the same rule to `skills/opencode/fetch/SKILL.md`, plus an opencode-only load-bearing note linking https://github.com/anomalyco/opencode/issues/13715.
- Inside the project, paths are written relative to the working directory and are never composed from the project-root string.
- Outside the project, paths are used exactly as supplied and are never derived by string manipulation.
- The rule is inherited by every agent that loads fetch on both harnesses. It governs how a path is written, not where an agent may go.
- `sai/install-manifest.json`, agent files, configs, permission blocks, and `sai/policies/explore-agent.md` are unchanged.

## Capabilities

### New Capabilities

- `fetch-path-composition`: the fetch skills gain a rule governing how a path is written — relative inside the project, literal outside — inherited by every agent that loads fetch.

### Modified Capabilities

- `fetch-resolution-path-scoping`: the shared fetch path contract now includes path-composition rules in `## Active harness and roots` without changing existing resolution, namespace, or out-of-namespace-stop requirements.
