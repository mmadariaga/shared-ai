## Why

Azure DevOps returns relation URLs with the project GUID between the organization and `/_apis/` (`https://dev.azure.com/<organization>/<project-guid>/_apis/wit/workItems/<n>`), while the Azure publication adapter compared each relation URL as exact text with the `<organization>/_apis/wit/workItems/<n>` form it writes. Every native relation the tool had just created was therefore reported as not verified: slice-set publication stopped with `Native relation not verified`, recovery listed no existing native link, and the run could only finish through the written fallback, leaving a mixed native and written representation in Boards. Single-item planning compared the parent URL the same way, so a correct parent in the project-GUID form was rejected as `A different native parent already exists` or stayed pending with a `partial_failure` outcome. The test doubles echoed the written URL back unchanged, so the suite caught neither case.

## What Changes

- `sai/tools/from-backlog-azuredevops.js` gains one exported relation-identity extractor, `workItemIdentity`, built from the `/_apis/wit/workItems/<n>` expression and `address()`. It returns the lowercased organization and the work-item number whether or not the URL carries a project segment (GUID or name), and `null` for a URL that names no work item, without raising an error. `planningFields` and `nativeRelations` use it, so the repository keeps one relation-URL parser; import keeps its existing errors for an invalid relation identity.
- `sai/tools/to-backlog-azuredevops.js` compares relations by identity through a `sameWorkItem` helper: `hasRelation` (used by `publish-set`, `continue-set`, and `recover-set`) matches `rel`, organization, and work-item number, and single-item planning compares the parent by identity in the different-parent guard of the preflight, in `pendingPlanning`, and in `applyPlanning`. A URL that names no work item matches nothing.
- `relationURL` keeps writing the `<organization>/_apis/wit/workItems/<n>` form, and `planningState` keeps storing the URL as Azure returns it, so the digests of saved receipts and continuations do not change.
- The Azure doubles in `test/azure-publication.test.js` and `test/backlog-slice-provider-parity.test.js` return relation URLs in the project-GUID form. New tests cover the identity rules (project GUID and project name segments, no segment, other organization, case-insensitive organization, the legacy `visualstudio.com` host, whole-number comparison, and URLs that name no work item), the rejection of another existing parent in the project-GUID form, and a slice-set recovery that recognizes the existing native relations and adds none.
