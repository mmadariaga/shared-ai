> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Apply promoted learnings to the root `SAI_LEARNINGS.md` once, after a passing Final sweep, so a stopped run never promoted. The runs that fail are the ones that learn the most: in the analysed session a GREEN worker reported three verified repository facts in report field 6 and all three were lost.

## What Changes

- New step file `sai/commands/apply/steps/learnings-promotion.md` is the single source of the promotion rule, moved out of `sai/commands/apply/steps/terminal-lifecycle.md` § 3. The apply coordinator promotes once at each closing report, stopped or completed, before the report prints. Candidates are the appendix entries written so far and the workers' field-6 learnings, the stopped Step's included. The qualification rule and the learnings format are unchanged.
- `terminal-lifecycle.md` § 3 loads that file after a passing sweep. Its opening paragraph and the § 0 terminal suite gate stop state that a stop promotes.
- `sai/policies/implementation-closing-report.md` gains `## Apply stop: learnings promotion`: before an apply stopped report prints, the coordinator loads the step file and promotes. When the promotion wrote the file, the report lists the path, the entries added and superseded, and that the file is uncommitted; when it wrote nothing, the report carries no learnings line. A stop outside the apply coordinator (Build's implement segment, Direct Build) promotes nothing.
- A stop makes no commit. `terminal-lifecycle.md` § 4 makes root `SAI_LEARNINGS.md` eligible for the terminal documentation commit whenever it is modified, exempt from the protected-path exclusion, including when it was already modified at run start and when § 3 wrote nothing in this run.
- `sai/tools/apply-step.js` names root `SAI_LEARNINGS.md` as coordinator-owned: a change to it is never a preservation error, is never reported as protected or unrelated work, and is never counted among a Step's written files.
- `sai/commands/meta-build/coordinator.md`: the supervisor promotes no learnings and prints, in its single stopped report, the learnings lines the apply coordinator hands over.
- A run that continues after a stop (an authorized Step retry) promotes again at its next closing report; an entry already written is superseded by its key. A stop that prints fixed text instead of the closing report, and an interruption, promote nothing.
- New `docs/ddr/0163` records the decision and amends DDR 0155; `docs/ddr/0155` itself is not edited. `docs/ddr/0000-INDEX.md` lists the new record. `docs/adr/0073` points its citation at the new step file.
- `AGENTS.md`, `sai/SAI_AGENTS.md`, and `docs/commands/sai-4-apply.md` state that apply promotes on a stop as well as at the end.

Accepted limitations:

- A stop may record a fact reported by a worker that failed. The qualification rule excludes change-specific facts, and a wrong entry is superseded later by its key.
- A manual edit of `SAI_LEARNINGS.md` made before a run enters that run's terminal commit; with fast-track or `/sai-build` it enters without a question.
- A run that continues after a stop promotes more than once.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `sai-learnings-promotion`: promotion runs at every closing report, a stop included; a stop makes no commit; the terminal documentation commit takes the learnings file whenever it is modified; the apply tool treats the file as coordinator-owned; the Build supervisor prints the handed-over lines.
- `apply-routed-card-set`: the contract tests assert the single-sourced promotion step file, the stop promotion, and the new learnings eligibility rule.
- `apply-steps-library`: the steps library contains `learnings-promotion.md`, and the terminal lifecycle loads it.
- `terminal-report`: the terminal suite gate stop promotes learnings before its stopped report prints.
- `apply-coordinator-ownership`: root `SAI_LEARNINGS.md` is exempt from the initially-protected-path exclusion of the terminal documentation commit.

## Request Additional Notes

In the analysed project the learnings file already held an entry about resx files that was true but read too broadly, and the design derived the defective plan from it; the lost field-6 facts would have superseded it. The live capability specs `sai-learnings-promotion` (its statement that a stop before the sweep promotes nothing) and `apply-steps-library` (its statement that the learnings file is eligible only when promotion wrote it) describe the previous behaviour. `docs/ddr/0155` states that the terminal commit is independent of promotion; it was not read during exploration. The apply page under `docs/commands/` and the remaining apply specs were not checked for the same claims. The exit code of `apply-step.js inspect` on a preservation error was not read, only its `ok: false` payload.
