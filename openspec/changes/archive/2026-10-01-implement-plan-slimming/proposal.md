> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Every `implementation.md` carried the same `## Prerequisites` branch-selection boilerplate (default-branch resolution, three-option picker, branch-base picker), although under `/sai-build` it always resolves to auto-stay. The audit-ingestion block (used in few plans) and the re-run preservation block (used in fewer still) loaded on every implementation-worker dispatch. The diff moves each out of the always-loaded surface and loads it only when its condition holds.

## What Changes

- The branch prelude is removed from `sai/commands/implement/implementation-plan.template.md` and from the schema scaffold `openspec/schemas/sai-workflow/templates/implementation.md`.
- The branch-selection logic moves unchanged to the new `sai/commands/apply/steps/branch-selection.md`. `sai/commands/apply/coordinator.md` fetches it as a plain fetch only when the picker must be shown: without fast-track, or with fast-track and a detached HEAD. Fast-track on a non-detached branch still stays on the current branch and loads nothing. A `## Prerequisites` section in an older plan is ignored.
- The audit-ingestion block moves from `sai/commands/implement/steps/artifact-analysis.md` to `sai/commands/implement/steps/audit-ingestion.md`, loaded only when an audit artifact exists at run start. The ADR/DDR part stays in `artifact-analysis.md`.
- The re-run preservation block moves from `sai/commands/implement/steps/plan-generation.md` to `sai/commands/implement/steps/rerun-preservation.md`, loaded only when `implementation.md` already exists at run start. No new step id and no machine change.
- Tests are retargeted: `test/implement-coordinator-worker.test.js` reads the audit rubric from its new home, and `test/report-template-authority.test.js` no longer pins a `Prerequisites` heading.

## Capabilities

### New Capabilities
- `apply-branch-selection-step`: apply owns branch selection in a step file loaded only when the picker must be presented.
- `implement-conditional-step-loading`: audit ingestion and re-run preservation load from their own files only when their condition holds.

### Modified Capabilities
- `sai-apply-branch-prompt`: the prompt's home moves from the plan template to the apply step file.
- `sai-implement-branch-prompt`: the generated plan carries no branch prelude.
- `schema-template-authority`: the implementation scaffold and authority payload expose no `## Prerequisites` heading.
- `sai-fast-track-flag`: apply auto-stay is defined against the apply step file.
- `implement-steps-library`: the file inventory gains two conditional sub-files.
- `apply-steps-library`: the file inventory gains the branch-selection step file.

## Impact
