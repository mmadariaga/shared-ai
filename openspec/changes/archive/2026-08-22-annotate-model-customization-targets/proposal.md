## Why
The setup model-customization selector mixed generic delegation agents with routed workers, mixed utility commands with other commands, and gave users no view of each target's current model configuration.

## What Changes
The setup customization flow now derives four target families from manifest and Worker Matrix metadata: routed Workers, generic delegation Agents, Commands, and Utilities, with an All scope covering every family. OpenCode and Claude Code generic delegation agents are classified separately from routed workers, and the four initial utility commands are separated from the remaining commands.

Checklist selection values use stable family-prefixed identities independently from their display labels. Display labels retain the family identity and append a subdued effective model annotation. The annotation reads project-local frontmatter before installed or global sources, formats Claude effort and OpenCode variant in the tuning position, and safely falls back when settings are unavailable or malformed.

The implementation also preserves family-aware local override paths, updates the shared checklist renderer with optional display labels, and extends focused coverage for both harnesses, taxonomy, selection identity, annotation precedence, and navigation.

## Capabilities
### New Capabilities
- Stable family taxonomy and identity-preserving model customization selection.
- Effective model annotations for customization targets.

### Modified Capabilities
- Existing post-setup model-customization menu and manifest-derived target traversal.

## Impact
- `bin/model-customization.js` derives target families, parses stable identities, reads effective settings, annotates labels, and persists family-correct overrides.
- `bin/install-flow.js` renders optional checklist display labels while returning stable option values.
- `openspec/specs/model-customization-menu/spec.md` now records the implemented taxonomy, identity, annotation, and fallback behavior.
- Focused model-customization and navigator tests cover the changed behavior and both harnesses.
- Known technical debt: the utility family uses a fixed command-name list, frontmatter parsing is intentionally textual, malformed or missing settings use an unavailable fallback, and the complete repository test suite can exceed the available execution window.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill.
