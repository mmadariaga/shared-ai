> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The original cache-warmer change shipped `/sai-cache-warmer` as a skill-only workflow by design. The `sai-commands` skill treats `commands/sai-*.md` as the only command registry, so a user who typed `/sai-cache-warmer` was told that the command was not installed. Issue #322 decision Q2 reverses the skill-only choice: the documented command must exist on both harnesses and load the existing `sai-cache-warmer` skill.

## What Changes

- Add `commands/claude/sai-cache-warmer.md`: a thin Claude Code command wrapper with `allowed-tools: {{capabilityAllowedTools}}`. It reads `.claude/skills/sai-cache-warmer/SKILL.md`, falls back to `~/.claude/skills/sai-cache-warmer/SKILL.md`, reports that the skill is not installed and stops when neither copy exists, follows the skill in the current conversation, and passes `$ARGUMENTS` unchanged as the invocation input.
- Add `commands/opencode/sai-cache-warmer.md`: the same wrapper for opencode with `subtask: false`, reading `.opencode/skills/sai-cache-warmer/SKILL.md` first and `~/.config/opencode/skills/sai-cache-warmer/SKILL.md` second.
- Both wrappers end with the `<!-- User customizations below this line -->` marker and mirror the existing `sai-context-cache-ttl-benchmark` wrappers. They read `SKILL.md` directly instead of invoking the skill through the harness skill tool, so the skill keeps `disable-model-invocation: true` and starts only on the user's explicit invocation.
- The existing `sai-cache-warmer` → `cache-warmer-command` assignment in `sai/install-manifest.json` now backs a command wrapper on both harnesses; the `claude-commands` and `opencode-commands` projections install the new files with no manifest change. `new-change-branch` remains the only skill-only command assignment.
- Update the regression tests for the new wrapper: capability-profile assignments, the generated opencode output count and hash, the context-preserving wrapper set and the wrapper counts (21 `sai-*` wrappers, 25 files per harness), and the opencode command list of the model-customization menu.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `cache-warmer-invocation`: `/sai-cache-warmer` is available as an explicit command on Claude Code and opencode, with the skill's current behavior.
- `contract-tool-capabilities`: the `sai-cache-warmer` command assignment is backed by a command wrapper on both harnesses, replacing the requirement that it needs none.
- `thin-wrappers`: the per-harness wrapper inventory counts twenty-one `sai-*.md` files, with `sai-cache-warmer.md` as a second skill launcher.
- `command-wrapper-body`: each source wrapper directory contains twenty-one `sai-*.md` files and twenty-five wrapper files.
- `claude-default-preset-alignment`: the generated opencode output fingerprint covers 42 entries, including the `sai-cache-warmer` command wrapper, with the updated SHA-256.
- `coordinator-protocol-single-source`: `sai-cache-warmer.md` joins `sai-context-cache-ttl-benchmark.md` as a wrapper that runs in the current conversation without the clean-start line.
