**Complexity**: high (1 new capability, four capability deltas across two routed phases; no breaking change)

## Why

The design phase worker received roughly 480 lines of contracts up front (worker card plus invocation router plus instructions.md) before executing its first step, so instruction salience decayed over the run and produced adherence drift — the same problem the `/sai-1-spec` step-gated experiment had already solved for its phase. Splitting the mass into one file per progress-plan step turns each plan boundary into a just-in-time delivery gate: the worker holds only run-long boundaries plus the instructions for its currently active step, keeping small-model attention aligned with the work actually in progress while leaving every undeclared phase byte-for-byte unchanged under the runner's default-off behavior. The salience gain is smaller than spec's case (design peaks around 6–7k tokens of up-front contracts versus the ~15–25k that motivated the original experiment), with the benefit concentrated in the dense tasks block.

## What Changes

- Created `sai/commands/design/steps/` with seven files keyed by progress-plan step id rather than physical file order: `common.md` (always-active boundaries: step-delivery meta-rule, generation scope, artifact-only scope, collaboration style, cost discipline) plus `research.md`, `design.md`, `tasks.md`, `interfaces.md`, `review.md`, and `overview.md`; interleaved sections attach to the milestone they serve.
- `sai/commands/design/coordinator.md` declares a static `step_pointer_map` over both plans' id superset (`prereqs-resolution` → none; each other step → its file), sends exactly two-line progress continuations whose second line is the `Active step:` pointer, never derives the inert `overview` entry on base-plan activations, requires the departing worker's `active_step_id` in replacement reconstruction, and carries the correct pointer line on the replacement's first continuation.
- `sai/commands/design/worker.md` loads `steps/common.md` at dispatch, adds the Active Step Execution section (execute only the coordinator-named step; never prefetch any other step file), replaces the wholesale invocation fetch with execute-only-the-active-step discipline, adds `active_step_id` to replacement reconstruction, re-derives `overview_language` from raw `arguments_value`, and realigns its Architecture Snapshot presentation sentence with the existing Target-State comparison contract single-sourced in `sai/commands/design/instructions.md` (the previous sentence retained a superseded interfaces.md-text comparison basis) — a realignment, not new behavior.
- The worker card retains its "### Overview generation (design-worker-owned lifecycle)" section verbatim because the test suite pins those mechanics there; `steps/overview.md` is therefore a thin reinforcement file referencing the card, not an extraction target. Any future wholesale extraction first requires repointing those test assertions (tests are out of scope by constraint).
- Extended the AGENTS.md active-experiment paragraph to document the `/sai-2-design` replication.
- Known limitation carried forward: like the spec baseline, no automated test asserts the pointer-delivery machinery itself; normative coverage lives in the openspec capability specs. The experiment now covers two of ten routed phases; the remaining eight still load their instruction mass wholesale.
