## Why

The `sai-review` audit batch dispatches security and performance workers concurrently against one session file. Two parallel emits read the same snapshot and the last write discards the other's marks, which sent the security machine back to its initial stage mid-run. Every emit and reset rewrote the whole file from a possibly stale snapshot, so concurrent writers on disjoint keys still collided because the write unit is the entire file.

## What Changes

- `bin/sai-state.js` `persistMachineOutcome` re-reads the file just before writing, preserves sibling machines by max `rev`, merges the target `done[]` by union in canonical order, derives stage and pointer from the merged state, and returns the merged state for session and wire use. `commandEmit` consumes the merged result for its session update and wire payload. `commandReset` applies the same merge, replacing only the target entry. Helpers `entryRev`, `stateByMachineMap`, `unionDoneInCanonicalOrder`, and `canonicalizeMergedState` are exported for test use. No lockfile or CAS retry is added.
- `sai/commands/meta-review/coordinator.md` keeps parallel worker dispatch and serializes store operations on the same session `id` one-writer-at-a-time in fixed order security → performance → accessibility. Artifact concurrency stays safe through disjoint artifacts.
- `sai/policies/stage-machine.md` documents the one-writer-at-a-time invariant, the fresh-read merge behavior, the accepted residual TOCTOU window, and the single-file invariant with per-machine `rev`.
- `test/sai-state.test.js` adds an acceptance case where two concurrent emits to different machines on the same session `id` preserve both `done` sets.
- Known limitation: a residual TOCTOU window remains because read-then-write is not atomic. Serialization leaves it with no real pressure and the merge keeps survivors harmless for monotonic step sets.

## Capabilities

### New Capabilities

- `concurrent-store-safety` — concurrent emits and resets on one session file preserve every machine's marks through fresh-read merge and canonical done-union.
- `audit-store-serialization` — the meta-review audit batch serializes store access in fixed order and records the one-writer invariant with its accepted limits.

None.
