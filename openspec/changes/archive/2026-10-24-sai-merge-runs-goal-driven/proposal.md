> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

`/sai-merge` was the last mutating build-side command still in the old orchestration style: eight cards in `sai/commands/merge/` (2,109 lines), five kinds of user question (dirty tree, method, branch, working language, and a strategy gate on every conflict stop), and a finalization that went ahead after three verification rounds even when tests still failed. Everything the command does is local and reversible, so those questions guarded inputs rather than judgments, while the missing comparison against a pre-launch suite result let an unattended finalization leave new failing tests that nobody had accepted.

This change rewrites `/sai-merge` as a goal-driven, always-unattended command outside the shared orchestration, keeps `sai/tools/merge.js` as its deterministic engine, and verifies the integrated tree against a suite baseline taken at `HEAD` before the launch.

## What Changes

- `sai/commands/merge/coordinator.md` is rewritten as the single coordinator card in the shape of `/sai-3-implement` (Goal, Start, a cycle per conflict stop, Final, Commit messages, Obstacles, Run state, Resuming, Close). It loads only `public-chat`, `remember`, `safe-operations`, `tool-resolution`, and `incremental-review`, no budget binding, and none of `command-runner`, `worker-core`, `bounded-recovery`, `stop-options`, `unattended-runtime-recovery`, or `no-commit-guard`; it runs `merge.js` and git itself.
- The invocation is `/sai-merge [<branch>] [--rebase|--squash]`. `--squash` wins over `--rebase`, `--fast-track` is accepted and ignored with no banner, and any other option or a second branch ends the run with a usage line before anything is written. The branch is asked through the native picker only when it is missing; the method, language, dirty-tree, and strategy questions are retired, and the closing report uses the chat language.
- Start guards: a merge or rebase in progress is resumed only when a recorded `/sai-merge` run of the same branch owns it, and otherwise left untouched with the reason; staged content before the launch stops the run; unstaged changes proceed when git allows the launch, and a rebase or squash checks git's refusal before the first mutation; a branch already integrated into `HEAD` closes the run with no changes.
- Baseline verification: the test command is fixed once before the launch, the suite runs once at `HEAD` as the baseline (`merge.js verify --baseline --record`), and the final tree is verified once against it (`merge.js verify --baseline-record --baseline-hash`). A failure missing from the baseline is rerun once and counts as new only when it fails again; flaky, pre-existing, not-comparable, and unavailable results are reported and never block. A rebase runs the suite only on the final tree and corrects a new failure in one additional local commit on top of the rebased branch.
- Each conflict stop is captured, decided by the worker by commit intent, checked with `merge.js resolution`, materialized for whole-side choices by the coordinator's checkout, reviewed by the coordinator for up to three rounds with `review-delta.js` under `incremental-review.md`, and staged. Findings still open after round three are recorded as pending and do not stop the run.
- When commit intent cannot decide between two sides, the coordinator escalates at once through the native picker with options it writes, including leaving the operation in progress and aborting it; it aborts only on that explicit choice. Every other obstacle has a budget of three attempts before escalation, and a replacement worker receives a hand-over file the coordinator writes in the run directory.
- Invoking the command authorizes only the listed local operations (the launch and squash, whole-side checkouts, staging, ADR/DDR repair edits and `git mv`, the merge and squash commits, each `git rebase --continue`, the final-tree correction commit, and the repair commit), each commit sent with `git commit -F <file>`; nothing is pushed, amended, forced, or hook-bypassed.
- The closing report names the method, branches, operation and resulting `HEAD`, the conflicts per stop, the verification against the baseline, pending findings, collision repairs, assumptions and escalations, the pre-launch `HEAD` with its `git reset --hard <sha>` restore command for every run that changed the branch, and the force-push need when a rebase or squash rewrote commits the upstream already holds. A finalized run ends with exactly `Merge done.`.
- `sai-state/machines/merge-run.js` adds the `merge-run@1` machine on the shared run core (registered in `sai-state/registry.js` and in the `sai/tools/lint.js` stage-machine id list): it holds the method, branch, stop index, baseline path, pre-launch `HEAD`, attempts per obstacle, the open escalation, and the paths of the obstacle, finding, and assumption files. The session key is `merge-{branch}` and the run directory comes from `temp-root.js mkdtemp --prefix merge-`; it is removed only when the run completed.
- `sai/tools/merge.js`: `verify` gains the baseline mode and the comparison against a baseline record, naming failing tests from the output of common runners and ignoring a runner's summary header that ends with a colon (such as `node --test`'s `failing tests:`); `provenance` records the current branch's upstream facts (`ref`, `rewritten_commits`, `shared_with_upstream`, `force_push_needed`); the `enter --stage` and `instructions --stage` entry points (including `--reconstruct`) and their stage tables are removed.
- `sai/commands/merge/worker.md` becomes the contract of one standalone worker per run: it returns the ready handshake, follows `Active step:` pointers to `sai/commands/merge/steps/{strategy,apply,test-correction,renumbering-plan}.md` (with shared definitions in `steps/common.md`), writes each report to the run directory and returns only its path, writes the repository only through `merge.js write`, runs only read-only git commands, and dispatches no subagent. `merge` joins `STANDALONE_PHASES` in `bin/worker-matrix.js`, so the binding renders from the standalone template on both harnesses; the worker keeps the name `sai-merge-worker`.
- `sai/commands/merge/mechanics.md` is reduced to the evidence contract of `merge.js`. Retired: `command-bootstrap.md`, `coordinator-stages.md`, `instructions.md`, `lifecycle.md`, and `presentation.md`, each with a retirement entry in `sai/install-manifest.json`, plus the merge adaptive TODO section of `sai/policies/todo-structure.md`.
- Both wrappers load the harness fetch skill and the coordinator directly, with no boot adapter; both `boot.md` adapters drop `merge` from the routed names and both `panel-render.md` bindings drop the merge adaptive TODO. The install manifest's `merge-command` profile adds the `safe-operations` skill and drops the `transfer.js` shell grant, and the opencode wrapper sets `subtask: false`.
- `sai/policies/fast-track-flag.md` no longer lists `sai-merge` among the parser owners, `sai/policies/no-commit-guard.md` drops merge's `conflict_detected` language-question example from boundary 1, and `sai/policies/command-execution.md` no longer names merge.
- ADR 0201 records that `/sai-merge` leaves the shared orchestration and supersedes ADR 0175a; `AGENTS.md`, `docs/commands/sai-merge.md`, `docs/on-demand-commands.md`, `docs/sequential-pipeline.md`, `docs/adr/0000-INDEX.md`, the thin-wrapper fixture, and the merge and affected tests are updated (`test/merge-contextual-conflict.test.js` is removed; `test/merge-goal-driven.test.js`, `test/merge-baseline-verification.test.js`, and `test/merge-run-machine.test.js` are added).

## Capabilities

### New Capabilities

- `merge-run-state`: the `merge-run@1` machine, the `merge-{branch}` session and run directory, and resuming an interrupted run from the store and the git state.

### Modified Capabilities

- `sai-merge-command`: goal-driven unattended run from arguments, start guards, suite baseline and final-tree verification, the conflict stop cycle with review, escalation and obstacle budgets, command-local authority, the closing report, direct wrappers, upstream rewrite facts, and retirement of the stage entry points and the old gates.
- `merge-worker-discipline`: one standalone worker per run, steps by pointer, reports as run-directory files, writes only through `merge.js write`, and replacement from a hand-over file.
- `merge-presentation-seam`, `merge-lifecycle-validation-seam`, `merge-batched-questions`, `merge-resolution-transport`: retired surfaces replaced by the goal-defined coordinator.
- `merge-branch-scope-presentation`: branch candidates from the preflight with picker free text, and full scope without a presentation seam.
- `sai-fast-track-flag`: `/sai-merge` leaves the fast-track parser membership and accepts and ignores the token.
- `no-commit-guard`: the merge coordinator no longer carries the guard.
- `method-selection`, `branch-selector-localization`: the method question and the worker-sourced branch gate are retired; the method is an argument and a missing branch is asked by the coordinator.
- `worker-matrix-collapse`: the merge binding renders from the standalone worker template.
- `backfill-draft-transport`: the `merge-command` profile carries no `transfer.js` grant.
- `thin-wrappers`: both `sai-merge.md` wrappers load the coordinator directly.
- `progress-plan-declaration`, `harness-panel-render-binding`, `non-blocking-runtime-panel-tool-degradation`: the `/sai-merge` adaptive TODO is retired.
- `portable-command-invocation`: `/sai-merge` is no longer a command-execution mutation surface.
