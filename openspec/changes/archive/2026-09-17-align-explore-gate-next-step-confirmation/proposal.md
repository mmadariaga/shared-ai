> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The two idea-stage agreement gates of `/sai-explore` modelled the `next-step` token two different ways. The half that composes the gate question told the model to name `next-step` as a separate advancement action alongside two answer paths, so the emitted question framed confirming the list and advancing the stage as sequential acts. The half that evaluates the answer already stated three times that a bare `next-step` turn records agreement and advances in the same turn. A model that obeys the question it just published contradicts the rule it must then apply: an observed run classified a bare `next-step` as not-yet-confirmation and re-asked the gate instead of advancing.

## What Changes

- `sai/commands/explore/steps/common.md`, edge-case review gate (stage 2): the question-composition sentence now additionally requires the question to state that a bare `next-step` confirms the list as written and advances in the same turn.
- `sai/commands/explore/steps/common.md`, edge-case review gate evaluation: the ambiguity branch now explicitly excludes a bare `next-step`, which is always confirmation.
- `sai/commands/explore/steps/common.md`, implementation-details stage (stage 3): the same confirming clause is added to the question-composition sentence, and the same explicit exclusion is added to its ambiguity branch.
- The three sentences that already declare the bare-`next-step` rule are left byte-identical; no fourth restatement was added.
- The cross-cutting `next-step` recognition paragraph, the stage machine intent allowlist (`sai-state/machines/explore-idea.js`), and `bin/sai-state.js` are unchanged.

## Capabilities

### New Capabilities

None. No new capability is introduced; the change refines three published ones.

### Modified Capabilities

- `explore-edge-case-review` — the stage-2 agreement question must now state that a bare `next-step` confirms the list as written and advances in the same turn.
- `explore-implementation-details` — the stage-3 confirmation question must now state the same.
- `explore-progression` — a bare `next-step` at either gate is explicitly excluded from the ambiguity branch, so it can never be routed to clarify-and-re-ask.
