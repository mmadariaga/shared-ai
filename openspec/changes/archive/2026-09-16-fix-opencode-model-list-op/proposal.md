## Why
OpenCode 2.0.4 dropped the `v2.` operation prefix, so the old variant query exits 1 with Operation not found and setup silently degrades to model-only. Verified on 2.0.5 that `model.list` returns the same `.data` shape with variants.

## What Changes
- Rename the single cached variant-discovery query from `opencode api v2.model.list` to `opencode api model.list` (provider-free vector `['api', 'model.list']`) in `bin/model-customization.js`.
- Keep parsing, matching, extraction, caching, persistence, and the single-query-per-run reuse across back navigation unchanged.
- Keep failure behavior unchanged: any query failure degrades to model-only with the existing diagnostic and no fallback to the old operation name.
- Update `test/model-customization-menu.test.js` fixtures, runner vectors, and comments from the old operation name to the new one.
- Staged-evidence note: the selected staged diff also evidences README.md and docs/ restructuring outside this change's intent; that scope drift is reported above and is not specified here.

## Capabilities
### New Capabilities
None — this change modifies existing capabilities only.
### Modified Capabilities
- opencode-variant-discovery: variant source query name renamed to `model.list`.
- opencode-settings-selection: variant screen restored for models with variants on opencode 2.0.4+.
