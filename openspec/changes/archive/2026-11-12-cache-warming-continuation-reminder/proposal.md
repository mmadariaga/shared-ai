## Why

Historical runs showed pauses after user choices while warming turns returned `ok`; the precise cause remains unproven. The implementation adds a reminder at the arm and wake tool boundary so the main session checks its current conversation and command contract without storing a potentially stale next action.

## What Changes

- Added one shared, self-contained English `reminder` to both arm decisions and all normal warm results, including `continue` and `finished`.
- Distinguished main-session continuation from the unchanged subagent wake protocol. Main sessions handle unhandled user responses and work already authorized by their command, while preserving legitimate waits and completed commands.
- Kept the reminder outside chain records, state, and state tokens. Existing fields, timings, rearming limits, disposal, authorization, `begin`, and independent `prepare` and `wait` behavior remain unchanged.
- Aligned hand-off instructions with the continuation check without supplying `next-slice` or moving the fixed deadline. Kept background watches, not warming notifications, responsible for finding undelivered reports.
- Added output-shape, CLI, state-isolation, and instruction-text regression coverage, with the same universal implementation for Claude Code and opencode.
