> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

A `to-pr` request written in the documented YAML `description: |` style failed with `A complete marked Inherent Risk block and valid placement are required`. A YAML `|` block scalar always keeps a final line break, and the risk-block guard required `risk_block` to end exactly at the END marker, so unattended publication (`/sai-build`, Direct Build, `/to-pr`) skipped such requests as incomplete. The guard now normalizes trailing line breaks once, so the documented request style works.

## What Changes

- `plan()` in `sai/tools/to-pr-comments.js` strips trailing `\r` and `\n` from `risk_block` once, right after its string-type check, and uses the normalized value for the marker checks, the description comparison, the comment-overflow length check, the returned proposal `block`, and the managed comment body.
- Line breaks inside the block stay as written. Text or spaces after the END marker, a line break before the START marker, a missing or repeated marker, a missing `## Inherent Risk` heading, and a non-string `risk_block` are still rejected.
- `skills/universal/to-pr/SKILL.md` and `skills/universal/to-pr/description-format.md` state that the tool drops the trailing line breaks of `risk_block`, as it already does for `title` and `description`.
- `test/to-pr.test.js` covers the accepted JSON endings (`\n`, `\r\n`, and repeated), YAML `|`, `|-`, and `|+` block scalars read through `readRequest`, description and comment placement, publication with the confirmation of the normalized request, and the rejected boundaries.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `to-pr`: risk-block input normalization — `query` and `publish` accept a `risk_block` that differs from a valid block only by trailing line breaks, and every later use carries the normalized block.

## Impact

- Modified: `sai/tools/to-pr-comments.js`, `skills/universal/to-pr/SKILL.md`, `skills/universal/to-pr/description-format.md`, `test/to-pr.test.js`.
- New: none.
- Behavior: GitHub, GitLab, and Azure DevOps requests that supply `risk_block` in a YAML block scalar now pass the guard; the proposal and the published managed comment carry the block ending at the END marker. A request that already ends at the marker keeps its confirmation unchanged.
- Known limitations: a trailing space after the END marker still fails with the generic complete-block error, and only trailing line breaks are stripped; every other malformation keeps its existing rejection.
- Claude Code and opencode run the same `sai/tools/to-pr-comments.js` and read the same skill files.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
