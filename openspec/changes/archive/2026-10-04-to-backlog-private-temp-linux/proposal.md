**Complexity**: high

## Why

The to-backlog workflow required an existing private temporary directory for publication receipts but did not provide a deterministic preparation operation. Historical rejection of receipts directly under `/tmp/opencode`, followed by success in a private subdirectory, demonstrates a privacy-validation failure rather than an established shell-permission denial.

## What Changes

- Added the skill-owned `scripts/prepare-temp.js` helper for Linux, using native Node filesystem operations to create a unique receipt directory under `/tmp` for Claude Code or the existing `/tmp/opencode` for OpenCode.
- Verified the shared root before and after creation, including ownership, symbolic-link exclusion, stable identity, and sticky-bit protection for shared-write permissions. The helper reports a missing-root prerequisite without creating or repairing that root.
- Verified that each new directory is outside the repository, owned by the current user, not a symbolic link, and mode `0700`. Descriptor-based permission setting and identity checks reject detected substitutions.
- Integrated preparation after explicit creation or update approval and before publication. Preparation failure stops publication without an insecure fallback; recovery retains the original receipt.
- Added mirrored installation of the helper and its instructions, plus concrete installed invocation declarations for to-backlog and `/sai-explore`.
- Added a scoped exploration exception for explicitly confirmed to-backlog temporary preparation and receipt/publication operations, without permitting repository edits. Updated the common read-only reminder to preserve this distinction and the absence of authorization from proposal emission.
- Added Linux filesystem, failure, concurrency, installation, access-declaration, and workflow regression coverage. Existing creation and update tests use the helper on Linux.

Delivery is Linux-only. The workflow retains its existing Windows path without adding verified Windows privacy guarantees. The additional helper, instructions, installation rules, access declarations, and tests are the accepted maintenance cost of deterministic preparation.
