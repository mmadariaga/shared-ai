> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Three files under `openspec/specs/` described no live capability.

`openspec/specs/worker-skill-path-update/spec.md` was a six-line husk: a TBD purpose and an empty `## Requirements` section. Its two requirements were added by `openspec/changes/archive/2026-08-05-neutral-worker-binding-paths/specs/worker-skill-path-update/spec.md` and retired the next day by `openspec/changes/archive/2026-08-06-restore-coordinator-instruction-loading/specs/worker-skill-path-update/spec.md`. The archive workflow behaved as designed; the defect was the surviving directory, not the emptiness.

`openspec/specs/extract-bodies/spec.md` and `openspec/specs/update-install-docs/spec.md` carried `## What` / `## Acceptance Criteria` work-order structure with zero `### Requirement:` headers, and their work is executed on disk — `sai/commands/` holds 15 directories, `INSTALL.claude.md` references `sai/commands` three times and `README.md` six. They are work orders misfiled as capability specs.

A fourth file blocked the change's own expressibility. `openspec/specs/update-active-specs/spec.md` opened with `## ADDED Requirements` and carried no `## Purpose`, so `openspec show` returned an error and zero requirements — making the requirement that pins `openspec/specs/extract-bodies/spec.md` invisible to the delta mechanism.

## What Changes

- Copies `openspec/specs/extract-bodies/spec.md` and `openspec/specs/update-install-docs/spec.md` into `openspec/changes/archive/2026-05-21-extract-sai-commands-shared-body/specs/`, then deletes them from the active corpus. That change had no `specs/` directory, so these were the only surviving copies.
- Deletes `openspec/specs/worker-skill-path-update/spec.md`, matching the REMOVED delta that already emptied it.
- Repairs `openspec/specs/update-active-specs/spec.md` by adding a `## Purpose` section and changing `## ADDED Requirements` to `## Requirements`. The repair is limited to those two header lines; no requirement text is rewritten. Its 12 requirements now parse.
- Retires the `extract-bodies spec examples contain no caveman fetch line` requirement from `update-active-specs`, which pinned a file this change deletes.

The three deletions are not expressible as spec deltas: each file has zero parseable requirements, so a `## REMOVED Requirements` block would have nothing to list. Only the `update-active-specs` retirement produces a delta.

## Trade-offs Accepted

- The archived change gains a `specs/` directory it never had, so the archive stops being a byte-faithful record of what was archived.
- One of the 107 active specs carrying delta headers is repaired while 106 are left, so the corpus becomes slightly less uniform in its brokenness.
- Deleting a capability directory loses the breadcrumb that the capability once existed; only the archived deltas carry that history afterwards.

## Alternatives Considered

- **Set `skip_specs: true` on the change instead of repairing anything** — rejected: the change deletes three spec files and edits a fourth, so declaring that it modifies no specs is false regardless of what the validator accepts; and the key appears in no local schema and in no change in this repository.
- **Edit all four files directly and generate no `specs/` delta** — rejected: the retirement would exist only in git history and never in the change's own record.
- **Drop the retirement and leave the reference dangling** — rejected: it would point at a file the same change deletes, which is strictly worse than the state before the change.
- **Repair all 107 specs carrying delta headers** — rejected: out of proportion to a four-file cleanup, and no consumer requires it today.

Out of scope for the cleanup itself: the other 106 active specs carrying delta headers, `update-active-specs`'s own work-order nature, and the uncommitted working-tree state.
