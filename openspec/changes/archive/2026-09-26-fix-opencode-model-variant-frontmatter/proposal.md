## Why

OpenCode command frontmatter accepts only a single model line in provider/model#variant form, and agent markdown accepts model with an optional #variant suffix; a separate top-level variant key is invalid and ignored, so declared variants could be silently dropped. The change corrects every opencode markdown emitter and reader to the single-line form while preserving per-file tuning values as-is.

## What Changes

- 19 commands/opencode wrappers merge the existing variant value into a single model line and delete the variant line, with no value renormalization.
- 3 generic agents plus the opencode worker template apply the same merge, and the 15 matrix-generated workers inherit it through suffix values.
- The model customizer and installer read the legacy separated form for migration but always write the single-line form, remove residual variant lines, and render variant-less models as a bare model line.
- Preset JSON keeps the separate model and variant shape; configs/opencode.jsonc is untouched.
- Docs and tests are updated to assert the single-line physical shape.

## Capabilities

### New Capabilities

- opencode-command-model: correct model#variant rendering in all 19 opencode wrappers.
- opencode-agent-model: correct model#variant rendering in generic agents, worker template, and generated workers.
- model-customizer: migrating read and write for the single-line form with no-variant handling.

### Modified Capabilities

None — all capabilities in this change are new.
