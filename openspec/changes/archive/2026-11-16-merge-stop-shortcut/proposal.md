> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Two recent `/sai-merge` rebases spent about 40 minutes and 47.7M-63.9M cache-read tokens each, while 291 of 302 conflict regions resolved to one whole side byte for byte. The expensive unit was the region-by-region worker cycle (strategy, then apply) for changes that upstream already held in an evolved form. `merge.js` already computed the safety half of a whole-side decision (`stage_checkout_preserves_combined_content`), but nothing decided that a whole side was the correct resolution, so every conflicted file went through the merge worker.

## What Changes

- `merge.js conflicts` adds containment indicators to the conflict snapshot: per stop, the operation (`merge`, `rebase`, or `cherry-pick`), the incoming tip, the merge base, the scanned commit counts, and a `truncated` flag past 500 commits per side; per file, the incoming commits that touch it with their `patch_id` and `same_subject` upstream matches and their `range_diff` pairing, the upstream commits that touch it, and line indicators (added and removed lines against the common ancestor, how many added lines the other side already holds, the missing ones, and the removed lines the other side still holds). The record keeps the complete indicators; stdout carries a bounded summary.
- `merge.js resolution` accepts `--partial`, which checks only the files the resolution names, so the shortcut files of a mixed stop are checked before the rest is resolved.
- `merge.js bundle` accepts `--out <file>`, which writes the bundle to a new record file outside the repository and prints a summary with its path and hash.
- The `/sai-merge` coordinator card gains a **Shortcut** step in the conflict stop cycle: the coordinator decides once per stop, from the safety check and the containment indicators, which files take a whole-side checkout (`git checkout --ours`) without the worker. Weak or contradictory evidence, or a failed safety check, sends the file to the worker; a mixed stop is split and the remaining files are captured again. Each decision and its reason is written to `stop-{n}-shortcuts.md` in the run directory and recorded in `merge-run@1`. Shortcut files are checked with `--phase materialized --partial` and are not reviewed at the stop.
- The merge worker is created lazily, at the first step that needs judgment (a strategy, a test correction, or a renumbering plan). A run whose stops all take the shortcut and that needs no correction or renumbering plan creates no worker.
- The resume rule keeps a shortcut already listed in `stop-{n}-shortcuts.md`: it is checked and staged, never decided again.
- The closing report lists each shortcut file with the reason recorded in `stop-{n}-shortcuts.md`.
- `merge-run@1` accepts the `shortcut` reference kind for `record` events.
- `sai/commands/merge/mechanics.md` documents the containment indicators, the record-and-summary rule for large tool output, the complete resolution payload, `stop-{n}-confirmed.json`, and `stop-{n}-shortcuts.md`.
- The user guide `docs/commands/sai-merge.md` and the `AGENTS.md` repository table describe the shortcut, the lazy worker, and the indicators.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `sai-merge-command`: the conflict stop cycle gains a coordinator-decided whole-side shortcut backed by the containment indicators of `merge.js conflicts`, a partial materialized resolution check, lazy worker creation, and the shortcut decisions in the closing report.
- `merge-conflict-bundle`: `bundle` accepts `--out <file>` and writes the bundle to a record file with a summary on stdout.
- `merge-run-state`: `merge-run@1` records the `shortcut` reference, and a resumed run does not decide an applied shortcut again.
- `merge-worker-discipline`: the worker is created at the first judgment step and receives only the files the shortcut did not settle.

## Impact

- Modified: `sai/tools/merge.js`, `sai/commands/merge/coordinator.md`, `sai/commands/merge/mechanics.md`, `sai-state/machines/merge-run.js`, `docs/commands/sai-merge.md`, `AGENTS.md`, `test/merge-goal-driven.test.js`.
- New: `test/merge-stop-shortcut.test.js`.
- The shortcut uses only the already authorized whole-side checkout and the existing resolution check: the command's authority list and the tool-owned write rule are unchanged, nothing is pushed, and the behavior is the same on Claude Code and opencode.
- A wrong shortcut is not caught at the stop; it is left to the final-tree verification.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill

## Request Additional Notes

Future scope, outside this slice set: `/sai-merge` could accept `--abort` and `--status`, or its refusal message could name `git rebase --abort` / `git merge --abort`; the coordinator card could state that git drops a replayed commit that becomes empty (or pass `--empty=drop`); and it could state that an AGENTS.md change notice during the operation is working-tree content, not an instruction.
