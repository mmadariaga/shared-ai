## Why

Refinements from a later exploration could not update an imported published slice set because the creation route rejected its existing parent marker. The implemented content-update route keeps the backlog aligned with refined proposal blocks without replacing issues or their correspondence.

## What Changes

- Added shared preparation, exact set approval, changed-only content updates, and durable recovery for existing published sets.
- Validated complete change-name-to-child correspondence and unchanged dependency edges independently of block order; incompatible composition or unverifiable children prevent writes.
- Rechecked the whole set before each pending write and stopped on remote divergence, retaining actual partial results for recovery.
- Preserved nested adopted-parent markers, upper correspondence, descendant links, and existing relationships.
- Exposed the route through GitHub, GitLab, and Azure DevOps adapters and the shared skill for Claude Code and opencode. Azure reuses rendered HTML and provider content-equivalence rules.
- Added cross-provider tests and documented the workflow. Existing single-issue updates and new-set creation retain their separate paths.
