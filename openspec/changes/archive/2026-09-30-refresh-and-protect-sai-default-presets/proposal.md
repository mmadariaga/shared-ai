**Complexity**: high

## Why

The installer previously left existing distributed presets unchanged, so users did not receive updated defaults. Separating installer-managed defaults from user-owned personal presets allows default updates without overwriting personal configurations.

## What Changes

- Rename the five distributed preset files with the literal prefix `[sai-default]-`, preserving their remaining filenames and JSON content.
- Replace `copy-if-absent` with `copy` for both harness preset projections so each installation refreshes the distributed default files.
- Preserve legacy unprefixed files, personal presets, and other files that are not distributed by SAI, including other reserved-prefix files.
- Keep preset installation separate from applying presets to projects.
- Reject personal-save destinations whose resolved basename starts with `[sai-default]-`, case-insensitively; explain the reservation and repeat name entry without leaving the selected harness.
- Preserve loading of defaults and existing presets, and retain personal-preset overwrite confirmation.
- Document replacement behavior and personal-save guidance, and update regression coverage for both harnesses.
- Record the resulting doctor behavior: missing distributed defaults are fatal file-census errors because their projections now use `copy`, not the warning-only `copy-if-absent` strategy.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `preset-install`: Refresh distributed defaults on installation, preserve non-distributed files, and reflect the copy strategy in missing-file diagnostics.
- `install-model-presets`: Reserve the default filename prefix during personal saves while retaining load and personal-overwrite behavior.
- `preset-docs`: Document the renamed default files, replacement behavior, and separate personal saves.
