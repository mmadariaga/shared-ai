## Why

Commit, archive, backfill, the runner validator, and PR calls used repo-relative `node sai/tools/*.js` paths that fail with MODULE_NOT_FOUND outside this repo. The prereqs/change-picker/worktree pattern already solved this by trying project-local then global roots verbatim. This change generalizes that pattern into one shared rule so every tool call site resolves the same way.

Known limitations carried from the block: no prose fallback when no candidate exists; no invocation-semantics change beyond path resolution; explicitly out of scope are finding 3 stage-TODO restore, findings 4-11, and wrapper permission pre-approvals beyond what path resolution needs. Fix-loop converged in Round 2 with no findings; tests 1607 pass / 58 fail identical to baseline.

## What Changes

Added `sai/policies/tool-resolution.md` as the single owner of tool-location resolution for `sai/tools/*.js` and `bin/sai-state.js`, and applied it to every call site:

- New shared policy with per-harness verbatim candidate order, opencode XDG fallback only when neither verbatim candidate exists, first-existing-wins version rule, and byte-identical invocation per harness.
- `sai/commands/commit/coordinator.md`, `sai/commands/commit/instructions.md`, `sai/commands/commit/worker.md`: `commit.js` resolved via the shared rule for `collect --json --cwd` and `apply` (including `--amend` and `--acknowledge-secrets` heredoc forms).
- `sai/commands/archive/coordinator.md`, `sai/commands/backfill/coordinator.md`, `sai/commands/backfill/instructions.md`: `check-delta-headers.js` resolved via the shared rule (`node <tool-path> <change-name> --delta-dir`, no `--cwd`).
- `sai/orchestration/command-runner.md`: `worker-report-validator.js` resolved on every Result Loop turn (`node <tool-path> validate --kind <kind>`), missing validator never skips validation.
- `sai/commands/pr/instructions.md`: `pr.js` resolved via the shared rule (`collect --json --change --cwd`; `apply --cwd` plus `--parent` where needed, no `--json`/`--change` on apply).
- `sai/policies/stage-machine.md`: `bin/sai-state.js` resolved via the same rule (`node <tool-path> <verb>`, neither `--json` nor `--cwd`); store failure stops `step_machine` coordinators per contract.
- `sai/policies/change-picker.md`, `sai/policies/no-commit-guard.md`, `sai/policies/prereqs-check.md`, `sai/commands/worktree/instructions.md`: inline candidate lists replaced with a reference to the shared policy, mirrored verbatim, first existing wins.

## Capabilities

### New Capabilities

- `shared-tool-resolution`: single resolution order for tool copies per harness.
- `commit-tool-paths`: resolve `commit.js` via the shared rule.
- `delta-header-tool-paths`: resolve `check-delta-headers.js` via the shared rule.
- `validator-tool-paths`: resolve `worker-report-validator.js` via the shared rule.
- `pr-tool-paths`: resolve `pr.js` via the shared rule.
- `sai-state-location`: resolve the stage-machine CLI via the same rule.

### Modified Capabilities

None — all capabilities are new deltas; existing behaviors change only by path resolution, specified under their respective new capabilities above.
