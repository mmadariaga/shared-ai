> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Direct Build and backfill runs rejected altered message-text copies of stored Ready to Propose blocks. Appending hygiene verdicts to a separator without a final newline also rejected valid amendments. The implementation replaces model transcription with private-file references and composes the delivery boundary mechanically.

## What Changes

- Added stored-block export through the existing transfer utility for Claude Code and opencode, returning a paired private file and existing hash instead of block text.
- Added receiving-file verification and updated direct implementation, backfill preparation, and supervised specification handoffs to require file/hash references before dependent work.
- Required fresh exports after amendments and retained transfer directories through possible continuations and recovery.
- Added shared block/verdict composition and executable file interfaces for registration, amendment, and specification validation. Incomplete blocks and invalid verdicts remain errors.
- Extended origin attachment to verify input file references and return amended private-file references for validated storage.
- Added regression coverage for Unicode, final separators, no-final-newline delivery, stale or altered references, unsafe/unreadable files, both harnesses, composition failures, and origin transport.
