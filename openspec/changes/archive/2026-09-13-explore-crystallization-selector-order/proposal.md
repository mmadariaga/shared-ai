## Why
The explore crystallization close showed its pipeline selector before the Ready to Propose block was visible, forcing a correction with a repeated selector, and a Direct Build choice did not launch the build route. The staged change fixes close ordering and Direct Build dispatch in the explore step instructions.

## What Changes
- `sai/commands/explore/steps/crystallization-language-gates.md`: continuation after the language-gate answer always resumes at Ready to Propose block emission and never jumps directly to the selector, with no overview-language question at emission; fast-track skips the language question but never skips or auto-selects the selector.
- `sai/commands/explore/steps/crystallization-protocol.md`: same-turn block guard for items 5, 6, and 7 — selector only when block(s) ending at `---` were emitted in the same turn; language-gate answer resumes at block emission; premature selector without a block is discarded and the correction turn emits block plus shared close plus a single selector with re-selection from `last_crystallization_set`; identical order on both harnesses.
- `sai/commands/explore/steps/pipeline-selector.md`: selector fires only when block(s) with `---` were emitted in the same turn, exactly once at the end through the native picker; Direct Build enters only through emit plus `next.follow` to `pipeline-direct-build.md`, never via an ad-hoc Temp script; identical order on both harnesses with fixed titles.

## Capabilities
### New Capabilities
- None — all staged behavior modifies existing explore close mechanics.

### Modified Capabilities
- `crystallization-close`: same-turn guard, language-gate continuation, premature-selector discard and correction, identical block-first order.
- `explore-pipeline-selector`: end-of-turn single selector gated on same-turn block, stage-machine-only Direct Build entry, identical order with fixed titles.
