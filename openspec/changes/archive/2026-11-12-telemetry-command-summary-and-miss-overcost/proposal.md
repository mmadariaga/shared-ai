> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

`telemetry.md` added up the figures of a change per execution, agent, and segment, but never per command. On Claude Code every cost read `unavailable`, because the transcripts record no cost. The cache-miss count only caught requests whose cache read was `0`, so partial cache expiries (the conversation tail expires while the system prompt stays cached) went unseen, and real telemetry files showed zero misses where the cache had in fact been rewritten.

## What Changes

- New installable module `sai/tools/model-prices.js`: a dated default price table (`date`, plus per model `inputPerMTok`, `outputPerMTok`, `cacheReadPerMTok`, `cacheWrite5mPerMTok`, `cacheWrite1hPerMTok`, the shape of the benchmark corpus `prices`) and the pricing helpers `findPrice` and `priceFromTable`, moved out of `benchmark/cost.js`. The benchmark imports them and keeps the corpus table as its input.
- `sai/tools/change-telemetry.js`:
  - A cache miss is now a request after an agent's first whose cache read is smaller than the previous request's cache read plus cache write; the shortfall is the rewritten token count. A context compaction counts as a miss.
  - Each miss carries an overcost: rewritten tokens × (cache write price − cache read price), from the price table, at the write price of the lifetime the request recorded (5 minutes or 1 hour); a write without the lifetime split, including every opencode write, is priced as the 5-minute write.
  - The `telemetry-totals` comment of each section stores two more figures, `rewritten` and `overcost`.
  - Every table gains two derived columns: `Cache hit` (cache read ÷ (cache read + cache write + input)) after `Cache write`, and `Overcost/miss` (total overcost ÷ total misses, `n/a` with no misses) after `Cache misses`. Both are computed from summed figures when a table is rendered and are never stored.
  - On Claude Code the cost of each request is estimated from the price table and marked `~`; each Claude Code section states the price table date. A model with no price has an `unavailable` cost and overcost, and every total that includes it is marked `≥`.
  - A new `## By command` section right after `## Change total`: one row per command label of the execution headings with the execution count, plus a separate `sai-explore (exploration)` row that stays out of the change total. Every collection rebuilds it from the stored totals.
  - Sections written before these figures existed keep their text; their `Cache hit` and `Overcost/miss` are `unavailable`, and totals that add them up are marked `≥`.
- `sai/policies/change-telemetry.md`, `docs/project-settings.md`, and `openspec/schemas/sai-workflow/templates/telemetry.md` describe the new miss rule, the overcost, the cache hit, the estimated Claude Code cost, and the `By command` section.
- `test/change-telemetry.test.js` and `test/benchmark-cost.test.js` cover the new figures and the moved helpers.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `change-telemetry`: prefix-shrink cache misses with their overcost, the `Cache hit` and `Overcost/miss` columns in every table, an estimated Claude Code cost from the shared price table, and a `By command` section in `telemetry.md`.
- `outcome-benchmark`: the run cost uses the price lookup and pricing helpers of the shared installable module `sai/tools/model-prices.js`.

## Impact

- New: `sai/tools/model-prices.js`
- Modified: `sai/tools/change-telemetry.js`, `benchmark/cost.js`, `sai/policies/change-telemetry.md`, `docs/project-settings.md`, `openspec/schemas/sai-workflow/templates/telemetry.md`, `test/change-telemetry.test.js`, `test/benchmark-cost.test.js`
- Claude Code costs are estimates that depend on a dated price table that needs manual upkeep.
- Executions recorded before this change show `unavailable` for the new figures, and totals that include them are marked partial.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill

## Request Additional Notes

The default price values in `sai/tools/model-prices.js` must come from the providers' published price lists on the date the table states; no value is invented. Future scope, outside this change: a per-command roll-up across changes and projects in `retrospective.js cost`.
