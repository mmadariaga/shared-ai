> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The `design`, `tasks`, and `interfaces` instructions in `openspec/schemas/sai-workflow/schema.yaml` and the write-time-authority pointers in the `design.md`, `tasks.md`, and `interfaces.md` templates still cited the retired `sai/commands/design/instructions.md`, which no longer exists. The tests in `test/design-coordinator-worker.test.js` and `test/change-overview-contract.test.js` pinned that string, so they kept passing while the pointer led nowhere. A test that pins a pointer string does not prove the pointer resolves; the check must resolve the cited file.

## What Changes

- `openspec/schemas/sai-workflow/schema.yaml`: the `design`, `tasks`, and `interfaces` instruction blocks now cite `sai/commands/design/steps/design.md` `## Generate design.md`, `sai/commands/design/steps/tasks.md` `## Generate tasks.md`, and `sai/commands/design/steps/interfaces.md` `## Generate interfaces.md`. The cited section heading level changes from `###` to `##` to match the headings in the step files. The proposal and specs instructions are unchanged.
- `openspec/schemas/sai-workflow/templates/design.md`, `templates/tasks.md`, and `templates/interfaces.md`: each write-time-authority comment names its own design step file and its `## Generate <artifact>.md` section.
- `test/design-coordinator-worker.test.js` and `test/change-overview-contract.test.js`: the pointer and skeleton assertions expect the per-artifact step file `sai/commands/design/steps/<id>.md` and the `## Generate <id>.md` anchor instead of the retired shared path.
- New `test/schema-instruction-pointers.test.js`: extracts every `sai/...md` path (with or without a leading `@`) cited by `schema.yaml` and every `.md` template under `openspec/schemas/sai-workflow/templates/`, and fails when a cited file does not exist in the repository. It also checks that the schema cites the three design step files, and that the extraction reports the retired `sai/commands/design/instructions.md` as missing.

## Capabilities

### New Capabilities

- `schema-instruction-pointers`: every instruction file cited by the sai-workflow schema and its templates exists, and a test fails on a missing one.

### Modified Capabilities

- `tasks-scaffold-format`: the `tasks` schema instruction delegates to `## Generate tasks.md` in `sai/commands/design/steps/tasks.md` instead of the retired `sai/commands/design/instructions.md`.

## Impact

- New files: `test/schema-instruction-pointers.test.js`.
- Modified files: `openspec/schemas/sai-workflow/schema.yaml`, `openspec/schemas/sai-workflow/templates/design.md`, `openspec/schemas/sai-workflow/templates/tasks.md`, `openspec/schemas/sai-workflow/templates/interfaces.md`, `test/design-coordinator-worker.test.js`, `test/change-overview-contract.test.js`.
- The schema and templates are shared by Claude Code and opencode, so the repair applies to both harnesses.
- The `sai-workflow-schema` capability already requires the step-file pointers; this change brings the schema, templates, and tests in line with it.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
