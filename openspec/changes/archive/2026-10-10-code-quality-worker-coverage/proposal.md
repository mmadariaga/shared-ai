## Why

Implementation planning already loaded the code-quality priority policy, but that guidance did not explicitly reach all workers making coding decisions. Direct Build also bypasses implementation planning. The implemented change closes this instruction-delivery gap by loading the existing policy in the relevant code-writing workers.

## What Changes

- Added the existing policy Fetch to shared Apply RED/GREEN instructions, constrained by the assigned Step and role restrictions.
- Added the same Fetch to Direct Build and review-fix workers, constrained by the crystallized block and selected findings respectively.
- Added conditional Fetch instructions before merge code-resolution authorship and proposed test corrections. Whole-side selection alone requires no load.
- Clarified that merge active-stage instructions may require the policy before code authorship.
- Extended policy tests to check coverage, role boundaries, single-source references, merge stage disclosure, and shared instruction projection for Claude Code and opencode.

The policy remains a single source. The change does not expand worker permissions, authorized paths, assignments, or Git mutation ownership.

## Capabilities

### New Capabilities

- `code-quality-worker-coverage`: Explicit delivery of the existing code-quality policy to Apply RED/GREEN, Direct Build, review-fix, and code-authoring merge stages within their existing restrictions.

### Modified Capabilities

None. Existing planning, review, and worker contracts remain in place; the new capability records additive policy-loading coverage.
