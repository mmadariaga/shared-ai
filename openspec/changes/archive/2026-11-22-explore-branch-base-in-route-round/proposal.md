> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Round 2 of the `/sai-explore` post-crystallization close asked the branch base either alone or beside the backlog publication approval, which cost a separate interaction before the route picker. Deciding the base in round 3 takes every start-up decision of the change in one block, and creating the single or `shared` branch at the point where `per-slice` branches were already created gives the three branch modes one creation rule.

## What Changes

- `sai/commands/explore/steps/route-selector.md`: round 2 now asks only the backlog publication approval and is not presented when the prepared proposal reports `auto_approve: true`. The branch base question moves into round 3 (new `## Branch base question`), immediately before the publication question, in the order route, Direct Build continuation, change overview, base, publication. It is asked only in the first round 3 of the set while a branch is pending; `More` re-presents it alone inside the same round.
- The steps after round 2 run whether or not round 2 was presented: publication, branch name resolution (taking the created issue's identifier, so any name question runs before round 3), and base preparation through `new-change-branch` "Prepare for a caller". No branch is created there.
- A new `## Branch creation point` creates the single, `shared`, and first `per-slice` branch right after exactly one valid round-3 route answer and before `{intent: route-choice}` (before the hand-off for Manual). A missing or cancelled base answer creates no branch, sets `branch_strategy` to `none`, starts the route on the current branch, and withholds publication (`publication_withheld`) so every route reads the answer as `no`. A failed creation blocks the route start as an obstacle with `retry`, `skip`, and `stop` options. The Manual hand-off names the created branch.
- `## Publication question` names the pending branch by its exact name and remote and says it does not exist yet; it reads the current branch with `git symbolic-ref` only when no branch is pending, and a detached HEAD skips the question only when no branch is pending.
- `## Slice branch chain` describes the first `per-slice` branch as created at the creation point.
- `sai/policies/question-rounds.md`: on Claude Code, a round with more than four questions takes consecutive `AskUserQuestion` calls in round order that count as one round; the opencode rule is unchanged.
- `sai/commands/explore/direct-build-coordinator.md` and `sai/commands/explore/steps/pipeline-plan-unattended.md`: a withheld publication reads as `no`.
- `README.md`, `docs/commands/sai-explore.md`, and `docs/project-settings.md` describe the new round composition and creation point.
- `test/explore-question-rounds.test.js`, `test/explore-pipeline-selector.test.js`, and `test/explore-question-tools.test.js` pin the new composition, the base-before-publication order, and the shared creation point.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `explore-route-close`: round 2 holds only the publication approval; round 3 carries the branch base question before the publication question; one branch creation point with missing-base and failed-creation handling; Claude Code rounds of more than four questions.
- `explore-pre-route-actions`: the base is asked in round 3 and single, `shared`, and `per-slice` branches are created at the creation point.
- `explore-publication`: the publication question names the pending branch and its remote when a branch is pending creation.
- `explore-route-choice`: the base question joins the round 3 route call.
