> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The time a CLI response carries describes when the tool received the invocation, not a property of the validation, yet it lived only inside the validator verdict as `validated_at`. As a result `sai-state` `reset`, `spawn`, `close` and plain `emit` responses carried no time at all, so a segment's start time was never observable, and the name `validated_at` was wrong wherever nothing is validated.

## What Changes

- `sai/tools/worker-report-validator.js`: `generateValidatedAt` becomes the exported `generateReceivedAt`; `validateText` becomes a pure function returning `{ok, action, kind, errors}` with no time field for valid and invalid verdicts; the `validate` CLI reads the time once and writes `received_at` as the first key of its JSON response; the valid text line becomes `valid (<kind>) received_at <ts>`; the invalid line, the usage text and exit codes follow; `VALIDATED_AT_PATTERN` becomes `RECEIVED_AT_PATTERN`.
- `bin/sai-state.js`: every verb (`spawn`, `emit`, `emit --progress`, `reset`, `close`) loads the validator module, reads `received_at` once per invocation, and writes every stdout JSON response through one `writeResponse` helper that puts `received_at` first, including `rejected`/`warnings` responses and exit-1 machine errors; a missing validator or missing `generateReceivedAt` exits 2 naming the tried paths on every verb. The `emit --progress` `validation` block is the timeless verdict.
- Prose: `sai/orchestration/command-runner.md` § Validation, `sai/orchestration/worker-core.md`, `sai/policies/todo-structure.md` (Milestone Stamp source), `sai/policies/stage-machine.md` (every verb carries `received_at`), `sai/commands/merge/presentation.md`, `sai/commands/backfill/worker.md`, `sai/commands/design/phase-contract.md`, `GLOSSARY.md` (`Validated At` becomes `Received At`) and the `AGENTS.md` tools row now describe `received_at` and no `validated_at` anywhere, with no alias.
- New `docs/ddr/0162-received-at-is-the-cli-response-clock.md` (with index entries) amends DDR 0140 and DDR 0141; ADR 0144 and the single-clock intent are unchanged.
- Tests updated or added: `test/worker-report-validator.test.js`, `test/sai-state-progress-emit.test.js` (byte comparison no longer normalizes a time; new every-verb first-key test), `test/result-emission-time.test.js`, `test/todo-structure-policy.test.js`, `test/routed-progress-same-turn.test.js`, `test/sai-state.test.js`, `test/design-coordinator-worker.test.js`, `test/explore-stage-machine-consumption.test.js`, `test/implement-coordinator-worker.test.js`.
- Milestone Stamps stay closure-only and read `HH:MM` from the `received_at` of the response that marked the step; format, worker-payload timelessness and ADR 0144 are unchanged.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `validator-stamping`: the verdict becomes timeless; the `validate` response carries `received_at` first; one exported clock.
- `step-machine-progress-emit`: `emit --progress` returns top-level `received_at` and a timeless `validation` block; validator module loaded by every verb.
- `stage-machine-cli-interface`: every `sai-state` verb's JSON response carries `received_at` as its first key.
- `sai-todo-timestamps`: the Milestone Stamp reads `HH:MM` from the marking response's `received_at`.
- `stamp-on-progress`, `panel-stamp`, `orchestration-core`, `worker-lifecycle-protocol`, `coordinator-progress-ownership`, `progress-render-act`, `prompt-display`, `audit-command-progress-plans`, `review-phase-coordinator`, `review-phase-worker`, `security-phase-coordinator`, `security-phase-worker`, `accessibility-phase-coordinator`, `accessibility-phase-worker`, `design-coordinator`, `design-planning-worker`, `design-subagent-delegation`, `spec-coordinator`, `apply-coordinator-ownership`, `merge-presentation-seam`: stamp-source wording moves from `validated_at` to `received_at`.
