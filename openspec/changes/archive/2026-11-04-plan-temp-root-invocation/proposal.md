## Why

The plan segment cycle told the coordinator to create its run directory with `temp-root.js mkdtemp ... --cwd <project-root>`. `temp-root.js` rejects `--cwd` as an unknown argument, so the first attempt to open a fresh plan run failed. The usual recovery attempt, `temp-root.js --help`, also failed, because the tool validated `--harness` before it looked at the request for help. Each failure cost the run extra turns (`sai/commands/plan/cycle.md:20`, `sai/tools/temp-root.js:267-274`).

## What Changes

- `sai/commands/plan/cycle.md`: the fresh-run instruction now calls `node <tool-path> mkdtemp --harness <claude|opencode> --prefix plan-{name}-`, without `--cwd <project-root>`, which matches the documented `mkdtemp` syntax.
- `sai/tools/temp-root.js`: when `--help` appears anywhere in the arguments, the CLI prints `{ "ok": true, "usage": <usage> }` and exits 0, before it validates `--harness` or the sub-command. The usage text is one shared `USAGE` constant, used both by `--help` and by the usage error for an unknown sub-command. The header comment documents `node temp-root.js --help`.
- `temp-root.js` keeps rejecting unknown arguments: `mkdtemp --harness claude --cwd /project` still exits 2 with code `USAGE`.
- `test/temp-root.test.js`: a new test covers `--help`, `mkdtemp --help`, and `bogus --help` (each exits 0 with `ok: true` and a usage string) and confirms that `--cwd` is still rejected with exit 2 and code `USAGE`.
