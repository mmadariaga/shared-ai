## Why

Seven policy files totalling 742 lines describe formats a model is asked to self-verify, while `sai/tools/check-delta-headers.js` already proves the same class of rule can be decided verbatim in code rather than inferred. The artifact-format policies are currently expressed only as prose; mechanically checkable format rules should be enforceable through deterministic validation.

## What Changes

Added `sai/tools/lint.js` (713 lines) — a single runnable tool with selectable sub-checks that validate artifact-format policies and report findings on stdout with the same exit-code contract as the existing delta-header checker (exit 0 = pass, exit 1 = findings found, exit 2 = usage/IO error).

Added comprehensive behavior tests in `test/lint-tool.test.js` (622 lines, 31 behavior tests) covering all six mechanically-decidable sub-checks with no placeholder assertions. A round-1 functional fix loop (High=1 Medium=1 Low=0) expanded coverage from three to six policies and added body-wrap and blank-line rules to commit-rules validation; all findings were resolved before delivery. The test suite now sits at exactly 8 pre-existing baseline failures, none related to this change.

Added cross-reference comments to seven policy files:
- `sai/policies/commit-rules.md`
- `sai/policies/glossary-format.md`
- `sai/policies/ready-to-propose-format.md`
- `sai/policies/artifact-review-contract.md`
- `sai/policies/sai-learnings-format.md`
- `sai/policies/step-contract-format.md`
- `sai/policies/todo-structure.md` (with note explaining why no check applies)

Extended the `sai/tools/` registry row at AGENTS.md:95 to name all seven tools now in the directory. The row previously named four tools while the directory held seven. This update adds `status.js`, `openspec-yaml.js`, and `lint.js` to the registry. The status.js and openspec-yaml.js entries were inherited gaps from the preceding slice and are repaired here; their registry entries were missing until now, and their names and descriptions are preserved alongside the existing four, with no other changes to AGENTS.md.

The lint tool implements six mechanically-decidable sub-checks:
- `commit-rules`: Validates commit message subject length (≤50 chars), Conventional Commits format, no trailing period, blank line before body, body line wrapping (≤72 chars)
- `glossary-format`: Validates H1 heading, Language section, Relationships section, term definitions, and *Avoid* lines
- `ready-to-propose`: Validates Ready to Propose block heading and required sections in order
- `artifact-review`: Validates review finding format, severity vocabulary (High/Medium/Low), identifier format (H/M/L + number), and summary tally
- `sai-learnings-format`: Validates H1 heading, four sections in order (Stack, Conventions, Avoid, Test Command), and section content rules
- `step-contract`: Validates Step N section format with required Interfaces and Test assertions fields, or the sentinel "None — no step contracts"
