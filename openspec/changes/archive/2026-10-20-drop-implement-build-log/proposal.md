> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

`build-log.md` only summarized run-directory files plus `git log`. In eight real runs it was never part of the history, it moved into the archive with the change, and in the four inspected it carried zero pending findings and changed no review outcome. The deviations and the findings left pending after the third fix round are still worth showing to the user, so they move into the `/sai-3-implement` closing report instead of a file.

## What Changes

- `sai/commands/implement/coordinator.md` no longer composes `openspec/changes/{name}/build-log.md` at run close. Learnings promotion now runs before the report; the coordinator reads the run directory files the report needs (the deviations with their reasons, the overrides, and the findings still pending after the third fix round), and the closing report is their only record.
- The closing report lists the steps committed, the deviations each with its reason, the suite result against the baseline, the pending findings, the audit findings fixed, and whatever remains open. It always lists the deviations and the pending findings and says so explicitly when there are none; a run that did not complete adds the blocker with the options offered and the answer. The report no longer mentions `build-log.md`.
- A completed run removes its run directory once the report content is read, instead of after a build log is composed.
- Step review findings left after the third fix round are still written to `findings.md` in the run directory; the closing report lists them instead of a later review reading them.
- The review (`sai/commands/review/steps/common.md`, `establish-diff-scope.md`, `resolve-review-analysis.md`) no longer reads `build-log.md` or treats its pending findings as leads.
- `sai/commands/build/coordinator.md` and `sai/commands/deep-review/coordinator.md` no longer say that a blocked or stopped segment wrote `build-log.md` or name it in the segment report.
- `AGENTS.md` (§ Resilience, § Review, § Single artifact home, the Generated artifacts tree), `docs/commands/sai-3-implement.md`, `docs/commands/sai-4-review.md`, `docs/commands/sai-build.md`, and `docs/sequential-pipeline.md` describe the closing report and drop `build-log.md` as an output and as a review input.
- `test/implement-family.test.js` and `test/review-command.test.js` assert that the coordinator and the review sources no longer name `build-log.md` and that the closing report lists the deviations with their reasons and the pending findings.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `implement-new-run-log`: the run close prints a closing report with the deviations and the pending findings and persists no `build-log.md`.
- `implement-new-resilience`: a completed run removes its run directory once the report content is read.
- `implement-new-adversarial-review`: findings pending after the third fix round are listed in the closing report.
- `review-new-command`: the review no longer reads `build-log.md`.
- `build-new-command`: the build closing line no longer names `build-log.md` for a stopped segment.

## Impact

- Modified: `sai/commands/implement/coordinator.md`, `sai/commands/review/steps/common.md`, `sai/commands/review/steps/establish-diff-scope.md`, `sai/commands/review/steps/resolve-review-analysis.md`, `sai/commands/build/coordinator.md`, `sai/commands/deep-review/coordinator.md`, `AGENTS.md`, `docs/commands/sai-3-implement.md`, `docs/commands/sai-4-review.md`, `docs/commands/sai-build.md`, `docs/sequential-pipeline.md`.
- Modified tests: `test/implement-family.test.js`, `test/review-command.test.js`.
- After the chat closes, the deviations and the pending findings are recoverable only from the conversation. A `build-log.md` that already exists in a change stays untouched: nothing reads, removes, or regenerates it.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
