## Why

A standalone GitHub issue could never be assigned at implementation start. The REST `/parent` lookup answers 404 when an issue has no parent, the gh runner turns that into a generic error, and the run ended in `failure_before_publication`. The controlled "no verified native parent" branch only fired on a mocked `200 {}` response, so the tests hid the defect. There were two defects: a classification bug (a 404 treated as a generic failure) and a contract gap (standalone issues were undefined in backlog-slice-lifecycle).

## What Changes

- GitHub responsibility inspection (`inspect` in `sai/tools/backlog-assignment-github.js`) reads the hierarchy through one GraphQL query: `parent{url}` and `subIssues(first:1){nodes{url}}`. This replaces the REST parent endpoint. Only a complete response decides. A missing issue, a missing `parent` field, a parent without a URL, a missing sub-issue page, a GraphQL error or a transport failure fails the inspection.
- A GitHub issue with no SAI correspondence marker, no native parent and no sub-issues is a standalone leaf. Inspection returns it with `parent: null` and skips parent identity verification. `propose-assignment` and `assign` accept it, and the confirmation digest includes `parent: null`.
- An unmarked GitHub issue with no native parent and at least one sub-issue, open or closed, is rejected as a parent (`Selected issue has sub-issues; parent responsibility is preserved`).
- A marked issue whose correspondence declares native hierarchy and has no native parent still fails with the unverified-parent error. Marked issues and native children keep the existing verification flow.
- `verify-assignment` requires `expected_parent` to equal the currently inspected parent for every choice before it reports `verified: true`. `assign` verifies against the parent of its approved proposal.
- `sai/policies/backlog-implementation-start.md` step 1 accepts the GitHub standalone leaf, shows it as having no parent, and keeps the child-and-parent requirement for GitLab and Azure. Step 4 passes `expected_parent` in every case.
- `sai/tools/from-backlog-github.js` exports its GraphQL `api` helper for reuse.
- `test/github-backlog-slice-lifecycle.test.js` mocks the real GraphQL hierarchy shapes, removes the REST `/parent` mock, and covers the standalone leaf, unmarked parents, incomplete or failing hierarchy responses, the marked native case, native children with their own sub-issues, and parent-stable verification.
