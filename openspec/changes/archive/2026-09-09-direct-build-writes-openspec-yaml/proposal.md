## Why

Every change produced by the Direct Build route was left un-archivable by `/sai-archive`. The archive gate reads `openspec/changes/{name}/.openspec.yaml` and treats an absent file as `backfilled: false`, which keeps `design`, `tasks`, and `implementation` in the blocking CORE set. Direct Build never generates those three artifacts by design, so the gate stopped with "Missing CORE artifact(s): design, tasks, implementation. Archive blocked." The relaxation already existed — the archive gate skips exactly those artifacts when `backfilled` is `true` — but the Direct Build pipeline never mentioned `.openspec.yaml` in its artifact set, so the file was never written. Observed on the change `retire-name-only-spec-obligations`: the archive run closed without archiving until the file was created by hand, after which the same command succeeded.

## What Changes

- `sai/commands/explore/steps/pipeline-direct-build.md` — steps 3, 4, 5, and 6 now include `openspec/changes/{name}/.openspec.yaml` in the backfill artifact-set description, making the metadata file part of the required draft set at preparation and part of the execute order at backfill execution.
  - Step 3 (Sibling backfill preparation): The dispatch requests the backfill worker to compose the draft set including `.openspec.yaml` in the canonical form.
  - Step 4 (Spec review): The explorer validates and accepts `.openspec.yaml` as part of the returned draft set.
  - Step 5 (ADR/DDR pass): The artifact set is restricted to the schema-validated OpenSpec drafts plus `.openspec.yaml` in canonical form.
  - Step 6 (Backfill execution): The execute order includes `.openspec.yaml` in the validated draft paths.

## Additional Notes

- **Rationale for reusing the standalone route's shape**: a Direct Build change is a backfilled change by construction; a second shape definition would create unnecessary divergence.
- **Why this is an artifact-set gap, not an archive-gate problem**: the gate and its relaxation are correct; the route simply never produced the input the gate reads.
- **Edge case — existing `.openspec.yaml` files**: a pre-existing file must not be silently overwritten with a different `created` date; the coordinator's validation step handles this in its accept/reject logic.
- **Known limitation**: `.openspec.yaml` is ignored by `.gitignore:13`, whose negations re-include only directories and `proposal.md`, so the file fixes the local archive gate but is not committed. Whether it should be tracked is a separate decision, out of scope here.
