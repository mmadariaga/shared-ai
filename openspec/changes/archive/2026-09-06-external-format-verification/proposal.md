## Why

Externally supplied `sai-explore` findings blocks were previously validated in prose by the receiving worker, introducing interpretation variability. Making validity deterministic ensures consistent application of the shared artifact-review contract rules across spec and design phases.

## What Changes

The spec and design review steps now call a deterministic format validator (`validate-findings.js`) before processing externally supplied findings blocks. The validator runs the `artifact-review` check from `lint.js` against the block and returns `needs_input` with exact violations if the format is malformed, enabling bounded-retry correction instead of silent mis-parsing.

Tool path resolution follows a candidate list (project-local, then user-global) for both Claude Code and opencode harnesses. Missing validators degrade gracefully with a report and proceed without validation.

Two new files: `sai/tools/validate-findings.js` (the validator) and `test/validate-findings.test.js` (13 behavior tests). Modified files: `sai/commands/spec/steps/review.md`, `sai/commands/design/steps/review.md`, `AGENTS.md` (registry update naming the new tool).

Three functional fix rounds ran and converged. The test suite sits at exactly the 8 pre-existing baseline failures.

## Capabilities

### New Capabilities

#### external-verification

The findings block's format is decided by the validator before it is processed. A malformed block returns `needs_input` with the exact violations rather than being mis-parsed.

### Modified Capabilities

#### worker-active-step-execution

The review step now includes a validation gate before processing externally supplied findings.

#### planning-artifact-review-loop

Worker-owned and design review paths now validate findings format as a prerequisite to processing.
