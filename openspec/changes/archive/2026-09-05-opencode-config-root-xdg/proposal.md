## Why
The installer derived the opencode base from the home directory in two independent places, so when XDG_CONFIG_HOME redirects opencode's real config root the installer wrote where opencode never reads. The same hardcoded root fed the sai permission pattern and harness detection, so XDG installs also carried a silently non-matching permission and a false absent report.

## What Changes
- Centralizes opencode config-root resolution in bin/install-flow.js behind resolveOpencodeBase, which parses the config entry from opencode debug paths when the binary is present and falls back to ~/.config/opencode otherwise.
- Derives the sai permission pattern, probe path, agents display string, and config prefix rewriting from the resolved root, preserving the ~/.config/opencode/sai/** literal only when the resolved root equals the default.
- Threads an explicit pattern base through installOpencode, copyOpencodeConfig, mergeOpencodeAgents, classifySaiPermission, invalidPermissionResult, and printOpencodeConfigMessage while keeping destBase and override injection.
- Makes detectInstalledEditors accept overrides and otherwise use the resolved root, and updates the installer main flow, doctor harness inventory, model-customization agent and command roots, and uninstall enumeration to consume the same root.
- Without the binary or with an empty XDG value, resolution falls back to today's default so installation without opencode keeps working, at the cost of one extra debug paths probe when the binary exists.

## Capabilities
### New Capabilities
- opencode-config-root-resolution: single authoritative resolution of the opencode config root with binary-present and binary-absent paths, applied to installs, permission merging, and harness detection.

### Modified Capabilities
- None.
