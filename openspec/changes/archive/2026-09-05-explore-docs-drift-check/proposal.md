## Why

Explore answers treated ADRs, DDRs, specs, and docs as current truth without code confirmation, so stale records could mislead correctness claims. A bounded check that confirms only the load-bearing claims keeps freshness without turning research into a full audit, with headroom from a 30 to 40 per-segment ceiling to absorb the extra lookups.

## What Changes

- `sai/policies/explore-agent.md` — per-segment ceiling raised from 30 to 40 with every tool call including reads counting, discard-logging reference updated to the 40-call ceiling, and a new inline Docs-vs-code drift check section.
- `skills/claude/budget-explorer/SKILL.md` — description and tool-call ceiling updated from 30 to 40.
- `skills/opencode/budget-explorer/SKILL.md` — per-spawn cap updated from 30 to 40.
- Verification fires only when a document is cited as the normative basis for a correctness claim about current code behavior, confirms at most 1-2 load-bearing claims with ladder-governed lookup plus one read each then stops, and reports confirmed drift as a low informative non-blocking note citing both sides without gating the answer.
- Unmappable claims report as unverified unknown never as drift, out-of-root needs record in out_of_root_requests as unverified without widening, pure summarize reads require no verification unless later used to assert current behavior, absent indexes are a non-event, and ceiling exhaustion declares leftovers explicitly.
- Preserved: explore stays read-only, ladder order and out_of_root_requests handling unchanged, no new files, and no new artifact kinds.
