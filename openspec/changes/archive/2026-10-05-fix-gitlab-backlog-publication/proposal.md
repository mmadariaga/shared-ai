**Complexity**: medium (3 affected files, no breaking change)

## Why

On the affected GitLab 19.0.8 host, issue listing with `order_by=id` failed with HTTP 400 before publication, while JSON requests without an explicit Content-Type failed with HTTP 415. The implemented correction uses supported listing order and explicit JSON transport without weakening exact-content verification or duplicate-creation protection.

## What Changes

- Changed publication and recovery issue listing to ascending `created_at` order while retaining scope, state, page size, pagination, and identifier-based baseline checks.
- Added `Content-Type: application/json` in the shared GitLab API helper only when a request body exists. POST and PUT retain JSON serialization on stdin with `--input -`; approved title and description remain data rather than command arguments.
- Extended simulated-request tests to check POST and PUT headers, exact submitted and stored content, bodyless GET requests, and unchanged comment-query ordering.
- Added regression coverage for multi-page identifier baselines, invalid or repeated listing responses, listing failures before POST, retained uncertain-creation receipts, read-only recovery, and issues whose title matches but description is empty.
