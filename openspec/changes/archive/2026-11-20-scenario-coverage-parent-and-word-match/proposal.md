## Why

The scenario coverage hint of `/sai-3-implement` reported false positives in two ways. A branch cut from a release branch had its change base taken against the default branch, so every file of the release branch counted as changed by the change. Scenario titles also matched inside other words, so the title `valid input` was found inside `invalid input`. Both made a scenario look covered by a test that does not exist (issue #486, F2 and F3).

## What Changes

- `sai/tools/scenario-coverage.js` accepts an optional `--parent-branch <branch>` in `step` and `change` modes. The change base is the merge-base of `HEAD` with that branch. A branch that does not resolve to a commit exits 2 with a message that names it. Without the option, the tool keeps its default order (the default branch of `origin/HEAD`, then `master`, then `main`), the same order `/sai-4-review` follows.
- Title matching treats every punctuation run as a word separator and matches on word boundaries: a normalized title must appear between spaces in the space-padded normalized content of a changed file. `valid input` no longer matches `invalid input`, and `valid-input` still matches `valid input`. Two titles that differ only in punctuation now share one normalized title and are reported as `ambiguous`. Matching still covers every changed text file outside `openspec/`, and the tool's header comment says so.
- `/sai-3-implement` accepts `--parent-branch <branch>` and passes it to both scenario coverage modes. Without the option, it passes the branch that the `**Reviewed:**` line of `review.md` names when that file exists and `git rev-parse --verify --quiet <branch>^{commit}` accepts it, and otherwise passes no option. The option changes only the scenario coverage check: the inherent-risk ratings at close keep the `**Reviewed:**` parent. A `--parent-branch` without a branch, or given twice, ends the run before anything is written.
- `/sai-build` accepts `--parent-branch <branch>` and forwards it to both implementation segments and to the review segment. A `--parent-branch` without a branch, or given twice, ends the run before anything is written.
- The Claude Code and opencode wrappers of `/sai-3-implement` and `/sai-build` declare the new option, and the command usage pages document it.
- The `scenario-coverage.js` invocation line in `sai/policies/tool-resolution.md` lists the optional `--parent-branch <branch>` for both modes.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `scenario-test-coverage`: the change base can be taken against an explicit parent branch, and titles match on word boundaries with punctuation as a word separator.
- `implement-new-adversarial-review`: the scenario coverage checks of `/sai-3-implement` take a parent branch from the `--parent-branch` option or from the `**Reviewed:**` line of `review.md`.
- `build-new-command`: `/sai-build` accepts `--parent-branch` and forwards it to its segments.
