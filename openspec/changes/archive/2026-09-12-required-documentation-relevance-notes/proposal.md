## Why

Design phase research already records each consulted file's role through the `budget-explorer` subagent's report, but this information is flattened into a bare path list in `tasks.md`. The implementation phase may not explore the codebase (per its boundary constraints), so it must reread every listed file and re-derive its role — losing the design phase's research context. Specs are also scattered or duplicated between sections (under both Spec files and Local files), creating ambiguity about which entry is authoritative.

## What Changes

- The `## Required Documentation` section of `tasks.md` reorders from `### Local files` → `### Spec files` → `### External URLs` to `### Spec files` → `### Local files` → `### External URLs`
- Each entry under `### Local files` now carries a relevance note in the form `<path> — <note>`, with whole-file paths only and no line ranges
- Each entry under `### External URLs` now carries a relevance note in the form `<URL> — <note>`
- Every spec is listed only under `### Spec files`, both change delta specs and consulted main specs, and no path or URL is listed twice
- The design instruction is updated to that structure and no longer instructs the agent to use line ranges
- The sai-3 reading rule, in both canonical copies, explains that the path or URL is the text before ` — ` and that the note guides the reading; it still honors a line range when an entry carries one
- The `tasks.md` template shows the new subsection order and entry format
- Tests assert the new subsection order and the new entry-format rules

## Capabilities

- **tasks-authoring-rules**: the Spec files subsection comes first and covers delta and main specs alike; Local files and External URLs entries are whole-file paths or URLs with relevance notes
