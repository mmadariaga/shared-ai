## Why

The `/sai-pr` command contained approximately 159 lines of procedural prose that directed the model to read `spec.md` and `implement.md` files. However, the `sai-workflow` schema does not produce these files in any project. When they were absent, the model would improvise silently instead of failing with clear guidance. Additionally, the prose created a temporary file to hold the PR body, which had to be cleaned up after execution—a pattern that leaves orphans on failure and couples the implementation to transient filesystem state.

## What Changes

- New tool `sai/tools/pr.js` with `collect` and `apply` subcommands, following the established pattern in `sai/tools/commit.js`
  - `collect` subcommand reports branch, derived parent, commits, diff inventory, artifact presence and absence, capability specs, gh availability, and any existing pull request as JSON
  - `apply` subcommand reads drafted title and body from stdin via `gh pr create --body-file -`, validates the title, and creates the pull request
- New check in `sai/tools/lint.js`: `checkPrTitleRules` validates PR title format (≤70 characters, Conventional Commits prefix, no emoji, no trailing period)
- `sai/commands/pr/instructions.md` refactored from prose-heavy direction to routing plus JSON handling; stale references to `spec.md` and `implement.md` removed
- Audit annotations for "not applicable" surfaces remain a model judgement rather than computed from per-project configuration

## Capabilities

### New Capabilities

- **pr-collect**: Report branch, derived parent, commits, diff inventory, artifact presence and absence, capability specs, gh availability, and any existing pull request as JSON
- **pr-apply**: Read drafted title and body from stdin, validate the title using PR title rules, and create the pull request
- **pr-title-validation**: A linter check enforcing pull request title format (≤70 chars, Conventional Commits prefix, no emoji, no trailing period), callable as CLI subcommand or exported function
- **pr-command-prose**: Reduced command prose focusing on routing to collect and apply subcommands, with stale artifact references removed

### Modified Capabilities

- **format-linting**: Added pr-title-rules check as seventh sub-check; updated requirement body to accommodate checks that examine files or accept text input rather than only files

## Impact

**New files:**
- `sai/tools/pr.js` — tool with collect and apply subcommands

**Modified files:**
- `sai/tools/lint.js` — gained checkPrTitleRules function and pr-title-rules subcommand
- `sai/commands/pr/instructions.md` — refactored to routing and JSON handling

**New observable behaviors:**
- pr-collect subcommand outputs branch and pull request readiness as JSON
- pr-apply subcommand creates pull requests from stdin-supplied title and body
- pr-title-rules check validates pull request titles
- /sai-pr command no longer directs models to read spec.md or implement.md

Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
