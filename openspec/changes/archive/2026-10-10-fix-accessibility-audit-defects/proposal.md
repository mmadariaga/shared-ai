## Why

The `/sai-8-accessibility` static audit ended on "every phase that applies to its component types" with "applies" defined nowhere, and the `map-ui-framework` step had no completion criterion, so two runs over the same diff could audit different checklists. This change fixes that core defect together with the minor worker-instruction defects listed below, as the defect-fixes slice of issue #65.

## What Changes

- `sai/commands/accessibility/steps/map-ui-framework.md`: the step is done when it has recorded five results (`UI files in scope`, `frameworks detected`, `component types`, `design tokens`, and `accepted trade-offs`), each as a list or `none`. The component types use the trigger vocabulary `forms`, `media`, and `dynamic content`. Interactive widgets, navigation, and static content are marked as triggering no checklist. The framework list adds Vue (`.vue`), Svelte (`.svelte`), and "Any other framework the UI files use".
- `sai/commands/accessibility/steps/resolve-static-audit.md`: each checklist opens with a `Trigger:` line. The first three are `Trigger: always.` (Semantics & Structure, ARIA & Naming, Keyboard & Focus). Forms, Media & Non-Text Content, and Dynamic Content & SPA use `Trigger: component types include forms|media|dynamic content.`. Visual Design uses `Trigger: UI files in scope include a CSS file, or design tokens is not none.`. The step is done when every component in `component types` has been evaluated against every triggered checklist and, when Visual Design is triggered, every CSS file and design token as well. Checklist content is unchanged.
- `sai/commands/accessibility/steps/common.md`: component-bearing markdown is defined beside the UI file list. It is `.mdx` files, plus `.md` files containing an HTML element or a capitalized component tag such as `<Button>`; a `.md` file with neither is not a UI file. Remediation is aligned with the `frameworks detected`. The screen-reader rule now requires every statement about what a screen reader will announce or do to be written as an inference prefixed `Inferred:`. The "Diff-scoped by default. Out-of-scope risks get a one-line note" rule is removed.
- `sai/commands/accessibility/steps/close-accessibility-outcome.md`: the self-critique "Framework idiom respected" check says fixes follow the idioms of the `frameworks detected`.
- `sai/commands/accessibility/worker.md`: with zero active changes the worker returns `failed` with exactly: No active changes found. Run `/sai-1-spec` to create one.
- `test/accessibility-coordinator-worker.test.js`: a new structural test asserts the five-result mapping criterion. It checks that the `Trigger: component types include ...` lines name exactly `forms`, `media`, and `dynamic content`, each of which appears in the mapping type list. It also checks the `every triggered checklist` criterion, the component-bearing markdown definition, the `Inferred:` prefix, and the no-active-changes literal. Existing step id and title assertions are unchanged.
