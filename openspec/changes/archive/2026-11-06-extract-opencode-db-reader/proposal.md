## Why

The per-change telemetry collector planned under `record-change-telemetry` needs the same read-only opencode database access that `sai/tools/retrospective.js` already performs: opening `opencode.db` read-only behind a schema guard, linking child sessions to their root by `parent_id`, and detecting the change a run belongs to. That code lived inside `retrospective.js` with no exported seam, so a second consumer could only copy it, and two copies would drift at the next opencode schema migration. This change is an enabling refactor with no user-facing value of its own: it extracts that code into a shared module first, so a regression in `retrospective.js` can be reviewed without the noise of the new feature.

## What Changes

- New module `sai/tools/opencode-db.js`, the read-only opencode database reader shared by the SAI tools. It exports `OPENCODE_MAX_DEPTH`, `OpencodeUnavailable`, `defaultLoadSqlite`, `openOpencodeDatabase` (read-only `node:sqlite` open of `$XDG_DATA_HOME/opencode/opencode.db`, default `~/.local/share/opencode/opencode.db`, followed by the schema guard on `session_v2` and `session_message`), `opencodeRoot` and `opencodeChildren` (recursive `parent_id` linkage with a depth cap of 16), and the change-name detection functions `changeNameFromArgs`, `writtenChanges`, and `changeNameOf`.
- `sai/tools/retrospective.js` no longer defines those constants and functions; it imports them from `./opencode-db`. The rest of its logic stays in place.
- `changeNameOf` now receives the set of pipeline commands as a fourth argument instead of reading the `retrospective.js`-local `PIPELINE_COMMANDS` constant; both `retrospective.js` call sites (Claude Code and opencode sources) pass `PIPELINE_COMMANDS`, so the detected change name is unchanged.
- `retrospective.js` output was verified identical before and after the extraction, and the functional fix loop converged on its first pass with no findings.
