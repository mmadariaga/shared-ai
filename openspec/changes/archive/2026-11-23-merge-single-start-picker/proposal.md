> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

`/sai-merge` used up to three consecutive turns at the start of a run: the branch question, then the method question (which waited for the pre-launch simulation of the picked branch so it could recommend squash), then the autostash question. The user wants fewer turns at the start, and judged the squash recommendation not worth a dependent second turn.

## What Changes

- The `/sai-merge` coordinator asks every open start question (branch, method, autostash) in one native picker call, in that order, answered in one turn: one `AskUserQuestion` call with one entry of `questions` per open question on Claude Code, one `question` call with several questions on opencode. With no open question, no picker opens.
- On Claude Code, when the preflight returns fewer than 2 branch candidates and the branch is open, the branch is asked first in plain text (because `AskUserQuestion` needs at least 2 options) and the rest in one picker call; opencode keeps one picker.
- The autostash question joins the same picker call. It opens when a tracked unstaged change exists (a `dirty` entry that is not untracked `??`) and `git config rebase.autoStash` is not true, and its wording says it applies only to a rebase or squash. A merge ignores the answer and launches without `--autostash`; a rebase or squash with a declined answer, or with no picker under an explicit `--rebase` or `--squash`, ends the run before the first mutation.
- Without a native picker, a missing branch is asked in plain text, the method is a merge, and no autostash question is asked. Cancelling or dismissing the picker ends the run with nothing launched and nothing written; the simulation has not run, so no directory is left.
- `merge.js simulate` now runs after the start answers, for the chosen method (the method of the arguments, the answer, or a merge without a picker). No question reads the prediction and none recommends a method: its predicted stops and `repeated_files` go only to the `simulation` record and the closing report. An unavailable simulation is noted in the report.
- `AGENTS.md` (`### Merge coordinator and worker`), `docs/commands/sai-merge.md`, and `sai/commands/merge/mechanics.md` (§ Simulation) describe the new start order.
- `test/merge-goal-driven.test.js` and `test/merge-pre-launch-simulation.test.js` assert the grouped questions in one call, the simulation after the answers, and no squash recommendation in the questions.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `sai-merge-command`: the start questions are grouped into one picker call; the simulation runs after the answers and feeds only the closing report; the squash recommendation in the method question is removed.
- `method-selection`: the method question is part of the grouped start picker, does not depend on the simulation, and recommends no option.
