## Why

Repeated fetch arguments produced redundant resolution work and output. Existing tool-location lookups deliberately repeat one path, so eliminating duplicates must keep those calls in path-only mode.

## What Changes

- Resolve each exact subpath argument once per invocation and emit one resolution or error block, preserving first-occurrence order.
- Choose content versus path-only mode from the original argument count before deduplication. A repeated singleton still returns one location block without content; a single argument retains content output.
- Keep distinct argument spellings separate, even when they resolve to the same file, without introducing options, path normalization, or cross-call state.
- Update both harness fetch instructions and regression tests for repeated paths, ordering, errors, and mode compatibility.

- `fetch-resolution-path-scoping`: verify opencode continues to mirror the shared fetch behavior, including repeated-singleton location lookups.
