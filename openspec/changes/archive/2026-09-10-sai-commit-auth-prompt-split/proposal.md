## Why
The five-element question-context wording plus the coordinator's unaltered payload blocks crowded the opencode question tool into one unreadable wall. The change splits authorization presentation so the staged file inventory and proposed message render as ordinary text while the picker asks one short decision, keeping decision context visible without repeating it inside the question.
## What Changes
- `sai/commands/commit/worker.md`: authorization ask changed to short "Run `git commit` on the staged changes above?" with ordered options `yes (Recommended)` / `no` / `Allow on this session` as the registered commit-authorization exemption; staged inventory with Totals plus proposed subject/body render as ordinary text above the picker, unaltered and in fixed order; secret-file confirmation and already-pushed amend warning keep full context and are excluded from shortening; identical short wording on Claude Code and opencode.
- `sai/commands/commit/instructions.md` Step 6: file inventory with Totals shown as ordinary text above the picker unaltered, proposed subject/body shown as ordinary text above the picker after the inventory in fixed order, short decision asked without Totals or option explanations inside the question, secret and amend gates excluded from shortening.
- `sai/commands/commit/coordinator.md`: worker-authored payload content rendered as ordinary text above the picker unaltered in fixed order inventory then message, picker kept to the worker's one short line with no added Totals or option explanations, secret-file confirmation and already-pushed amend warning keep full context, same short ask re-presented unchanged on off-option reply or silence, identical presentation on both harnesses.
- `sai/policies/question-context.md`: registered sixth pinned exemption for the commit authorization short ask with blocks-above-picker context rule and secret/amend exclusion.
