## Why

The model customizer buried the most-used All scope at the end, labeled orchestrating commands as COMMAND, and listed All targets by family so each command was separated from its workers.

## What Changes

- Scope screen in bin/model-customization.js now offers All first, then Workers, Agents, Orchestrators, Utilities, with Orchestrators resolving to the stable command family.
- Checklist TYPE column now renders ORCHESTRATOR for the command family via a display mapping, with the TYPE width widened from 7 to 12 in the header and every row.
- All-scope checklist now builds a phased order: alphabetical agents, then one block per command in command-alphabetical order with its semantic workers directly below, then leftover workers alphabetically, then alphabetical utilities.
- Stable selection values worker:, agent:, command:, and utility: plus parseTarget behavior are unchanged; only visible labels and All ordering changed.
- Test coverage in test/model-customization-menu.test.js and test/model-customization-taxonomy.test.js was updated to assert the new scope order, ORCHESTRATOR labels, width-12 header, and phased All order.

## Capabilities

### New Capabilities

- `model-customizer-scope`: All as the first scope option with Orchestrators as the visible command-family label
- `model-customizer-labels`: visible ORCHESTRATOR TYPE label with width 12 in header and rows
- `model-customizer-grouping`: phased All checklist grouping with semantic command-worker pairs

### Modified Capabilities

- None — all three capabilities are new deltas; no existing capability was modified in place.
