## Why

Dispatches cancelled before the task handle returned left no resumable session, orphaned a guard snapshot, and forced a from-scratch retry, seen on sai-2 design dispatches. Tightening the existing handshake doctrine so every worker returns its handle before expensive work and deferring the guard snapshot until handle capture narrows that window with one policy change.

## What Changes

- `sai/orchestration/worker-core.md`: defines handshake as first early return before expensive work, handle as harness-native resumable identifier, guard window as one snapshot-to-verify span; extends handshake to every routed worker with a progress plan or routing-only step map; adds no-handshake case and late-or-duplicate non-resumable rule.
- `sai/orchestration/command-runner.md`: coordinator retains the harness-native handle before any guard snapshot or continuation; cancelled-before-handle retry starts from zero with deferred snapshot; same-worker continuation resumes on the retained handle with existing literals.
- `sai/orchestration/workers/bindings/claude/worker-template.md`: mirrored Claude transport retains the agent ID from run_in_background dispatch before any snapshot; cancelled-before-ID leaves no handle.
- `sai/orchestration/workers/bindings/opencode/worker-template.md`: mirrored opencode transport retains the task ID from task dispatch before any snapshot; cancelled-before-ID leaves no handle.
- `sai/policies/no-commit-guard.md`: snapshot runs only after handle capture, verify closes every window as today; cancelled-before-handle opens no window; HEAD movement between dispatch and capture is baselined by the deferred snapshot; batch snapshot waits for all batch handles.

## Capabilities

### New Capabilities

- `worker-fast-handshake`: handle-first routed-worker startup handshake with deferred guard windows. Every routed worker with a progress plan or routing-only map returns its startup progress as a handshake before any subagent, excess read, write, or analysis; the coordinator retains the harness-native handle before opening the guard window; both binding templates mirror the transport with no common syntax; matrix expansion propagates the change to all generated bindings.

### Modified Capabilities

- None — this change tightens shared doctrine and mirrored templates only; no existing capability behavior is re-specified as a modified delta in this backfill.
