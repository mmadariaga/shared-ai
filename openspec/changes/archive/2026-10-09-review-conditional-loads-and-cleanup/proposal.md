> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The review Direct Build close loaded `command-execution.md` and `unattended-runtime-recovery.md` before knowing whether a fix runs, the review worker loaded the glossary format in projects without a `GLOSSARY.md`, and the review instruction files repeated rules across files that are loaded together. Material only one branch needs now loads on that branch, and each rule is stated once, beside the step that uses it, with no change to review behavior.

## What Changes

- `sai/commands/meta-review/direct-build-close.md`: the loads of `command-execution.md` and `unattended-runtime-recovery.md` move from the file header into the Fix loop section, after the user chooses to fix. The selector and the decision to offer the fix stay in the close. `/sai-5-review` and `/sai-review` share this close, so both get the delayed loads.
- `sai/commands/review/steps/common.md`: the glossary-format load and the Step delivery section are removed; the severity definitions move here as a `## Severity` section; the write-scope phrase "your only writable artifact" and the clause telling the reviewer to praise a correct change "in the report's Summary" are dropped.
- `sai/commands/review/steps/resolve-review-analysis.md`: pass 9 fetches `sai/policies/glossary-format.md` only when `GLOSSARY.md` exists. One sentence before passes 3 to 5 states that audit recommendations come only from those passes, together with one blatant-defect rule that keeps one calibrating example per domain (hardcoded password, `SELECT *` in a per-row loop, `<img>` without `alt`) and the existing severities. The per-pass blatant-defect sentences and the pass 11 "adds no audit recommendation" sentences are removed. The delegated-mode text now defers to the scope step.
- `sai/commands/review/steps/close-review-outcome.md`: classification points to `common.md` § Severity; the severity list and the resilience cross-reference are removed.
- `sai/commands/review/steps/establish-diff-scope.md`: the delegated-mode entry carries the per-group `budget-explorer` output contract (`file:line` + pass category + ≤80 words per finding).
- `sai/commands/review/worker.md`: the OpenSpec prerequisite sentence is removed; the pointer rule reads positively ("execute only the step it names") without the prefetch prohibition; the joint first progress event wording is condensed.
- Tests updated to pin the new text: `test/review-coordinator-worker.test.js`, `test/review-shared-dependencies.test.js`, `test/routed-progress-same-turn.test.js`, `test/step-machine-wiring.test.js`.

Thresholds, the shared dispatch cap of eight, the eleven passes, the adversary dispatch, the scope step's git commands, and the fixed stop texts are unchanged.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `review-direct-build-close`: the close loads its fix-loop policies only after the user chooses to fix.
- `review-phase-worker`: the glossary format loads at pass 9 only when `GLOSSARY.md` exists; severity definitions, the blatant-defect rule, and the worker rules are each stated once.
- `step-pointer-task-disclosure`: the review worker references the first-pointer rule from its worker contract instead of `steps/common.md`.
