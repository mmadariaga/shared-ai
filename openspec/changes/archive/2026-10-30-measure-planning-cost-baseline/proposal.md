## Why

Issue #292 questions the cost of the `/sai-1-spec` and `/sai-2-design` contracts, but no cost had been measured. `sai/tools/retrospective.js` recorded identifiers, loaded instructions, and tool errors per execution but no token usage, and Claude Code transcripts older than the retention window disappear, so the "before" figures had to be captured before the design contracts change.

## What Changes

- `sai/tools/retrospective.js` (the `/sai-retrospective` collector) now reports, for every execution, the coordinator and each agent with `usage` (input, output, cache read, cache write, and `cost` where the harness records it), `tool_calls`, `pipeline_segment` (`spec`, `design`, or `implement`, derived from the agent type; `null` for any other agent), and `parent_agent_id` (the agent that dispatched it). Usage a transcript does not hold reads `unavailable`, never zero, and the execution stays in the index.
- Dispatched agents are linked to the agent that dispatched them (`parentAgentId` in Claude Code subagent meta files, `parent_id` in opencode `session_v2`) and their figures are kept apart from the dispatcher's.
- A new `cost` mode reads every planning and implementation run of the projects (`/sai-1-spec`, `/sai-2-design`, `/sai-plan`, `/sai-3-implement`, `/sai-build`, and any other execution whose workers did a spec, design, or implement segment), pairs planning runs with implementation runs by change name (the invocation's argument, otherwise the `openspec/changes/<name>/` path its workers wrote to), reports unpaired runs, and totals cost by segment, role, and agent type. `--format markdown` prints the baseline report; `--alias "<path>=<alias>"` shows a project only under its alias with numbered changes.
- A new `--with-worktrees` option of `index` and `cost` (and of `/sai-retrospective`) measures a project together with the worktrees `git worktree list` reports for it.
- `skills/universal/sai-context-cache-ttl-benchmark/adapters.js` gains the non-throwing token readers `claudeTokens` and `opencodeTokens` (and the `UNAVAILABLE` marker) beside `claudeUsage` and `opencodeUsage`, which keep their behavior.
- The baseline `docs/measurements/planning-baseline-2026-10-30.md` is committed, generated from the `cost` mode, with the second project under an alias.
- `sai/commands/retrospective/body.md`, `docs/commands/sai-retrospective.md`, and `AGENTS.md` document the new fields, the `cost` mode, and `--with-worktrees`.
- `test/retrospective-tool.test.js` gains fixtures for both harnesses covering usage, unavailable usage, tool calls, nested dispatch, worktree grouping, and pairing.

## Capabilities

### New Capabilities

- `planning-cost-baseline`: a versioned, anonymizable report of current planning and implementation cost under `docs/measurements/`, generated by the collector and comparable after later contract changes.

### Modified Capabilities

- `sai-retrospective`: the collector reports per-agent token usage, tool calls, pipeline segment, and dispatcher link, gains the `cost` mode with run pairing, and accepts `--with-worktrees`.

## Impact

- New files: `docs/measurements/planning-baseline-2026-10-30.md`.
- Modified files: `sai/tools/retrospective.js`, `skills/universal/sai-context-cache-ttl-benchmark/adapters.js`, `sai/commands/retrospective/body.md`, `docs/commands/sai-retrospective.md`, `AGENTS.md`, `test/retrospective-tool.test.js`.
- Accepted limits: review rounds and coordination stay one combined figure inside the coordinator's usage; the baseline reflects only runs still present in transcripts; sessions of worktrees already removed from disk stay out of their project's figures.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
