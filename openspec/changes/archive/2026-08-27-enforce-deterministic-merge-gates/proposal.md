## Why

The previous merge lifecycle slice created a shared validation seam but allowed every transition. This implementation makes lifecycle ordering auditable and deterministic: clean and conflicted routes have explicit gates, and invalid transitions stop before operation selection. Valid behavior, the scope-only fast-track exception, worker analysis, and coordinator mutation ownership remain unchanged.

## What Changes

- `sai/commands/merge/lifecycle.md` defines an exhaustive transition table and deterministic operation-context preconditions for preflight, clean merges, conflicted merges, ADR/DDR handling, authorization, and terminal closure.
- `sai/commands/merge/coordinator.md` requires validation before each named operation and halts invalid transitions before operation selection, worker dispatch, mutation, or presentation updates.
- `sai/commands/merge/presentation.md` requires presentation state updates only after validated lifecycle boundaries.
- `test/merge-contextual-conflict.test.js` verifies valid paths, invalid ordering and context, fast-track scope-only bypass, non-committing closure, neutrality, ownership, and no mutation on invalid transitions.

No standalone new capability was added in this staged slice.
