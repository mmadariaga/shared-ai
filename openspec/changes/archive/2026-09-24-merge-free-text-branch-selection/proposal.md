## Why

The current `sai-merge` branch selection only offers unmerged local branches and ends when that list is empty, preventing use of a remote branch such as `origin/esta-rama-no-es-local`. Free-text entry for local names and `origin/<branch>` references with coordinator-owned fetch and exact-ref validation removes that block without changing the listed path.

## What Changes

- `sai/commands/merge/instructions.md`: Branch candidates keep the existing query, ordering, and labels; the routing choice `sai:enter-branch` (`Enter a branch name`) is always appended including when the list is empty; an empty list no longer closes the run; Step 4 proposes launch with the full `source_ref` and defers fetch and exact-ref checks to the coordinator.
- `sai/commands/merge/coordinator.md`: Batch 1 sentinel routing with a coordinator-owned open prompt pre-authorizing only `git fetch --prune origin`; `branch_selection_source` and `branch_entry` kept as invocation-scoped state; free-text entries derive one exact ref (`origin/<name>` to `refs/remotes/origin/<name>`, others to `refs/heads/<name>`) followed by fetch, `check-ref-format`, `show-ref --verify`, and `rev-parse --verify`; listed candidates use `refs/heads/<name>` with no fetch; no local branch is created for `origin/<branch>`; failures close with no integration; provenance and launch use `source_ref`.
- `sai/commands/merge/lifecycle.md`: `branch-selection` selects the listed or text route with no integration launched; new `branch-validation` refreshes and checks a free-text entry as an exact ref with no integration launched; transitions cover sentinel selection, text receipt, listed success, fetch or ref failure to terminal, and validation success to `merge-outcome`.
- `sai/commands/merge/presentation.md`: Candidate labels and order unchanged with the `Enter a branch name` sentinel always present; empty-list messaging explains text entry remains available; the summary notes the exact fetch command and its pruning effect; a coordinator-owned open prompt asks for one local name or `origin/<branch>` reference; `branch_selection_source` tracks `listed` or `free-text`.
- `sai/commands/merge/worker.md`: Branch-entry refresh and validation declared coordinator-owned; the worker never runs fetch or exact-ref checks and never treats the sentinel as a selected branch.
- `sai/policies/todo-structure.md`: No merge TODO while free-text validation is pending or after it fails; `merge: in_progress` renders only after provenance is captured.
- `test/merge-contextual-conflict.test.js` and `test/merge-incremental-collision.test.js`: Launch assertions updated to `source_ref`; new coverage for sentinel presence, empty-list text path, fetch and exact-ref order, no-fetch for listed, no local-branch creation, and TODO gating.
