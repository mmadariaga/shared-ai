> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The merge tool already captured the content of every conflict, but it returned the worker a view without that content, and the worker instructions sent the worker to extract three versions of each file through the shell (`git cat-file blob <oid>`). In a measured run this caused repeated extractions, improvised temporary files, and a detour to convert encodings. The merge cards gave no guidance on encoding, so the bytes a resolution ended with depended on the model and on the shell.

## What Changes

- `sai/tools/merge.js` gains a read-only `bundle` command. From the captured conflict snapshot it returns the conflict bundle: for each conflicted file its conflict category, the sides present, each side's commit messages, and each conflict region with its three decoded versions (`ours`, `base`, `theirs`) and bounded context (3 lines by default, `--context 0-20`).
- Files with no text to compare (`binary`, `deleted-on-one-side`, `renamed`, `no-markers`) and files whose encoding the tool cannot determine (`encoding-undetermined`) appear in the bundle with their category, no regions, and `whole-side-only` resolution. Only UTF-8, with or without a BOM, counts as a determined encoding.
- `sai/tools/merge.js` gains a `write` command. The worker sends a region identifier and resolved text on standard input, and the tool splices the text into conflict regions or coordinator-named correction ranges. The tool takes encoding, BOM, and line endings from the pre-write snapshot, whatever the text arrives with.
- A write call is whole: text with a conflict marker line, an unknown region, an undetermined encoding, a stale snapshot, or a file changed by anything but the tool rejects the call, and a rejection writes nothing. The tool keeps a ledger of placed text beside the snapshot record (`<record>.writes.json`), so a region can be rewritten and each call rebuilds the file from the protected pre-write content.
- The existing `resolution` check now expects the same stored bytes as the write (shared conversion of line endings and BOM), so it still validates every write.
- The merge tool's standard input accepts UTF-8 with or without a BOM and UTF-16 with a BOM.
- Stage blob OIDs leave the `strategy` disclosure. The worker reads conflicts through `bundle` on the snapshot reference and hash, and its permitted merge-tool calls become `instructions`, `valid`, `bundle`, and `write`.
- The write surface is unchanged: conflict regions and coordinator-named correction ranges. Whole-side choices remain coordinator-run checkouts.
- `sai/commands/merge/instructions.md`, `worker.md`, `mechanics.md`, and `coordinator-stages.md` describe the bundle and the tool-owned write; `docs/commands/sai-merge.md` and the "Merge efficiency" section of `AGENTS.md` document them.
- Known limitation accepted: a file whose encoding cannot be determined safely admits only a whole-side choice. Classifying trivial conflicts before analysis is not part of this change.

## Capabilities

### New Capabilities

- `merge-conflict-bundle`: one merge-tool call gives the worker each conflict prepared, with three decoded versions per region, bounded context, the conflict category, and each side's commit messages.
- `merge-resolution-write`: the merge tool places the worker's resolved text into conflict regions and correction ranges, preserves the file's encoding, BOM, and line endings, and rejects invalid input without writing.

### Modified Capabilities

- `sai-merge-command`: the worker supplies resolution text and the tool places it; whole-side-only files include undetermined encodings; resolution validation expects the snapshot's line endings and BOM; the `strategy` disclosure no longer carries stage blob OIDs.
- `merge-worker-discipline`: the worker may also call `bundle` and `write`; corrections are placed through the tool; disclosure state carries region identifiers without stage identifiers.
