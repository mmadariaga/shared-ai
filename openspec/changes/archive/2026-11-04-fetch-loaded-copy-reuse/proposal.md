> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Several skills loaded together repeat the same `Fetch @` directive: `sai/policies/cache-warming.md` loads three times whenever the `budget` skill loads its three role skills (`skills/claude/budget-explorer/SKILL.md`, `skills/claude/budget-executor/SKILL.md`, `skills/claude/budget-subagent/SKILL.md`), and `sai/policies/explore-agent.md` loads twice when `budget` and `budget-ro` load together. The fetch skills carried no rule against reloading, so every project on both harnesses paid for the repeated loads.

## What Changes

- `skills/claude/fetch/SKILL.md` and `skills/opencode/fetch/SKILL.md` gain one `### Loaded-copy reuse` section, placed after `### Recursion` and worded identically apart from the harness skill tool name (`Skill` on Claude Code, `skill` on opencode). The agent judges each directive against its own context:
  - A `Fetch @<subpath>` directive whose subpath the fetch tool already returned in this conversation, with that complete content still in context, is followed from the loaded copy with no tool call. A complete result is the full fetch tool output, or the full Read of the header `path` after a `too-large` result.
  - A `Fetch @skills/<name>/SKILL.md` directive for a skill already loaded through the skill tool, with its content still in context, is followed from the loaded skill with no second skill-tool call.
  - The agent runs the fetch tool or the skill tool again when the loaded content has left its context (a compaction or summary kept only a mention of it), when it is unsure the content is still there, or when the earlier read was partial. A file the harness attached from an `@path` mention, and a Read of another copy of the file, are not loaded copies.
  - The copy is keyed on the subpath: a copy installed under another root after the first load is picked up once the loaded content has left the context.
  - Only content the agent loaded itself counts: a subagent or worker never reuses its dispatcher's loaded copy, and a continued subagent reuses only what it loaded itself.

## Capabilities

### New Capabilities

- `fetch-loaded-copy-reuse`: the fetch skills of Claude Code and opencode follow an already-loaded copy of a fetched file or skill instead of loading it again, and reload it once it has left the context.

### Modified Capabilities

- `claude-fetch-resolution`: the one-call-per-directive rule and the `Skill` tool mapping gain the loaded-copy exception on Claude Code.
- `fetch-resolution-path-scoping`: the opencode one-run-per-directive rule and the `skill` tool mapping gain the same loaded-copy exception.
- `fetch-existence-check-before-read`: the skills-path rule keeps invoking the skill tool except for a skill already loaded and still in context.
