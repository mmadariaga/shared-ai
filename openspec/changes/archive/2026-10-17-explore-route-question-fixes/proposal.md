## Why

The branch-base page could show up to four bases plus `More`, five options against the four-option picker cap that Claude Code declares (`skills/universal/new-change-branch/SKILL.md`, `sai/policies/remember.md`). The Direct Build continuation "Yes" authorized one local commit per slice while the next sentence said the continuation answer authorized no other mutation (`sai/commands/explore/steps/route-selector.md`), so the scope of that answer was contradictory.

## What Changes

- `skills/universal/new-change-branch/SKILL.md`: when Claude Code has more than four bases, the first page carries three bases plus a More option; four or fewer bases carry all of them without More. Free-text entry stays on every page. The prepare-without-creating section states the same page shape: up to four options in all, three bases plus `More` above four bases, every base without `More` at four or fewer, plus the free-text entry.
- `sai/commands/explore/steps/route-selector.md` round 2 branch base question: the first page shows the suggested bases in the skill's order with the same page shape (three bases plus `More` above four bases, every base without `More` at four or fewer) and the free-text entry.
- `sai/commands/explore/steps/route-selector.md` continuation question: one authorization sentence. The continuation `yes` starts each later slice in order with its single local commit and authorizes nothing else; switches between chained branches stay authorized by the `per-slice` answer of the branch question, and no answer selects another route.
- `test/explore-question-rounds.test.js`: the `new-change-branch` preparation assertion matches the new page-shape wording.

Option order, free-text entry, the `More` interaction for the base only, and the separate publication confirmation are unchanged. The picker cap itself stays at four options.
