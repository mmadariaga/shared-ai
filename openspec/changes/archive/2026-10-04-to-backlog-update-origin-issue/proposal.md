## Why

The creation-only to-backlog workflow had no publication path for refinements to the existing issue that originated a conversation. The implemented change adds reviewed title-and-description updates while retaining issue creation for conversations without an originating issue.

## What Changes

- Select creation or origin-issue update before extracting content, using the conversation's starting request and explicit provenance rather than incidental later links.
- Keep one explicitly invoked to-backlog skill with shared preparation, review, confirmation, and reporting, and disclose creation or update mechanics only in the selected branch.
- Retain the originating issue's canonical identity during from-backlog import when that issue is the conversation's starting point; later imports do not silently replace it.
- Reuse GitHub issue-reference normalization and issue-only reading for full or domainless issue URLs without requiring a from-backlog invocation.
- Add GitHub read-update, query-update, update, and recover-update operations through the existing provider registry and adapter dispatch.
- Preserve unrelated description content, require approval of the canonical issue, baseline, and exact final content, and change only title and description.
- Bind update confirmation to the authenticated actor and repository visibility as well as the target and content.
- Reread before mutation, require renewed review when the baseline changes, and disclose that the final read and GitHub mutation cannot be atomic.
- Record update attempts in private local receipts and verify remote content after submission, including after a lost response; recovery distinguishes applied, pending, divergent, and unreadable results without remotely mutating.
- Return a verified no-op when the proposed title and description already match the current baseline.
- Install the branch files and update-provider instructions for both Claude Code and opencode, with simulated regression coverage for the new operations.

None.

### Modified Capabilities

- `to-backlog-conversation-capture`: origin-based mode selection, branch-local mechanics, preserved description content, and exact mode-specific confirmation.
- `to-backlog-github-publication`: editable-origin inspection, baseline-bound update, restricted mutation, private receipts, remote verification, recovery, and concurrency disclosure.
- `to-backlog-provider-resolution`: registry-declared origin-update operations and branch-specific instruction selection without using creation defaults to guess an origin.
- `to-backlog-harness-installation`: mirrored branch and provider installation, updated invocation descriptions, and simulated update regression coverage.
- `from-backlog-conversation-import`: conversation-scoped originating-issue provenance distinct from later reference links.

## Additional Notes

GitHub's updateIssue API has no atomic content-version precondition. An external edit detected before submission requires renewed review and approval, but an edit between the final read and mutation can still be overwritten; each update proposal discloses this limitation before approval. Failed updates never become replacement-issue creation, and unresolved verification remains uncertain rather than permitting an automatic retry.
