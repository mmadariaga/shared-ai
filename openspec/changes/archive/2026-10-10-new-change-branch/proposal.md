## Why

Creating a branch needs a consistent naming format and an explicit starting point without asking users to repeat information already available in the conversation. A provider-neutral workflow supports feature, fix, documentation, and maintenance changes, with an optional actual work-item identifier.

## What Changes

- Added an explicitly requested `/new-change-branch` universal skill for Claude Code and opencode. It reuses relevant conversation context and asks only for missing or ambiguous naming information.
- Added a stdin-JSON Node helper with `inspect`, `name`, `base`, and `create` operations. The helper owns Git inspection, name validation, base resolution, local creation, and completion verification.
- Implemented `<type>/<id>_<name>` and `<type>/<name>` naming for `feat`, `fix`, `docs`, and `chore`. Only the name is normalized; a supplied identifier is preserved.
- Added deterministic parent suggestions by matching available reference tips against at most 20 first-parent commits, nearest HEAD first. Full reference names break ties alphabetically.
- Added native base selection with free text, absent-reference omission, reference deduplication, and Claude Code pagination when necessary.
- Rechecked name availability, base validity and unchanged SHA, and merge/rebase state before creation. Creation uses separate Git arguments and does not configure remote tracking.
- Preserved existing staged, unstaged, and untracked work. Cancellation performs no mutation; blocked or incomplete creation reports actual execution state without automatic cleanup or retry.
- Added a capability profile and skill-only requirements assignment, with existing installation projections covering both harnesses.
- Added temporary-repository tests and instruction/projection checks, including operation-specific failure reporting.

The bounded parent search is a starting-point suggestion, not proof of historical ancestry. It can miss older origins, merged-side branches, and references whose tips moved. Available remote-tracking references can be stale because the workflow does not refresh them.
