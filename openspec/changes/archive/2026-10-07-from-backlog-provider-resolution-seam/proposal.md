**Complexity**: medium (1 capability, 2 requirements, 3 affected paths, no breaking change or new dependency)

## Why

The existing from-backlog dispatcher rejected references that failed shared URL parsing before adapters could classify them. Its default host selection also used exact registered-host equality. These mechanics prevented a subsequent adapter from claiming contextual identifiers or organization-specific URL hosts at the existing registry boundary.

This change opened a bounded provider-classification seam ahead of the separate Azure DevOps integration. It is an enabling refactor, not delivery of Azure DevOps support or new reference acceptance by the shipped providers.

## What Changes

- Added opt-in `classification: provider` selection through an adapter's `classify(value)` operation on the trimmed reference.
- Restricted classifier results to `match`, `fallback`, or `null`, rejecting other results as `invalid-registry`.
- Combined default registry classification and provider-owned classification into one selection process: direct matches precede fallback candidates, and exactly one candidate must remain in the winning tier.
- Retained shared URL parse errors when no classifier claims an otherwise unparsable reference.
- Cached loaded adapters within each resolution call and invoked context resolution only on the selected adapter.
- Retained the existing selected-adapter `resolve(value, io)` or `normalize(value)` dispatch and metadata attachment.
- Documented pure reference classification separately from context resolution, including the prohibition on CLI reads, context lookup, and side effects during classification.
- Added regression coverage using synthetic providers for non-URL references, organization subdomains, fallback selection, ambiguity, invalid classifier results, non-readable entries, and delegated outcomes.
- Added assertions that shipped providers still reject isolated IDs and other incomplete references with their existing error behavior and without CLI context reads.

No shipped registry entry opted into provider-owned classification. No GitHub or GitLab adapter, retrieval implementation, or provider registration changed.
