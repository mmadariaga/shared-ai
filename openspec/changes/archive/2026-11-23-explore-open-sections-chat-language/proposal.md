> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

When `/sai-explore` works on an issue written in a language other than the conversation's, the issue's open sections were shown with the issue's original text. The user then discussed and agreed edge cases and implementation details in a language that is not the conversation's, which raises the risk of agreeing to something not fully understood. The list display rule in `sai/commands/explore/list-writing.md` applied the conversation language only to the question, not to the list items.

## What Changes

- `sai/commands/explore/list-writing.md` gains a **Display language** rule beside **Display and question**: every item of an `E`/`I` list is displayed in the conversation language (the `explore.chatPublicLanguage` setting when it holds a value, otherwise the language the user writes in). An item whose starting text is in another language (an issue, pasted text, or a file) is translated for the display, including every revision, which is displayed again in full. An item already in the conversation language is displayed as written. Identifiers, item order, paths, code, and technical literals stay verbatim. A domain term with no faithful translation keeps its original form and is explained once in the conversation language. Confirming the displayed list agrees the displayed version; the block's language stays with the crystallization language gate.
- `sai/commands/explore/steps/issue-intake.md`: when a seeded issue resumes at its first open section, an open `What`/`Why` is displayed in the conversation language by pointing to the `list-writing.md` § Display language rule, without restating it.
- `test/explore-contract-preservation.test.js` gains a contract test that pins the display-language rule in `list-writing.md` and the pointer to it in `issue-intake.md`.
- `docs/commands/sai-explore.md`: the issue-intake paragraph states that open sections and their revisions are shown in the conversation language, while the block's language keeps its current rules.

The crystallization language gate, the Ready to Propose format, and the explore stage machine are unchanged. The change is instruction and documentation text shared by Claude Code and opencode.

## Capabilities

### New Capabilities

- `explore-list-display-language`: explore displays `E`/`I` list items, and the open `What`/`Why` of a seeded issue, in the conversation language during exploration, translating source text written in another language while keeping identifiers and technical literals verbatim.

### Modified Capabilities

None
