## Why

The installed `to-backlog` skill cited `publication-recovery.md` from six of its files (for example `skills/universal/to-backlog/SKILL.md` and `skills/universal/to-backlog/slice-set.md`), but the `to-backlog-references` projection in `sai/install-manifest.json` did not include it. In opencode runs on 2026-11-02, a partial GitLab slice publication could not read its recovery protocol because the file was absent from both installed copies. No test checked that files a skill references are actually installed, so this gap could recur for any universal skill.

## What Changes

- `sai/install-manifest.json`: the `to-backlog-references` projection adds `publication-recovery.md` to its `include` list, so the file is installed into `skills/to-backlog/` for both `claude` and `opencode`. No other projection changes, and the projection stays an explicit list rather than a `**/*.md` wildcard.
- `test/universal-skill-references-installed.test.js` (new): a `node --test` guard that, for each harness (`claude`, `opencode`), builds the installed source set from `expandInstallManifest(loadInstallManifest(repoRoot), { harness, repoRoot, destinationRoot })`, keyed by `sourcePath`, so it reuses the installer's own include and exclude matching (glob entries such as `providers/**/*.md` count as installing the files they match).
  - It scans only installed `.md` files under `skills/universal/`; a skill file that no projection installs adds no obligations.
  - It extracts `.md` references with one regular expression over backtick spans and Markdown link targets, and resolves each one relative to the directory of the referencing file (so `../publication-recovery.md` in `providers/github.md` resolves to `to-backlog/publication-recovery.md`).
  - It skips a reference that resolves to no existing file in the source tree.
  - It fails when an existing referenced file is not installed for a harness that installs the referencing file, and each failure names the referencing file, the reference text, the resolved path, and the harness that lacks it. There is no exception list.
- `skills/universal/to-backlog/slice-set.md`: the bare `backlog-origin-transport.md` mention becomes `sai/policies/backlog-origin-transport.md`, the path form the skill already uses for other policies. No other text changes.

## Impact

- New files: `test/universal-skill-references-installed.test.js`
- Modified files: `sai/install-manifest.json`, `skills/universal/to-backlog/slice-set.md`
- Installed output: `skills/to-backlog/publication-recovery.md` is now installed for both `claude` and `opencode`.
- No spec-level behavior changes: this is an installer coverage fix and a test guard with no user-visible behavior change, so the change carries no capability spec.
- Known limitations: the guard checks only references that resolve to an existing file beside the referencing file, so dangling references and bare mentions of files in other trees stay undetected. Installer pruning of stale installed files (such as old `issue-format.md` copies) and changes to the fetch skills' project-local probing remain out of scope.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
