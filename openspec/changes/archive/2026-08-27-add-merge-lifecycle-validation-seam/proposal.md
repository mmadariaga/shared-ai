## Why

The merge lifecycle is expressed through coordinator contracts, but the existing flow has no shared boundary for validating lifecycle order before selecting the next merge operation. This refactor establishes that boundary before deterministic enforcement is added, while preserving the behavior of existing merge commands.

## What Changes

- Add `sai/commands/merge/lifecycle.md`, defining the merge lifecycle states, paths, transition contract, coordinator-owned integration boundaries, and current placeholder behavior.
- Update `sai/commands/merge/coordinator.md` to fetch the lifecycle seam and validate transitions before merge operations.
- Update `sai/commands/merge/presentation.md` to connect presentation state with the lifecycle seam.
- Add regression coverage for the lifecycle states, validation contract, integration points, neutrality, and enabling-refactor scope.

## Capabilities

### New Capabilities

- **Coordinator lifecycle validation seam** — Defines a shared, harness-neutral boundary for validating merge lifecycle results before the next coordinator operation is selected.

### Modified Capabilities

- **Merge coordinator lifecycle integration** — The coordinator now references the lifecycle seam at operation boundaries while retaining existing worker and mutation ownership.

## Impact

- `sai/commands/merge/lifecycle.md` — new lifecycle validation seam.
- `sai/commands/merge/coordinator.md` — lifecycle seam loading and transition-validation integration.
- `sai/commands/merge/presentation.md` — lifecycle state reference.
- `test/merge-contextual-conflict.test.js` — regression coverage.
