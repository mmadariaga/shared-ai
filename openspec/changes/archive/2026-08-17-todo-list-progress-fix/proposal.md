> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation. It describes a decision already made, not one being proposed.

## Why

Progress events were not reaching coordinators because worker contracts used "emit" ambiguously. Workers could print progress inside their own session, but the only channel to the coordinator is the task return value. As a result, TODO lists did not update during long-running work. The backfill also records the startup handshake and explicit task-list render ordering needed to keep progress resumable and visible.

## What Changes

- Define progress events and design notices as returned nonterminal worker results that end the current worker turn.
- Require coordinators to mark returned progress, re-render the task list, and resume the same worker with the fixed continuation acknowledgement.
- Require a startup handshake after prerequisite and scope resolution, before subagent dispatch, artifact writes, or analysis.
- Render declared task lists before dispatch and re-render them before every progress continuation.
- Apply the transport and handshake wording consistently to planning and audit worker contracts.

## Capabilities

### New Capabilities

- `nonterminal-result-transport`: Workers return progress events and design notices as resumable nonterminal results instead of printing them inline.
- `startup-handshake`: Planned workers return an early progress handshake before expensive, analytical, or mutating work begins.

### Modified Capabilities

- `todo-list-progress-rendering`: Coordinators render plans before dispatch and re-render after each returned progress event before resuming the worker.
