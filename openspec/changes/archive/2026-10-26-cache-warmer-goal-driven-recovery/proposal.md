## Why

The cache warmer could stop before its fixed closing time after a failed wait or an inapplicable background execution-limit check. Recovery now belongs to the main agent so that an interrupted wait is an obstacle rather than completion.

## What Changes

- Keep the main conversation active until the fixed closing time or user cancellation.
- Assign continuation and exceptional recovery to the main agent, preserving the original state and closing time without prescribed retry counts or failure-specific stopping rules.
- Match background execution requirements to Claude Code and opencode's actual behavior; a foreground execution limit is not a prerequisite for a background wait.
- Report environmental interruptions without claiming completion and continue toward the same closing time when control returns.
- Retain wait.js and native completion notifications without polling or independent loops.
- Extend instruction-contract tests while preserving existing temporal and error-propagation tests.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `cache-warmer-cycle`: Goal-driven continuation and agent-owned recovery with fixed-state preservation and completion only at closing time or cancellation.
