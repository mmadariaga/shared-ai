> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Standalone and Explore-supervised `sai-1-spec` previously depended on duplicated lifecycle, progress, validation, and write-boundary instructions while an inactive invocation contract remained in the source tree. That split allowed contracts to drift, reject valid progress results, lose validation warnings, disagree about write scope, and increase instruction load for smaller models.

## What Changes

Introduce `sai/policies/spec-phase-contract.md` as the canonical contract consumed by the standalone coordinator, spec worker, and Explore-supervised adapter. It centralizes ownership, the six-step progress declaration, routing-only pointer delivery, the closed write surface, lifecycle result handling, and structured validation reports.

Retire `sai/commands/spec/invocation.md`, remove duplicated plan and warning declarations from active instruction surfaces, and update the shared runner, worker core, bindings, installation metadata, documentation, and regression tests. Standalone and supervised execution retain their existing lifecycle, recovery, feedback, artifact ownership, and harness-parity semantics while differing only in presentation and supervision behavior.

The selected diff also updates command inventory fixtures and counts to include `sai-review`. This is recorded as implemented scope drift rather than as part of the supplied sai-1 intent. The change does not alter production-code behavior.

## Capabilities

### New Capabilities

- `sai-1-phase-contract`: A centralized contract defines the routed sai-1 ownership, progress, pointer, write-surface, result, and validation-report declarations.
- `sai-1-command-inventory`: Both harness command inventories include the staged `sai-review` command entry and updated count.

### Modified Capabilities

- `sai-1-entry-path-parity`: Standalone and Explore-supervised execution consume the same lifecycle and artifact-boundary declarations while preserving their established presentation differences.
- `sai-1-routing-pointers`: Routing-only step-pointer maps remain active when visual progress rendering is suppressed.
- `sai-1-validation-reporting`: Validation warnings travel as metadata and are rendered by the coordinator or supervising Explore surface.
- `sai-1-contract-retirement`: The inactive spec invocation contract is removed from active routing and source inventories.
