> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

SAI never offered the third-party `writing-for-agents` skill, and the Explore edge-case and implementation-detail list stages did not use it. Their lists are agent input: `/sai-1-spec` and later commands consume them. Using the skill for list wording makes that input clearer. SAI must stay fully usable without the skill, and the skill must remain user-owned rather than SAI-managed (GitHub issue mmadariaga/shared-ai#78).

## What Changes

- `bin/install-flow.js` adds `offerWritingForAgentsInstall`, an injectable offer shaped like `offerCodegraphInstall` (`probe`, `selectRunner`, `runInstall`, `promptYesNo`, `isTTY`, `env`, `opencodeBase`, `notices`). `main()` calls it after the harness installs and before the CodeGraph offer, passing the selected assistants and the resolved opencode base.
- Detection (`probeWritingForAgents`) checks each selected assistant's user-global skills roots for `writing-for-agents/SKILL.md` using a symlink-following stat. For Claude Code that is `~/.claude/skills`. For opencode it is the opencode skills directory, `~/.claude/skills`, and `~/.agents/skills`. A dangling link counts as absent.
- The install command is the fixed `skills@latest add mattpocock/skills --skill=writing-for-agents` with no assistant, scope, or answer preselection. It runs through a runner mapped from `npm_config_user_agent` (`npm/` → `npx`, `pnpm/` → `pnpm dlx`, `bun/` → `bunx`) when that runner is available. Otherwise the first available of `npx`, `pnpm dlx`, `bunx` is used. The command is spawned with an argument array and inherited stdio; a shell is used only on Windows, for `.cmd` shims.
- Offer flow:
  - With a TTY, one yes/no prompt names every assistant that lacks the skill.
  - A decline, a failed install, or no available runner adds the manual command as a notice.
  - Without a TTY, only the manual-command notice is added and no process is spawned.
  - After a successful install, detection runs again and a notice names each assistant that still lacks the skill.
  - All output goes through the deduplicated `notices` list.
- New `sai/commands/explore/list-writing.md` is the single source of the load-and-warn rule. Before drafting an `E` or `I` list, the stage loads `writing-for-agents` through the harness-native skill tool, reusing a copy already loaded in the chat. When the skill is absent, unloadable, or denied, the stage prints one fixed warning per `/sai-explore` invocation and drafts with the existing rules. The skill shapes wording only.
- `sai/commands/explore/steps/review-edge-cases.md` and `sai/commands/explore/steps/implementation-details.md` now state `Use the writing-for-agents skill to create the list.` and point to `list-writing.md`.
- README documents the installer offer, the manual install command, the user-owned status (doctor and uninstall ignore the skill), and the warn-and-continue Explore behavior.
- Tests: new `test/install-writing-for-agents.test.js`. Install test expectations for both harnesses now include `list-writing.md` among the explore card files.

## Capabilities

### New Capabilities

- `installer-writing-for-agents-offer`: per-assistant detection of `writing-for-agents` and an optional, consented skills.sh install offer in the npx installer, with manual-command notices and a post-install re-check.

### Modified Capabilities

- `explore-edge-case-review`: the edge-case list stage loads `writing-for-agents` to shape list wording and warns and continues when it is unavailable.
- `explore-implementation-details`: the implementation-detail list stage loads `writing-for-agents` to shape list wording and warns and continues when it is unavailable.

## Impact

- New files: `sai/commands/explore/list-writing.md`, `test/install-writing-for-agents.test.js`
- Modified files: `bin/install-flow.js`, `sai/commands/explore/steps/review-edge-cases.md`, `sai/commands/explore/steps/implementation-details.md`, `README.md`, `test/install-claude.test.js`, `test/install-opencode.test.js`
- The OpenSpec, opencode, and CodeGraph installer offers keep their behavior. No manifest projection targets `writing-for-agents`.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
