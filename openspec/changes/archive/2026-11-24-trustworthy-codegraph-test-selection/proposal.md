> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The per-step test selection of `/sai-3-implement` was either noise or silently incomplete. `codegraph affected` at its default depth of 5 selected most of the suite. The tool trusted an index built by an older extractor because it only checked `pendingChanges` in `codegraph status --json`, and it answered `selected` with an empty list when the changed code was reached only indirectly. A step then ran only its own `Test Command`, and regressions surfaced only at Close. The selection is a trust decision, not only a list: when the graph cannot vouch for a changed file, the tool now answers `full` with a reason.

## What Changes

- `sai/tools/test-select.js select` makes one `codegraph affected --json --stdin --depth 2` call per changed file instead of one call for every file. The depth is the fixed constant `AFFECTED_DEPTH = 2`; no option or setting changes it. Each file travels alone on stdin, so the command line carries only fixed arguments.
- The per-file calls run concurrently, at most 4 at a time (`AFFECTED_CONCURRENCY`), through `codegraphAsync`, an asynchronous variant of the `codegraph()` helper that reuses the Windows supervisor that kills the process tree on timeout. `--timeout-ms` becomes one shared deadline for the per-file calls of a run; when it expires the calls still running are ended and the answer is `full` with `timeout`. Results are kept in file order, so the finishing order changes neither the verdict nor the test list.
- `stale-index` also fires when the `index` block of `codegraph status --json` reports `reindexRecommended: true`, a `builtWithExtractionVersion` different from `currentExtractionVersion`, a `state` other than `"complete"` (including `null`), `filesNeedingReindex` above 0, or `rebuildInProgress` true. When the `index` block is absent, only `pendingChanges` is checked, as before.
- A new `full` reason, `no-dependents`, lists in `files` every changed file that is not a test file and whose own call reports `totalDependentsTraversed: 0`. A changed file is a test file when its own call lists it in `affectedTests`; fixtures, mocks, and configuration count as code. The existing reasons keep priority and are checked first.
- Without a `full` reason, `selected` returns the deduplicated, sorted union of the `affectedTests` of every per-file call.
- `main` and `selectTests` become asynchronous; the tool header documents the new terms and the `no-dependents` reason.
- `no-dependents` is added to the list of `full` reasons in `AGENTS.md`, `sai/policies/tool-resolution.md`, `sai/commands/implement/coordinator.md`, and `docs/commands/sai-3-implement.md`, texts shared by Claude Code and opencode. The coordinator records it in `selection.md` and the closing report like the other reasons.
- The fake codegraph of `test/test-select.test.js` answers per file (dependents and tests of each) and returns a configurable `index` block, so the tests cover the fixed depth, the stale-index signals, the absent `index` block, `no-dependents`, test files, the union, the finishing order, and the shared deadline. `test/implement-family.test.js` follows the updated reason list.

## Request Additional Notes

Measurements behind the decisions (codegraph 1.6.4, fresh indexes, ground truth = test files that import exactly the changed file): onira-hub-backend (Java, 315 test files) depth 1/2/5 recall 36/39 each, median 2 files selected at depth 2 (max 8); onira-hub-front (TypeScript, 77 test files, e2e excluded) depth 1 18/29, depth 2 25/29, depth 5 25/29, median 1 file at depth 2 (max 33 for a widely shared file); files without dependents in random samples of 20: backend 4 and 7, front 2 and 4. Stale index values captured before the rebuild in both projects: `builtWithVersion` 1.1.6, extraction version 24 vs 29, `reindexRecommended: true`, `state: null`, `filesNeedingReindex: 0`, `pendingRefs` about 18.9k.
