## Why

Claude Code previously combined every valid model-and-effort pair into one settings list, while OpenCode used dependent selection screens. Separate Claude Code screens make navigation consistent across both supported harnesses without repeating each Claude model for every effort level.

## What Changes

- Replaced Claude Code's combined settings list with `Model for …:` followed by `Effort for …:`.
- Derived unique model choices and model-specific effort choices from the existing static Claude catalog.
- Added an explicit `Default (no effort)` confirmation for Haiku that returns `{ model: 'haiku' }`, with no `effort` property.
- Made back navigation from effort reopen model selection and recompute effort choices for the newly selected model; back from model returns to target selection.
- Preserved cancellation without saving the current selection and kept settings collection separate from persistence.
- Updated tests for separate screens, catalog validation, model-specific efforts, back navigation, cancellation, Haiku effort removal, and the twelve production choice invocations.
- Preserved OpenCode's provider/model/variant flow, Claude's catalog, and existing configuration formats.
