## Why

The current `sai-merge` presentation exposes lifecycle payloads instead of the small branch, scope, or commit decision the user needs to make, especially when many branches or staged ADR/DDR changes produce large technical context. The staged implementation moves decision-oriented context into the coordinator-owned presentation seam while preserving verification-round behavior and mutation ownership.

## What Changes

- `sai/adapters/claude/panel-render.md` and `sai/adapters/opencode/panel-render.md` define exclusive ownership and merge-specific rendering/degradation behavior for the adaptive merge TODO.
- `sai/commands/merge/coordinator.md` activates concise branch, scope, authorization, and adaptive TODO presentation without changing worker continuation or mutation ownership.
- `sai/commands/merge/instructions.md` defines date-bearing branch labels, category-filtered scope options, collision applicability, family-aware collision metadata, and compact authorization context.
- `sai/commands/merge/presentation.md` defines the concise renderer, compact authorization summary, canonical adaptive TODO transitions, panel ownership, and terminal cleanup.
- `sai/commands/merge/worker.md` carries the updated branch, scope, collision, and authorization source contracts while remaining read-only.
- `sai/policies/todo-structure.md` defines the coordinator-owned adaptive merge TODO separately from worker progress plans.
- Verification-round behavior remains unchanged; final reconciliation remains required for panel cleanup, collision metadata validation, and the updated presentation capability.

- `question-context-policy`: concise merge questions rendered with adjacent decision summaries.
- `progress-plan-declaration`: the adaptive merge TODO exception for a phase without a worker progress plan.
