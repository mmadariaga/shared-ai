## Why

The explore-stage progression state survived only in the agent's conversation context: the conversation was the sole persistence layer, and the restore-per-turn cycle cost one extra call plus snapshot JSON on every stage-event turn. The sidecar process dies each turn by design (`bin/sai-state.js` stdin-exit and parent-poll guards), so conversation-carry was load-bearing and fragile — context loss meant state loss. Making the `sai-state` sidecar the single owner of the machine state removes the agent-memory fragility and the redundant restore round-trip: state persists across process restarts, responses shrink to minimal wire outcomes, and the exploring agent stops carrying or memorizing any state JSON.

## What Changes

- `bin/sai-state.js` — the sidecar now owns the progression state as a durable store: it persists each machine's state plus a minimal per-machine ledger (`rev`, `lastEventId`, `lastOutcome`) and a record `createdAt` (record shape: `createdAt` + `stateByMachine`), seeds lazily from the session file inside the request flow that already reads it (no dedicated boot call), and reloads it automatically, so the required client cycle becomes `spawn → /emit`.
- `/emit` returns the minimal wire outcome `{stage, next, rejected?, warnings?}` — no state object and no snapshot travel on the wire in either direction; `/restore` is demoted to an optional body-less read-only probe (`{stage, next, warnings?}`) for recovery and panel re-render, and a probe on a chat with no persisted machine returns the closed-vocabulary `UNKNOWN_MACHINE` error with no state fields.
- A closed optional `warnings` attribute (first value `SESSION_FILE_CORRUPT`) piggybacks store-degradation notification on responses the agent already receives; a corrupt file is treated as absent (initial seed) and heals on the next successful persistence, while an absent file stays legal and silent.
- Session-file writes are atomic (temp file + rename); `/close` purges the persisted state and tombstones the record so reopening the same chat identifier restarts from the initial state; the same `eventId` retried after a process restart replays the persisted last outcome without re-applying (cross-process idempotency for the last event); legacy records without `stateByMachine` load tolerantly as the initial state with no version bump.
- `sai/commands/explore/instructions.md` and `sai/commands/explore/steps/common.md` — the sidecar session-lifecycle prose is simplified to the minimal `spawn → /emit` cycle: the sidecar owns the state as a durable store, the agent holds only a disposable presentation hint (never sent in requests, never authoritative), `/restore` is optional, and the conversation-only-state clause is replaced by sidecar-owned state.
- Tests: `test/sai-state.test.js` (minimal seam outcomes, store shape, atomic writes, corruption warnings, cross-process restart replay, close purge), `test/explore-stage-machine-consumption.test.js`, and `test/explore-pre-crystallization-stages.test.js` updated to the sidecar-owned-state contracts.

## Capabilities

### New Capabilities

None — this change amends two existing capabilities.

### Modified Capabilities

- `explore-stage-machine` — the machine spec's snapshot-carrying requirements are replaced by the sidecar-owned durable store: minimal wire outcomes, cross-process idempotency for the last event, session-file degradation warnings, atomic writes, and `/close` purge semantics.
- `explore-pre-crystallization-stages` — the conversation-only stage-state clause is replaced by sidecar-owned state (the machine-owned portion persists in the sidecar's temp session file; the project stays read-only), and the sidecar session lifecycle becomes the minimal `spawn → /emit` cycle with `/restore` as an optional probe.
