**Complexity**: low (4 files, menu ordering and complexity display only)
## Why
sai-commit is architecturally a routed orchestrator with a coordinator plus a worker, but the model-customization menu listed it as a utility, splitting it from sai-commit-worker across the phase/utilities separator. Separately, worker:sai-4-green-worker displayed a single up-arrow that understated its implementation task complexity relative to sibling workers.
## What Changes
- In bin/model-customization.js, sai-commit leaves UTILITY_NAMES and joins the command family so it enumerates, displays, and persists as a command target.
- In bin/model-customization.js, TASK_COMPLEXITY for worker:sai-4-green-worker changes from single to double up-arrow; the complexity key for sai-commit changes from utility:sai-commit to command:sai-commit with value unchanged.
- In bin/model-customization.js, COMMAND_WORKER_ORDER gains sai-commit mapped to sai-commit-worker, and ALL_PHASE_ORDER phase 4 becomes sai-backfill, sai-archive, sai-merge, sai-commit with the merge-to-commit tail before utilities.
- In test/model-customization-menu.test.js, test/model-customization-taxonomy.test.js, and test/model-customization-utility-source-root.test.js, fixtures pin the new utility set, the commit block after the merge block, and the updated slice offsets, identically for OpenCode and Claude Code.
- Display columns TYPE, TARGET, TASK COMPLEXITY, and SETTING stay aligned with existing setting text unchanged; provider, model, and variant selection flows are unchanged.
