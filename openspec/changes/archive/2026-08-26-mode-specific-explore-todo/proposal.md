## Why

The existing `sai-explore` TODO does not communicate which execution mode was selected during crystallization. The implemented route projection gives the active slice meaningful, mode-specific progress without claiming implementation work that did not run or duplicating review evidence.

## What Changes

The explore instruction contracts now define a temporary, coordinator-owned route projection for the selected crystallized slice. The projection replaces that slice's baseline evidence entries while preserving the research item, non-selected slices, existing ownership markers, and panel-rendering mechanism.

Auto exposes the planning-only `sai-1` and `sai-2` sequence. Auto (fast implementation) exposes the high-level `Build/Implement`, `Backfill`, and `Archive` stages while retaining its internal contractual steps. Manual and unmapped selections expose only a completed handoff and dispatch no worker. Non-clean outcomes remain pending and retryable, and route state stays conversation-only and slice-scoped.

## Capabilities

### New Capabilities

- Temporary mode-specific route projection for the selected crystallized slice.
- Auto progression from `sai-1` to `sai-2` without claiming `sai-3` or code implementation.
- Auto-fast high-level progression through `Build/Implement`, `Backfill`, and `Archive`.
- Manual handoff-only route behavior.

### Modified Capabilities

- Explore idea-list rendering now temporarily substitutes route items for the selected slice's evidence entries while preserving evidence marking semantics, panel ownership, markers, and no-stamp behavior.
- Explore selector and pipeline lifecycle contracts now retain retryable route state across non-clean outcomes and isolate state between slices.
