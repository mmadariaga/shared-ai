**Complexity**: high (4 modified capabilities, 5 requirements, no breaking change)

## Why

Successful `/sai-review` runs with no recommended audits ended even when the fresh review contained fixable findings. This change connects that branch to the existing correction choice without activating an audit.

## What Changes

- Route successful zero-audit runs with valid triage through the existing shared Direct Build close, using only freshly generated `review.md`.
- Preserve the exact zero-audit completion literal when no eligible findings remain, including existing warnings and blocked-finding explanations.
- Exclude stale, non-activated audit reports from eligibility, findings selection, and fix input; leave those reports untouched.
- Retain missing-review and wholly illegible-triage error closes, individual triage warnings, explicit selection, exclusions, fix-round limits, and existing write/local-commit authorization.
- Add five regression tests covering both harnesses, terminal preservation, stale-report exclusion, triage boundaries, and consent.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `composition-terminal-report`: condition the zero-audit terminal on correction eligibility while preserving the pinned literal.
- `conditional-audit-activation`: allow the existing correction close without activating audits or changing triage behavior.
- `review-direct-build-close`: include eligible zero-audit findings and restrict composition input to current-run reports.
- `standalone-close-selector`: keep zero-audit correction ownership with the composition, never the standalone review adapter.
