> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Losing a change's originating issue before archival deprives the existing commit-to-pull-request closing-reference flow of its input. Backfill's metadata drafting and validation previously excluded that origin, although planning already carried it. The implemented change preserves verified per-change issue identity and lets manually written child closing references contribute to parent coverage.

## What Changes

- Added a shared issue-origin preservation protocol for Claude Code and opencode. It retains the selected child's verified URL, preserves valid existing metadata, and warns without blocking when a known origin is lost, unverifiable, or conflicts with a valid existing origin.
- Connected issue intake, block creation, planning, backfill drafting and validation, Direct Build handoffs, and both archive execution routes to that protocol. Block amendments reuse validated storage operations and refresh verification hashes.
- Allowed optional validated `backlog_origin` independently of `prior_intent` in both backfill metadata forms and their ordinary and Direct Build validators.
- Added pre-move and post-move archive comparisons and warning-only checks before deriving archive commit closing lines. Changes without an associated issue remain silent; branch identifiers and ordinary `Refs` mentions do not supply completion evidence.
- Updated pull-request parent coverage to include explicit manual child closing references alongside commit-derived references, retaining manual text and duplicate suppression.
- Added contract regression checks, real archive-boundary integration fixtures for three child changes with and without prior intent, and GitHub/GitLab parent coverage, repository-separation, and repeat-update cases.

## Capabilities

### New Capabilities

- `issue-origin-preservation`: verified selected-child provenance through block, planning, backfill, and archive handoffs, with non-blocking diagnostics and existing closing-line integration.

### Modified Capabilities

- `to-pr`: manually written child closing references contribute to complete parent coverage without duplicate references or loss of manual text.
