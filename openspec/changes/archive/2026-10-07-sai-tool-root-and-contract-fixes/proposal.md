> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Three small defects surfaced in one Direct Build retrospective.

- Without `--root`, `sai/tools/check-delta-headers.js` and `sai/tools/check-cited-paths.js` resolved the project root from the script's own location. An installed copy therefore looked for `openspec/` beside the installed script instead of in the project, while the cards that call `check-delta-headers.js` pass no root and state that specs resolve from the project root.
- The worker contract did not say what a worker does with a command that is still running when it returns. Workers ended their turn with a build still in progress.
- The explore step text described recording an agreed list and advancing the stage in a way that reads as a single event. The coordinator had to read the machine source to learn they are two events.

## What Changes

- `sai/tools/check-delta-headers.js` and `sai/tools/check-cited-paths.js` use the working directory as the project root when no `--root` is passed. An explicit `--root` still wins. `--delta-dir` and `--specs-dir` combine with the root as before. Neither tool searches parent directories: run from a subdirectory, each returns its existing not-found error.
- The help text of both tools names the working directory as the default root.
- `sai/orchestration/worker-core.md`, section Nonterminal Result Transport, states that the turn ends with the result: a command that ends on its own is awaited, and a process that never ends on its own, such as a development server started for the worker's own checks, is stopped before returning.
- `sai/commands/explore/steps/common.md`, list-stages section, states that recording the list and advancing are two separate events to `explore-idea@1`, sent in that order within the same turn. The two sentences of the staged-progression paragraph that described the same-turn behavior now refer to those two events.
- `test/tool-default-root.test.js` is new. It runs both tools from a temporary project, so the working directory differs from the script location.

Known limitations accepted with this change:

- A caller that relied on the script-relative root without passing `--root` changes behavior. None was found.
- Running either tool from a subdirectory of the project fails with the tool's existing not-found error.
- The turn-end rule is wider than one sentence, because it also covers a process that never ends on its own.
- No machine behavior changes: `sai-state/machines/explore-idea.js` is untouched. No tool option is added. The calling cards (`sai/commands/backfill/coordinator.md`, `sai/commands/archive/coordinator.md`) and the invocation line in `sai/policies/tool-resolution.md` are not edited.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `delta-header-preflight`: `check-delta-headers.js` defaults its project root to the working directory.
- `cited-path-existence-check`: `check-cited-paths.js` defaults its project root to the working directory.
- `nonterminal-result-transport`: a worker's turn ends with every command it started finished.
- `explore-progression`: list-stage recording and advancement are stated as two ordered events within one turn.
