> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Agents followed the fetch skill's "once per directive" and "one call at a time" wording and loaded one file per turn, so the `/sai-explore` load in the exploring session took about 19 turns for 19 files (about 128 KB). An improvised shell loop that concatenated content overflowed the shell output limit twice and left three policies unread. The latency of a load is bounded below by the depth of nested directives, not by the number of files, so the fetch tool and the fetch skills needed a way to resolve a whole level of directives in one call and read the files in parallel.

## What Changes

- `skills/universal/fetch/fetch.js` accepts one or more subpaths (`<subpath> [<subpath> ...]`). One subpath keeps the existing output unchanged: the header, one blank line, and the content, the `too-large` line above the output cap, and the error on stderr. Two or more subpaths run in path mode: the tool prints one block per subpath argument, in argument order, entirely on stdout, and never prints file content. A resolved subpath prints a resolution block (`subpath:`, `path:`, `root:`); a failed subpath prints an error block (`subpath:`, `error:`); one blank line separates the blocks. A repeated subpath prints one block per occurrence.
- In path mode every subpath passes the scope check before any subpath touches the filesystem; a rejected or unresolved subpath does not stop the others. The exit code is 0 when every subpath resolved, 1 when at least one error block was printed, and 2 on a usage error (no subpath, missing or invalid `--harness`, unknown option), which prints no block.
- On opencode, the `opencode debug paths` fallback runs at most once per call, whatever the number of subpaths that reach it.
- `skills/claude/fetch/SKILL.md` and `skills/opencode/fetch/SKILL.md` change with the same wording apart from the harness names: the resolution table and the tool section describe the multi-subpath invocation and path-mode output, a new **Batching** section tells the agent to collect the unconditional directives without a loaded copy into one call, load the `Fetch @skills/<name>/SKILL.md` directives of the batch with the skill tool in the same turn, and read every returned `path` in parallel in a single turn. An error block stops only its own directive; a failed read of a returned `path` stops that directive with no composed or guessed path. **Path scope** states that the check covers every subpath of a call. **Recursion** replaces "one call at a time" with "the directives found in the files and skills of one batch form the next batch". **Loaded-copy reuse** counts the full read of a `path` that a multi-subpath call returned as a complete result. The line "The tool takes one subpath per call" is gone.
- `sai/policies/explore-agent.md` § Shell restriction admits the multi-subpath fetch tool form `node "<base directory>/fetch.js" --harness <harness> <subpath> [<subpath> ...]`.
- `test/fetch-tool.test.js` covers the single-subpath behavior, path-mode blocks, error blocks and exit codes, repeated subpaths, the single `opencode debug paths` call, the batch scope check, and the batching, parallel-read, conditional-directive, and loaded-copy wording of both fetch skills.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `claude-fetch-resolution`: the deterministic fetch tool accepts several subpaths and resolves them in path mode; the Claude Code fetch skill batches unconditional directives into one call, reads the returned paths in parallel, and resolves nested directives batch by batch.
- `fetch-resolution-path-scoping`: the opencode fetch skill mirrors the batching behavior, the `opencode debug paths` fallback runs at most once per call, and the scope check covers every subpath of a call before any filesystem access; a call with no subpath is the usage error.
- `fetch-loaded-copy-reuse`: the full read of a `path` that a multi-subpath call returned counts as a complete loaded copy.
