## Why

The previous emission-time rule did not bound clock reads while a worker was composing an undecided payload. This change closes that loop by requiring one authoritative clock read per returned payload.

## What Changes

- In `sai/worker-core.md` §Result Emission Time, the field order in Closed Outcomes is declared serialization order rather than composition order.
- A worker decides every other payload field, reads the clock exactly once as its final action before returning, and never re-reads for that payload.
- A read for an abandoned composition is discarded; each later returned payload, including one after a continuation acknowledgement, has its own read.
- An unavailable or failed clock read produces the valid sentinel `1970-01-01T00:00:00+00:00` instead of a failure path, with an explicit exception to the non-decreasing-values rule.
- The Milestone Stamp rationale is reanchored to the final-read ordering rule.
