## Why

People need to review a change's complete plan before implementation. Previously planning ended without a publication offer, ignored documents could remain outside commits, and explicit draft publication was limited to Azure DevOps.

## What Changes

- Added one optional draft PR/MR offer after successful `/sai-plan`, including the Explore Plan route. Planning and its run close before the offer; publication instructions load only after acceptance. Standalone spec and design keep their existing behavior.
- Added exact-current-change plan inspection and separately authorized local inclusion, including ignored documents, control files, specifications, tracked deletions and an optional overview. A private index keeps unrelated staging and working files intact.
- Extended `/to-pr` to create, reuse and explicitly convert draft requests on GitHub and GitLab alongside existing Azure DevOps support. Approval binds draft state; readback and read-only recovery must verify it.
- Kept publication on the change branch, disclosed its full committed changes, and preserved independent remote approval, non-force push and uncertain-outcome recovery.
- Updated shared instructions, manifest permissions, provider references, user documentation and tests for both Claude Code and opencode.

## Capabilities

### New Capabilities

- `plan-artifact-publication`: Exact authorized inclusion of the complete current-change plan without incorporating unrelated work.

### Modified Capabilities

- `plan-command`: Successful planning closes its report and run before a single optional publication offer.
- `to-pr`: Three-provider explicit draft publication and conversion, verification, and the narrow authorized plan inclusion exception.
