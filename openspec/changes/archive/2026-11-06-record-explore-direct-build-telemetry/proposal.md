## Why

The `/sai-explore` Direct Build - Unattended route recorded no change telemetry: the collector found an in-session route only through a worker that wrote under `openspec/changes/{name}/` (`sai/tools/change-telemetry.js:189-213`), while Direct Build writes through transfer files and git, and the change folder is already archived when the route collects. Its single local commit is built by the archive worker from a closed path order (`sai/commands/archive/worker.md:122-169`), so a telemetry file written after Step 8 needs a second pre-authorized local commit, and its fix loop kept no per-round finding tallies (`sai/commands/explore/direct-build-coordinator.md:61`).

## What Changes

- `sai/tools/change-telemetry.js` discovers a Direct Build slice through the route's workers: the window starts at the slice's first route worker, a slice begins after the last backfill or archive worker that named a different change, a replaced worker of the current slice stays in, and a POC implementer whose session carries `--no-specs` is excluded.
- The collector treats any tool input naming the change path as a touch, because Direct Build workers write through `transfer.js materialize` and git in shell calls rather than a write tool.
- The collector resolves the change folder to the active `openspec/changes/{name}/` or, when that is absent, the latest archived `openspec/changes/archive/YYYY-MM-DD-{name}/`, and writes `telemetry.md` there.
- Direct Build's Implement findings come from `reviews/implement-round-{k}.md` under the `--run-dir` directory: found counts from the first round and pending counts from the last. Backfill and Archive report `unavailable`.
- The Direct Build coordinator opens the slice's run directory with `temp-root.js mkdtemp`, writes each fix-loop pass to `reviews/implement-round-{k}.md` with its snapshot identifier in `reviews/implement-round-{k}.tree` and a closing `Summary: High=<n> Medium=<n> Low=<n>` line counting open findings, passes `--run-dir` to the collector, and removes the run directory at accepted closure.
- `sai/policies/change-telemetry.md` replaces the writing-worker window with the slice-worker window and the archived-folder gate; `sai/policies/tool-resolution.md` lists the four `collect` commands; `docs/project-settings.md` documents the archived folder and the slice window.
- The `telemetry.md` header names the `/sai-explore` in-session routes.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `change-telemetry`: the collector accepts the archived change folder, discovers a Direct Build slice through its route workers, and reads Direct Build Implement findings from run-directory round files.
- `direct-build-reviews`: each functional fix-loop pass is written to the slice run directory with its finding states, snapshot identifier, and `Summary:` tally.
- `review-round-summaries`: a Direct Build fix-loop round file carries the same base-form `Summary:` tally as a plan round file.
- `explore-pipeline-supervision`: the Direct Build run state includes the slice run directory and its round files, opened before dispatch and removed at accepted closure.
