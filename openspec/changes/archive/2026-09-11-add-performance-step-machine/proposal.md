## Why

`sai/commands/performance/coordinator.md:29-39` is one of the two audit coordinators still carrying a hand-written pointer table and continuation prose. Spec, design, implement, review, and security already route through `sai-state` step machines. Moving performance's routing to a registered step machine (`performance-standalone@1`) brings it into parity with the machine-routed coordinators and consolidates routing data into registered machines rather than coordinator prose.

## What Changes

- **New file:** `sai-state/machines/performance-standalone.js` — a data module built by the linear-step factory that owns stateful stage routing for standalone performance runs and chained performance segments in `/sai-review`. Declares five steps: `resolve-performance-scope` (fileless), `map-stack-hot-paths`, `audit-performance-tiers`, `resolve-diagnostics`, `close-performance-outcome`.

- **Updated file:** `sai-state/registry.js` — registers `performance-standalone@1` machine alongside existing standalone machines (spec, design, implement, review, security).

- **Updated file:** `sai/commands/performance/coordinator.md` — replaces the static `step_pointer_map` table (lines 29-39) with a `step_machine: performance-standalone@1` declaration. Adds a fetch for `@sai/policies/stage-machine.md` to own continuation behavior. Updates the `replacement_reconstruction_fields` documentation to reference the step machine instead of the static map.

- **Test updates:** Modified `test/linear-step-machines.test.js`, `test/performance-coordinator-worker.test.js`, and `test/step-machine-wiring.test.js` to include performance-standalone@1 in machine registration and discovery validation tests. A six-coordinator discovery scenario is added to step-machine-wiring-verification.

## Capabilities

### New Capabilities

- **performance-standalone-loading** — Performance's step machine governs every activation of the performance adapter, direct (`/sai-7-performance`) and chained (as an audit segment of a chained `/sai-review` invocation). No shared sessions or state exist between activations.

### Modified Capabilities

- **performance-step-gated-delivery** — Static step pointer map is replaced by step machine architecture. Pointer continuations are now delivered through the step machine via `@sai/policies/stage-machine.md`.

- **coordinator-step-pointers** — Performance moves from the static-map list to the step_machine list, joining implement, review, and security in the two-routed-phases requirement.

- **step-machine-wiring-verification** — Performance coordinator discovery and validation now includes performance alongside spec, design, implement, review, and security (six coordinators total).
