## Why

GitHub Project auto-add can insert a newly created issue after publication checks membership but before it sends its own insertion. The resulting `Content already exists` response previously stopped publication even when the requested membership had been established. This required manual recovery and further approvals.

## What Changes

- Single-issue publication and recovery, set publication, and approved set continuation now share the same membership check, insertion, and verification operation.
- Only the specific `Content already exists` insertion error permits fresh issue-side membership verification. Structured GraphQL errors must all have the exact duplicate message and no conflicting mutation path; command errors must match the bounded duplicate response form.
- Confirmed membership in the requested Project completes the operation. Failed reads or unconfirmed membership retain partial results, pending insertion, and existing issue identities for recovery. Unrelated errors remain failures.
- The shared GitHub provider instructions describe this behavior for Claude Code and opencode without adding publication or continuation approval.
- Regression coverage exercises concurrent insertion, delayed visibility, wrong-Project membership, failed reads, unrelated errors, and recovery or continuation without duplicate issue creation.

- `backlog-slice-lifecycle`: GitHub set publication and approved continuation use the same verified concurrent-insertion recovery while retaining partial results.
