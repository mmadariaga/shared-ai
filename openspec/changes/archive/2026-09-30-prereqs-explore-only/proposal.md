> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Roughly 15 surfaces loaded the OpenSpec prerequisite policies, so workers re-ran `prereqs.js` after `/sai-explore` had already run it (the spec worker ran it twice in a row). The fix-loop also found that `sai/policies/tool-execution-permissions.md` § Status still listed `prereqs.js` after the `sai-status` allowlist dropped it, so the doc now names two node tools.

## What Changes

- `/sai-explore` stays the only command that runs the prerequisite check (`prereqs-check.md` + `prereqs-paths.md`, `prereqs.js`).
- Prerequisite loads and restated halt literals are removed from the apply `invocation.md`, the `pr` and `status` bodies, the archive, backfill, and meta-review coordinators, the design, implement, review, security, performance, accessibility, and spec worker cards, and the meta-build coordinator wording.
- Files that still need the artifact path table fetch `@sai/policies/prereqs-paths.md` directly under an "Artifact paths" heading.
- `sai/policies/prereqs.md` is deleted and recorded as a retirement (`retired-policies-prereqs`, both harnesses) in `sai/install-manifest.json`.
- The `prereqs.js` allowlist entries are dropped from `commands/claude/sai-status.md`; `tool-execution-permissions.md` § Status now lists two node tools.
- The commit and merge coordinator exemption notes become an "OpenSpec independence" note that no longer names `prereqs.md`.
- `AGENTS.md` § Prerequisite check and the affected tests (apply, design, implement, install-claude, install-opencode) are updated.
- Accepted risk: a project that never runs `/sai-explore` and lacks `schema: sai-workflow` or the CLI gets OpenSpec's native error or default templates, with no substitute notice.

## Capabilities

### New Capabilities
- `prereq-check-ownership`: `/sai-explore` alone owns the OpenSpec prerequisite check; other commands run none; `prereqs-paths.md` stays the path table.

### Modified Capabilities
- `routed-archive-command`: coordinator loads only the artifact path table.
- `routed-backfill-command`: coordinator loads only the artifact path table.
- `routed-commit-command`: independence of OpenSpec, no prereqs.md reference.
- `prereqs-composition-compatibility`: all requirements removed (prereqs.md retired).
- `sai-review-command`: no composition-start prerequisite run.
- `security-phase-worker`, `accessibility-phase-worker`, `review-phase-worker`: workers gate only on proposal.md.
- `thin-command-surface`: status body carries the path table, not prerequisite checks.

## Impact

Modified: `AGENTS.md`, `commands/claude/sai-status.md`, `sai/commands/{accessibility,design,implement,performance,review,security,spec}/worker.md`, `sai/commands/{archive,backfill,commit,merge,meta-build,meta-review}/coordinator.md`, `sai/commands/apply/invocation.md`, `sai/commands/pr/body.md`, `sai/commands/status/body.md`, `sai/install-manifest.json`, `sai/policies/tool-execution-permissions.md`, and five test files under `test/`. Removed: `sai/policies/prereqs.md`.

Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
