## Why

The to-pr workflow fixed GitHub and GitLab in adapter selection, host recognition, and instruction loading. The implemented refactor makes the existing provider registry select these resources, allowing the extension point to be reviewed independently of a later provider feature.

## What Changes

- Select provider adapters from registry entries instead of a fixed provider identifier list.
- Use registry host metadata for the existing unknown-host clarification check, including an explicit `gitlab.com` host entry.
- Load the supplied registry for every CLI operation and use it for destination inspection, request queries, publication, and recovery.
- Validate adapter and instruction references before loading the selected adapter.
- Load only the resolved instruction reference, relative to the existing to-pr skill directory.
- Extend tests with a synthetic registry entry, unsafe-reference rejection, supplied-registry enforcement, destination precedence, and unknown-host clarification.
- Retain regression tests for GitHub/GitLab create and update, separate authorization checks, recovery without another publication, explicit skill invocation, and Claude Code/opencode installation and tool access.
- Register no additional publication provider.

None.

### Modified Capabilities

- `provider-resolution`: registry-backed host recognition, adapter selection, and conditional instruction loading for the existing to-pr workflow.
