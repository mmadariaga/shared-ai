> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Pre-crystallization Explore spent far more executor dispatches than needed to settle a single investigation question: in one session it sent 11 dispatches where about 4 were enough. Reads were chained one per dispatch, access credentials were guessed, and a result that already answered the question was not reported. Because the executor contract stops on the first failure and allows no retries or workarounds, every unplanned failure cost a full round trip.

## What Changes

- Added the policy `sai/policies/investigation-batch.md`, which governs how pre-crystallization Explore plans, groups, caps, and closes executor dispatches for one investigation question:
  - Explore names the investigation question, lists every command it needs, and sends every independent command in one investigation batch instead of chaining independent reads one per dispatch.
  - Each command that can plausibly fail carries a pre-planned fallback inside the same batch as a single conditional shell command (`primary || fallback`), so the executor still runs exactly the commands it is given.
  - Only known access data is used: an unknown credential, tenant, or base URL is obtained from project configuration or seed data through a command in the batch, or requested from the user, and never guessed.
  - The dispatch cap is 2 executor dispatches per investigation question. A dependent dispatch is allowed and counts toward the cap; an identical-prompt retry after a transport failure does not.
  - A failed fallback command is reported like any other failure, and the executor adds no retries beyond those written in the batch.
  - When a result settles the question, Explore reports the answer in its next reply and sends no further dispatch for that question.
  - When the cap is reached without an answer, Explore stops dispatching, reports what is established and what is missing, and asks through the native picker whether to continue; an approved continuation starts with a fresh dispatch cap.
- Added a directive to the Behaviors section of `sai/commands/explore/body.md` that fetches the new policy before the first executor dispatch of pre-crystallization Explore.
- Executor use outside pre-crystallization Explore (Direct Build gates, the POC lane, other commands) and `sai/policies/executor-agent.md` are unchanged; the change touches only shared sources under `sai/`, so Claude Code and opencode receive the same behavior.
