> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

A second `/sai-explore` invocation in the same chat reused the spawned session with its old stage and agreed lists, although the chat-start rule promises a fresh idea list (`sai/commands/explore/body.md`, `sai/commands/explore/steps/common.md`). `sai-state spawn` with the same key returns the existing session, so nothing reset the state on a new invocation. Separately, ADR 0137a still stated that clear natural-language stage intent advances the progression, while the `explore-idea@1` machine advances only on the `next-step` intent.

## What Changes

- `sai/commands/explore/body.md` (load section): on an invocation turn (a user message that runs `/sai-explore`), the load runs `sai-state reset <id> explore-idea@1` and `sai-state reset <id> explore-slice@1` right after `sai-state spawn`. The invocation starts from the initial stage, empty lists, and no slice inventory, even when the chat holds the receipt of an earlier invocation.
- The same rule states that a parked Direct Build resumes only inside the invocation that parked it; a new invocation discards its parked cursors with the rest of the state.
- A recovery load (a turn that is not an invocation, lacks the load receipt, and completes the load before answering) runs `spawn` only and keeps the current stage, the agreed lists, and the slice inventory.
- New ADR `docs/adr/0197-next-step-is-the-only-stage-advancement-keyword.md` **Amends** ADR 0137a: `next-step` is the only stage-advancement keyword, and the 0137a sentence "Clear natural-language stage intent also advances the progression" is retired for every stage. At a list stage, a bare `next-step` or the user's explicit confirmation of the proposed list records the list and then advances, as two ordered events in the same turn. The rest of 0137a and ADR 0196 stand.
- `docs/adr/0000-INDEX.md` lists ADR 0197 under the `/sai-explore` group, under the `Explore crystallization & the review loop` category, and in the `ADRs that extend or correct prior ones` table as amending 0137a.

## Capabilities

### New Capabilities

- None

### Modified Capabilities

- `explore-load-receipt`: the load distinguishes an invocation from a recovery load, resets both explore machines on an invocation, and keeps the slice inventory on a recovery load.
- `explore-slice-machine`: a parked Direct Build cursor is resumable only inside the invocation that parked it; the invocation reset discards it.

## Impact

- New files: `docs/adr/0197-next-step-is-the-only-stage-advancement-keyword.md`
- Modified files: `sai/commands/explore/body.md`, `docs/adr/0000-INDEX.md`
- Accepted trade-off: a parked Direct Build cannot be resumed after a new invocation in the same chat; its work stays on disk and is resumed manually.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
