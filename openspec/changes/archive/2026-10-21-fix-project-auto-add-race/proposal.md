## Why

GitHub can return `Content already exists in this project` when Project auto-add wins a race with publication. The duplicate detector rejected this observed response before checking membership, producing avoidable partial failures and extra confirmations even when the issue was already in the requested Project.

## What Changes

- Extended the shared `ensureMembership` duplicate detector to recognize both exact duplicate messages in structured GraphQL errors and command-line errors.
- Retained operation-specific structured error checks, repeated `gh:` prefixes, and the optional ` (addProjectV2ItemById)` suffix. Mixed or unrelated errors remain failures.
- Reused existing fresh destination-membership verification and its retry bound for individual publication, set publication, and approved continuations. Recognition alone does not establish membership.
- Extended regression coverage for accepted message forms, verified membership, partial results, preserved issue identities, continuations, and unrelated failures. Successful ordinary race resolution does not consume the separate automatic recovery allowance.
