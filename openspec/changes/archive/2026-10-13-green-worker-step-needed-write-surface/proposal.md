> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

A plan that omitted a production file its Step needed stopped the apply run. The GREEN worker contract limited the worker to the production files the plan authorized, while plan amendment fires only after a worker has already written and reported the omitted file. A worker that obeyed its contract therefore never wrote the file, and the amendment written for that case was never reached.

## What Changes

- `sai/commands/apply/green-worker.md` § Allowed files now defines the GREEN write surface as the production files the Step needs to pass its verification. The plan's file list, and the production allowed files named in the task disclosure, are the expected set and a prediction, not the boundary of the write surface. When the Step cannot pass without a production file the plan omits, the worker writes that file.
- The same section requires the worker to report every file it wrote in report field 8, and each file outside the plan's list also under Deviations (field 5), with the path and the reason the Step needs it. The coordinator verifies an unplanned file and amends the plan.
- Test files and `interfaces.md` stay outside the write surface. The `blocking-contradiction` return now names both cases explicitly: passing needs a change to a test or to `interfaces.md`. A `continue_after_recovery` continuation still never creates or modifies a test file or `interfaces.md`.
- `sai/commands/apply/steps/plan-amendment.md` states that the existing verify trigger is the only route by which an unplanned production file enters the plan. No trigger and no continuation are added.
- `test/apply-coordinator-verification.test.js` asserts the new contract wording: the write surface sentence, the reporting sentence, and the test and interface exclusion.

Accepted limitation: a budget-tier model may widen a Step on its own judgment. The bounds are the Step's own verification, the unchanged test and interface prohibitions, and the coordinator's existing judgment at the verify trigger that the file is one the Step needs.
