## Why

The `new-change-branch` skill never ran `git fetch`, so every remote option in the branch-base question (for example `origin/master`) carried a "possibly outdated" note. The user could not trust a remote reference as a base, and the warning appeared on every run. No decision record justified the no-fetch rule; the archived proposal only stated it.

## What Changes

- `sai/tools/new-change-branch.js`: `inspect` lists the remotes with `git remote` and runs `git fetch --prune <remote>` once per remote, after the HEAD and merge/rebase checks and before it lists references. Each fetch runs without interaction (`GIT_TERMINAL_PROMPT=0`, ignored standard input, SSH BatchMode only when no `GIT_SSH_COMMAND` or `core.sshCommand` is configured) with a 30-second limit per remote; reaching the limit is a failure with reason `timeout`.
- The `inspect` result adds `fetch: {status: updated|partial|failed|none, failed: [{remote, reason}]}`, where `none` means no remotes and `reason` is the first line of the Git error. A failed fetch never blocks inspection or creation.
- `inspect` accepts `{fetch: false}`, which runs no fetch and keeps the HEAD and merge/rebase checks; `base` and `create` never fetch, so the unchanged-SHA check still holds.
- `skills/universal/new-change-branch/SKILL.md`: runs `inspect` once per base question (a repeated question or a later page reuses the list), passes `{"fetch": false}` when the invoking workflow supplies the base, marks as possibly outdated only the options of a remote in `inspect.fetch.failed` with one warning naming that remote and its reason, carries the `inspect.fetch` warnings in the prepare-without-creating mode, and removes fetch from the excluded Git operations with a note that prune removes remote-tracking references only, never branches.
- `test/new-change-branch.test.js`: the `without fetching` instruction assertion is replaced, and helper tests against local bare-repository remotes cover a successful fetch, an unreachable remote, a partial failure, a repository without remotes, a prune that removes a reference, untouched local state, and `{fetch: false}` with `base` and `create` running no fetch.
- `docs/commands/new-change-branch.md`, `docs/backlog-commands.md`, and `AGENTS.md`: the "never fetches" statements describe the new refresh behavior.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `new-change-branch`: `inspect` refreshes every remote with `git fetch --prune` before the base question, reports per-remote failures without blocking creation, and skips the refresh when the base is supplied; the base question warns only for options of remotes that could not be refreshed.
- `change-branch-creation`: base preparation for a caller returns the `inspect.fetch` warnings with the first page and allows the remote-tracking refresh as its only repository change, still creating no branch and changing no local branch, working tree, or index.
