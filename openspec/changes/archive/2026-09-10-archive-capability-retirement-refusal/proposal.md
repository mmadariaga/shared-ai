## Why

When a change delta removes every requirement from an active capability with no replacement added for that capability, `openspec validate <change>` passes as clean because it only checks delta well-formedness. However, the mutation step `openspec archive` runs, rebuilds the spec in memory, validates the rebuild against scenario-preservation rules, and fails at that point—leaving the user with a late error. The error's fix hint points to `openspec validate <capability>`, which inspects the unchanged published spec (since archive wrote nothing) and returns green, creating a false lead. Meanwhile, SAI already owns a dedicated capability-retirement path at `/sai-retire-docs` with a per-candidate confirmation gate, but the archive contract never mentions it. A read-only pre-flight check closes this gap by detecting the capability-emptying delta shape before any mutation and refusing early, naming the existing retirement path and asking the user to reshape the change as ADD-only.

## What Changes

- **`sai/commands/archive/instructions.md`** - Added a new "Capability-emptying delta refusal" section documenting the refusal behavior, the delta shape that triggers it, the supported retirement pattern (ADD-only changes with the old capability moved through `/sai-retire-docs`), and an explanation of why `openspec validate <capability>` is not evidence of correctness.
- **`sai/commands/archive/worker.md`** - Added the capability-emptying delta assessment to the list of read-only pre-flight checks, alongside the existing missing-main-spec assessment; added the exact stop-text pattern for when the check detects an emptying delta, naming `/sai-retire-docs` as the owning path and requesting reshaping as ADD-only.
- **`test/direct-build-archive-ordering.test.js`** - Added a contract test asserting that the archive worker and instructions document the refusal behavior, delta shape, retirement path, and the false-lead explanation for `openspec validate`.

## Capabilities

### New Capabilities

- **Archive capability-emptying delta refusal**: The archive command must detect at pre-flight (read-only, before any mutation) when a change delta's REMOVED section names every requirement currently published for a capability with no ADDED section for that same capability, refuse with a stop-text that names `/sai-retire-docs` as the path that owns capability retirement, and request reshaping as ADD-only. The refusal must explain that `openspec validate <capability>` will return green and is not evidence, because archive's pre-flight refusal stops before any write, leaving the published spec unchanged. Capability retirement itself remains owned by `/sai-retire-docs` with its per-candidate confirmation gate; archive gains no move or delete power under `openspec/specs/**`.
