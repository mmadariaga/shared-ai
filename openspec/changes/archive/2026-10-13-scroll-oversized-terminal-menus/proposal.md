## Why

Issue #72 reports repeated model-customization menus on Windows when the menu exceeds the terminal height. The shared navigator previously accounted for the previous frame's physical rows without bounding its frame by terminal height. The implementation now limits the visible frame and keeps the highlighted option visible.

The suspected cursor-redraw limitation remains a hypothesis. Actual terminal reproduction and verification on Windows and Linux are pending; this record does not declare the issue resolved.

## What Changes

- Bound shared navigator frames by the terminal height, reserving a final cursor row when the terminal has more than one row.
- Preserve the complete frame when it fits; otherwise scroll a contiguous visible portion of the option list as the cursor moves.
- Count wrapped lines and embedded newlines when budgeting frame height.
- Prioritize the highlighted option by reducing auxiliary headers first, then instructions, then the title when necessary.
- Clip an option that exceeds the available physical rows while preserving its leading cursor and text.
- Recalculate the view on resize, clear the visible screen, and establish a new drawing origin rather than seeking old rows.
- Remove resize handling when the navigator settles.
- Add simulated-terminal regression coverage for fitting menus, scrolling, wrapping, screen redraw, resizing, one-row windows, offscreen selection, and cleanup.
