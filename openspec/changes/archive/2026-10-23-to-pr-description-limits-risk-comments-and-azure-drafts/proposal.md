## Why

Oversized Azure PR descriptions previously passed local checks and failed during publication. Explicit requests to create or convert Azure PRs to draft were not represented in the payload, and Inherent Risk had no supported comment alternative when it contributed to overflow.

## What Changes

- Added final composed-description validation in query preparation and publication: Azure accepts 4000 UTF-16 units and reports provider, length, limit and excess on overflow.
- Added an optional author-selected, overflow-only placement of the complete unchanged Inherent Risk block in a managed comment across GitHub, GitLab and Azure DevOps. Final descriptions must still fit the accepted limit, including generated closing references. Original overflow evidence uses authored text before generated references and is bound to approval.
- Extended complete proposal approval to the selected risk allocation, comment content, authenticated author, destination, baseline and explicit Azure draft state.
- Added provider comment reads, unique marked-author identification, in-place comment updates, full readback and separate PR/comment receipt outcomes. Pending-comment-only resume requires exact fresh approval after read-only recovery; uncertain submissions cannot be blindly retried.
- Added explicit Azure draft creation/conversion, omission when unrequested and separate draft-state verification. Shared instructions and docs apply equally to Claude Code and opencode.
