## Why

The repository delivers behavior through prompts, instructions, policies, and command contracts as well as executable code. The staged implementation replaces the narrow Direct Build file allowlist, which misclassified those instruction sources as non-code, with a repository-artifact scope that accepts any required format while preserving protected update protocols.

## What Changes

- Adds the shared policy `sai/policies/repository-artifact-scope.md` defining repository-artifact scope and protected protocols for published OpenSpec specs and historical ADR/DDR records.
- Updates `sai/commands/explore/direct-build-worker.md` to use the shared scope, permitting any required artifact while forbidding direct published-spec edits.
- Updates `sai/commands/explore/steps/pipeline-direct-build.md` delegated-write description to apply the shared rule to the implementer.
- Updates `sai/commands/apply/worker-common.md` so RED and GREEN reference the shared protected-surface rule while retaining role-specific file boundaries.
- Updates `sai/commands/implement/worker.md` to reference the shared rule as planning reference without widening its planning write surface.
- Updates `sai/commands/meta-build/coordinator.md` to preserve protected protocols across both inherited segment adapters.
- Updates `test/direct-build-schema-writes.test.js` to assert repository-artifact scope, protected protocols, and delegation instead of the schemas-only boundary.

## Capabilities

### New Capabilities

- `repository-artifact-scope`: shared protected-surface rule defining general artifact scope, OpenSpec and ADR/DDR update protocols, and role-specific retention.

### Modified Capabilities

- `direct-build-schema-scope`: schemas-allowed implementer boundary broadened to repository-artifact scope with updated contract tests.
- `auto-fast-implement-worker`: code-only write containment broadened to shared artifact scope with retained exclusions.
