## Why

Crystallization previously named `start-pipeline` only in prose while the contract prohibited offering it through a picker. Delegated `sai-1` and `sai-2` execution was therefore discoverable only to users who already knew the token. The implemented selector makes the choice explicit at handoff close while preserving explicit authorization for delegated writes.

## What Changes

The literal `start-pipeline` trigger is replaced by a localized two-option selector emitted after every crystallization handoff and keep-window reminder. `Auto` is the sole authorization for the existing supervised `sai-1` and `sai-2` lifecycle; it dispatches from the latest crystallization set and preserves worker ownership, review rounds, chaining, and retries. `Manual` dispatches nothing, closes with the `review-loop` reminder, and remains re-invocable. Review navigation remains a picker-free standing invitation. Fast-track does not auto-select delegated execution. Existing capability specifications, glossary terminology, ADR indexing, the decision record, and selector tests were synchronized with the implemented behavior.

## Capabilities

### New Capabilities

- `explore-pipeline-selector`: Replaces the literal pipeline token with an explicit Auto/Manual crystallization-close selector.

### Modified Capabilities

- `explore-context-isolation`: Makes Auto the explicit authorization for delegated writes.
- `explore-pipeline-token`: Retires the obsolete literal-token supervision contract.
- `explore-crystallization-block`: Closes crystallization with the review reminder and selector.
- `explore-pipeline-supervision`: Reuses the existing supervised lifecycle under Auto selection.
- `explore-crystallization-language-gate`: Localizes selector controls while preserving literals.
- `explore-overview-language-gate`: Scopes overview-language forwarding to Auto supervision.
- `supervised-pipeline-forwarding`: Binds language forwarding to selector-dispatched execution.
- `pipeline-phase-transition`: Makes Auto the invocation boundary for phase transition.
- `pipeline-design-phase-chaining`: Retains chained design behavior under Auto supervision.
- `pipeline-question-autonomy`: Scopes autonomous worker answers to Auto selection.
- `explore-idea-list`: Separates review tracking from latest-turn selector dispatch.
- `review-loop-navigation`: Keeps review navigation picker-free beside the execution selector.
