## Why

The overview-language question fired at crystallization before mode selection although only the supervised Auto branch consumes its value: Auto (fast implementation) never generates change-overview.md, and Manual forwards nothing because `sai-1-spec` neither parses nor re-forwards it. Asking there was noise on two of three selector branches and interrupted a decision it could not inform. Relocating the ask to supervised Auto activation makes every question produce a value that is actually used; Manual users keep the later opt-in via `--overview-lang` on `/sai-2-design`.

## What Changes

- `sai/commands/explore/instructions.md`: gate 9 no longer runs at Crystallize entry — the Crystallize sequence is slicing → crystallization language gate (item 8) → blocks; gate 9 instead asks once per crystallized idea or slice set immediately after deterministic selection confirms a dispatchable change in a supervised Auto run, before the first spec-worker dispatch. Items 5/6/7 drop the emission-time gate; the `**Overview language**` template line renders only an explicit `--overview-lang` option value or the literal `None`, and printed blocks are never retro-edited. The gate's fast-track/suppression/persistence matrix is rewritten: fast-track resolves the literal `None` without asking including at Auto activation; explicit `--overview-lang` suppresses the ask in every mode (documented no-op under Auto (fast implementation)); resolution is chat-scoped per crystallized idea or slice set and survives failed or cancelled attempts. A new "Gate 9 at Auto activation" block fixes the exact timing under item 10, non-dispatchable selection outcomes end before the gate, and the `overview_language` state variable plus the chained design-envelope persistence paragraph are redefined accordingly.
- `sai/commands/explore/body.md`: overview-language validation now states that with the option absent, gate 9 may later resolve the value "at a supervised Auto activation" instead of "during crystallization".
- `AGENTS.md`: the `sai-explore` fast-track opt-out entry additionally skips the overview-language ask at a subsequent Auto activation with `overview_language` resolving to `None`; an explicit `--overview-lang` still suppresses the ask in every mode and stays a documented no-op under Auto (fast implementation).
- `test/explore-pipeline-selector.test.js`: the E8 payload assertion accepts the new `<explicit --overview-lang option value or literal None>` placeholder form ("option value" alternative added to the regex).
- Implemented behavior not named in the supplied intent: the suppressed-gate design-envelope example now carries the `--supervised` marker (`arguments_value: "{name} --fast-track --supervised --overview-lang {overview_language}"`).
