> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation. It describes a decision already made, not one being proposed.

## Why

The routed apply architecture dropped the documented fast-track branch auto-stay and session-scoped commit authorization behaviors. As a result, fast-track apply runs re-asked the branch and commit gates instead of applying their documented opt-outs. The backfill interview also rendered each open-ended question twice because its delivery mechanism was not explicit.

## What Changes

- Restore the session-scoped commit authorization flag and its fast-track pre-activation in the routed apply invocation card.
- Restore fast-track branch auto-stay on a non-detached current branch, with interactive fallback for detached HEAD.
- Point the apply documentation at the current implementation plan template for the branch-selection and branch-base prompts.
- Pin fixed and adaptive backfill interview questions to one ordinary free-text conversation emission without option-picker routing.
- Ignore `.tmp` scratch content through `.gitignore`.

## Capabilities

### New Capabilities

None. The implementation restores and clarifies existing capabilities.

### Modified Capabilities

- `commit-auth-gate`: the routed apply invocation now defines the session flag lifecycle, fast-track pre-activation, two-gate scope, and safety boundaries.
- `commit-rules`: the documented session-scoped authorization now has an explicit apply command home.
- `sai-fast-track-flag`: fast-track again auto-stays on the current branch when possible and pre-activates apply commit authorization.
- `sai-apply-branch-prompt`: apply documents the current three-option prompt and its detached-HEAD and branch-base behavior.
- `apply-routed-card-set`: the invocation card contains the restored apply fast-track gate contracts.
- `apply-coordinator-ownership`: the coordinator-owned commit gates now include session-flag handling while retaining mandatory reports and safety stops.
- `backfill-interview`: fixed and adaptive questions are emitted exactly once as ordinary free text.
- `backfill-sequential-interview`: sequential interview ordering and response waits now use the pinned free-text delivery mechanism.

## Impact

- **New files**: none in the implemented diff.
- **Modified files**: `.gitignore`, `sai/commands/apply/invocation.md`, `sai/commands/backfill/instructions.md`.
- **Out of scope**: `design.md`, `tasks.md`, `implementation.md` — not generated by `/sai-backfill`
