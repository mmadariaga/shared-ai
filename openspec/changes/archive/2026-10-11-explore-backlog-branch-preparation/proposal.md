## Why

Explore previously moved directly from displaying the crystallized proposal to implementation route selection. Users need an opportunity to capture the work in their backlog and prepare a local branch before choosing how to implement it.

## What Changes

- Offer backlog creation or update through the existing `to-backlog` skill, then local branch creation and switching through the existing `new-change-branch` skill, after displaying every crystallized proposal block.
- Present each optional question explicitly with Yes, No, and free-text support in Claude Code and opencode, including under `--fast-track`.
- Keep both questions and the existing implementation route picker in `sai/commands/explore/steps/route-selector.md`, delivered together through the existing state-machine `next.follow` pointer.
- Wait for each accepted skill to finish, or for the user to explicitly skip its action, before proceeding. Keep unresolved replies and unavailable skill access pending.
- Track action completion once per crystallized proposal set in conversation state; preserve it across picker retries and later slices, and reset it when a new crystallization replaces the set.
- Preserve skill-owned confirmations, naming, destination and base selection, errors, and cancellation handling. Permit only user-authorized local branch creation and switching through the branch workflow, without production code edits.
- Replace stale same-turn route-picker rules with references to the shared crystallization close and selector completion gate.
- Update documentation and regression coverage for joint delivery, ordering, reply handling, both harnesses, fast-track questions, and explicit implementation selection.

## Capabilities

### New Capabilities

- `explore-pre-route-actions`: Sequenced optional backlog and local branch workflows before implementation route selection.

### Modified Capabilities

- `explore-instruction-delivery`: Joint deferred delivery of optional questions and the route picker, with a scoped local branch workflow exception.
- `explore-crystallization-block`: Shared crystallization close starts optional actions after displaying the complete block set instead of requiring an immediate route picker.
- `deferred-selector`: Deferred picker presentation waits for optional action completion while retaining explicit later-turn route selection.
- `explore-slice-machine`: Selector-pointer guidance includes the optional actions without changing machine state, pointer delivery, or route activation semantics.
