> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

**Complexity**: medium (many files, no breaking user API, two machines + pin lift).

## Why

After sidecar-owned persistence, explore still kept post-crystallize TODO and slice cursor in conversation. A second machine is needed for Direct Build and Plan lists without falling back to the first machine, and `bin/sai-state.js` still pinned the first emit (`VERSION_MISMATCH` on a second `machineId`).

## What Changes

- Host `explore-slice@1` as the post-crystallization machine combining slice inventory (`set` / `active` / `done`) and Direct Build TODO (`mode` + `stage` cursor).
- Rename `explore-stage@1` to `explore-idea@1` (file `explore-stage.js` → `explore-idea.js`) with no alias.
- Lift the one-machine session pin so `explore-idea@1` and `explore-slice@1` can emit in the same chatId; crystallize does not `/close`.
- Require `machineId` on every `/emit` and `/restore`; omitted id is `INVALID_EVENT`, unknown id is `UNKNOWN_MACHINE`, version-only mismatch is `VERSION_MISMATCH`; nothing falls back to the first persisted machine.
- Direct Build cursor travels in `stage` (`build-implement` → `backfill` → `archive` → `idle`); completing Archive marks the slice done and clears `active`. Direct Build never uses `next-slice`.
- Plan and Manual close a slice with `next-slice` (same recognition rule as `next-step`); that table stays prose in this change. Slice names come from Ready to Propose blocks, not the wire.
- Glossary **State Machine Sidecar** now names `explore-idea@1` and `explore-slice@1`.
- Empty-inventory Direct Build uses anonymous active name `current` (scope drift, implemented).

## Capabilities

### New Capabilities

- `explore-slice-machine`: post-crystallize combined inventory and Direct Build TODO machine, including Archive-done, fail/cancel pending, already-running, next-slice rejection, required `machineId`, and anonymous `current` active.

### Modified Capabilities

- `explore-stage-machine`: pre-crystallize machine identity is `explore-idea@1` with no `explore-stage@1` alias; restore requires `machineId`.
- `machine-registry-envelope`: session pin removed; every emit/restore names a machine; same chat may host two machines.
- `sidecar-session-lifecycle`: packaged machine modules are `explore-idea.js` and `explore-slice.js`.
- `explore-pre-crystallization-stages`: sidecar cycle uses `explore-idea@1` then `explore-slice@1` in the same chat; restore names a machine; crystallize does not `/close`; `next-slice` closes Plan/Manual slices.
- `explore-pipeline-supervision`: Direct Build emits `direct-build` / `complete` on `explore-slice@1`; inventory and TODO are sidecar-owned; conversation-only run state no longer covers that surface.
