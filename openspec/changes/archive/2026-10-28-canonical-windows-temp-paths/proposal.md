## Why

On Windows, `makeTempDir` in `sai/tools/temp-root.js` resolved each created SAI temp directory with the JavaScript `realpathSync`, which keeps 8.3 short names (for example `MIKEL~1.MAD`) when `TEMP` is spelled that way. `sai/tools/validate-backfill-drafts.js` requires the OpenSpec `root.path` (reported in long form) to equal the temporary project path that `makeTempDir` returned. On such hosts the two spellings never matched, so receiver-side draft validation rejected every valid draft set, and neither standalone `/sai-backfill` nor the Direct Build backfill step could write a draft.

## What Changes

- `makeTempDir` in `sai/tools/temp-root.js` resolves the created directory on win32 through `realpathFor(io, platform)`, which prefers the native resolver `realpathSync.native` and falls back to `realpathSync` when the provided `io` has no native resolver. On win32 every SAI temp directory it returns is therefore the native long form. Its doc comment states this.
- Behavior on platforms other than win32 is unchanged: the JavaScript `realpathSync` and the existing ownership, permission, and symbolic-link checks still apply.
- `resolveTempRoot` and the root-path comparison in `validate-backfill-drafts.js` are unchanged; on win32 the temp root and a created child may now differ in spelling.
- `test/temp-root.test.js` gains a test that runs on every platform: it calls `makeTempDir` with `platform: 'win32'` and an injected `io` whose `realpathSync` returns the short form and whose `realpathSync.native` returns the long form, asserts the long form is returned, and asserts the fallback to `realpathSync` without a native resolver.
- The win32-sensitive assertions in `test/temp-root.test.js`, `test/to-pr.test.js`, `test/to-backlog-prepare-temp.test.js`, and `test/transfer-tool.test.js` compute the expected parent directory with `fs.realpathSync.native`.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `sai-temp-root`: on Windows, `makeTempDir` returns the native long form of the private child it creates.
- `pre-write-backfill-validation`: receiver-side validation of a valid draft set succeeds on Windows when the SAI temp root is spelled with 8.3 short names.
