## Why

The v0.12.0 milestone review found five places where a card, a policy, or a tool comment said something the code does not do, or left a term undefined (issue #486, F5, F10, F11, F13, F14).

## What Changes

- `sai/policies/opencode-dispatch.md` matches each result of a parallel `start` batch to its worker by the `Bash` task id kept at start, not by the `sessionID` the result itself supplies (F5).
- `sai/tools/project-settings.js` drops the `section` metadata of its catalogue, which nothing read and which disagreed with the menu; the grouping of the post-setup menu stays fixed in `bin/project-settings-screen.js` (F10).
- `sai/policies/cache-warming.md` defines an unanswered escalation: an escalation whose question the user dismissed or that could not reach the user (F11).
- `sai/commands/merge/coordinator.md` removes the simulation directory when the run ends in the step that opens the run state, before the simulation is recorded, so no run leaks it (F13).
- `sai/commands/implement/coordinator.md` says the watch input file is written once per step, because the RED and GREEN workers live for the whole run and each step names other paths (F14).

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `opencode-agent-dispatch`: parallel results are matched by the kept `Bash` task id.
- `project-settings`: catalogue entries declare no `section`.
- `agent-self-warming`: the unanswered escalation is defined.
- `sai-merge-command`: a run that ends while the run state opens removes the simulation directory.
- `undelivered-report-recovery`: the `/sai-3-implement` watch input file is written once per step.
