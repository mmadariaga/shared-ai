> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Setup only checked that each external CLI runs (`--version` exits 0), so an outdated `codegraph` or `openspec` passed unnoticed. An old CodeGraph keeps indexes built by an older extractor, which made `codegraph affected` miss tests, and nothing told the user to upgrade.

## What Changes

- A new module `bin/cli-versions.js` holds the minimum versions SAI supports (CodeGraph 1.6.4, OpenSpec 1.13.1, opencode 2.2.0), `compareVersions`, and `readVersion`, the reader of the first `X.Y.Z` of a `--version` output. `bin/doctor.js` imports the opencode minimum and `compareVersions` from it instead of its private copies; the opencode version check keeps its behavior.
- `bin/install-flow.js` declares the upgrade commands (`codegraph upgrade`, `npm i -g @fission-ai/openspec@latest`), the manual CodeGraph command (`npm i -g @colbymchenry/codegraph@latest`), and `codegraph index` beside the install commands, and adds two setup-only offers:
  - `offerCliUpgrade` compares the version read before the install offers with the minimum. A CLI that was absent, or whose version output holds no `X.Y.Z`, gets no offer (the latter prints one line saying the version cannot be verified). A CLI below the minimum is reported; with a TTY setup asks `[y/n]` and runs the upgrade on yes, without a TTY it prints the upgrade command and continues. A declined offer prints the command. A failed upgrade prints the manual command. After a successful upgrade setup reads the PATH binary's version again and, when it is still below the minimum, warns that the PATH resolves another, older binary and names its path.
  - `offerCodegraphReindex` runs only after a successful CodeGraph upgrade whose new read reaches the minimum, or after the upgrade command was only printed (no TTY), and only when the project already has `.codegraph/`. With a TTY it asks to run `codegraph index` and prints the command when declined or when the rebuild fails; without a TTY it prints `codegraph index`.
- `bin/setup.js` reads both CLI versions before the install offers, then, after the install offers, runs the OpenSpec and CodeGraph upgrade offers and the reindex offer before the existing `codegraph init` index bootstrap. None of these steps blocks setup.
- `bin/doctor.js` adds a `[CLI versions]` section with an OpenSpec and a CodeGraph version record. A version below the minimum, or an unparseable one, is a `warn`; a version at or above it is `ok`. An absent binary yields no record: CodeGraph is optional and the OpenSpec presence check already reports a missing `openspec`. Doctor offers and runs no upgrade.
- `README.md` and `docs/doctor.md` describe the setup version check and the doctor warnings.
- Tests in `test/install-codegraph.test.js`, `test/install-openspec.test.js`, and `test/doctor-opencode-version.test.js` cover the offers and the doctor records through injected execution, with no real CLI.

## Capabilities

### New Capabilities

- `setup-cli-version-check`: setup compares the installed `codegraph` and `openspec` versions with the minimum SAI supports, offers an upgrade, and, after a CodeGraph upgrade, offers to rebuild an existing index.
- `doctor-cli-version-report`: doctor reports a `codegraph` or `openspec` version below the minimum, or an unreadable one, as a warning.

### Modified Capabilities

None

## Impact

- New: `bin/cli-versions.js`
- Modified: `bin/doctor.js`, `bin/install-flow.js`, `bin/setup.js`, `README.md`, `docs/doctor.md`, `test/doctor-opencode-version.test.js`, `test/install-codegraph.test.js`, `test/install-openspec.test.js`
- Unchanged by design: `bin/install.js`, the install flow of `bin/install-flow.js`, and `sai/tools/prereqs.js` gain no version check; the doctor opencode check stays an `error` below 2.2.0.
