> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Claude Code wrappers could not run what their flows mandate: explore allowed only `openspec:*`/`git:*` shell yet must run three `node` tools, and worker coordinators allowed no shell yet must run the result validator every turn plus the commit-guard snapshot/verify every window, so each call prompted or stopped outright.

## What Changes

- Adds `sai/policies/tool-execution-permissions.md` as the single closed source for permitted `node` invocations per role.
- Grants `commands/claude/sai-explore.md` exactly three tools (prereqs, research probe, stage store) in both roots.
- Grants nine worker-coordinator wrappers (`sai-1-spec`, `sai-2-design`, `sai-3-implement`, `sai-5-review`, `sai-6-security`, `sai-7-performance`, `sai-8-accessibility`, `sai-build`, `sai-review`) exactly three tools (validator, guard, store) in both roots.
- Leaves `sai-4-apply`, `sai-commit`, `sai-archive`, `sai-backfill`, and `sai-merge` execution surface unchanged.
- Updates four test files to assert the closed node-scoped grants and forbid unscoped `Bash`.

## Capabilities

### New Capabilities

- `shared-permissions-rule`: single source naming the closed set of permitted `node` invocations per phase.
- `claude-explore-allowlist`: minimal grant covering prereqs, research probe, and stage store.
- `coordinator-allowlist`: minimal grant covering validator, guard, and stage store for all worker coordinators.
- `unattended-no-prompt`: no unattended route depends on an interactive permission prompt.

### Modified Capabilities

- None — all capabilities in this change are new.
