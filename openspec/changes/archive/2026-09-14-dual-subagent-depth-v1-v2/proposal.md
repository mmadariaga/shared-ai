## Why
Fresh install shipped only the top-level depth key and doctor performed no config-content checks, so v2 runtimes could miss the depth setting and nested helper dispatch failed. The staged change adds parallel v1 and v2 depth handling across the sample, the installer merge, and read-only doctor validation while preserving user tuning and file precedence.

## What Changes
- `configs/opencode.jsonc` now ships both top-level `subagent_depth` at 2 and `experimental.subagent_depth` at 2.
- `bin/install-flow.js` backfills only absent depth keys at 2 through surgical `jsonc-parser` edits, preserving any present value, comments, formatting, and unrelated keys.
- `bin/doctor.js` adds read-only depth validation with at-least-one present and minimum 2 semantics, honoring `opencode.json` over `opencode.jsonc` precedence.
- Test fixtures and exact-keys assertions updated for the new shape with no agent keys introduced.

## Capabilities
### New Capabilities
- `fresh-install-writes-both` — fresh install writes both depth keys at 2.
- `existing-config-backfill` — existing config backfills only missing depth keys preserving present values.
- `doctor-at-least-one` — doctor passes with at least one valid depth key and errors otherwise.
- `json-precedence` — winning-file-only operation preserving `opencode.json` over `opencode.jsonc`.

### Modified Capabilities
- None — all new behavior is captured as new capability deltas; existing `opencode-config-install` and `doctor-cli` requirements are extended context only.
