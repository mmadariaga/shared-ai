## Why
`node ./bin/install.js setup → Customize models` is broken on opencode v2 because `opencode models <provider> --verbose` no longer exists and aborts variant selection with `Unrecognized flag: --verbose`, so no model customization can be saved on v2.0.0. Restoring customization now keeps the setup flow usable on v2 without changing provider and model selection.

## What Changes
- bin/model-customization.js now sources OpenCode variants from a single cached `opencode api v2.model.list` call per setup run, filtered by exact providerID and id, with BOM-tolerant JSON parsing of the `.data` array and original-order `variants[].id` options.
- bin/model-customization.js retires the `models <provider> --verbose` invocation and the `parseVerboseModelRecords` and `extractVariants` functions; variant absence, model absence, parse failure, or API non-zero exit now degrades to model-only without cancelling setup.
- test/model-customization-menu.test.js now drives the dependent flow with `api v2.model.list` vectors and `{ data: [...] }` fixtures covering variants present, empty variants, missing model, and API failure, plus BOM and plain-array parsing.
- test/navigator-back-navigation.test.js now asserts the v2 list is fetched once per setup run and reused across back navigation with a provider-free argument vector.
- Persistence is unchanged: selections save as `variant` frontmatter and resolve as `provider/model#variant`.

### Modified Capabilities
- opencode-variant-discovery — variant source, parsing, matching, extraction, and failure semantics changed from provider-scoped verbose records to cached v2 model-list with graceful degradation.
- opencode-settings-selection — variant-discovery failure handling changed from full cancellation to model-only degradation for the confirmed subset.
