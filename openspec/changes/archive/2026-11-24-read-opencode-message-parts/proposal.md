> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

opencode v2.4.1 moved a message's content items (text, tool calls, reasoning) out of `session_message.data.content` into the new `session_part` table. The readers of `opencode.db` only read `data.content`, so `/sai-retrospective` reported opencode sessions as `analyzed` while reading no text, no tool calls, no loaded instructions, and no tool errors from them, and change telemetry lost the tool items from which it derives subagent links and wake detection. Both failures were silent.

## What Changes

- `sai/tools/opencode-db.js` gains one shared content reader (`opencodeContent`, with the `withOpencodeContent` helper that attaches its reading to message rows). For each message it uses a non-empty `data.content` as the content, and otherwise the `data` of the message's `session_part` rows in `ordinal` order, loaded with one query per session. It keeps only `text`, `tool`, and `reasoning` items, counts part rows whose `data` is not valid JSON, and marks an assistant message with a token counter above 0 and no content item in either layout as unread, only when the database has the `session_part` table.
- The opencode schema guard declares `session_part` (`message_id`, `ordinal`, `type`, `data`) as an optional table: its columns are checked only when the table exists, and a database without it is read as before.
- `sai/tools/retrospective.js` takes the text, tool items, loaded instructions, and excerpt content of opencode records from the shared reader. Part rows with invalid JSON join the existing `unparseable-records` count, and each session (root, principal worker, other linked child, opencode-routed worker, or its helper) with messages without readable content receives one `messages-without-content` `unread` entry with their count, while opencode stays `analyzed`.
- `sai/tools/change-telemetry.js` takes the tool items of each opencode request from the shared reader, so subagent links and wake detection work with both layouts. A request whose message has no readable content supplies no tool figure: tool calls, tool errors, and subagents dispatched become partial or unavailable instead of 0, and the per-tool breakdown is unavailable when at least one request is unreadable and no readable request made a call.
- The `AGENTS.md` structure table names `session_part` among the `opencode.db` tables the retrospective collector reads.
- `test/retrospective-tool.test.js` and `test/change-telemetry.test.js` add fixtures for the part layout, both layouts mixed, a database without `session_part`, a `session_part` table missing a column, and messages without readable content; the existing fixtures stay unchanged.

## Capabilities

### New Capabilities

None

### Modified Capabilities

- `sai-retrospective`: the opencode source reads message content from both storage layouts, the schema guard treats `session_part` as optional, and sessions with messages that record usage but no readable content are listed as unread.
- `change-telemetry`: the opencode source derives tool items, subagent links, and wakes from both storage layouts, and reports tool figures as unavailable for requests whose messages have no readable content.

## Impact

- Modified: `sai/tools/opencode-db.js`, `sai/tools/retrospective.js`, `sai/tools/change-telemetry.js`, `AGENTS.md`, `test/retrospective-tool.test.js`, `test/change-telemetry.test.js`.
- `opencode.db` stays read-only. Token and cost figures still come from `session_message.data`. `sai/tools/claude-transcripts.js` and `benchmark/measure.js` are unchanged. `reasoning` parts stay out of `excerpt` output and tool counts.
- Known limitations: a message whose `data.content` is non-empty never has its `session_part` rows read, even if the parts hold more items; a message holding only `reasoning` parts counts as readable, so it raises no `unread` entry while adding nothing to excerpts or tool counts.
