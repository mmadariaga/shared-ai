## Why

Pressing back (left-arrow, Backspace, or Esc) on the `Choose a harness:` screen of the post-setup model customization flow skipped one level: it returned to `Post-setup customization:` instead of the `Model customization:` submenu the user had just left. The submenu was rendered inline inside the main-menu screen of the post-setup menu loop, so it had no screen state of its own for back navigation to return to. That broke the one-level-per-back behavior the other screens of the loop follow.

## What Changes

- `bin/model-customization.js`: the `Model customization:` submenu becomes its own screen (`'model-menu'`) of the `runPostSetupMenuInternal` loop. Choosing `Model customization` in the main menu moves the loop to that screen. The screen prompts for the action with the cursor on the action chosen last, records the action's mode, and moves to the harness selector. Back on it returns to the main menu, and a cancellation (`q` or Ctrl-C) or an unknown answer still cancels the whole menu.
- `bin/model-customization.js`: back on the `Choose a harness:` screen now returns to the `Model customization:` submenu instead of the main menu, for all four submenu actions (`Customize models`, `Reset to default models`, `Save preset`, `Load preset`). After returning, choosing another action runs that action's own flow.
- `test/navigator-back-navigation.test.js`: the test that pinned the skip now expects `Choose a harness:` followed by `Model customization:`. New tests cover back from the submenu returning to the main menu with the cursor on `Model customization`, the submenu cursor returning to the chosen action for every submenu action, and a different action chosen after returning running its own flow.
- `test/model-customization-menu.test.js`: the scripted empty-target-enumeration test sends one more back step before `Exit`, because back from the harness selector now lands on the submenu.

Unchanged: the scope, targets, settings, reset, save-preset, and load-preset screens behave as before apart from where back from the harness selector lands; the "No" answers of the save-preset and load-preset confirmations still return to the main menu; back on `Post-setup customization:` still redraws the same menu.
