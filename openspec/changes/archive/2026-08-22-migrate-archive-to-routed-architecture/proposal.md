## Why

`sai-archive` was the last openspec-dependent command still shipped in the legacy utility shape: a single `body.md` executed entirely in the main session, with the destructive mutating surface — the delta-spec sync writes, the archive directory move, and every git operation of the post-archive commit gate — fused in one context with the cheap read-only pre-flight work (artifact classification, checkbox scanning, delta-sync diffing, collision checking). Every other pipeline phase already delegates technical work to a budget-routed managed worker while the coordinator keeps lifecycle routing and human gates, and yesterday's commit migration proved the minimal-lifecycle adapter pattern for a non-phase command. Replicating that exact pattern for archive removes the last special case from both boot adapters' routing tables and gives `sai-archive` the same closed lifecycle payloads, changed-files union, and reconstruction fields every other routed command carries — while keeping it distinct from commit on the one axis that matters: archive REQUIRES the openspec project and performs full prerequisite checks.

## What Changes

- New `sai/commands/archive/coordinator.md`: minimal-lifecycle archive phase adapter — `original_envelope` is the opaque single-string fast-track-cleaned request; dispatches exactly one `sai-archive-worker` through the `archive-worker.md` binding with the resolved change name as `arguments_value` and declares `fast_track_active` alongside the envelope as session state (never an envelope key); declares NO `progress_plan` and NO `recovery_policy`; fetches verified-precondition-handback, safe-operations, the upstream `openspec-archive-change` skill (mutating steps only), and `@sai/policies/prereqs.md` (archive REQUIRES the openspec project — no commit-style exemption); parses `--fast-track` itself with the exact `> FAST-TRACK MODE ACTIVE` banner; resolves the change through the shared change-picker BEFORE dispatch; presents worker `needs_input` results through the native picker and forwards answers verbatim; alone executes ALL mutations — the sync writes, the date-prefixed move into `openspec/changes/archive/YYYY-MM-DD-{name}/`, and the post-archive commit gate per `archive-commit-gate.instructions.md` (skip rule, three-option selector, fast-track new-commit auto-select, two-path staging, shared empty-index guard, pushed-HEAD guard); terminal navigation prints the worker-authored summary verbatim and closes with exactly `Archive done.` only when the move executed.

## Capabilities

### New Capabilities

- `routed-archive-command`: the routed coordinator/worker architecture for `/sai-archive` — minimal lifecycle adapter with `fast_track_active` as coordinator-owned session state, worker-owned read-only pre-flight with an absolute mutation prohibition, needs_input transport for both pre-mutation gates with byte-preserved skip/auto-proceed semantics, coordinator-only execution of sync/move/git, the openspec prerequisite REQUIREMENT carried by the coordinator card, end-to-end worker registration, and the fixed content assignment across the two cards.

### Modified Capabilities

- `apply-red-green-worker-model`: the installer's binding-derived roster and validator surfaces now accept eleven managed workers instead of ten, admitting `sai-archive-worker`.
- `sai-fast-track-flag`: parser membership is unchanged at four commands, but `sai-archive`'s parse home moves from the retired utility body file to its coordinator card, which also owns the run-start banner; explore/design/apply keep their body-file parsing unchanged.
