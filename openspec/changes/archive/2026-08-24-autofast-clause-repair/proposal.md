## Why

The auto-fast lane's write-scope clauses defined the writable surface through the undefined term "production code". In this prompt-library repository — whose product is markdown command cards and policy files — commodity-model implementer workers resolve that term inconsistently against repo contents. A real auto-fast run refused a legitimate change because the term resolved against the repo's actual product, then improvised a pre-dispatch veto that no clause defines. Undefined normative vocabulary under delegated autonomous execution produces inconsistent refusals and unowned implementation targeting; the same silence left tests and implementation targeting unowned.

## What Changes

- `sai/commands/explore/autofast-implement-worker.md`: replaces "production code only" with a closed permission/exclusion model — code, tests, and required project configuration are writable; everything else is banned by named exclusions (writes under `openspec/`, planning artifacts `design.md` / `tasks.md` / `implementation.md`, mutating git commands, subagent dispatch). The planning-artifact exclusion no longer names `.template.md`.
- `sai/commands/explore/instructions.md` item 1: the Auto (fast implementation) exception now reads "writes only code, tests, and the project configuration the selected block requires under its closed exclusions (never under `openspec/`)".
- `sai/commands/explore/instructions.md` Auto (fast implementation) flow: adds a documented Pre-dispatch compatibility refusal step that judges the emitted block against the closed exclusion list before Step 1, reading only the block, refusing by naming the violated clause and block evidence instead of improvising a veto.
- `sai/commands/explore/instructions.md` Auto (fast implementation) flow: repairs a live-observed sequencing defect by reordering the tail into eight steps — validated drafts are materialized and specs synced (hands materialize payload) BEFORE the archive pre-flight runs over materialized artifacts, and the finish payload executes archive move, owned staging, and the local commit after gate resolution.
- `sai/commands/explore/instructions.md` stage 3: agreed Implementation Details items MAY carry exact repository-relative paths when the agreed decision is grounded in specific files, without adding a field to the block template.
- `sai/commands/explore/autofast-hands-worker.md`: owned-staging wording aligned to "the implementer's listed changed paths"; the closed order is split into marker-selected materialize and finish payloads executed at their gated points of the eight-step flow.

Evidenced scope drift implemented alongside the named intent: `.template.md` was dropped from the planning-artifact exclusion list in `autofast-implement-worker.md`.
