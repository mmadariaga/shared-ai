## Why

The shared Result Loop asked the coordinator to validate every closed payload it receives by hand: the status vocabulary, an ISO-8601 `emitted_on` carrying a numeric offset and never `Z`, and the field shapes of terminal, notice, progress and extension payloads. That check runs on every result of every phase, which makes it the most repeated mechanical act in the loop and the one most exposed to prose drift. Schema checking is a pure function and belongs in code.

## What Changes

A stateless CLI is added at `sai/tools/worker-report-validator.js`. It reads a closed payload on stdin with a kind flag covering `terminal`, `notice`, `progress` and `conflict_detected`, and returns a structured verdict carrying an `ok` boolean and an `errors` list. It enforces `emitted_on` as `YYYY-MM-DDTHH:MM:SS±HH:MM` and rejects the `Z` designator. It exits 0 for a valid payload, 1 for a validation failure and 2 for a usage or IO error.

The tool never repairs, infers or reformats a value: a malformed payload is reported as malformed and the run stops exactly as it does today. It accumulates nothing, so the invocation-scoped `changed_files` union stays coordinator-owned and prose-described.

`sai/orchestration/command-runner.md` sheds the restated schema in favour of invoking the tool and reading its verdict, following the pattern `sai/policies/prereqs-check.md` already uses for `sai/tools/prereqs.js`. Every behavioural sentence that sat beside the deleted schema is retained, including that an extension is a pause rather than a terminal status, that no question, answer or mutation may be inferred from an extension payload, and the merge-phase `conflict_detected` handling with its `affected_files` inventory and its two `continuation_state` values.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `orchestration-core` — gains one requirement recording the validator's contract. No published requirement is invalidated. `Shared coordinator contract` norms that the canonical source defines one shared contract for lifecycle result validation and that the adapter does not reimplement payload validation; both outcomes still hold, because the runner still defines the contract and delegates only the mechanics to a tool it invokes. This is the same reading applied when `sai/policies/prereqs-check.md` moved four preconditions into `sai/tools/prereqs.js` without rewriting any requirement.

## Impact
