> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The implementation worker checked for `docs/ddr/0000-INDEX.md` with a file-name search. That search skips folders the project ignores in git, so it reported the index absent in a project holding 41 DDRs. The run asked the user an unneeded creation question three times, numbered new records `0001`, and rebuilt the existing index from the template. No implement step stated how the next record number is computed, and a second planning pass wrote a second record for a decision that already had one.

Whether a decision-record index exists, which records exist, and which number comes next are facts of the folder. A tool that reads the folder with `fs` reports them identically on Claude Code and opencode and for folders ignored in git.

## What Changes

- New tool `sai/tools/decision-records.js` with the sub-command `inventory --family adr|ddr --json --cwd <root>`. It reads `docs/<family>/` and `docs/<family>/archive/` from disk and prints one JSON object with `family`, `index_exists`, `records` (`number`, `suffix`, `path`, `archived`), `next_number`, and `duplicates`. A record is a file named `NNNN-slug.md` or letter-suffixed `NNNNx-slug.md`; every other entry is ignored, `0000-INDEX.md` included. A suffixed record counts under its number and archived records count toward the next number. The tool reports only; it renames and repairs nothing. A missing or unknown family, a missing sub-command, an unknown flag, or a missing working directory exits 2.
- `sai/commands/implement/steps/artifact-analysis.md` runs the inventory once per resolved family after the three criteria hold. The inventory is the only source of index existence, the record list, and the new record's number for the rest of the step. Before any ask, the worker looks in the inventory's `records` for a record that already documents the decision and creates none when it finds one. The first record a run creates in a family takes `next_number`; each further record of that family in the same run takes the next consecutive number.
- The culture check keeps the physical family index as the sole culture signal and now reads it from the inventory's `index_exists`. The question to the user still depends on the index alone, even when records exist.
- `sai/commands/implement/steps/decision-record-index.md` selects the cold-build or warm-splice branch from `index_exists` in the inventory the artifact-analysis step ran. Its rerun idempotency rule is unchanged.
- `sai/policies/tool-resolution.md` § Invocation declares the `decision-records.js` invocation form.
- `AGENTS.md` § ADR/DDR Proposal Check names the inventory as the way the index is detected.
- Known limitations: text searches that start at the repository root still miss content inside ignored folders, and recognising an existing record of a decision is the worker's judgment over record slugs, so a vague slug can hide a match. `retire-docs` and `merge.js` are unchanged and do not consume the inventory. No general rule about search tools and ignored files is added.
