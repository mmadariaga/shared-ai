## Why
Every sai-merge needs_input was an independent user trip (~7-8 trips per conflicted merge). An absent user takes ~10 minutes per trip so the merge stalled ~1 hour, while answering 3 questions in one trip costs seconds — round-trip cost dominates, not question count. Batching N closed questions per trip (Batch 1 pre-merge, Batch 2 language+scope) cuts the run to 3-4 trips while keeping strategy and authorization in their own content-dependent trips.
## What Changes
Implemented batched closed questions for sai-merge: pre-merge Batch 1 (dirty + method + branch, all-or-nothing with Dirty=no abort discarding other answers), conflict Batch 2 (coordinator-assembled language + scope with three-version classification moved before the language hand-off, same work earlier, scope worded in English/ambient), singular global-strategy confirmation trip authored once for the chosen scope in the chosen language, singular squash gate (rebase path, normal mode only) and singular authorization trip, batch v1 shape questions:[{id, question, options}] with singular question/options still valid, dual validation in worker-report-validator.js, merge-only pilot with plain-text fallback preserving order and exact values, no speculative strategy pre-authoring and no extra worker analysis. Fix loop converged in round 1 with no findings: targeted validator+merge tests 63/63 green, empirical CLI check accepts batch and singular, full-suite failures (~60) verified byte-identical on the clean tree via stash comparison so all pre-existing and unrelated.
