## Why

`AGENTS.md` had drifted from the cards it describes. Its subagent-lifetime paragraph still said "one explorer per search", although `sai/policies/cache-warming.md` and ADR 0202 keep one live explorer per coordinator, and the policy load lists it gives for the implement, review, build, deep-review, plan, spec, design, and audit coordinators omitted `cache-warming`, which those coordinators now fetch. Separately, a comment in `sai/tools/lint.js` cited `sai/policies/stage-machine-write-ownership.md`, a file that does not exist, so a reader of the installed tool could not find the rule the check enforces.

## What Changes

- `AGENTS.md`, implement/review/build/deep-review Boundary: the list of cross-cutting policies these contracts load now ends with `cache-warming`.
- `AGENTS.md`, `/sai-deep-review`: the coordinator's load list now includes `cache-warming`.
- `AGENTS.md`, plan/spec/design Boundary: the spec and design coordinator load list and the `/sai-plan` load list now include `cache-warming`.
- `AGENTS.md`, audit coordinators: the shared audit coordinator's load list now includes `cache-warming`.
- `AGENTS.md`, budget-subagent hang containment: the subagent-lifetime sentence now reads "one live explorer per coordinator" and cites ADR 0188 and ADR 0202.
- `sai/tools/lint.js`: the header comment of the worker emission-ownership check states the rule itself ("only coordinator cards emit to a stage machine") instead of citing the missing policy file. The check's behavior is unchanged.
