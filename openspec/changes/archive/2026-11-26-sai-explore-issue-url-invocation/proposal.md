> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

`/sai-explore` treated its argument as the starting content of an idea. An issue URL passed as the whole argument was inert text: the issue was not imported, and the user had to run `/from-backlog <url>` first and then bring the issue into the exploration, a separate manual step for the same intent. The existing resolver could not serve as a local detector, because GitLab has `resolution: provider` and no `hosts` in the provider registry, so every HTTPS URL is a GitLab fallback candidate and resolution may call the provider CLI.

## What Changes

- `sai/tools/from-backlog.js` gains the pure sub-command `detect <registry> --input-file <path>` (JSON `{"reference": ...}` in the input file), which prints `{verdict: "issue"|"none", provider}`. It selects candidate providers with the same tiers as `resolve` (a positive match wins, otherwise the provider-owned fallbacks), then asks the selected adapter's `issueRoute`; it resolves nothing, reads nothing, starts no process, and uses no network. An empty or missing reference is the `invalid-reference` error (exit 2).
- Each adapter exports a pure `issueRoute(value)`: GitHub (`/owner/repo/issues/N` over `https://`, reusing `normalize`), GitLab (`/<group…>/<project>/-/issues/N` on any HTTPS host, reusing `issueURL`), and Azure DevOps (`.../_workitems/edit/N`, reusing `resolveLink`). The query string and the fragment do not count toward the shape.
- `sai/commands/explore/body.md` adds the Issue URL import step: only on an invocation turn, right after the chat-language read (so after the prerequisite check, the loads, `sai-state spawn`, and the resets), and never on a recovery load. When the cleaned request is exactly one `https://` URL, Explore runs `detect`; on `verdict: issue` it announces the import in one line and follows the from-backlog skill with the URL in the same session, read-only, and asks the `work`/`context` question of `steps/issue-intake.md` in place of the skill's step 5 continuation question. Other text, several URLs, `#N`, path-only references, and `verdict: none` enter as ordinary idea content.
- A `resolve` or `read` failure is shown with the concrete message through the native picker with `retry` and `stop`; on `stop` the exploration stays active with no candidate idea and the URL is not used as content. A `detect` call that cannot run or prints unreadable output offers `retry` and `continue without import`, the latter entering the URL as ordinary content.
- `sai/commands/explore/steps/issue-intake.md` names the imported issue URL as an intake trigger.
- `skills/universal/from-backlog/providers/resolution.md` documents issue URL detection and that an adapter without `issueRoute` never detects (scope drift: the change document did not name this documentation, but the diff evidences it).
- `docs/commands/sai-explore.md` documents the new entry.
- `test/from-backlog.test.js` covers `detect` offline per provider with negative cases, the spawned CLI with an empty `PATH`, and the `body.md` / `issue-intake.md` wording.

## Capabilities

### New Capabilities

- `issue-url-entry`: passing one issue URL as the whole `/sai-explore` argument imports that issue after the load and starts the exploration from it.

### Modified Capabilities

- `explore-issue-intake`: the intake trigger now includes an issue URL that the `/sai-explore` load imported; a link elsewhere still triggers nothing.
- `from-backlog-provider-resolution`: adds the offline `detect` sub-command and the per-adapter `issueRoute` shape functions.
- `from-backlog-conversation-import`: the explicit `/sai-explore <issue-url>` invocation becomes a third authorized import path, and inside it the intake's `work`/`context` question replaces the skill's continuation question.

- Modified: `sai/tools/from-backlog.js`, `sai/tools/from-backlog-github.js`, `sai/tools/from-backlog-gitlab.js`, `sai/tools/from-backlog-azuredevops.js`, `sai/commands/explore/body.md`, `sai/commands/explore/steps/issue-intake.md`, `skills/universal/from-backlog/providers/resolution.md`, `docs/commands/sai-explore.md`, `test/from-backlog.test.js`.
- New: none.
- No wrapper changes: Claude Code and opencode share `body.md`.
- Known limitation: from-backlog gains one sub-command although its import behavior stays unchanged.
- Known limitation: GitLab detection accepts only the `/-/issues/N` route; a `/-/work_items/N` URL, which import accepts, gets `verdict: none` and enters as ordinary idea content.
- Out of scope: design.md, tasks.md, implementation.md — not generated by /sai-backfill
