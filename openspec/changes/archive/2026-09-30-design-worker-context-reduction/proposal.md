> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

Every design-worker dispatch paid for roughly 16 KB of overview-lifecycle rules (about half of the 32 KB `sai/commands/design/worker.md` card) that only matter when `--overview-lang` is passed, plus a 6.6 KB `sai-learnings-format.md` policy fetched at dispatch by `sai/commands/design/steps/common.md` that only the tasks step uses. Both costs were paid on runs that never needed them.

## What Changes

- The overview lifecycle (first materialization, regeneration, failure mapping, diagnostics persistence, bounded recovery, the Overview state machine and Generator failure-kind mapping tables) moves from `sai/commands/design/worker.md` into `sai/commands/design/steps/overview.md`, which becomes its normative home; generation behavior is unchanged.
- `sai/commands/design/worker.md` keeps only the rules that fire during any source write (Stale-before-first-write, the run-start no-effective-change capture, plan gating) plus a pointer to the step file.
- `sai/commands/design/coordinator.md`: the Continue generation-trigger continuation now starts with the line `Follow @sai/commands/design/steps/overview.md`, so the lifecycle loads even when the `overview` pointer was not delivered.
- `sai/commands/design/steps/common.md` no longer fetches `sai-learnings-format.md`; its step-delivery meta-rule now states that the overview step file is the normative home of the lifecycle.
- `sai/commands/design/steps/tasks.md` fetches `sai/policies/sai-learnings-format.md` at its point of use (the Implementation Context item), only when a project-root `SAI_LEARNINGS.md` exists.
- `AGENTS.md` step-gated delivery paragraph is updated to match.
- Evidenced scope drift: the contract tests `test/bounded-worker-recovery.test.js`, `test/change-overview-contract.test.js`, and `test/design-coordinator-worker.test.js` now read `steps/overview.md` together with `worker.md` for their overview-lifecycle assertions.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `design-steps-library`: the overview step file is the normative home of the overview lifecycle; `common.md` no longer carries the learnings-format fetch; the worker card keeps only the source-write rules; the generation-trigger continuation names the overview step file.
- `change-overview-generation-routing`: the transport contract tests pin the contract Fetch and both harness bindings on `steps/overview.md` instead of `worker.md`.
- `sai-learnings-consumption`: the design side fetches the learnings format in `steps/tasks.md`, only when `SAI_LEARNINGS.md` exists.

## Impact

- Modified: `AGENTS.md`, `sai/commands/design/coordinator.md`, `sai/commands/design/worker.md`, `sai/commands/design/steps/common.md`, `sai/commands/design/steps/overview.md`, `sai/commands/design/steps/tasks.md`.
- Modified tests: `test/bounded-worker-recovery.test.js`, `test/change-overview-contract.test.js`, `test/design-coordinator-worker.test.js`.
- Both Claude Code and opencode are covered: the files are shared instruction bodies, and the worker never touches `sai-state`.
