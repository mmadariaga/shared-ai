## Why

Users need to weigh meaningful approaches before reviewing edge cases without fabricated alternatives or guessed priorities. Approach selection must remain separate from stage advancement so an advancement request does not silently accept a recommendation.

## What Changes

- Added conditional approach comparison beside discovery ownership in `sai/commands/explore/steps/common.md`, using the existing idea-maturity point rather than another readiness threshold.
- Compare multiple defensible approaches with meaningful trade-offs; skip comparison when only one is defensible and continue investigating when none is viable.
- Ask about an unstated priority when it could change the recommendation, then present the grounded recommendation before alternatives.
- Reference the comparison rule from the shared closure rule. Before and during comparison, omit advancement offers and `next-step`, ending with the pending substantive question.
- Resolve comparison only after the user chooses an approach and substantive questions about that choice are answered. Restore ordinary closure afterwards without treating selection as advancement.
- Preserve unsolicited advancement recognition without implicit recommendation acceptance; respect fixed choices and use existing material-change reset behavior.
- Keep comparison in conversation and carry its outcome into existing decision, alternative, and trade-off handoff fields.
- Added seven contract/machine regression tests covering applicability, presentation, closure, refinements, handoff, both harness entry paths, and unchanged advancement machinery.
