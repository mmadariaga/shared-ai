**Complexity**: medium

## Why

GitLab can return an ordinary issue with `issue_type: issue` and a `/-/work_items/N` source URL. The import adapter previously accepted only `/-/issues/N` input links and required literal equality with that response route. It therefore rejected otherwise valid ordinary issues.

The previous combined response error also concealed which validation failed. Import instructions could then ask users to replace a complete reference or explain a failure using a cause the helper had not established.

## What Changes

- Centralized GitLab issue URL interpretation in the existing provider adapter. Both project-level `/-/issues/N` and `/-/work_items/N` routes are accepted. Query parameters and fragments do not change project and issue-number identity.
- Added concrete reference and response validation errors for protocol, credentials, missing components, invalid numbers, project destination, issue identity, response URL, issue type, title, description, and state.
- Required a verifiable `issue_type: issue`; missing or unsupported types do not permit import.
- Preserved the issue URL returned by GitLab instead of rewriting its display route. Comment links preserve its query parameters and replace its fragment with the note anchor.
- Corrected note retrieval to request supported `order_by=created_at` pagination and sort user comments by identifier before returning complete or incomplete results.
- Updated common and GitLab import instructions to explain established helper failures, ask only for identified missing components, present complete incompatible references as provider limitations, and communicate uncertainty when the cause is unknown.
- Added regression coverage for equivalent routes, invalid references, response validation, original content and provenance, pagination, partial retrieval, and shared publication approval and recovery boundaries.

Compatibility remains limited to ordinary project-level issues. Tasks, incidents, epics, and items whose type cannot be verified are not imported. Narrow destination and identity checks remain in force. The implementation did not change publication approval or recovery code, broaden work-item support, or add a new provider skill.
