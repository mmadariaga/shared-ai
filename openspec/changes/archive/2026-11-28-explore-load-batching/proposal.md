> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

The `/sai-explore` load spent fetch calls it did not need: the fetch tool already prints the absolute path of every node a tree resolves, yet the load asked for those same subpaths again in a second call, and it resolved the tool paths it needed in three separate calls. The tree also printed a `§` section line that the next read answered anyway, and that line misattributed a header-level directive to a section it did not belong to. The change makes the load read the paths the first tree resolved, resolve every tool path its unconditional steps need in one call, and stop printing the section line.

## What Changes

- `sai/commands/explore/body.md` gains a **Load mechanics** paragraph: read each path a tree resolved from its printed node path, never request that subpath from the fetch tool again within the load, read only the unconditional nodes, resolve every tool path the unconditional steps need in one path-mode call, repeat a partial read until it is complete, and load `[skill]` nodes with the skill tool.
- Both fetch skill copies (`skills/claude/fetch/SKILL.md`, `skills/opencode/fetch/SKILL.md`) carry the same batching rule and the same legend: the legend drops the `§` entry, the `§ <heading>` bullet leaves the tree shape, `### Batching` gains the node-path read rule and the one-call tool-path step, and the partial-read clause of `### Loaded-copy reuse` sends the agent back to the same path.
- `skills/universal/fetch/fetch.js` stops emitting the `§ <heading>` line: `renderGraph` loses the section state and emission, `LEGEND` loses its entry, and the position record no longer carries `section`.
- `test/fetch-tool.test.js` updates the four places that pin the legend and the section line; the golden tree counts of `body.md` stay unchanged.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `claude-fetch-resolution`: the batching requirement gains the tree-node read and one-call tool-path rules, the legend requirement drops the `§` symbol, and the section-printing requirement is replaced by one that marks conditional edges, skills, and unresolved paths without a section line.
- `fetch-resolution-path-scoping`: its element-by-element mirror scenario drops `section` from the tree shape and gains the tree-node read and one-call tool-path rules.
- `fetch-loaded-copy-reuse`: the incomplete-copy requirement reads the same path again for a partial read instead of running the fetch tool, and its partial-read scenario follows.
