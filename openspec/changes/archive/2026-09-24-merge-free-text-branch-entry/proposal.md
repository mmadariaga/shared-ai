> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation against a user-supplied statement of intent. It describes a decision already made, not one being proposed.

## Why

On opencode, typing a branch such as `origin/main` directly into the `/sai-merge` branch picker was rejected, and the user had to choose `Enter a branch name` and type the branch a second time. The coordinator's branch gate named Claude Code as the only harness with a free-text answer, which contradicted the `Harness-parity merge contract` requirement of `sai-merge-command`. The defect was not a missing opencode feature: a shared card named a harness where harness-neutral text was enough.

## What Changes

- `sai/commands/merge/coordinator.md` § Gates step 2 now classifies the branch answer the picker returns in a fixed, harness-neutral order. An answer equal to the exact value or exact label of a listed candidate or of the sentinel option is that option's selection, mapped to its value first. An exact listed candidate value sets `branch_selection_source: listed`, including picker free text that exactly matches a listed value. The sentinel `sai:enter-branch` still leads to the branch-entry open prompt. Any other non-empty answer is picker free text: it becomes `branch_entry` exactly as typed, with no second prompt, recorded only through its existing Batch 1 history pair. An empty or whitespace-only answer repeats the branch question with no fetch.
- The rule that typed text wins even when it matches a listed branch now applies only to the sentinel path.
- The harness-specific wording ("native `Other` answer (Claude Code)", "This is the opencode path", "a harness-native free-text answer") is removed from the coordinator. The branch-gate block names no harness.
- `sai/commands/merge/presentation.md` § Branch entry replaces the per-harness parenthetical with a neutral statement: picker free text needs no prompt, and the sentinel leads to the open prompt.
- `sai/commands/merge/instructions.md` Step 3 states that `branch_entry` arrives from either the sentinel prompt or picker free text, and that the coordinator classifies the answer while the worker only receives the value.
- `test/merge-contextual-conflict.test.js` replaces the assertions that pinned the harness asymmetry with assertions for the neutral classification order, the sentinel-only typed-text-wins rule, the empty-answer repeat, and the absence of `Claude Code` and `opencode` from the coordinator branch gate and the presentation Branch entry gate.
- Unchanged: the `Enter a branch name` option (still the only option when no candidate exists), the `dirty` = `no` short-circuit applied before classification, the free-text branch validation flow (`git fetch --prune origin`, exact ref check, failure closes the run without integration), `sai/commands/merge/lifecycle.md`, and `sai/policies/remember.md`.

## Capabilities

### New Capabilities

- None.

### Modified Capabilities

- `sai-merge-command`: the branch picker answer is classified harness-neutrally as a listed branch, the branch-entry routing choice, or typed branch text, and picker free text becomes `branch_entry` directly without a second prompt.

## Impact

Known limitations: a typo or extra prose in a typed branch still fails validation and closes the run without integrating anything, which forces a relaunch; recovery from a failed entry is out of scope. Free text on the method, language, and scope questions, message wording, and every other command are out of scope.
