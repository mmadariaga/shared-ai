## Why

The Direct Build (unattended) archive worker staged its allowlist and then committed the whole index, so index entries that were already staged before the slice entered the archive commit unnoticed. Apply already restored unrelated index entries after its guard remediation, but that behavior lived only in the apply coordinator, so SAI had no single rule for keeping foreign index entries out of a slice's commit.

## What Changes

- Add `sai/policies/foreign-index-preservation.md`, the single shared rule for apply and archive. It defines owned paths and foreign entries and five steps: set aside the foreign entries before the slice stages anything, write a record under `git rev-parse --git-path sai-foreign-index` before unstaging, unstage the foreign entries from the index only, restore them after the commit after checking every record line, and restore nothing (keeping the record and reporting the exact paths) when any entry changed after it was set aside. An owned path that was staged before the slice stays staged and enters the commit. A record on disk is a pending restore that any later run completes first.
- `sai/commands/archive/worker.md` fetches the new policy for the Direct Build (unattended) index. Before staging the allowlist, the execute order restores a pending record from an earlier order first, then sets aside the foreign entries with the exact owned staging paths as the owned paths; a restore that stops ends the order. After the commit step, whether a commit was created or the index was left empty, the order restores the foreign entries; a restore that stops is reported in the summary with its exact paths and the record stays for recovery.
- `sai/commands/apply/coordinator.md` § No-commit guard states that its restore of initial unrelated index entries through `apply-step.js restore-unrelated-index` runs under the shared policy; the apply mechanism itself is unchanged.
- `sai/policies/unattended-runtime-recovery.md` makes a failed execute order restore any pending foreign index entries first, ending recovery with a report when that restore stops, before the no-effect check runs.

## Capabilities

### New Capabilities

- `foreign-index-preservation`: the shared set-aside, record, unstage, restore, no-overwrite, and recovery rule for index entries staged before a slice.

### Modified Capabilities

- `auto-fast-archive-execution`: the Direct Build archive commit excludes foreign index entries and restores them afterwards.
- `no-commit-guard`: apply's restore of initial unrelated index entries is apply's realization of the shared rule.
- `unattended-resilience-rule`: a failed execute order restores pending foreign index entries before the no-effect check.

## Impact

- New: `sai/policies/foreign-index-preservation.md`
- Modified: `sai/commands/archive/worker.md`, `sai/commands/apply/coordinator.md`, `sai/policies/unattended-runtime-recovery.md`
- No tool code changes: `apply-step.js restore-unrelated-index` keeps its behavior, and the archive worker runs the policy's Git commands itself.
