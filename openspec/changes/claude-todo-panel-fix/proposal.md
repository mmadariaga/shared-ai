> **⚠ POST-HOC RECORD** — This proposal was backfilled after implementation. It describes a decision already made, not one being proposed.

## Why

The routed Claude Code coordinators required a full progress-panel render before dispatch, but their `allowed-tools` lists omitted the Claude task tools used by that render. This made the coordinator contract unsatisfiable: dispatching without rendering violated the contract, while rendering was unavailable under the wrapper scope. The staged implementation closes that contradiction and defines behavior when a statically declared panel tool is unavailable at runtime.

## What Changes

- The seven routed Claude Code wrappers explicitly allow `TaskCreate`, `TaskUpdate`, `TaskGet`, and `TaskList` while retaining their non-writing coordinator scope.
- `sai-4-apply` declares an explicit execution allowlist that includes its existing execution capabilities and panel tools.
- Claude Code and opencode panel bindings record one visible notice and continue without panel rendering when a declared panel tool is unavailable at runtime.
- Routed coordinators, apply's Step Projection, and `sai-explore` use the same non-retrying degradation route without runtime probing or dynamic Markdown fallback.
- Tests, glossary terminology, and ADR documentation record the behavior.
