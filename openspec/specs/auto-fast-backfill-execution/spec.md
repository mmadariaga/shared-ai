## Requirements

### Requirement: Attribute backfill execution to Direct Build

Direct Build (unattended) SHALL use the existing backfill worker's read-only preparation followed by coordinator validation and one explicit execute continuation. The backfill worker SHALL write only the validated draft set during that continuation.

#### Scenario: Direct Build prepares backfill drafts

- **WHEN** Direct Build reaches backfill preparation
- **THEN** the existing backfill prepare and validated execute boundaries remain unchanged under the Direct Build route.

### Requirement: Coordinator-authorized backfill execution

The Direct Build backfill worker SHALL keep preparation free of repository writes and SHALL execute only a coordinator-authorized closed order containing the validated change name and, for every draft, the validated reference `{path, sha256, destination}`, never the draft contents.

#### Scenario:

- **WHEN** the worker receives the prepare envelope
- **THEN** it SHALL compose the drafts and hand them over as transfer-file references without writing repository files or running state-changing git commands

### Requirement: Exact backfill draft writes

The execution continuation SHALL write only the validated `.openspec.yaml`, `proposal.md`, and capability specification destinations represented in the prepared references, and only after `transfer.js verify` passes for every reference.

#### Scenario:

- **WHEN** the coordinator forwards a valid execution order
- **THEN** the worker SHALL materialize the verified transfer-file bytes byte-for-byte to the named destinations and report an ordered duplicate-free `changed_files` union

### Requirement: Backfill correction feedback after execution

The worker SHALL accept same-run correction feedback carrying the verbatim archive failure plus the named draft sections to recompose. The worker SHALL recompose only those named sections from the staged diff, the block grounding, and the CLI error, SHALL rewrite only those draft files, SHALL report every rewritten path in the invocation-scoped changed_files union, and SHALL carry no commit authorization. A defect that repeats without progress after correction SHALL end this worker's corrections: the worker returns `failed` with the verbatim failure.

#### Scenario: Archive failure routes to same-worker correction

- **WHEN** the same run continues this worker with the verbatim archive failure plus named draft sections to recompose
- **THEN** the worker SHALL recompose only those named sections and rewrite only those draft files with no commit authorization

#### Scenario: A defect repeats after correction

- **WHEN** the same defect is reported without progress after a correction
- **THEN** the worker SHALL return `failed` with the verbatim failure

### Requirement: Backfill execute orders are one-shot

The worker MUST reject a repeated execution continuation carrying the same closed order after successful execution. A write or parent-directory failure SHALL return a closed failed result with the exact completed and uncompleted state, SHALL set unrecoverable true only when the evidence establishes that continuation is unsafe, and SHALL end the order there: the worker leaves the state as it is for the coordinator to verify. The worker SHALL accept a new execute order only after an order that failed before its first write; the coordinator issues one under the Execute orders rule of `sai/commands/explore/direct-build-coordinator.md`, after the no-effect check passes. Otherwise the coordinator SHALL report the worker's concrete partial state and stop, and SHALL never fall back to coordinator-side writes.

#### Scenario: A repeated completed order is rejected

- **WHEN** an execution continuation or replacement attempts to repeat a completed mutation
- **THEN** the worker SHALL reject it without another write

#### Scenario: Partial-mutation failure reports without refire

- **WHEN** a write or parent-directory failure leaves a partial mutation
- **THEN** the worker SHALL report the exact completed and uncompleted state and end the order there, and no new order is issued onto that state

#### Scenario: A new order follows a failure before the first write

- **WHEN** an execute order failed before its first write and the coordinator's no-effect check passes
- **THEN** the worker SHALL accept the new execute order the coordinator issues

### Requirement: The backfill execute order is generated by a tool

On the Direct Build worker route, the coordinator SHALL generate the backfill worker's `--direct-build-execute` order with `validate-backfill-drafts.js order` from an input file holding the change name, the accepted validation fingerprint, the accepted `draft_references`, and the worker's latest `prepared_references`, and SHALL send exactly its output. The order text format SHALL be defined only in the backfill worker contract's Direct Build execution continuation: the marker line, `change_name`, `fingerprint`, and a `drafts` list with one `path`, `sha256`, and `destination` entry per draft. The tool SHALL print no order when `prepared_references` is missing, when the accepted references do not match the latest prepared set, when a reference is malformed, when a destination is duplicated or outside `.openspec.yaml`, `proposal.md`, and `specs/<capability>/spec.md` of the change, or when `.openspec.yaml` or `proposal.md` is absent; that failure SHALL be an obstacle of `step-6`.

#### Scenario: Matching references produce the order

- **WHEN** the accepted references equal the worker's latest prepared references and include `.openspec.yaml` and `proposal.md`
- **THEN** `order` prints the `--direct-build-execute` order with the change name, the fingerprint, and one entry per reference

#### Scenario: Mismatched references produce no order

- **WHEN** the accepted references differ from the worker's latest prepared references
- **THEN** `order` prints an error and no order, and the coordinator records a `step-6` obstacle

#### Scenario: Missing prepared references produce no order

- **WHEN** the input carries no `prepared_references` for the backfill target
- **THEN** `order` prints an error and no order
