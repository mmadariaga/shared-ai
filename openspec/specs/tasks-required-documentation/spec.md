## Requirements
### Requirement: tasks-required-documentation-section
`tasks.md` SHALL contain a `## Required Documentation` section generated by `/sai-2-design` immediately after all implementation steps.

The section SHALL have three subsections, in this order:

    ### Spec files
    <!-- one path per line; change delta and main specs alike -->

    ### Local files
    <!-- one entry per line: <path> — <note>, or None -->

    ### External URLs
    <!-- one entry per line: <URL> — <note>, or None -->

The `### Spec files` subsection SHALL NOT be empty and SHALL NOT contain `None`. If no local files apply, the agent SHALL write `None` under `### Local files`. If no external URLs apply, the agent SHALL write `None` under `### External URLs`.

No path or URL SHALL be listed twice in the whole section. Every spec, whether a change delta spec under `openspec/changes/{change-name}/specs/**` or a consulted main spec under `openspec/specs/**`, SHALL be listed only under `### Spec files` and never under `### Local files`.

Each `### Local files` entry SHALL be a whole-file path followed by ` — ` (space, em dash, space) and a relevance note: one short sentence, about 20 words at most, stating why that file matters for implementing the change. Line ranges SHALL NOT be emitted.

Each `### External URLs` entry SHALL be a URL followed by ` — ` and a relevance note of the same shape, stating which API or version-specific behavior to consult there.

A relevance note SHALL be derived from the design-phase research and SHALL NOT be invented; it SHALL contain no code or snippets and SHALL NOT restate requirements. A resource with several roles SHALL carry one note naming them all, and a resource consulted with no implementation role SHALL remain listed with a note saying so.

The section SHALL NOT be left empty or omitted.

#### Scenario: sai-2-design populates both subsections from research findings

- **WHEN** `/sai-2-design` generates `tasks.md` after researching the codebase and external docs
- **THEN** `tasks.md` contains `## Required Documentation` with `### Spec files` listing every spec consulted, `### Local files` listing every file read with its relevance note, and `### External URLs` listing every external doc consulted with its relevance note; `### Spec files` is never empty, while a `### Local files` or `### External URLs` subsection with nothing to list contains only `None`

#### Scenario: sai-3-implement reads section without re-exploring

- **WHEN** `/sai-3-implement` reads `tasks.md` to produce `implementation.md`
- **THEN** it reads only the files and URLs listed under `## Required Documentation`, taking each path or URL from the text before ` — ` and using the note after it as reading guidance, and does not perform additional codebase exploration to recover this information

#### Scenario: no relevant external URLs

- **WHEN** `/sai-2-design` finds no external documentation relevant to the change
- **THEN** `tasks.md` contains `### External URLs` followed by `None`

### Requirement: tasks-required-documentation-schema
The `tasks` artifact instruction in `openspec/schemas/sai-workflow/schema.yaml` SHALL include a directive requiring `/sai-2-design` to populate `## Required Documentation` from docs visited during codebase research.

#### Scenario: schema instruction includes required documentation directive

- **WHEN** `openspec instructions tasks --change <name>` is run
- **THEN** the returned `instruction` field references the `## Required Documentation` section and explains that it must be populated from design-phase research findings, not left empty
