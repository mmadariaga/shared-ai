## Requirements

### Requirement: tasks-implementation-context-section

`tasks.md` SHALL contain a `## Implementation Context` section generated by `/sai-2-design` immediately after `## Required Documentation`.

The section SHALL contain exactly one field:

    **Test Command**: <the exact command that runs this project's test suite>

The section SHALL NOT carry **Stack**, **Conventions**, or **Avoid** fields. Project conventions and anti-patterns reach the implementers through the root `SAI_LEARNINGS.md`, which design, RED, GREEN, and review read directly, and through the code itself; no instruction copies them into `tasks.md`.

**Test Command** SHALL be derived from codebase research performed during design, not copied from generic content or inferred from the change description alone. When `SAI_LEARNINGS.md` has a **Test Command** section, design SHALL compare the two: when they agree, it SHALL write that command; when they disagree, it SHALL write the `SAI_LEARNINGS.md` command, because an entry wins over contradicting findings and execution settles it. When it takes a value from that section, it SHALL take only the command line, never the `*Observed:*` provenance line or a bullet marker.

**Test Command** SHALL be directly executable from the project root by a subagent that has read neither `design.md` nor any other plan artifact. Where the project's runner supports scoping a run to a subset of tests, the field SHALL also carry that project's scoping idiom in parameterised form — the concrete flag and the concrete test-project or path argument, with a substitutable placeholder for the test identifier (for example `dotnet test tests/<Project> --filter FullyQualifiedName~<TestName>`).

**Test Command** SHALL NOT pin a specific Step's filter value. The field carries the reusable form, not one Step's instance of it.

When the project has no test runner at all — a documentation, prompt, or configuration repository with no executable test surface — **Test Command** SHALL carry the explicit sentinel `None — no test runner in this project`. That sentinel is a researched finding, not placeholder text, and SHALL NOT be treated as a violation of the no-placeholder rule below.

`/sai-2-design` SHALL produce **Test Command** for every change, including changes whose Steps carry no RED block.

The section SHALL NOT be omitted or left with placeholder text. A `tasks.md` written earlier that still carries **Stack**, **Conventions**, or **Avoid** SHALL be implemented and reviewed without failure: those fields are ignored.

#### Scenario: sai-2-design derives context from codebase research

- **WHEN** `/sai-2-design` generates `tasks.md`
- **THEN** `## Implementation Context` contains only **Test Command**, with the exact command observed in the project's own test tooling

#### Scenario: Test Command carries the project's scoping idiom

- **WHEN** `/sai-2-design` writes **Test Command** for a project whose runner supports filtering a run to a subset of tests
- **THEN** the field shows the concrete test-project path and the concrete filter flag with a substitutable placeholder for the test identifier, rather than a bare whole-suite invocation

#### Scenario: Project has no test runner

- **WHEN** `/sai-2-design` researches the test command for a repository that has no executable test surface
- **THEN** it writes the sentinel `None — no test runner in this project` in **Test Command**, and this does not violate the no-placeholder rule

#### Scenario: sai-3-implement uses context as authoritative contract

- **WHEN** `/sai-3-implement` reads `tasks.md` to start its run
- **THEN** it takes **Test Command** as the first source of its test commands, and departs from it only when execution shows that it does not work, recording the deviation

#### Scenario: conventions are project-specific, not generic

- **WHEN** `/sai-2-design` writes `## Implementation Context`
- **THEN** it writes no **Conventions** field, and project-specific conventions reach the implementers only through `SAI_LEARNINGS.md` and the code

#### Scenario: Test Command is not written as a Conventions bullet

- **WHEN** `/sai-2-design` records how this project's tests are run
- **THEN** it writes the command in the **Test Command** field, the only field of the section

#### Scenario: Test Command is produced even when no dispatch will read it

- **WHEN** `/sai-2-design` generates `tasks.md` for a change whose Steps contain no RED block
- **THEN** `## Implementation Context` still contains a populated **Test Command** field rather than omitting it or writing a placeholder

### Requirement: tasks-implementation-context-schema

The design tasks step, `sai/commands/design/steps/tasks.md`, SHALL require `/sai-2-design` to populate `## Implementation Context` from codebase research, with explicit guidance that placeholder content is not acceptable.

The template at `openspec/schemas/sai-workflow/templates/tasks.md` SHALL show only a **Test Command** field in its `## Implementation Context` scaffold, with no **Stack**, **Conventions**, or **Avoid** placeholder.

#### Scenario: schema instruction prohibits generic implementation context

- **WHEN** `sai/commands/design/steps/tasks.md` is read at its `## Implementation Context` item
- **THEN** it states that **Test Command** is derived from actual codebase research and that the section must contain real content, not placeholder text

#### Scenario: template scaffolds the Test Command field

- **WHEN** `openspec/schemas/sai-workflow/templates/tasks.md` is read
- **THEN** its `## Implementation Context` section shows a `**Test Command**:` placeholder and no `**Stack**`, `**Conventions**`, or `**Avoid**` placeholder
