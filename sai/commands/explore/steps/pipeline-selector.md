# Item 10: Plan - Unattended / Direct Build - Unattended supervision state

This is one phase-aware, chat-scoped supervision contract. It persists no state, discovers no repository changes, and leaves the post-crystallization `review-loop` contract (item 9) in force. Explore's manual post-crystallization Review Engine and the supervised in-session Review Engine rounds are the only surfaces that form planning-artifact findings; phase workers have no worker-owned reviewer path. For the selected phase, supervised in-session rounds are the sole automatic convergence mechanism. Explore has no direct write tool; the explicitly user-selected **Plan - Unattended** route may dispatch only the existing `sai-1-spec-proposal-worker` and `sai-2-design-worker` bindings, whose writes remain limited to their selected owned change directory and the artifacts owned by that phase. The explicitly user-selected **Direct Build - Unattended** route may dispatch the existing fast-lane workers under `pipeline-direct-build.md`. Every other delegated write is unauthorized.

The route choice itself — presentation, deterministic selection over pending slices, and the route entries — lives in `route-selector.md`, which loads this file for the state below.

**State contract**: Maintain these values in conversation only:
- `tracked_changes`: the existing ordered, duplicate-free records in first-emission order. It is the review loop's (item 9) source only, and is never the deferred choice's dispatch source.
- `last_crystallization_set`: the ordered, duplicate-free `**Change name**` values emitted by the **most recent** crystallization turn (items 5 and 6), in emission order. Each crystallization turn replaces it wholesale; it starts empty.
- `completed_changes`: names whose applicable terminal worker returned `completed`; the spec worker is terminal when design is not entered, and the design worker is terminal after spec convergence.
- `active_change`: the selected name from dispatch until the applicable terminal phase ends; while non-null, another **Plan - Unattended** or **Direct Build - Unattended** choice is acknowledged as already running and dispatches and queues nothing.
- `active_phase`: `spec`, `design`, or null.
- `specs_converged_changes`: names whose spec review converged and whose spec artifact gate proceeded; membership survives a failed or cancelled design worker.
- `auto_answered`: phase-keyed `spec` and `design` ordered auto-answer records containing exact question, forwarded answer, and grounding citation.
- `escalated_count`: phase-keyed `spec` and `design` counts, with a running escalated count for each phase.
- `review_rounds`: one object with separate `spec` and `design` counters for the supervised in-session review rounds. Each phase has a budget of three rounds per `plan-unattended` attempt. At the start of each new attempt, reset `review_rounds.spec` and `review_rounds.design` to `0`; each counter counts only completed supervised rounds in that phase during the current `plan-unattended` attempt. Manual-loop reviews (item 9) are separate from supervised rounds and count toward neither counter, and failed or cancelled attempts do not count toward the new three-round bound.
- `diagnosis_rounds = { spec: 0, design: 0 }`: one conversation-only object with one counter per phase. Each counter is exactly `0` or `1` for the current `plan-unattended` attempt; reset both counters to `0` at the start of every new `plan-unattended` attempt and increment a phase counter exactly once when that phase's Diagnosis Round runs. These counters are independent of `review_rounds`, never change the ordinary three-round review budget, and stay out of worker payloads, journals, artifacts, configuration, and `.openspec.yaml`.
- `overview_language`: the selected language token for the crystallized idea or slice set, or the literal `None` when overview creation is declined, resolved non-committally, or bypassed by fast-track. A non-`None` value is the sole overview opt-in signal: it is selected by gate 9 at supervised **Plan - Unattended** activation or supplied by an explicit `--overview-lang` value. It is chat-scoped per crystallized idea or slice set; it survives a failed or cancelled supervised attempt so a later design retry can reuse it, and it resets when a materially new idea is explored. It is never written to any file.

Spec and design review rounds and autonomy records remain separate. State is chat-scoped, in-conversation-only, and never read from or written to repository state. A diagnosis-eligible non-clean result leaves the change uncompleted and retryable at that worker's phase. Cap exhaustion is non-failure and continues the run; only a result in the shared **Bounded Recovery** non-clean set or the Explore-only post-resolution supervised phase-worker `cancelled` exception interrupts it.

**Explore item-10 bounded Diagnosis Round**: On a resolved supervised phase-worker result in the shared **Bounded Recovery** non-clean set — a structurally valid `failed` result (any closed failure class), a coordinator-disproved `completed` result, or a `completed` result carrying STOP — or the Explore-only post-resolution supervised phase-worker `cancelled` result, an unused phase counter increments once and invokes `Review Engine(changeName, "sai-1")` or `Review Engine(changeName, "sai-2")` exactly once. Form the ordered `Reported`, `Evidence`, `Cause`, `Correction`, `Verification` record. Review Engine findings are forwarded to the same phase worker with at most one same-worker re-dispatch, expressed as exactly one `continue_after_recovery`, only for an actionable correction and a resumable worker; a cancelled result never becomes a standalone or manual recovery path. The phase worker alone applies the `Correction`: Explore never applies, writes, edits, or repairs it itself, and never dispatches a replacement worker. `sai/policies/bounded-recovery.md` is the single shared **Bounded Recovery** contract; its generic ledger and routing stay there. `continuation/transport loss` consumes the diagnosis round and never triggers replacement dispatch. Clean `completed` results (not coordinator-disproved and without STOP), `needs_input`, `progress`, `notice`, every pre-resolution result, and cancellations outside the Explore-only post-resolution supervised phase-worker exception never start diagnosis.

**Diagnosis-stop guidance**: An exhausted or failed diagnosis leaves the phase pending and `plan-unattended`-retryable on a later **Plan - Unattended** choice, never dispatches `/sai-3-implement`, and emits only the existing phase guidance — `Next step: run /sai-1-spec` for spec or `Next step: run /sai-2-design` for design — with no second next-step handoff.
