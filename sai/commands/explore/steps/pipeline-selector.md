# Item 10: Plan - Unattended / Direct Build - Unattended supervision state

This is one chat-scoped supervision contract. It persists no state, discovers no repository changes, and leaves the post-crystallization `review-loop` contract (item 9) in force. Explore's manual post-crystallization Review Engine is the only explore surface that forms planning-artifact findings; the plan coordinator's own review rounds belong to `/sai-plan`. Explore has no direct write tool; the explicitly user-selected **Plan - Unattended** route follows the `/sai-plan` coordinator, which may dispatch only the existing `sai-1-spec-proposal-worker` and `sai-2-design-worker` bindings, whose writes remain limited to their selected owned change directory and the artifacts owned by that phase. The explicitly user-selected **Direct Build - Unattended** route follows the Direct Build coordinator card (`sai/commands/explore/direct-build-coordinator.md`, loaded by `pipeline-direct-build.md`), which may dispatch only the existing `sai-direct-build-worker`, `sai-backfill-worker`, and `sai-archive-worker` bindings. Every other delegated write is unauthorized.

The route choice itself — presentation, deterministic selection over pending slices, and the route entries — lives in `route-selector.md`, which loads this file for the state below.

**State contract**: Maintain these values in conversation only:
- `tracked_changes`: the existing ordered, duplicate-free records in first-emission order. It is the review loop's (item 9) source only, and is never the deferred choice's dispatch source.
- `last_crystallization_set`: the ordered, duplicate-free `**Change name**` values emitted by the **most recent** crystallization turn (items 5 and 6), in emission order. Each crystallization turn replaces it wholesale; it starts empty. It holds names only: the validated block text of each name lives only in the `sai-state` store and reaches a worker only through `sai-state block <id> <change-name>`.
- `completed_changes`: names whose route ended with its applicable terminal result: the design segment of `/sai-plan` completed, or Direct Build archived.
- `active_change`: the selected name from dispatch until the applicable terminal outcome; while non-null, another **Plan - Unattended** or **Direct Build - Unattended** choice is acknowledged as already running and dispatches and queues nothing.
- `overview_language`: the selected language token for the crystallized idea or slice set, or the literal `None` when overview creation is declined, resolved non-committally, or bypassed by fast-track when no project setting answered. A non-`None` value is the sole overview opt-in signal: it is selected by gate 9, asked in round 3 of the route round and applied only on a **Plan - Unattended** route answer, supplied by an explicit `--overview-lang` value, or read from the `explore.overviewLanguage` project setting (values and precedence: `docs/project-settings.md`). It is chat-scoped per crystallized idea or slice set; it survives a failed or stopped run so a later retry can reuse it, and it resets when a materially new idea is explored. It is never written to any file.

State is chat-scoped, in-conversation-only, and never read from or written to repository state. A non-clean Plan result leaves the change uncompleted and retryable by a later **Plan - Unattended** choice; its failure handling, attempts, and escalations belong to the plan coordinator.
