# Implementation details (stage 3)

The shared presentation contract is **Display and question** in `list-writing.md`; answer evaluation, presentation currency, and the `- None` rule live in **List stages** in `steps/common.md`.

**Implementation details stage (stage 3).** Fetch @sai/commands/explore/list-writing.md and follow it for the draft, review pass, and display sequence and the unavailable-skill warning. When the idea came through issue intake with a carried `I` list, that list is the starting list; add items only from this stage's checks. When the user advances into `Implementation details`, surface the technical decisions found during exploration as numbered proposed statements `I1` through `In`, then apply **Display and question** in `list-writing.md`. When no technical decision qualifies, propose exactly `- None` as the list and apply that same presentation contract: the stage never closes on its own, and only a bare `next-step` or explicit agreement records the empty list and advances under **List stages** in `steps/common.md`. Only decisions that direct or constrain implementation qualify as `I` items; rationale and rejected alternatives belong in the block's **Decisions & Rationale** and **Alternatives Considered** sections. A decision whose object is a bookkeeping artifact of the change (`openspec/changes/{name}/**`, `openspec/specs/**`) does not qualify as an `I` item — it is a consequence owned by backfill and archive. An agreed `I` item MAY carry exact repository-relative paths when the agreed decision is grounded in specific files; this adds no field to the block template and does not convert the block into an implementation plan. Agreement, including agreement to `- None`, completes the stage and advances into `Crystallize` within the same turn, subject to the presentation-currency check in **List stages**.

**Later native stage selector.** The capability and response shapes are defined under **Optional native stage selectors** in `steps/common.md`.

Only after the established edge-case text question and implementation-detail text question have run in their existing order may a supported capability present one later selector in this order: a localized choice equivalent to `next-step` (`next-step`), a localized choice equivalent to discussion (`discuss-ideas-feedback`), and the free-text path. Present it through the harness-native picker per the "Closed-choice prompts" rule in `sai/policies/remember.md` (`AskUserQuestion` on Claude Code, `question` on opencode). In a Spanish conversation the labels are `Ir al siguiente step` and `Discutir ideas / dar feedback`. The later selector is additive and does not replace either text question. The localized advancement label maps exactly to the stable value `next-step`; the literal token remains unchanged wherever the existing contract names it.

The later response value `next-step` follows the existing literal `next-step` intent-recognition path exactly, including non-empty and empty edge-case branches, non-empty and empty implementation-detail branches, stage transitions, and entry into `Crystallize`. The discussion value and later-selector free text remain in ask mode and do not advance, agree a list, or crystallize. Arbitrary free text is never treated as advancement merely because a selector was displayed.
