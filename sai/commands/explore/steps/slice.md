**Post-crystallization slice machine (`explore-slice@1`).** After crystallization, explore consumes `explore-slice@1` in the same store session as `explore-idea@1`. The wire stays `{stage, next, rejected?, warnings?}`: `stage` is the slice TODO cursor (`idle`, then Direct Build `build-implement` → `backfill` → `archive`, or Plan `sai-1` → `sai-2` → `implement`). Last `idle` is rest (slice done, `active` cleared); it does not restart Plan or Direct Build. Inventory (`set` / `active` / `done`) and TODO mode live in store-owned state and never travel on the wire. Slice names come from Ready to Propose blocks in chat, not the wire.

Every `/emit` and `/restore` names `machineId: "explore-slice@1"`. An omitted or mistyped id is a closed error (`INVALID_EVENT` / `UNKNOWN_MACHINE`); nothing falls back to the first machine. Crystallize does not `/close`; `explore-idea@1` stays at `crystallize` in the map.

**Direct Build TODO.** Selecting **Direct Build - Unattended** emits `{intent: "direct-build"}`, which sets `active` and moves `stage` to `build-implement`. Completing each route item emits `{intent: "complete"}`: `build-implement` → `backfill` → `archive`. Completing Archive marks the slice done, clears `active`, and returns `stage` to `idle`. Another Direct Build or Plan selection while `active` is set is already running: dispatch nothing. Fail/cancel leaves the active step pending and does not mark the slice done. Direct Build never uses `next-slice`.

**Plan TODO.** Selecting **Plan - Unattended** emits `{intent: "plan"}`, which sets `active` and moves `stage` to `sai-1`. Completing sai-1 then sai-2 emits `{intent: "complete"}`: `sai-1` → `sai-2` → `implement`. Last `idle` is rest; it does not restart Plan. `pipeline-plan-unattended.md` is `next.follow` for all three Plan stages. Gate 9 runs only at Plan activation (enter sai-1). Fail/cancel/STOP/exhausted recovery on sai-1 or sai-2 leaves that step pending, keeps prior completed steps, and leaves the slice retryable; no skip to implement. Another Plan or Direct Build selection while `active` is set is already running: dispatch nothing.

**`next-slice` (Plan and Manual only).** Plan and Manual close the active slice only on the literal token `next-slice` — recognized by the same bare-token/dominant-intent machinery as the `next-step` token, firing when the turn is a bare token (optionally with trivial punctuation or a greeting) or when closing the current slice is the turn's dominant intent. Mere containment of the string `next-slice` SHALL NOT fire the token, and a turn that negates, defers, quotes, or discusses the token SHALL NOT close the slice. Direct Build never uses `next-slice`. The Plan `next-slice`-on-implement rule lives in `pipeline-plan-unattended.md`. Manual has no TODO; the user closes the slice with `next-slice`.
