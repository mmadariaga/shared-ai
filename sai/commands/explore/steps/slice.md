**Post-crystallization slice machine (`explore-slice@1`).** After crystallization, explore consumes `explore-slice@1` in the same store session as `explore-idea@1`. The wire stays `{stage, next, rejected?, warnings?}`: `stage` is the slice inventory cursor (`idle`, then Direct Build `build-implement` → `backfill` → `archive`, or Plan `sai-1` → `sai-2` → `implement`). Inventory (`set` / `active` / `done`) and TODO mode live in store-owned state and never travel on the wire. Slice names come from Ready to Propose blocks in chat, not the wire. A `recordedList` replaces `set` without moving the cursor.

Every `/emit` and `/restore` names `machineId: "explore-slice@1"`. An omitted or mistyped id is a closed error (`INVALID_EVENT` / `UNKNOWN_MACHINE`); nothing falls back to the first machine. Crystallize does not `/close`; `explore-idea@1` stays at `crystallize` in the map.

**Idle serves the deferred route choice.** `idle` maps via `next.follow` to `sai/commands/explore/steps/route-selector.md` with no machine version bump. First-idle with pending (at least one pending slice) presents the deferred choice once; rest-idle without pending (no pending slice, `active` cleared) is rest and presents no choice, dispatches nothing, and never restarts a route. Another choice while `active` is set is already running: dispatch nothing. Fail/cancel leaves the active step pending and does not mark the slice done.

**Plan and Manual close.** Plan and Manual close the active slice only on the literal token `next-slice` — recognized by the same bare-token/dominant-intent machinery as the `next-step` token, firing when the turn is a bare token (optionally with trivial punctuation or a greeting) or when closing the current slice is the turn's dominant intent. Mere containment of the string `next-slice` SHALL NOT fire the token, and a turn that negates, defers, quotes, or discusses the token SHALL NOT close the slice. Direct Build never uses `next-slice`. The Plan `next-slice`-on-implement rule lives in `pipeline-plan-unattended.md`. Manual has no TODO; the user closes the slice with `next-slice`.
