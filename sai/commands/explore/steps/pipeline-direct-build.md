  **Direct Build `--no-specs` profile (POC).** The POC lane (the conditional stage `poc-lane.md`, between `Explore change` and `Review edge cases`) dispatches its POC via Direct Build with the `--no-specs` flag. This profile runs the implementer only: no backfill, no OpenSpec specs, no artifact archive. The POC is a disposable experiment that discriminates the agreed candidates `C1..Cn`: dirty code is acceptable, minimal tests or human observation are the verdict authority, and no OpenSpec trail is created for the POC itself. The lane fetches the `sai-direct-build-worker` binding, sends the worker an envelope that starts `--direct-build --no-specs` and carries no file, hash, or report-directory line, and runs the card's Step 1 and Step 2 (implement and functional fix loop) without the suite gate, then returns to the POC lane, which forms the verdict: the winning agreed candidate, or none. The suite gate and Steps 3–8 (backfill, spec review, ADR/DDR, archive) are skipped entirely. The profile spends no recovery attempt, because a POC failure is the experiment's observation and correcting it automatically could hide the result. The POC does not create or modify anything under `openspec/`, does not create planning artifacts, and does not run mutating git commands: that last prohibition binds the dispatched implementer, not the lane's own reversible isolation, which `sai-explore` creates and abandons as the coordinator under the POC lane's isolation authority. The implementer's `changed_files` union is returned to the lane for verdict assessment. The POC is a direct worker dispatch that emits nothing to `explore-slice@1` and bypasses the slice machine entirely.

  **The profile is pinned.** `--no-specs` is reachable only from inside the POC lane: the deferred crystallization route choice never offers it (`route-selector.md`), and it is never the Plan or Manual route. `sai-explore` isolates the POC reversibly for the lane (its own branch or worktree, created before the POC runs and abandoned when the lane closes), so the code the profile writes is discarded with the isolation and never by destructive deletion of the working tree; only the verdict survives.

  **`direct-build-unattended` route projection lifecycle.** The selected slice's temporary Build route is initialized before Step 1 and is rendered by the explore coordinator as exactly three high-level items: `Build/Implement`, `Backfill`, and `Archive`. `Build/Implement` starts `in_progress`; after the implementer and functional fix loop converge and the Step 2b suite gate is green or skipped under no test suite found, it becomes `completed` and `Backfill` becomes `in_progress`; after clean backfill execution, `Backfill` becomes `completed` and `Archive` becomes `in_progress`; after the final archive execution and pre-authorized commit return a clean terminal `completed`, `Archive` becomes `completed`. The route label `Build/Implement` is not `/sai-build` and does not mean that the `/sai-build` command ran.
