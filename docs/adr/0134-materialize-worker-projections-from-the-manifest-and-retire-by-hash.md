# ADR 0134: Materialize Worker Matrix projections from the manifest and retire by hash

## Status

Accepted

## Context

The Worker Matrix replaces source files that existing installations may still contain. The installer, doctor, and uninstall flows must agree about active generated bytes while preserving user-modified historical files and every previously managed byte variant.

## Decision

Represent Worker Matrix outputs as deterministic managed projections in the install manifest. Feed the same expanded active graph to install, doctor, and uninstall. Retire every removed per-phase binding and managed-agent destination with complete lowercase SHA-256 `managedHashes` records; delete a retired file only when its bytes match a registered hash, and report/preserve all other bytes as drift.

## Alternatives Considered

- Retire by filename alone — rejected because it can delete user-modified files and cannot recognize historical managed variants safely.
- Leave old sources active as compatibility aliases — rejected because duplicate active projections would reintroduce drift.

## Consequences

Active projections are generated from one matrix and one manifest expansion, while historical cleanup remains hash-gated. Retirement records require maintenance whenever a managed source revision is shipped, but installation, doctor, and uninstall retain deterministic parity.
